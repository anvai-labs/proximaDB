**Pattern:** Single canonical file + symlinks at former copy sites. Zero maintenance drift.

### Phase 2: Rust Production Code — Optimizer Self-Clone

**File:** `src/query/federated/optimizer/mod.rs`

Extracted `plan_extension_node()` helper method on `CrossModelOptimizer` that consolidates 86 lines of duplicated `PlanNode` construction for `Logs`/`Metrics`/`Traces`/`VectorDistance` extensions. Both `plan_federated_query_with_statistics()` and `plan_federated_query()` now delegate via a catch-all match arm:

```rust
other => self
    .plan_extension_node(other, query)
    .ok_or_else(|| anyhow!("unhandled query source in federated plan"))?,
```

**Design principle:** Single Responsibility — extension→PlanNode mapping lives in one place. Adding a new observability extension type requires editing exactly one method.

### Phase 3: Python gRPC Generated Files — Re-Export Consolidation

**30 files** in `clients/python/src/proximadb/v1/` and `v2/` replaced with thin re-export modules:

```python
"""Re-export from proximadb_sdk — single source of truth."""
from proximadb_sdk.v2.graph_pb2 import *  # noqa: F401,F403
```

`proximadb_sdk` retains the canonical generated protobuf code; `proximadb` (the thin protocol-namespace package) re-exports from it. Eliminates ~5,000 lines of duplicated auto-generated code. Future `protoc` regeneration only needs to target one package.

## Design Principles Applied

1. **Single Source of Truth** — Each piece of knowledge lives in exactly one place (openapi converter, memory profiler, protobuf generated code, pgwire test harness)
2. **Re-Export over Copy** — `proximadb` re-exports from `proximadb_sdk` instead of duplicating generated code
3. **Extract Method** — Optimizer's duplicated PlanNode construction → single `plan_extension_node()` helper
4. **Shared Test Infrastructure** — 11 test files → one `TestPgServer` with `start_with()` customization seam
5. **Symlink for Identity** — Exact file duplicates replaced with symlinks to canonical source (zero drift)
