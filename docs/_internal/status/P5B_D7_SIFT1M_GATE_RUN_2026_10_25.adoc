== Round 1 (binary `7d84e8074`): what the gate run found

Round 1 failed every depth and request gate (e.g. one-segment bed, directory on: 22.65 requests/q, 9 waves, 541 ms; directory off: 22.75, 9, 560 ms — the same within noise). The investigation found:

. **The P5b read path was dark in the server.** The server's search reaches `StorageEngine::search_vectors_unified` → the non-Arc `fallback_to_direct_search` (its log line once per query; the Arc fan-out's never), while D2/D5-hand-off/D6 were wired only into the Arc fan-out that the unit tests call. Every "directory on" arm measured the per-segment cascade; the invariants-cache hit ratio of 0.999 was the tell (decoded scans never populate it). Round 2 shows 0.0.
. **Every default (Adaptive) query listed the collection twice** — the vector count, then the scan — two sequential round trips (MinIO trace: two `ListObjectsV2` ~52 ms apart per query).
. **The top-k block hand-off fired only on metadata-decoded scans**, so a warm-metadata query paid the OID-chunk wave and then the rehydration wave.
. **The new wave counter undercounted single-task fan-outs**: the non-Arc fan-out polls per-segment scans with `join_all` in one task, so grouping by task merged skewed scans' waves (round-1 multi-segment wave figures are lower bounds; one-segment arms ran sequentially and are exact).
. **A bed could settle on a 2.8 MiB untrained L0 flush tail** that training compaction never replaces; the harness waited 20 minutes silently. The harness now names unready segments; the gate beds use `--training-compaction-min-mb 1`.
. **Cell geometry is coarse by default**: the per-segment rule (one cell ≈ one IOP of SQ8 bytes) gives about 15 cells per 1M rows, so a query probes ~50% of rows. 32 cells is the passing point; 64 cuts bytes 20% but adds a wave (more, smaller cells push the probe past the same-wave Region-B budget).

Each of 1–4 is fixed in this branch with a test that fails without it.

== Cold-query shape (MinIO trace, round 2, directory on, k default)

77 complete queries: 1 LIST, then one wave of ~14–17 parallel GETs (probed cells' Region A + same-wave Region B, ranges ≤ 4 MiB), then a wave of ~5 GETs (top-k blocks); ~10.5 of 21.4 GETs/q are full 4 MiB Region-B ranges. Region-B bytes (47.6 MB/q) dominate the request count; larger ranges (the S3 profile's 8 MiB) or finer cells are the remaining levers.
