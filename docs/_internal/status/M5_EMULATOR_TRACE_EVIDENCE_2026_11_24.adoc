== 3. RTT ladder (toxiproxy-injected, skip-ingest on the leg-1 bed)

Toxiproxy 2.12.0 (docker `m5-toxiproxy`), proxy 127.0.0.1:9100 → MinIO, symmetric latency toxics
(L/2 down + L/2 up), fresh proxy daemon per arm. Cohort: 25 queries/phase (the first 100-query arm
was killed mid-phase on a misread "hang" — see Incidents; it was slow, never stuck). GET/q and
recall are RTT-invariant (counts, not latency); p50s are the latency shape. Arms marked ⚑ ran
while a release build compiled in the background — treat those p50s as upper bounds (the
contention signal is the RTT50 PAIR's qps: 0.29-0.31 for the two contended 25q arms vs 1.07-1.34
for the clean re-runs; no qps was recorded for the other legs, so the marker there rests on the
build-calendar, not a measured signal).

[cols="1,1,1,1,1,1,1", options="header"]
|===
| Arm | recall@100 (cold) | GET/q (cold) | waves p50 | bytes/q (cold) | cold p50 | cold p95
| direct ⚑ (leg-1 object_cold, proxy-free; compile-contended AND a 100-query cohort vs the 25-query arms) | 0.9881 | 18.64 | 2 | 51.2 MB | 833 ms | 1,976 ms
| RTT 50 ms — first 100-query attempt ⚑ | killed mid-phase on a misread hang (see Incidents: slow under contention, never stuck); excluded — no phase completed | | | | |
| RTT 50 ms — clean 25q re-run, exit 0 | 0.9932 | 18.12 | 2 | 50.9 MB | 770 ms | 1,108 ms
| RTT 50 ms ⚑ contended 25q, exit 0 | 0.9932 | 18.12 | 2 | 50.9 MB | 2,234 ms | 11,305 ms
| RTT 100 ms ⚑ contended 25q, exit 0 | 0.9932 | 18.12 | 2 | 50.9 MB | 882 ms | 1,247 ms
| RTT 150 ms ⚑ contended 25q, exit 0 | 0.9932 | 18.12 | 2 | 50.9 MB | 1,033 ms | 3,858 ms
|===

Reading: counts and recall are RTT-INVARIANT — GET/q (18.12-18.64), requests/q and recall@100
(0.9881-0.9932 across cohorts) hold at every level; the billed shape does not change with latency.
THAT invariance is this leg's measured claim. Every p50 in this table is REPORTED-ONLY and an upper
bound: the ⚑ rows overlapped background release compiles (the 2,234 ms vs 770 ms pair at the SAME
50 ms RTT shows the contention factor), and the direct rung additionally mixes a 100-query cohort
against 25-query arms — no rung-to-rung latency comparison is sound, and none is made. A real-cloud
link couples RTT with limited bandwidth; these localhost shapes bound nothing about cloud latency.

== 5. Object-store round-trip latency floor (bench_object_store_latency) — exit 0 ×4

All four legs via the production `store_for_url` (the same PR routes this bench through it — bare
`parse_url` cannot target an emulator endpoint). Direct leg: 200 iterations; toxiproxy legs: 50.

[cols="1,1,1,1,1,1,1,1", options="header"]
|===
| Leg | GET 4KiB p50 | last-4KiB-range 4KiB obj p50 | GET 64KiB p50 | last-4KiB-range 64KiB obj p50 | last-4KiB-range 1MiB obj p50 | whole 1MiB p50 | LIST p50
| direct MinIO (Docker NAT) | 5.0 ms | 12.9 ms | 12.7 ms | 1.1 ms | 17.5 ms | 65.6 ms | 8.6 ms
| +50 ms injected RTT | 60.2 ms | 55.3 ms | 65.5 ms | 80.8 ms | 81.4 ms | 253.2 ms | 79.4 ms
| +100 ms injected RTT | 130.4 ms | 128.2 ms | 149.7 ms | 131.9 ms | 129.3 ms | 285.0 ms | 104.9 ms
| +150 ms injected RTT | 153.5 ms | 153.6 ms | 154.1 ms | 153.9 ms | 154.3 ms | 162.7 ms | 153.9 ms
|===

Reading: the per-op overhead above the injected RTT varies by leg (+3.5 to +4.3 ms at +150 ms;
+5.3 to +31.4 ms at +50 ms; +4.9 to +49.7 ms at +100 ms, the whole-GET 64 KiB row) and is NOT
attributed — no per-op breakdown was measured. Whole-object 1 MiB GET clearly adds a transfer
term (253-285 ms at +50/+100 ms; 162.7 ms at +150 ms). The "range" columns are the bench's
last-4KiB tail ranges of each object size (the footer-read shape), not ranges of that many bytes.
Failed operations COUNT AS SAMPLES (the bench records a failing op's observed latency and emits
no error counts), and every cell is 10 warmup + 50 timed iterations (200 direct). All p50s in
this table are transcribed from the run's raw stdout (now committed beside this artifact — see
`m5_raw_floor_bench.txt`; the whole-GET 64 KiB column was added in review round 2 against that
output, not from memory). These are FLOOR shapes on an emulator — the numbers a route-cost model
must beat, not cloud SLAs.

== Incidents (recorded, not hidden)

* **Apparent hang at RTT50 — RESOLVED AS NOT A HANG (round 3, verified against the run's complete
  server log; the previously filed the withdrawn S3-stall TD is WITHDRAWN and
  link:../../10-quality/td/TD-BENCH-3-sift-harness-no-intra-phase-progress.adoc[TD-BENCH-3]
  records the real gap):** the first 50 ms ladder attempt (100 queries) was killed mid-phase in
  the belief the server had blocked on a proxy-torn connection. The log shows the opposite:
  server lifetime 23:02:42.954Z → SIGTERM 23:10:09.357Z (7 min 26 s total — which rules out any
  multi-minute block); 46 search requests, 45 completed, the 46th 6.3 s in flight at
  SIGTERM; largest gap between search completions 38 s; the last completion 6.3 s before SIGTERM.
  One query hit the store's default request timeout ("Encountered error while reading response
  body … Retrying in 0.1s", exactly 30.00 s after that search started) and its RETRY SUCCEEDED
  (completed in 38,016 ms, 100 results). The run was SLOW under concurrent compile load
  (~7-12 s/query vs ~0.9 s clean) and never stuck; the harness prints only at phase end, so a
  slow phase reads as a hang from the outside. The kill left no result.json (my round-1-2 claim
  that it "records the partial phase" was wrong).
* **Compile contention — THE authoritative contended-arm list (the ledger points here and does
  not re-enumerate):** the leg-1 SIFT1M phase sweeps (including the 833 ms direct rung), the
  first RTT50 25q re-run, the RTT100 arm, the RTT150 arm, and briefly the pgwire leg overlapped
  background release builds (visible as qps 0.29-0.31 vs 1.07-1.34 on the clean runs); their
  p50s are upper bounds, marked ⚑ where they appear in tables. A clean RTT50 re-run landed
  (770 ms cold p50 vs the contended arm's 2,234 ms at the same injected RTT) and is the
  authoritative 50 ms row.
* **Dirty-worktree guard firings (2):** two ladder launches were refused by the harness's own
  "benchmark refuses a dirty worktree" guard after in-flight doc edits — recorded as exit 1 with
  that message; re-launched after committing. No measurement was affected.

== Reading the numbers honestly

* Store is an EMULATOR on localhost. GET/request/footer counts transfer to any S3-shaped backend;
  latency does not (Docker NAT adds ≈ 4-7 ms/op; toxiproxy adds its configured symmetric RTT and
  couples RTT into bulk transfer — the known rdstrat12 caveat).
* **Real-cloud confirmation deferred pending credentials (owner, 2026-11-24).**
* Latency legs are 25-query cohorts — the shape (growth with RTT), not calibrated percentiles.
