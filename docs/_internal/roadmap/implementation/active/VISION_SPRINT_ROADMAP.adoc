== Assumptions

* Sprint length: 2 weeks
* Time horizon: 0-3 months (S1-6), 3-6 months (S7-12), 6-12 months (S13-24)
* Roadmap prioritizes SOLID design and extensibility for new engines and protocols.

== SOLID Design Guardrails (Apply Across All Milestones)

* **Single Responsibility**: isolate parse/plan/execute, scan/provider, catalog/governance.
* **Open/Closed**: add engines, protocols, and catalogs via interfaces and adapters.
* **Liskov Substitution**: all engine/protocol implementations must satisfy shared contracts.
* **Interface Segregation**: split read providers (scan/filter/project) and protocol handlers.
* **Dependency Inversion**: query and governance depend on abstractions, not concrete engines.

== Phase 0-3 Months (Sprints 1-6)

=== M1: Unified Cross-Model Planner and Executor (S1-S3)

*Owner modules:* `src/query/federated/mod.rs`, `src/query/unified/mod.rs`,
`src/query/unified_query_optimizer.rs`, `src/network/rest/v1/unified_query.rs`,
`src/api_handlers/unified_handlers.rs`

*Sprint plan:*

* **S1**: Inventory all query paths and define a single Planner/Executor interface.
* **S2**: Route all multi-model SQL (`VECTOR_SEARCH`, `GRAPH_QUERY`, `DOCUMENT_QUERY`, `LOGS`,
  `METRICS`) through the federated context.
* **S3**: Remove or feature-gate redundant paths; unify plan/metrics schema.

*Acceptance criteria:*

* All multi-model SQL endpoints execute via one planner/executor path.
* `/api/v1/unified/explain` returns a single plan format across REST and gRPC.
* Legacy query paths are disabled or isolated behind compile-time flags.

*Test checklist:*

* Unit tests: parser and optimizer in `src/query/federated/*`.
* Integration tests: REST + gRPC multi-model queries.
* Regression tests: vector-only, document-only, and graph-only queries.
* Explain plan smoke test: consistent plan schema and metrics.

=== M2: Dual Columnar Execution (Arrow In-Memory + I/O Range Scan) - Core (S2-S5)

*Owner modules:* `src/storage/engines/core/formats/columnar/columnar_query_engine/*`,
`src/storage/engines/core/formats/columnar/unified_compaction.rs`,
`src/query/unified_query_optimizer.rs`

*Sprint plan:*

* **S2**: Introduce `ColumnarReadProvider` and scan-policy abstraction.
* **S3**: Implement Arrow RecordBatch in-memory scan provider (protocol-optimized).
* **S4**: Implement range-pruned I/O scan provider (physics-optimized).
* **S5**: Planner selects provider; metrics track bytes scanned and provider choice.

*Acceptance criteria:*

* Two scan providers co-exist and are selectable via planner policy.
* Same query returns equivalent result sets across providers (order differences allowed).
* I/O scan performs pruning and emits bytes-scanned metrics.

*Test checklist:*

* Unit tests: scan provider selection and Arrow conversion.
* Integration tests: identical query results across providers.
* Performance tests: pruning effectiveness on clustered data.

=== M3: Graph API Parity (REST/gRPC) (S4-S6)

*Owner modules:* `src/api_handlers/unified_handlers.rs`, `src/graph/service.rs`,

=== M4: Observability and Health Baseline (S5-S6)

*Test checklist:*

== Phase 3-6 Months (Sprints 7-12)

== Definition of Done (Applies to All Milestones)

* Feature flag is documented and defaults are safe.
* Tests pass in CI for affected modules.
* Docs updated in `docs/` and `docs/_internal/` as appropriate.
* Metrics cover the new feature path.
