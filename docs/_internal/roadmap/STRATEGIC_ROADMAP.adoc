== How a release closes

A release is done when its exit criteria pass as **executable checks**, not prose:

* every listed TD is Resolved (or explicitly moved to a later release here, with a reason);
* the conformance and recall ratchets did not go down (TPC-H, TPC-DS, ANN recall@k);
* durability and wire-protocol work ships with tests written first and an end-to-end smoke
  (pgwire e2e suites, crash matrices, `scripts/smoke_oltp_reattach_minio.sh`);
* every merged change had a fresh-context adversarial review;
* the reconcile in ADR-096 D5 was re-run: vision, PRD, roadmap, support contract and diagrams
  agree.

== Where we are

*Released (v0.4.1, 2026-10-16).* v0.3 and v0.4 built the SQL engine over object storage that
ADR-096 names as the direction:

* the unified storage substrate — format follows modality (ADR-094);
* pgwire `vector_search` and the `<->` operator, and DataFusion/DuckDB routing for analytical SQL
  (ADR-052, ADR-059);
* delete vectors and always-PAX flush and compaction;
* security hardening and WAL-replay durability fixes (see `CHANGELOG.md`).

*On `develop`, unreleased (ships in v0.5):* atomic COMMIT and writer-epoch fencing on a
reattachable volume, default-off (ADR-095); read-path correctness — deleted rows no longer
resurrected and flushed updates no longer lost (TD-PGWIRE-VECDEL-1).

The MVP corridor (REST v2 records on SST, single node) is the supported promise.

Release themes below are unchanged. Live P0–P6/SC0–SC6 status and branch ownership are

link:../status/ROADMAP_WORKTREE_RECONCILIATION_2026_10_26.adoc[the worktree audit] records WIP,

== v0.5 — Correct and durable

*Theme:* the SQL front door is correct, durable and tenant-safe before anything is added to it.

[cols="2,3,2", options="header"]
|===
| Work | Exit criterion | TDs

| Read correctness
| One total order for versions of a record on every read surface; standard literal predicates work; a collection created without an engine gets the Supported SST engine.
| TD-MEMTABLE-MVCC-1, TD-PGWIRE-LITPRED-1, TD-ENGSEL-1, TD-RELIDEQ-1

| Transactions and recovery
| Group commit; REST/gRPC writes share the atomic path; writer epoch stamped into the WAL and manifests; reattach smoke in CI.
| TD-PGOLTP-1 (S3, S4b), TD-PGOLTP-2 (S3)

| Bounded memory and WAL
| Relational memtable spills and the WAL truncates safely; path defaults never resolve against the working directory.
| TD-USUB-1, TD-CONV-1, TD-CONV-2

| Native table provider by default
| Window functions and ABAC behave the same for every session.
| TD-USUB-2, TD-USUB-3

| Tenant safety on every surface
| One admit/deny decision across REST, gRPC, Flight and pgwire; missing identity fails closed; the cross-model policy-matrix tests pass.
| TD-AUTHZ-1, TD-TENANT-2, TD-PGWIRE-VECTENANT-1, TD-SECSCAN-1

| Startup self-check
| A loopback Flight call verifies the instance identity at boot.
| TD-NET-1 (S3)

| pgwire reachable from the published image
| Authenticated pgwire exposure, so `docker run` plus a Postgres client works (ADR-096 durable outcome 1).
| TD-PGWIRE-CONTAINER-1

| Installs that work
| The Docker image persists data in its volume; the RPM/DEB service starts and keeps data under `/var/lib/proximadb`; the MSI installs a Windows service; each is smoke-tested (write, restart or recreate, read) in the release workflow.
| TD-PKG-3, TD-PKG-1, TD-PKG-2

| First run works from every client
| A collection created over gRPC stores records; the Python SDK raises on failed writes, never falls back silently, honours filters and engine choice, and its documented examples run in CI against the release image.
| TD-GRPCCREATE-1, TD-SDKERR-1, TD-SDKENG-1, TD-SDKDOC-1, TD-RESTGET-1

| Drivers work
| JDBC, asyncpg and psycopg 3 read relational tables over the extended protocol; smoke-tested against the release image.
| TD-PGEXT-1
|===

== Later (ordered, after v1.0)

. **Scale out**: distributed transport and failover verification (TD-077), then replication and
  multi-node failure-injection validation, then elastic compute modes (TD-089).
. **Agent memory**: write surface, framework adapters, branching, and the neutral fusion core
  (TD-101, TD-102, TD-117, TD-136, TD-137).
. **Time-series, events and observability** graduate as projections of the canonical record
  (TD-063); time travel by LSN (TD-116).
. **Lineage** hooks for vector, document and graph writes, beyond MLOps (TD-MLOPS-1).
. **Interoperability**: Iceberg snapshots readable by Spark and Trino (TD-119), Lance (TD-091),
  Spark and Hadoop connectors (TD-097, TD-099), external collections residual (TD-090).
. **In-database inference** and **billion-scale vector indexes** (DiskANN, after TD-064).

== History

Items marked in earlier drafts as coming from "the removed vision sprint plan" (M1, M5, M8, M9,
M10) or "the best-in-class tracker" are now owned by TDs listed above; those plans were deleted on
2026-10-17 and their text is in git history.

Until 2026-10-17 this roadmap was organised in numbered phases (1–8 and 2.5), alongside separate
milestone lists in the vision and the PRD. ADR-096 replaced all of them with this release frame.
In summary: Phase 1 (format and catalog contract), Phase 2.5 (execution-layer performance),
Phase 4 (hybrid search, time-series and event foundations) and Phase 5 (agentic research) were
completed or landed at Beta; Phases 2, 3, 6, 7 and 8 had open work, which is carried into the
releases above through their TDs. The phase tables, the 2026-06-24 and 2026-10-15
reconciliation notes and the per-row evidence are in git history.
