== Phase 2.5: Foundational Performance Alignment [✅ effectively complete]

[NOTE]
====
*Status reconciled 2026-06-24:* the Phase 2.5 execution-layer items have landed — TD-031 (vectorized
pipeline), TD-032 (Arrow cross-model), TD-033 (row-group pruning), TD-034 (spill-to-disk L2),
TD-036 (adaptive codec, already done), TD-038 (cross-modal durable commit), TD-039 (morsel
parallelism), TD-041 (vectorized executor wired) are all *Resolved* in the
link:../../10-quality/TECHNICAL_DEBT.adoc[Technical Debt Register]. TD-035 (graph executor) and TD-040
(read-side quant pruning) remain Open/Partial. The "📅 NEW / planned" markers and the April–July
sprint timeline below are *historical*; do not treat them as current.
====

[.lead]
_Performance Credibility: Align the execution layer between storage and API with single-node analytical system patterns (DuckDB, Polars). Without this, columnar analytics and cross-model query performance claims are not substantiable._

[IMPORTANT]
====
Added March 21, 2026 based on architectural review (archived at `docs/_archive/roadmap/2026-05/ARCHITECTURAL_REVIEW_2026_03_21.adoc`).
The storage layer (ProximaCodec, Parquet integration, WAL) is production-grade.
The gap is in the *query execution layer above storage* -- the layer that turns columnar storage into fast analytical queries and eliminates format conversion at model boundaries.
====

=== Phase 2.5 planned workstreams — History

The March 2026 plan's per-workstream tables are in this file's git history (before 2026-10-15).
They covered: DataChunk vectorized operators, selection vectors and pipelines; Parquet typed
row-group, page and bloom pruning; Arrow `RecordBatch` as the cross-model lingua franca; graph
executor completion; L2 NVMe spill, external sort and hash-join spill; morsel-driven parallelism;
wiring the vectorized executor into `UnifiedParquetReader`; and durable cross-modal 2PC.
The outcomes are in the table below. The single highest-ROI item, wiring the existing vectorized
executor into the primary path (TD-041), turned out to be plumbing, not new engine work. Later,
ADR-052 moved OLAP execution to DataFusion's kernels, so native HashAgg/HashJoin/Sort are no longer
a build target. Two rows remain open:

* *Graph Query Executor Completion (TD-035)* — Traverse, Filter, Project operators: complete stubbed
  `executor.rs`; execute plans from query planner instead of bypassing to direct engine calls; return
  `RecordBatch` from graph queries for integration with federated execution.
* *Read-side quantization-aware row-group pruning (TD-040)* — write-side stats landed; read-side
  pruning open.
