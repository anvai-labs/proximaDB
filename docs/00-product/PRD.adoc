== Positioning

For application and platform engineers who today join a vector index back to an operational
database and a warehouse, ProximaDB is a **SQL-first context engine on object storage**: a
Postgres-compatible database in which vectors, JSON and relationships are first-class, with one
governed record, standard interfaces and per-query cost evidence. Unlike a vector database it
serves transactional and analytical SQL over the same record; unlike a warehouse it is built
for low-latency retrieval and serving.

== Personas

[cols="1,2,3", options="header"]
|===
| Persona | Role | Key needs

| Application / AI engineer
| Builds RAG, agent memory, semantic search and recommendation features.
| SQL and SDK access to vectors with metadata filters in one query; read-after-write correctness; framework integrations; a working query within ten minutes of `docker run`.

| Platform engineer
| Runs the database in production.
| One binary or container; object-storage durability and boring recovery; tenant isolation; Prometheus metrics; backup and restore.

| Data engineer
| Builds pipelines and analytical queries.
| ANSI SQL from standard tools (psql, JDBC, BI, dbt); CDC; Parquet interoperability; analytical joins and aggregates.
|===

Use-case-specific requirements (for example the ibkrtrading migration's embedded mode,
sub-millisecond time-series reads and MiFID II audit) live in the
link:../11-usecases/USECASE_CATALOG.adoc[use-case catalog], not in this list (ADR-096 D2).

== Requirements

=== Must have for v1.0

[cols="1,3,2", options="header"]
|===
| Requirement | Acceptance | Tracked by

| Correct ANSI SQL over pgwire
| TPC-H (22) and TPC-DS ratchets over pgwire only go up; standard Postgres clients and drivers work; errors carry a specific SQLSTATE.
| `tests/tpch_pgwire_e2e.rs`, `tests/tpcds_pgwire_e2e.rs`, ADR-018

| Transactions with Postgres semantics
| COMMIT is all-or-nothing, survives a crash and a volume reattach, and a fenced writer cannot acknowledge; compatibility declared in levels.
| ADR-095, TD-PGOLTP-1..10, `scripts/smoke_oltp_reattach_minio.sh`

| Vectors inside SQL
| `vector_search` table function and the pgvector `<->` operator reach one canonical vector-search plan; filtered ANN holds recall within tolerance of the f32 baseline.
| TD-XMODAL-4, TD-064, recall ratchets (`tests/sift_pax_recall_ratchet_test.rs`, `tests/filtered_ann_recall_bands.rs`)

| One canonical record, read correctly everywhere
| A delete is never resurrected and a read after a write sees the write, on every read surface (SQL, REST, gRPC, Flight, `documents()`).
| Read-after-write invariant (dead records filtered at every read boundary), TD-MEMTABLE-MVCC-1, TD-PGWIRE-VECDEL-1

| Object-storage durability and recovery
| Crash/restart, bounded-memory and economic suites pass on each object store before it is claimed.
| MVP corridor, TD-OBJSTORE-*, TD-USUB-1

| Structural tenancy and policy
| Every surface admits or denies identically (REST, gRPC, Flight, pgwire); missing tenant identity fails closed.
| TD-AUTHZ-1, TD-TENANT-2, TD-PGWIRE-VECTENANT-1, TD-SECSCAN-1

| Per-query cost evidence
| Bytes, requests and egress are traced per query and metered per tenant; the planner routes from measured costs.
| Co-design mandate, `BENCHMARK_EVIDENCE.toml`
|===

=== Should have

* **Hybrid retrieval inside SQL** — BM25 plus vector fusion through one fusion seam (TD-138,
  TD-139, TD-143).
* **JSON documents as a SQL projection** — the `documents()` table function over the canonical
  record, with pushdown.
* **Graph as a projection** — traversal and the supported openCypher subset over the canonical
  record (TD-124 residuals: `ExecuteHybridQuery` on v2, Gremlin).
* **Continuous discovery loop** — deduplication, reclustering and re-embedding passes publish
  atomically into serving (TD-086).
* **Spec-generated SDKs** — Python, Node, Go and Rust REST clients generated from the OpenAPI
  spec, with drift gates (TD-126).
* **Framework integrations** — status today: not a Supported surface (see
  link:../SUPPORTED_SURFACE.adoc[SUPPORTED_SURFACE.adoc]). LangChain, LlamaIndex and others ship
  in the Python SDK.

=== Could have

* **Time-series and event projections** — status today: Beta (see
  link:../SUPPORTED_SURFACE.adoc[SUPPORTED_SURFACE.adoc]). ASOF joins, downsampling and immutable
  event logs, graduating as projections of the canonical record (ADR-096 D3).
* **In-database inference** — embedding and reranking models served inside the engine.
* **Distributed execution and elastic compute** — multi-node transport and failover (TD-077),
  then elastic modes (TD-089).
* **External collections** — ProximaDB indexes over lake-resident Iceberg, Lance or Parquet data
  without copying it (TD-090, TD-091).
* **Billion-scale vector indexes** — DiskANN, once predicate-aware top-k correctness is explicit
  (TD-064).

=== Won't have (now)

* A general-purpose cloud data warehouse competing feature-for-feature with Snowflake or
  Databricks.
* A full PostgreSQL replacement: stored procedures, triggers, PL/pgSQL and multi-writer sharding
  are not on the ADR-095 path.
* Model training, message-queue fan-out, or decentralized consensus.

== Non-functional targets

These are targets, not claims. A number becomes a claim only when a runnable benchmark backs it
in the evidence ledger (`docs/_internal/roadmap/BENCHMARK_EVIDENCE.toml`), measured as a
per-query end-to-end trace rather than a kernel microbenchmark.

[cols="2,2", options="header"]
|===
| Target | How it is measured

| Zero acknowledged-write loss under crash, kill -9 and volume reattach | Crash-matrix tests and the MinIO reattach smoke
| Filtered vector search recall within tolerance of the f32 baseline | Recall ratchets on SIFT1M and filtered bands
| TPC-H and TPC-DS conformance over pgwire that only goes up | `tests/tpch_pgwire_e2e.rs`, `tests/tpcds_pgwire_e2e.rs`
| Cold-start and recovery time bounded by checkpoint, not WAL length | Recovery integration tests (ADR-095 D6)
| Object-store requests and bytes per query reported and bounded | Per-query I/O trace (co-design mandate)
|===

== Quality bar

Enforced in CI, so it is not repeated as targets here: no `unwrap`, `expect` or `panic!` in
production code (panic-policy baseline); clippy with `-D warnings`; layering and tenant-path
guards; spec-generated SDK drift gates; the TD/ADR status guards; and the conformance and recall
ratchets, which only go up. Engineering practice — tests first, end-to-end smoke for durability
and wire-protocol slices, adversarial review before merge — is described in
link:../06-internals/contributing.md[the contributing guide].

== Compliance

* **SOC 2** — access control, audit logging, and encryption at rest and in transit.
* **GDPR** — deletion that is honoured on every read surface (the read-after-write invariant) and per-tenant data
  placement.
* Sector-specific requirements (MiFID II, SEC 17a-4) belong to the use cases that need them.
