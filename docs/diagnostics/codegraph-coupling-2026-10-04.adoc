== How to address (multimodal / database / large-codebase practice)

. *Hidden hubs first*: `advisor_observations.rs` (fan-in 564, absent from every
  slice) and `compute_bridge/global_cache.rs` (270) are higher-leverage than
  any named slice — audit, split, or convert to ports before Phase 3 moves.
. *Multimodal*: the fusion surface is already single-port-shaped
  (`FusionService` consumed by graphs/hybrid/entities) — formalize it as
  `FusionSearchPort` in `proximadb-runtime` (ADR-094 PR-3.1b) so multimodal
  stops reaching concrete services, and move the fusion params types
  (`crate::core::search::{cross_modal_fusion, fusion_route}`) to a query
  contract crate.
. *Database core*: `src/storage/engines → src/services` (185 edges) is the
  exact Slice-D remainder — finishing `IndexPort` + engine injection converts
  the largest cross-layer fan in the codebase.
. *Extreme-engineering ratchets*: adopt the storage-up-edges pattern for
  per-FILE fan-out ceilings (top table above gives the starting ceilings),
  wire `check_v2_root_imports.sh`-style count ratchets for the low-cohesion
  hubs (`src/core`, `src/services`), and add a periodic codegraph export +
  coupling-diff to CI so regressions in this table become visible PR-over-PR.
. *Engine thinning*: raptor (fan-out 65, experimental, ADR-093-family) —
  isolate behind its feature gate and schedule retirement review; do not let
  the highest-coupled file in the repo be an experimental engine.
