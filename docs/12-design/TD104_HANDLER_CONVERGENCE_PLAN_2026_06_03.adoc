== History

*Capability:* REST, gRPC, Arrow Flight and pgwire depend on port traits (`ApiHandlersPort`,
`RecordOpsPort`, `CollectionPort`) built at the composition root. The two-handler split was the
inherent-logic root `UnifiedHandlers` (12 concrete services, ~30 inherent methods) against the
port-based runtime one. It is gone.

*Decisive findings:*

* **The REST fallback looked dead but was load-bearing.** The `unwrap_or_else(ROOT)` fallback served
  multi-port mode with gRPC disabled. S1 had to hoist the `api_handlers` wiring out of the gRPC-gated
  block before the fallback could go. Replacing it with `.expect` would have panicked.
* **Arrow Flight was the last consumer.** Its record-batch request/result types lived in the root
  crate, so a port below the root could not name them. S3 first relocated `BatchOperationResult` down
  to `proximadb-runtime`, then defined `RecordOpsPort`.

*Lesson that still applies:* a same-trait reference swap is safe to land compile-only. A cross-crate
type relocation on a wire-protocol path is not, and needs a protocol smoke test (here a Flight
DoPut/DoGet/ListFlights loop).

*Evidence:* the 131 Arrow service/codec tests passed unchanged across S3b.
