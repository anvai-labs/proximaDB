== Decision Index

Every Q1–Q14 raised in the HLD is locked here with a single decision per row.

[cols="1,4,4", options="header"]
|===
| ID | Question | Decision

| Q1
| Wire format for persisted `TurboQuantVectorData`: byte layout, alignment, endianness.
| 16-byte aligned header followed by per-vector records. Little-endian only (assert at startup per `EMBEDDING_PRECISION_LLD` Q8). See §3.

| Q2
| Persistence file naming.
| `/{data_dir}/collections/{collection_id}/quant/turboquant_v1_{bit_width}b.tq` — co-located with the collection's other quantized projections.

| Q3
| Per-collection rotation seed derivation.
| `seed = u64::from_le_bytes(blake3("turboquant.v1.rotation" \|\| collection_id).as_bytes()[0..8])`. Persisted as `collection.turboquant.rotation_seed: u64` in xCatalog.

| Q4
| Lazy vs eager SIMD-blocked code materialization.
| Lazy on first `search()` after `add()`. Matches turbovec's `OnceLock` pattern. Avoids ingest latency cost; first-query cost is one-time and ≪ 1s at d=1536, n=1M.

| Q5
| Calibration storage location.
| Persisted *alongside codes* in the `.tq` file body (per-collection per-bit-width). Not in xCatalog — too large at high d. xCatalog only stores presence flag + epoch.

| Q6
| TQ+ minimum sample threshold.
| `TQPLUS_MIN_SAMPLES = 1000` (matches turbovec). Not parameterized in P1; revisit if benchmarks show drift on high-d / low-d edge cases.

| Q7
| Identity-calibration fallback semantics.
| Silent fallback with EXPLAIN surfacing `calibration_mode = "identity"`. Re-fitting triggered only on epoch bump or explicit `recalibrate` call.

| Q8
| AXIS adapter parameter shape.
| **New** parameter `candidate_set: Option<&dyn CandidateSet>` appended to existing `search()` signatures. The existing `filter: Option<&HashMap>` is retained for back-compat and metadata filtering at the storage layer.

| Q9
| Epoch-bump re-encode policy.
| Lazy: serve from stale codes until next `add()` / `search()`, then trigger async re-encode via the existing background-task scheduler in `src/services/`. Mismatching reads tagged in EXPLAIN as `epoch_mismatch`.

| Q10
| 3-bit path.
| Defer to a follow-up session. P2–P4 ship 2-bit and 4-bit only. The codebook + encode paths are bit-width-parameterized so 3-bit slots in without kernel changes; the `repack_3bit` SIMD layout is the only new work and not on the critical path.

| Q11
| Bit-identical-scoring test corpus.
| 1k random vectors at d=128, 768, 1536; 100 random queries. Encode on host arch, persist, search on a CI runner of the other arch (GitHub Actions provides both linux/amd64 and macos-arm64). Score arrays must be element-wise equal at f32 precision.

| Q12
| Prometheus metric naming.
| `proximadb_turboquant_blocks_skipped_by_mask_total` (counter, labels: `collection_id`, `bit_width`). Matches existing metric-naming convention in `src/observability/metrics.rs`.

| Q13
| EXPLAIN field name.
| `mask_pushed_to_kernel` (snake_case, matches existing ADR-004 field convention).

| Q14
| Recall validation gates.
| Per-bit-width gates: 2-bit R@10 ≥ 0.85 on OpenAI d=1536 / d=3072, ≥ 0.78 on GloVe d=200; 4-bit R@10 ≥ 0.95 on all three. Gates source the same datasets and metric methodology as turbovec's `benchmarks/results/` JSON.
|===

== Wire / Storage Layouts (Q1, Q2, Q5)

=== `.tq` file format v1

All multi-byte integers little-endian. All offsets relative to file start.

----
+--------------------------------------------------------+
| File header (64 bytes, 16-byte aligned)                |
|   [0..4]   magic = b"PQTQ"                              |
|   [4..6]   version = u16 = 1                            |
|   [6..7]   bit_width = u8 ∈ {2, 4} (P1); {2, 3, 4} (P10)|
|   [7..8]   calibration_mode = u8 (0=Identity, 1=TqPlus) |
|   [8..16]  rotation_seed = u64                          |
|   [16..24] dim = u64                                    |
|   [24..32] n_vectors = u64                              |
|   [32..40] encoded_epoch = u64                          |
|   [40..48] codes_offset = u64                           |
|   [48..56] scales_offset = u64                          |
|   [56..64] calibration_offset = u64 (0 if Identity)     |
+--------------------------------------------------------+
| Bit-packed codes (codes_offset..scales_offset)         |
|   n_vectors × ceil(dim * bit_width / 8) bytes           |
|   16-byte aligned start; pad-aligned to 16 at end       |
+--------------------------------------------------------+
| Per-vector scales (scales_offset..calibration_offset)   |
|   n_vectors × f32 (4 bytes each)                        |
+--------------------------------------------------------+
| Calibration (calibration_offset..EOF), if TqPlus only   |
|   dim × f32 shift, then dim × f32 scale_tq              |
+--------------------------------------------------------+
----

Validation invariants enforced at load:

* `magic == b"PQTQ"` and `version == 1` (else `ProximaDBError::InvalidFormat`).
* `dim > 0 && dim % 8 == 0`.
* `bit_width ∈ {2, 4}` (P1); reject 3 until P10.
* `codes_offset + n_vectors * ceil(dim * bit_width / 8) <= scales_offset`.
* `scales_offset + n_vectors * 4 <= calibration_offset || calibration_offset == 0`.
* If `calibration_mode == TqPlus`: `calibration_offset != 0` and `file_size - calibration_offset == 2 * dim * 4`.
* If `calibration_mode == Identity`: `calibration_offset == 0` and file_size == `scales_offset + n_vectors * 4`.

=== `CandidateMaskSet`

[source,rust]
----
// src/core/search/filter_contract.rs (extension)
pub struct CandidateMaskSet {
    bitmap: Vec<u64>,
    n_set: usize,
    n_slots: usize,
    id_resolver: Arc<dyn SlotIdResolver>,
}

pub trait SlotIdResolver: Send + Sync + std::fmt::Debug {
    fn id_for_slot(&self, slot: usize) -> Option<String>;
    fn slot_for_id(&self, id: &str) -> Option<usize>;
}

impl CandidateMaskSet {
    pub fn new(n_slots: usize, id_resolver: Arc<dyn SlotIdResolver>) -> Self {
        let n_words = (n_slots + 63) >> 6;
        Self { bitmap: vec![0; n_words], n_set: 0, n_slots, id_resolver }
    }
    pub fn bitmap(&self) -> &[u64] { &self.bitmap }
    pub fn set_slot(&mut self, slot: usize) {
        if slot >= self.n_slots { return; }
        let was = (self.bitmap[slot >> 6] >> (slot & 63)) & 1;
        if was == 0 {
            self.bitmap[slot >> 6] |= 1u64 << (slot & 63);
            self.n_set += 1;
        }
    }
}

impl CandidateSet for CandidateMaskSet { /* delegate via id_resolver */ }
----

The trait impl methods that take `id: String` resolve through `id_resolver`; methods that already operate on slots (`top_k`, future kernel-aware methods) operate directly on the bitmap. `intersect` between two `CandidateMaskSet`s with the same `n_slots` is a u64-wise AND across bitmaps; `union` is OR.

=== Per-block mask predicates

[source,rust]
----
// crates/modalities/proximadb-vector/src/quantization/turboquant/mask.rs
pub(crate) static BLOCKS_SKIPPED_BY_MASK: AtomicU64 = AtomicU64::new(0);

#[inline(always)]
pub(crate) fn mask_allows(mask: &[u64], slot: usize) -> bool {
    (mask[slot >> 6] >> (slot & 63)) & 1 != 0
}

#[inline(always)]
pub(crate) fn block_has_allowed(mask: Option<&[u64]>, base_vec: usize) -> bool {
    match mask {
        None => true,
        Some(m) => {
            let word = m[base_vec >> 6];
            let bit_offset = base_vec & 63;
            let allowed = ((word >> bit_offset) & 0xFFFF_FFFF) != 0;
            if !allowed {
                BLOCKS_SKIPPED_BY_MASK.fetch_add(1, Ordering::Relaxed);
            }
            allowed
        }
    }
}

#[cfg(target_arch = "x86_64")]
#[inline(always)]
pub(crate) fn block_pair_has_allowed(mask: Option<&[u64]>, base_vec_pair: usize) -> bool {
    match mask {
        None => true,
        Some(m) => {
            let allowed = m[base_vec_pair >> 6] != 0;
            if !allowed {
                BLOCKS_SKIPPED_BY_MASK.fetch_add(2, Ordering::Relaxed);
            }
            allowed
        }
    }
}
----

These three helpers are the **only** mask-related code that needs to ship in P5. The kernel imports them in P4.

== Algorithm Constants (locked)

[cols="1,2,4", options="header"]
|===
| Constant | Value | Rationale

| `BLOCK` | `32` | SIMD scoring tile (matches NEON 32-lane and AVX2 32-byte width).
| `FLUSH_EVERY` | `256` | Periodic accumulator flush so `FLUSH_EVERY * max_lut <= 65535`. Keeps NEON + AVX2/AVX-512BW bit-identical.
| `MAX_LUT` | `127` | u8 LUT cap shared across arches. NEON's u8 accumulator path requires 127; x86 could use 255 but shares 127 for cross-arch parity.
| `TQPLUS_MIN_SAMPLES` | `1000` | Empirical floor below which per-coord quantile estimates are too noisy (turbovec measurement).
| `TQPLUS_P_LO` | `0.05` | Empirical-quantile pair used for TQ+ fit.
| `TQPLUS_P_HI` | `0.95` | Same.
| `MAX_INPUT_MAGNITUDE` | `1e16` | Reject inputs that would overflow f32 sum-of-squares in norm computation.
| `ROTATION_SEED_GLOBAL_FALLBACK` | `42` | Used only in tests when no per-collection seed is available.
|===

== Error Model

Per `CLAUDE.md` clippy lints, NO `unwrap` / `expect` / `panic` in production code. The turbovec reference panics at boundaries; the ProximaDB port returns typed errors:

== Acceptance Criteria (P9 → Beta promotion)

All of the following must hold simultaneously to promote `support_maturity` from `experimental` to `beta`:

1. All unit tests pass on both x86_64 and aarch64 CI runners.
2. Bit-identical scoring test passes across arches (Q11).
3. Recall gates (Q14) met on all three datasets at both bit-widths.
4. Selective-filter benchmark beats oversample by ≥50% latency.
5. No regression in existing `cargo test` suite with feature flag off.
6. No regression in existing `cargo test --features experimental-turboquant` suite (feature flag on but no collection uses TurboQuant by default).
7. EXPLAIN integration test passes on all four wire protocols (REST, gRPC, pgwire, Arrow Flight).
8. Prometheus counter increments correctly under load (1k QPS sustained for 60s).
9. ADR-021 status promoted from `Proposed` to `Accepted` by the architecture review group.

== Open Risks and Mitigations

[cols="1,3,3", options="header"]
|===
| Risk | Probability | Mitigation

| `faer` QR decomposition slow at d=3072 | Medium | Cache the rotation matrix per collection; first-`search()` cost only. If still problematic, swap to Householder QR via `nalgebra` (already in deps).
| AVX-512BW pair-block kernel non-trivial to verify bit-identical | High | Write the scalar fallback first; assert pair-block matches scalar on a random 1M-vector corpus before declaring the kernel correct.
| Per-collection rotation seed cardinality | Low | `u64` is more than enough for 2^64 collections; no birthday-paradox risk at realistic scales.
| TQ+ calibration on highly-anisotropic data (e.g. domain-specific fine-tuned embeddings) | Medium | Identity-fallback path always available; EXPLAIN surfaces the choice. Future work: per-collection `recalibrate` endpoint.
| Feature flag drift (turboquant compiled in default builds) | Low | CI matrix runs `cargo build` both with and without the flag. Default `Cargo.toml` features must NOT include `experimental-turboquant`.
| Bitmap intersection between two `CandidateMaskSet`s with different `n_slots` | Medium | API requires same `n_slots`; mismatch returns `ProximaDBError::SlotCountMismatch` rather than silently truncating.
|===
