== History (shipped)

The audit (2026-05-27) found that `crate::index::{hnsw,ivf,diskann,sparse_hnsw}` had **no external
production users** — mentions elsewhere were names only (variants, strings, comments), not type
imports — so the "migration" was a delete/replace, not a port: the AXIS-native equivalents were already
the production implementations. **Lesson:** verify type imports and live caller chains before scoping
a port; name-only references inflate migration estimates.

* All four AXIS-native indexes compose the shared `FilterableMetadataCache` and implement the TD-064
  `AxisVectorIndex` predicate methods: `AxisHnswIndex` (native skip-through traversal predicate) and
  `UnifiedIvfIndex` / `AxisAnnoyIndex` / `AxisLshIndex` (oversample 2× then post-filter, disclosed via
  EXPLAIN).
* By design, kept separate: `src/index/geo/` (geospatial, not vector similarity — does not belong in
  AXIS); `src/index/edr/` was already integrated as the `EdrIndex` variant.
* `src/index/mod.rs` still carries a placeholder `SparseVectorIndex`; sparse-vector search was not
  re-homed in AXIS by this work.

== Open

=== IVF / Annoy / LSH inline predicate pushdown

IVF / Annoy / LSH inline-traversal predicate pushdown is tracked under
TD-064 Phase 3. Today the oversample-and-filter shape is correct and
disclosed via EXPLAIN; only the recall headroom differs.

=== DiskANN as an AXIS-native index (new capability; the legacy module was deleted, not migrated)

*Status: External Integration Candidate*

DiskANN implementation for billion-scale vector search with SSD optimization.

Key features targeted:

* Vamana graph structure (different from HNSW)
* SSD-optimized layout for sequential reads
* Product quantization for compression
* 1B+ vector capacity target

Migration strategy:

*Phase 1* (3-5 days): Design DiskANN as a new `AxisDiskannIndex` type

*Phase 2* (5-7 days): Implement AxisVectorIndex trait for DiskANN

*Phase 3* (2-3 days): Wire into AxisTieringManager for tiered caching

*Phase 4* (1-2 days): Add TD-064 filterable metadata support

Blockers:

* DiskANN graph structure is fundamentally different from HNSW/IVF
* Requires custom tiering logic for SSD-optimized layout
* May need specialized cache policies

Priority (from the original audit): P2, High effort (10-15 days), High impact (new capability), blocked on architecture work.
