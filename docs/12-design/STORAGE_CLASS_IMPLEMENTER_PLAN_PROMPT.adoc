Product intent:
- Per-collection economy / balanced / performance, default balanced.
- Durable object placement, local residency, provider tier and disk hardware are
  separate dimensions. Object storage remains the durable segment copy.
- No new data durability claim about a locally acknowledged WAL tail.
- Reserved bytes are a quota-checked entitlement. Prices remain in AnvaiOps.
- Scope initial performance behavior to supported object-backed SST/PAX on one
  serving owner; no fleet warmth or multimodal guarantee without its dependencies.

Resolve these in the plan using the review's proposed defaults:
1. One policy owner in canonical CollectionConfig; absent/UNSPECIFIED -> balanced;
   reject unknown explicit enums; preserve omitted PATCH fields; API status must
   distinguish desired policy from actual readiness.
2. Economy disables persistent payload admission/proactive warming, retaining bounded
   common metadata caching. Balanced preserves today's behavior. If this distinction
   is not accepted, leave economy inactive instead of shipping a redundant promise.
3. Atomic reserve/resize/release with tenant quota, exclusive physical-pool owner and
   space for headers, warming and old/new compaction generations. Initial admission
   failure rejects policy change; later cache failure/growth preserves writes and
   explicitly degrades readiness. Never silently claim a guaranteed pin after fallback.
4. Pins are separate from content-type eviction priority. Existing PersistentByteStore
   has the ranged and streamed primitives to evaluate first; no new cache backend.
5. Coverage keys use stable identity/incarnation, immutable object revision, generation
   and declared query profile. Begin with full immutable objects if that is the smallest
   provable implementation; measure footprint before selective optimizations.
6. Preserve normal freshness, ABAC, WAL merge, TTL/deletion and retirement rules.
   Immutable-byte pins are not result-cache pins or permission to keep stale rows.
7. Zero payload GETs is the first readiness gate. Zero total requests requires coherent
   discovery and all sidecars. TD-PAXDIR-2 is a dependency owned elsewhere; do not clone it
   or use TTL-only discovery to claim strong consistency with multiple writers.
8. Idle reservation usage needs durable interval/epoch accounting, not query traces.
   Separate reserved, resident, covered and object bytes; distinguish operation types,
   background work and unknown provider tiers; avoid double counting retries/observers.
9. New explicit access-tier policies are validated. Reuse current GCS/S3/Azure and
   ProximaObjectStore support. Preserve atomic/CAS/multipart semantics. Embedded footers
   inherit the segment tier; only separate control objects can stay Hot.
