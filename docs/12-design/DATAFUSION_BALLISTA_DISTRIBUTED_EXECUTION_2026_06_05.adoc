== Decision

ProximaDB should grow from single-node analytical execution to multi-node execution through the
existing DataFusion route. Ballista is the preferred first distributed substrate because it preserves
the DataFusion/Arrow execution model while adding scheduler/executor MPP execution.

AKS, Helm, autoscaling, node pools, and cost controls are not database semantics. They are
deployment/control-plane responsibilities owned outside this repository. ProximaDB owns the route
contract and the client/runtime adapter that can target a Ballista scheduler when one is configured.

== Route Contract

The read router must produce a typed `RoutedReadPlan` before execution. The plan records:

* selected `compute_route`: `Native`, `DataFusionLocal`, `DataFusionDistributed`, or rejected route;
* `authority_mode`, `workload_profile`, `policy_boundary`, and `freshness_sla`;
* split strategy, partition count, estimated rows/bytes, and stats freshness;
* pushed filters, residual filters, and rejected pushdowns;
* candidate routes and rejected routes with stable reason codes;
* optional distributed placement metadata: compute pool, scheduler endpoint, executor group.

Implementation anchor:

* `src/query/read_route.rs` — route/explain contract and tests.
* `src/query/compute_scheduler.rs` — current read-side selection point.
* `src/query/table_write_plan.rs` — shared `ComputeBackend` vocabulary.

== Sequencing

=== P0: Contract Only

Status: Contract + EXPLAIN items done (verified 2026-10-15; was Partial 2026-06-05). Explicit rejection of unsupported policy/freshness boundaries not re-audited.

* Define `RoutedReadPlan` and `ReadRouteExplanation`.
* `ComputeScheduler::route_select_plan` materializes the typed route plan from the existing
  read-side scheduler decision.
* pgwire `EXPLAIN SELECT` includes the nested `ReadRouteExplanation` payload while preserving the
  previous top-level route fields.
* Keep runtime behavior unchanged.
* Reject unsupported policy/freshness boundaries explicitly.
* Expose stable JSON-ready fields for ADR-004 EXPLAIN.

=== P1: DataFusionLocal

* Wire `ProximaDataFusionTable` / `ProximaScanExec` to consume planned splits.
* Support whole-collection fallback, then segment/object/row-group splits.
* Verify pushed/residual predicate behavior and no-overlap partition reads.
* `EXPLAIN` must report `DataFusionLocal`, split count, pushed filters, residual filters, and
  rejected routes.

=== P2: Ballista Adapter

* Add a ProximaDB adapter for `DataFusionDistributed` that submits DataFusion logical/physical plans
  to a configured Ballista scheduler.
* Fail closed when no scheduler endpoint, auth/TLS material, policy boundary, or split inventory is
  available.
* Preserve the same `RoutedReadPlan` fields for local and distributed execution.
* Do not special-case AKS in database code; use generic distributed placement metadata.

=== P3: Multi-Node Verification

* Same query returns equivalent results through `Native`, `DataFusionLocal`, and
  `DataFusionDistributed` for snapshot-safe workloads.
* Large scan/join tests validate partition coverage, shuffle behavior, residual predicate recheck,
  and policy enforcement.
* Failure tests cover unavailable scheduler, executor loss, stale projection, unsupported policy
  boundary, and insufficient freshness.

== MVP Readiness Impact

This work is post-MVP/Beta until:

* `RoutedReadPlan` is emitted by live read paths;
* DataFusionLocal consumes real split plans;
* distributed routes fail closed without configured safe placement;
* EXPLAIN surfaces selected/rejected routes;
* no-overlap and policy/freshness tests pass.

Until then, supported surfaces should describe distributed DataFusion/Ballista execution as planned
or experimental, not supported.
