== History (shipped)

*Why it exists:* #1726 showed candidate generation was no longer the binding constraint. The pool
ceiling was Recall@100 0.3734, but the selector delivered 0.3136. Comparing selectors fairly needs a
harness that separates three things: generation from selection, point estimates from evidence, and
recall from answer quality.

*Harness (gates 2/4):* seeded synthetic beds, paired sign-flip tests, bootstrap CIs and a promotion
gate that refuses to recommend without significance. Five protocol invariants are each pinned by a
test, including the rule that a W-deep reranker's Recall@k *is* its upstream's Recall@min(W,k).

*Lesson:* the first harness revision divided recall by k, so it was really reporting precision@k.
The synthetic numbers prove the harness discriminates. They are **not admissible** in
`BENCHMARK_EVIDENCE.toml`.

*Gate 5 (serving parity):* the production ONNX stack reproduces the #1726 Python evidence path with
max |Δ| 6.8e-06 and Spearman 1.000000. Two contract discoveries came out of it:

. Serving *rejects* over-budget pairs where the evidence path truncated them. Window-splitting is the
  caller's job.
. Fixed `max_seq_len` padding cost ~11× compute. Batch-longest padding fixed it: window-25 latency
  went from 1243 ms to 68.8 ms with parity unchanged.

The pinned model catalog (MiniLM `4bebbd56`, BGE `55611d7b`) cross-checks every catalog hash against
its parity fixture.

*Gates 3/3b (real NFCorpus data, 324 dev and 323 held-out queries):*

* The #1726 regression is a **depth-policy artifact, not model quality**. Unbounded MiniLM
  rerank-all pushes mid-tail relevant documents past rank 100. Any bounded depth preserves the
  union's Recall@100 by construction.
* **Model strength flips the sign.** BGE's unbounded reorder *gains* recall (0.3332 against 0.3208),
  so "bounded depth" is right for MiniLM-class rerankers but is not a universal rule.
* On held-out data, the incumbent unbounded MiniLM is **dominated by plain union-order on all four
  metrics**. BGE@20's precision gain did not confirm: NDCG@10 CI [−0.000754, +0.026174]. Its
  Recall@100 gain did confirm: +5.01%, CI [+0.002787, +0.028281].

*Decision:* retire unbounded rerank-all. BGE rerank@20 is an opt-in candidate, never worse than
union-order on held-out data. It is not a default-on promotion. #1763 changed `CrossModalReranker` to
*preserve* the tail past `rerank_top_k` instead of dropping it. Do not use `--rerank-all` for
delivered top-100 selection.

*Cost reference:* on macOS arm64, ort CPU, BGE costs about **21×** MiniLM at matched windows. MiniLM
is the latency-class default; BGE is a precision option behind a budget gate.

== Remaining gates

* **Length bucketing for heterogeneous windows**: one long document sets the whole
  window's batch width (window 50 containing a 359-token doc stays ~1.5 s for MiniLM,
  ~36 s for BGE). Bucketing or window-splitting recovers it; the parity fixtures re-run
  as the gate.
* **A third model** (e.g. an int8-quantized MiniLM): export → parity fixture →
  catalog row — the harness is mechanical to extend now.
* **C2 (length bucketing) and int8** remain conditional on an operator adopting
  BGE@20 with a latency budget; the merged config wiring (#1763) makes the
  policy expressible either way.
