== History

*Capability:* every SST flush writes a PAX segment. The default quant is RaBitQ, overridable by the
per-collection `pax_vector_quant` setting or the `PROXIMADB_PAX_VECTOR_QUANT` env. The cold scan
ranks by RaBitQ codes, reranks in SQ8/f32 and returns the top-k. Old `ProximaDataBlock` segments are
still readable.

*The phased pattern is canonical.* Engineering mandate #8 cites this plan as the template for any
storage-format change. Each phase was independently shippable:

. **A — read-side first:** detect the new format by magic byte; the manifest field defaults to the
  legacy format when absent. No new bytes are written yet.
. **B — write side, flag-gated OFF** (`PROXIMADB_PAX_VECTOR_SEGMENTS`).
. **C — new scoring branch** that activates only for blocks in the new format.
. **D — per-collection opt-in** replaces the global env gate.
. **E — compaction + recovery** read both formats and write the configured one (#580 unblocked
  default-on).
. **F — extend to the other engines.** The cascade made RaBitQ the deployment default.
. **G — cold-recall gate** at N ≥ 1000, so the cold path really runs (#106: recall@10 ≥ 0.90).

*Lessons that still apply:*

* Recovery must never assume the new format.
* Small-N tests are brute-force served and never exercise the cold path.
* Reuse the existing row↔columnar adapters; never hand-roll a decoder.

*Evidence:* the Phase G cold-recall harness, plus `resolve_pax_vector_quant` precedence tests in
`src/storage/engines/sst/flush/mod.rs`.
