= PAX v3 Unified Substrate — Format and Compute-Seam Specification
:toc: left
:toclevels: 3
:icons: font
:last-updated: 2026-09-21

*Normative authority:* ADR-094 (unified storage substrate and compute seam).
This document is the implementation specification for that decision. Where this
document and ADR-094 disagree, ADR-094 governs.

*Status:* Draft, tracking ADR-094 (`Proposed`). No clause here is implemented until
its owning TD (`TD-USUB-*`) lands, default-OFF.

== §1 Substrate model

=== 1.1 Three roles, kept distinct

[cols="1,3", options="header"]
|===
| Role | Owner
| **Authority** — schema, transactions, identity | xCatalog + canonical WAL + `ProximaRecord`. Unchanged by this spec (ADR-010: PAX is *not* a schema/WAL/txn authority).
| **Landing** — the durable physical copy a write produces | Chosen by modality (§1.2).
| **Serving metadata** — pruning/index structures that accelerate reads | Rebuildable. May live in the catalog with an in-object copy (§3).
|===

=== 1.2 Landing format follows modality

[cols="1,2,2", options="header"]
|===
| Table class | Landing format | Rationale
| Relational-only (no vector/graph column) | Parquet-encoded **Layer A** with PAX layout discipline | ADR-033: Parquet is within ~2× on scans and is the Iceberg seam. Avoids a second copy.
| Vector or multimodal (any embedding/edge stripe) | `PBLK` / `PXH1` PAX segment | ADR-026/ADR-062. Random access and ANN rerank dominate; the custom format wins ~100× there.
| Metering / trace | PAX segment, 0-embedding profile | ADR-027 Decision 1, TD-161.
|===

"PAX layout discipline" on the relational arm means: MVCC columns (`valid_from_ns` /
`valid_to_ns`) present, tenant column present for RLS skip, zone maps populated per
column, and row-group geometry chosen by the same rules as §2.2 — not that the bytes are
`PBLK`.

=== 1.3 Additional representations are optional and catalog-expressed

A table MAY carry more than one layout. Additional representations are an
optimization selected on cost, never a capability requirement, and never created
implicitly by a user-visible DDL side effect.

**Prerequisite:** `set_storage_layouts` currently *replaces* the list
(`src/services/dml/mod.rs:2052`), making multi-representation inexpressible. TD-USUB-4
makes it additive. Until then §5 routing is not implementable.

== §2 PAX v3 block format (vector / multimodal arm)

Version byte bumps `FORMAT_VERSION` 2 → 3
(`crates/storage/proximadb-block-format/src/header.rs`). **Mixed-read-safe per mandate
#8:** v2 blocks keep decoding indefinitely; readers dispatch on the byte. There is no
flag day and no rewrite requirement. v1 remains rejected (pre-release, never persisted).

=== 2.1 Typed columns become authoritative

*Today.* P-Shred (ADR-055) writes typed user-column stripes but explicitly duplicates:

[quote, 'crates/storage/proximadb-block-format/src/writer.rs:209']
____
a DUPLICATED pruning/projection index; the msgpack `PROPS` tail stays the source of
truth (the reader reconstructs from the tail and ignores `USER_BASE+` columns)
____

So every shredded value is written twice, and the typed column is advisory.

*v3.* For columns **declared in `CatalogTableSchema`**:

* the typed `ColumnRole::UserDefined` stripe IS the value — readers read it directly;
* the msgpack `PROPS` tail carries only the **residual**: undeclared, schemaless props;
* a declared column absent from the residual is not an error; it is simply typed.

This removes the double write and makes projection/pruning authoritative rather than
best-effort. Semantics deliberately mirror **Iceberg v3 Variant shredding** (shredded
fields authoritative, residual blob for the rest) — convergent design, and it makes the
export mapping in §6 near-mechanical.

*Consequence for `build_shred_stripe`.* It currently infers physical type from the first
non-null value and coerces non-conforming values to `None`
(`writer.rs:1250-1262`), which is safe **only** because msgpack is the fallback truth.
Under v3 that safety net is gone for declared columns, so the type must come from
`CatalogTableSchema`, and a value that does not conform is a **write error**, not a
silent `None`.

=== 2.2 Adaptive structural encoding

*Today.* `BlockMode { Oltp, Olap, Pax }` (`header.rs`) is a **static, per-block** choice,
and `encoding_id` is one flat byte per column (`stripe.rs`, `ColumnMeta[6]`).

*v3.* Adopt the Lance 2.1 separation — **structural** encoding (nesting, repetition,
validity → buffers) is chosen independently of **compressive** encoding (bitpacking,
dictionary, FSST, zstd). Structure is selected **per column**, by value width:

[cols="1,1,3", options="header"]
|===
| Value width | Structure | Effect
| ≥ 128 B | **full-zip** | Control word + optional length + value data zipped row-major; 1 IOP random access for fixed-width, 2 for variable. Separate repetition index.
| < 128 B | **mini-block** | 4–8 KiB chunks with a small header; decode cost amortized across ≥32 values.
|===

A 768-dimension `f32` embedding is ~3 KB and therefore lands in full-zip: **a 1-IOP
random vector fetch**, which is precisely the ANN rerank access pattern. This replaces
the ad-hoc pairing of `coalesced_rabitq.rs` / `coalesced_sq8.rs` with a derived rule.

`BlockMode` is retained in the header for v2 compatibility but becomes advisory in v3;
the per-column structure marker in `ColumnMeta` is authoritative.

*Composability note.* Vortex's layout tree (Struct → Zoned → Chunked → Compressor →
Buffered → Flat) is the reference for treating layout as *composable* rather than as a
fixed file shape. v3 does not adopt Vortex's tree wholesale — it adopts the principle
that structure is a per-column, composable decision.

=== 2.3 Zone-map honesty

Two properties must be documented rather than silently relied upon:

* `ColumnMeta` stores `min_val` / `max_val` as `[u8; 16]`
  (`stripe.rs`, offsets 24..40 and 40..56). For strings longer than 16 bytes these are
  **prefix-truncated**. That is a legitimate technique, but pruning weakens on long
  string columns and the planner must not assume exactness.
* `distinct_hint` is a HyperLogLog **sketch** (offset 20..24) — an estimate, never a
  count. Cost models may use it; correctness paths may not.

== §3 Catalog-resident serving metadata

=== 3.1 The depth problem

`ranged.rs` documents the cold read order for one block:

. `head`/size → `footer_tail_range` → fetch trailing 32 B → `BlockFooter`
. `metadata_ranges` → fetch column footer + vector params + row-group index
. `BlockLayout::assemble` → in-memory metadata view
. prune → `column_stripe_range` → fetch surviving slabs

Steps 1 → 2 → 4 are **serially dependent**: a 3-deep GET chain before any data byte is
read. ADR-033's cost spine ranks `DEPTH ≫ WIDTH ≫ BYTES ≫ CPU`, so this is the dominant
term on cold object-storage reads.

=== 3.2 The change

Promote ADR-045 **Layer B** — RowDirectory, ColumnMeta statistics, blooms, SegmentIndex,
deletion vector — into xCatalog. All of it is already classified *rebuildable serving
metadata* by ADR-045, so nothing authoritative moves.

Cold read becomes: **catalog query (ms, no S3 round-trip) → fetch surviving slabs = 1 GET.**
Depth 3 → 1.

=== 3.3 The object stays self-describing

The in-object footer copy is **retained**, not replaced. An object must remain readable
with no catalog present, for:

* disaster recovery and catalog rebuild;
* external tools reading the bucket directly;
* **BYOB storage** (ADR-090), where the customer owns the bucket and may access it
  independently.

Catalog is the fast path. The object remains the truthful one. On divergence, the object
wins and the catalog entry is rebuilt.

=== 3.4 Invariants preserved

* **ADR-062 D1 (one-object atomicity)** — no sidecar object is introduced. The catalog
  row is not an object in the data path.
* **ADR-045 Layer-A co-location** — untouched; only Layer B moves.

== §4 Compute seam

=== 4.1 One reader trait

Introduce the `RecordReader` trait ADR-027 already assumes. It does not exist today —
`read_segment_records` is an inline `match`
(`src/storage/engines/sst/segment_format.rs:76-86`). Implementations: PAX (`PBLK`/`PXH1`),
legacy `ProximaBlocks`, and Parquet (`PAR1`).

`SegmentFormat::detect` gains a `PAR1` arm. Today it knows only `ProximaBlocks` and `Pax`
(`crates/storage/proximadb-storage-common/src/segment_layout.rs:91-97`); Parquet magic is
recognized only in unrelated metadata-cache code. Detection precedence must stay
disjoint: `PBLK` / `PXH1` / `0x01` / `PAR1`.

=== 4.2 Lane discipline (ADR-039 leakage ratchet)

[cols="1,2", options="header"]
|===
| Route | PAX reader it may use
| DataFusion | `PaxSplitReader` (`src/datafusion/engine_adapters/pax_adapter.rs`) — inside the sanctioned adapter allow-list.
| Native / Volcano | `PaxSegmentScanner` / `PaxScanOperator` **only**. Must never reference `PaxSplitReader` — that would import DataFusion into the native lane and break the no-DataFusion build guard (TD-181).
|===

The deliberate ~30-line decode duplication this implies is accepted, and is already the
position TD-OLAP-14 records.

=== 4.3 Capability is storage-independent

`allow_engine_sql_fallback` MUST gate on **provider registration**, never on
`parquet_backed`. Any table with a registered provider gets the full SQL surface;
any table without one gets an explicit, observable decline — never a silent
capability downgrade.

ABAC composition (`relational_abac_required`, `src/services/dml/mod.rs:1423`) is
identity-derived and MUST NOT silently remove capability. Either `AbacScanResult`
(`:1436`) is pushed into the provider so enforcement happens in-plan, or the decline is
surfaced with a distinct, documented SQLSTATE.

== §5 Routing contract

`route_select` currently branches on a 2-bit match over
`(engages_relational, parquet_backed)` (`src/query/compute_scheduler.rs:734-781`).
Under this spec:

. Capability is uniform across representations (§4.3), so routing decides on **cost only**.
. The router enumerates the table's **available layouts** (§1.3) and scores each using the
  existing `CostQuantities` (`get_ops`, `bytes_read`, `egress_bytes`, `bytes_written`,
  `compute_ms` — `src/query/route_cost_model.rs:624-637`).
. Route stamping must reflect what **actually executed**. Today, enabling
  `PROXIMADB_DF_PAX_READER` changes only the stamp while Volcano still serves
  (`compute_scheduler.rs:392-396`, `pax_adapter.rs:73-82`), poisoning cost cells with
  mis-attributed samples. That is a correctness bug in the cost loop and is fixed before
  any cost-based flip (TD-USUB-9).

== §6 Interop seam

Parquet/Iceberg is the **export and external-read** seam. Target Iceberg **v3**:
deletion vectors (Roaring bitmaps in Puffin sidecars), row lineage, and Variant with
shredding — the last mapping directly onto §2.1.

Two live defects to fix as part of this work:

* **Silent publish failure.** `publish_iceberg_table` failure is swallowed with a
  `tracing::warn!` (`src/services/dml/mod.rs:2107-2111`), so Iceberg metadata can be
  absent while the table still reads fine locally. An interop seam that fails silently is
  worse than one that fails closed.
* **Dead parallel implementation.** `src/storage/formats/open/iceberg.rs` (1507 lines,
  `IcebergFormat`/`IcebergConfig`) has **zero non-doc references** — it is exported but
  never constructed. Delete it, or merge it into the live
  `crates/storage/proximadb-iceberg-engine` path. Two implementations of one seam is the
  drift this spec exists to remove.
