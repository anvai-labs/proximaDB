== History (shipped)

Planned (TD-181, ADR-031 execution): give every catalog object an immutable system-generated `u64`
`object_id`, key internal references *and the storage path* off it, demote names to mutable
attributes, phased behind compat shims (rename = O(1) metadata update; no data move).

* Phase 0 substrate: `object_id` minted from one system-wide sequence for table, namespace, index,
  column (column keeps its `i32` Iceberg field-id alongside — ADR-031 amendment 4); reverse
  resolvers for table + namespace; recovery raises the floor by scan (`raise_object_id_floor`).
* Phase 1/3-S2a: oid index persisted at `_syscat/index.json` with pair-atomic heal and dangling-entry
  pruning on read; oid-keyed metadata dual-written.
* **Decision that ended the plan:** carrying both a u64 and the composite was two identity systems —
  an inconsistency seam (the #1325 regression: `Collection.id` held a UUID while the composite lived
  elsewhere). Catalog-free engines + the structural-path mandate force the composite to be carried
  anyway, so ADR-0083 made it the identity; the global u64 survives at most as an ordering sequence.
  Rename-without-data-move is still the invariant to keep (name is metadata).

== Open (Phase 0 residuals, verbatim)

The remaining items here — the **reserved low range / pinned system oids** and the **durable persisted
high-water sequence** (vs today's recover-by-scan floor) — stay open (the reserved range can't be
retrofitted cleanly since existing oids already occupy `1..`).

NOTE: Under ADR-0083 the `object_id` is no longer an identity, so these residuals matter only if the
sequence is kept (e.g. as an ordering sequence or for TD-CAT-9's namespace surrogate). Re-confirm their
need against ADR-0083 before implementing.
