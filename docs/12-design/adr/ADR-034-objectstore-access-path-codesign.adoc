== Context

ADR-033 established the cost spine: on object storage, latency is the **depth of the
dependent-GET chain × RTT**, with priority **depth ≫ width ≫ bytes ≫ CPU**. A map of
ProximaDB's *actual* PAX format against that spine found the **physical layout is
sound but the access path reproduces Parquet's failure internally**. This ADR records
the access-path co-design principles and the concrete gap-closures; the format layout
itself (ADR-026) is not re-litigated.

Concretely, a pruned ranged read today is **`1 + 3K` serial dependent GETs** for `K`
surviving blocks: read the segment index, then *per block* serially `await` the
block footer (32 B) → the column metadata (N×64 B) → the block body
(`ranged_segment.rs:176-337`). That is footer→metadata→data — depth 4 — exactly the
chain a co-designed format exists to collapse.

[NOTE]
====
**Correction (runtime audit, 2026-06-27).** An earlier draft of this ADR (and the
original TD-168) claimed graph traversal *pointer-chases cold object storage*. That
conflated the *storage* layer (edges are durable in cold PAX columns) with the
*runtime*: the Orion graph engine already holds the **topology (CSR adjacency) AND
node/edge payloads in RAM** (`src/graph/engines/orion/storage.rs`,
`orion/mod.rs:1190` — `get_outgoing_edges` is an O(degree) in-RAM CSR slice, no
per-hop GET), rebuilt from canonical PAX edge records via WAL replay at startup. A
k-hop traversal is *already* RAM pointer-chasing. The real graph gap is the inverse
of P5's original framing — see P5.
====

== Principles (derived from the cost spine, not surveyed)

. **Optimize dependency DEPTH first.** A query's latency floor is the longest chain of
  *dependent* GETs. Collapse footer→metadata→index→data to depth 1-2: one cached/known
  read yields all byte ranges, then one batched `read_ranges` fetches them in parallel.
. **Metadata must be predictive, co-located, and cached — or computable.** To plan
  reads without a round-trip to discover where to read: hoist pruning metadata to a
  known, cached position (footer/index), or make offsets computable (fixed stride →
  O(1) random access).
. **Large outside, fine-grained inside.** Per-GET fees + footer overhead want *large*
  immutable segments; random access wants *small* addressable units. Resolve with large
  segments carrying a fine-grained internal offset index + ranged sub-reads — not a
  size compromise.
. **Codes-only residency (not egress).** Quantized codes win by keeping the candidate
  corpus *resident* (warm), so the scan never touches cold storage — provided codes and
  payload live in *separate, independently ranged-readable* regions. (Per ADR-033 this
  is a round-trip lever, not an egress lever.)
. **Graph traversal is the adversarial workload — keep topology in RAM, payloads cold.**
  Pointer-chasing IS the antithesis of object storage, so the topology (adjacency) must
  be RAM-resident — and in proximaDB it *already is* (the Orion CSR; see the Context
  correction). The principle still holds; the engine simply over-satisfies one half and
  *under*-satisfies the other: **(a) topology in RAM** ✅ (CSR, IDs-only — done); but
  **(b) payloads must be COLD + batched** ✗ — Orion keeps *every node/edge payload*
  resident too, so it is not object-storage-native (whole graph must fit in RAM); and
  **(c) the topology must be durable/spillable** ✗ — it is rebuilt `O(E)` from PAX via
  WAL replay at every startup. The corrected co-design target (TD-168): keep CSR topology
  in RAM, move payloads to object storage (cold, fetched in one batched `read_ranges` per
  frontier), and persist/spill the topology so a huge graph need not fit in RAM nor pay
  the `O(E)` cold-start. The original framing ("add a RAM topology") would have duplicated
  the CSR — the gap is residency *boundedness*, not pointer-chasing.
. **Tier by round-trip CRITICALITY, not temperature.** Anything on the serial critical
  path — segment indexes, zone-map summaries, vector codes, graph topology — stays hot
  regardless of data temperature; bulk payload (f32, large props) can be cold. The
  tiering boundary is metadata/index vs payload, not whole-segment.
. **The round-trip budget is a planner CONSTRAINT, not a metric.** Since latency = depth
  × RTT, the planner should cost routes in round-trips and *reject* a depth-5 plan for a
  depth-2 plan even at more bytes — a hard admission constraint, not just an EWMA input.
. **Immutability ⇒ LSM + merge-on-read, with FREE delta detection.** Buffer → flush
  large segments → tombstone+compact → merge deltas at read; CoW branching is free. The
  common case (no unflushed delta) must add **zero** round-trips (a cached per-(tenant,
  collection) delta pointer).

== Applied to the real PAX

=== Already right (no change)

* **True PAX stripes + per-column zone maps** — `ColumnMeta` carries `stripe_offset/len` + `min/max` + bloom (`stripe.rs:64-112`); projection-by-stripe + block pruning exist (P2/P3).
* **Quantization cascade** — `EMBED_BASE` holds RaBitQ codes *or* SQ8 (not f32); `RERANK_BASE` is SQ8; `rabitq_rank`→`rerank_rows` reranks without reading f32 (`reader.rs:329-388`) — P4 mostly satisfied.
* **Structural isolation** — `tenant_id_hash` in the block header skips RLS without row decode (`header.rs:56-64`).
* **LSM + mixed-read-safe** — flush→compaction→tombstone-merge with `PBLK`/`PAXSEG01` magic detection, default-OFF env gate (`flush/mod.rs`, `pax_block.rs:541`) — P8.

=== The six gaps (each a decision, ROI-ordered)

[cols="1,3,1",options="header"]
|===
| Gap | Decision | Principle / TD
| **Read-path depth** | A pruned read is `1+3K` *serial* GETs (`ranged_segment.rs:326-337`). (a) Hoist a per-block **canonical zone-map summary** into `SegmentIndex` (`pax_block.rs:18`) so pruning needs **zero per-block metadata GETs**; (b) batch surviving bodies via `FileSystem::read_ranges` (`lib.rs:383`) instead of the serial loop. → depth ~1-2. | P1/P2 — **TD-167 (HIGH)**
| **Graph residency (corrected)** | The Orion engine already holds CSR topology AND payloads in RAM (`orion/storage.rs`, `orion/mod.rs:1190`) — *not* pointer-chasing cold storage. The real gap: it is RAM-*bound* (whole graph resident, `O(E)` startup rebuild), not object-storage-native. Move payloads cold+batched; make topology durable/spillable. | P5 — **TD-168 (HIGH, re-scoped)**
| **Code residency** | Codes are one stripe *per block* (K scattered reads/scan). Lay the hot `EMBED_BASE` codes **contiguously across the segment** → one ranged read + one hot-cacheable object. | P4 — **TD-169 (MED)**
| **Round-trip budget** | The cost model *measures* `range_gets` but doesn't *constrain*. Make `ComputeScheduler` admit/reshape plans against a depth budget (≤3) using the now-predictable GET count. | P7 — **TD-170 (MED)**
| **Criticality tiering** | `FooterCache` caches footers; generalize to keep index + zone-map summary + code region + topology HOT, payload COLD. | P6 — **TD-171 (MED)**
| **Typed user columns** | `props_bytes` is opaque msgpack (no projection). Typed stripe + zone maps. **Lower priority** — < 2× on scans per ADR-033. | P2/P3 — **TD-162a-2**
|===

== Decision

Adopt principles 1-8 as the access-path co-design discipline, and close the six gaps
**in ROI order**: TD-167 (read-path depth) → TD-168 (graph topology) → TD-169 (code
region) → TD-170 (round-trip budget) → TD-171 (criticality tiering) → TD-162a-2
(typed stripes, last). TD-167 and TD-168 carry the round-trip cost model's largest
wins; TD-162a-2 is deliberately last because it buys < 2× (a scan term), not depth.

== Cross-cuts (apply to every gap-closure PR)

* **Mixed-read-safe, never a flag-day.** Format/index additions are *additive* and version-marked (e.g. a `SegmentIndex` version bump); a segment lacking the new summary falls back to today's per-block metadata path. Old and new coexist, detected by a marker — per the storage-migration mandate (#8).
* **Default-OFF until baked** (per-collection opt-in or env gate), promoted only on the recall ratchet.
* **Verification discipline (#6).** Every closure is justified by a **measured GET-count delta** from the `io_trace` harness (`range_gets` before/after on a representative trace), *not* a microbenchmark — and ANN/quant changes hold recall within the `pax-recall-ratchet` tolerance of the f32 baseline.

== Consequences

* The dominant cost term (round-trips) becomes both *measured* (today) and *minimized* (TD-167) and *bounded* (TD-170) — closing the loop ADR-027/ADR-030 opened on the read path.
* Graph workloads become object-storage-*native* (TD-168, re-scoped): topology stays RAM-resident (already the CSR), payloads move cold+batched, and the topology is made durable/spillable — so a graph larger than RAM is servable and cold-start avoids the `O(E)` rebuild. (The original "stop pointer-chasing cold storage" framing was a runtime mis-audit — see the Context correction.)
* No format rewrite: TD-167 is additive (summary + batching) and is the first PR; the heavier layout changes (TD-169) are version-gated.

== Verification

* A representative pruned vector-search trace shows `io_trace.range_gets` drop from `~1+3K` to `~1-2` after TD-167; recall unchanged within ratchet.
* Graph (TD-168, re-scoped): a graph whose payloads exceed RAM is servable (payloads cold+batched), and cold-start no longer pays the `O(E)` topology rebuild (durable/spillable topology) — verified against memory residency + cold-start time, not a per-hop GET count (traversal is already RAM-resident).
* Server binary builds in both feature states; the GET-count harness is a CI ratchet (counts only go down).
* Out of scope here: the per-gap LLDs (each TD owns its detailed design) and any change to the primary-format strategy (ADR-033 stands).
