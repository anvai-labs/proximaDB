== Context

ADR-039 froze DataFusion as a **swappable physical backend behind the engine-neutral
`LogicalNode` seam** and audited the boundary clean. But the arm it ratifies is
**not reachable at runtime**, and where it *is* reachable it plans **blind**:

[cols="2,3",options="header"]
|===
| Gap | Evidence
| **The OLAP arm is inert.** `ComputeScheduler::route_select` (P0) selects `ComputeBackend::Native` (Volcano over WAL+`RecordStorage`) for **every** SELECT; the `DataFusionLocal` / `DataFusionDistributed` destinations are *declared but not yet wired*. So analytical scans/joins/aggregates over Parquet-backed tables are forced through the row-at-a-time executor and never reach the engine built for them. | `src/query/compute_scheduler.rs:26-32` (doc: "P0 always selects Native… DataFusion/Polars destinations are declared but not yet wired… P1+ flip the OLAP arm"), backend labels `:236-238`, `QueryShape` routing seam `:136`
| **The planner is statistics-blind.** When a query *does* lower to DataFusion, `extract_statistics` hands the optimizer row/byte counts but every per-column `ColumnStatistics` is `new_unknown()` — no min/max, distinct, or null counts. Cost-based join ordering, filter selectivity, and the exact-vs-ANN crossover all plan without column-level cardinality. | `src/datafusion/schema_inference.rs:49,60` (`ColumnStatistics::new_unknown()`), `:68` (assembled vec), `:237` (`column_statistics: vec![]`)
|===

Meanwhile **ADR-042 already built the missing input**: a format-neutral, **mergeable**
per-segment `SegmentStatistics` view (per-column HLL distinct, t-digest quantiles, typed
min/max, null/value counts; segment counts + freshness watermark) produced at
flush/compaction across ProximaBlocks + PAX — *measured once at the write boundary,
aggregated not re-derived, no scan-to-answer `ANALYZE`_. That is exactly the column-level
statistic the DataFusion optimizer lacks. No ADR connects the two.

**Why now.** A downstream perf study (anvaiops, 2026-07-02) measured typed vector
`/search` collapsing under concurrency and, reasonably, suspected a "brute-force
TableScan vs indexed" divergence. The audit for this ADR found that is a **mis-diagnosis**
(see Non-goals) — but it surfaced the real, adjacent gap: the relational OLAP arm this
engine advertises is switched off and, when on, plans blind.

== First principles (why this shape)

* **Aggregate, never re-scan (ADR-042 / ADR-037 Decision 1).** The statistics that make
  routing sound already exist as mergeable sketches on the flush/compaction pass. Feeding
  them to the planner is a *projection*, not a new `ANALYZE` scan. Cost-based planning must
  not cost a scan to plan a scan.
* **Statistics are a lowering, direction preserved (ADR-039).** Our neutral
  `SegmentStatistics` is the source of truth; DataFusion `ColumnStatistics` is one
  *backend lowering* of it — never DataFusion's stats leaking up into the planner boundary.
  A `--no-default-features` Volcano-only build must still plan (degrading to row/byte
  counts), preserving the swap invariant ADR-039 ratchets.
* **Estimate, then correct with the measured truth (ADR-030 / ADR-034).** A static
  selectivity estimate seeds the route; the `IO_TRACE`→`route_cost_model` observed-cost
  substrate calibrates the crossover over time. Measurement corrects the estimate; it is
  **not** fused into the plan (no metering inside planning).
* **Route by shape, default to the safe arm.** Volcano stays the default for OLTP /
  point / strong-freshness / small; DataFusion is chosen only for analytical shapes over
  Parquet-backed tables above a cost crossover — with an operator `SET compute_engine`
  override. A wrong estimate degrades to "ran on Volcano," never to a wrong answer.

== Decision

=== D1 — Make the OLAP arm reachable: cost-based `route_select`

Replace the P0 hardcoded `Native(Volcano)` with a `QueryShape`-driven decision in
`ComputeScheduler::route_select`:

* **Inputs:** `parquet_backed` flag (materialized/federated Parquet vs live WAL+RecordStorage),
  estimated cardinality + selectivity (from D2), partition count, and the freshness
  requirement (strong freshness ⇒ Volcano; the WAL-tail is not in the Parquet arm — see
  ADR-046 for the coherent-merge exception).
* **Rule:** analytical scan/join/aggregate over a Parquet-backed relation above the cost
  crossover ⇒ `DataFusionLocal`; everything else ⇒ `Native(Volcano)`. `SET compute_engine
  = {auto|native|datafusion}` overrides per session.
* **Realizes TD-115.** The `QueryShape` / backend-label seam (`compute_scheduler.rs:136,236-238`)
  already exists; this ADR fills the decision, not the plumbing.

=== D2 — Feed real `ColumnStatistics` from the ADR-042 SegmentStatistics spine

`schema_inference::extract_statistics` populates DataFusion `ColumnStatistics`
(min/max, distinct count, null count, byte size) by **projecting the mergeable
`SegmentStatistics`** for the scanned segments — replacing the `new_unknown()` /
`vec![]` stubs. This is the load-bearing move: it turns blind planning into cost-based
planning **with zero new scan** (the sketches were produced at flush). The projection is
format-agnostic via ADR-042's `SegmentFormat::detect` seam, so ProximaBlocks and PAX
segments both feed the same `ColumnStatistics`.

*Status (2026-07-04):* first slice **landed** as
link:../../10-quality/td/TD-DFR-1-columnstatistics-for-datafusion.adoc[TD-DFR-1] —
`ObjectStoreParquetTable` (the provider serving the `DataFusionLocal` arm) now
implements `statistics()` from the already-read Parquet footer bounds
(schema-width, `Precision::Inexact` per D3) with the ADR-037 registry's HLL NDV
overlaid, and feeds post-prune projected stats into `ProximaScanExec`. Note the
canonical `SegmentStatistics` type / `SegmentFormat::detect` seam is not yet in
code — the ADR-042 generalization (PAX segments feeding the same projection)
continues under TD-OLAP-2.

=== D3 — Treat statistics as freshness-bounded hints (ADR-038)

Each `SegmentStatistics` block carries its own freshness watermark; the envelope floor is
the oldest source (ADR-038). The planner consumes stats as **hints, not truth**: a stale or
absent block degrades the estimate (→ conservative crossover → Volcano), never the
correctness of the result. The un-materialized WAL-tail is invisible to the Parquet arm's
stats by construction; strong-freshness queries route to Volcano (D1) or use the ADR-046
LSN-coherent merge.

=== D4 — Observed-cost calibration, not fusion (ADR-030 / ADR-034)

The crossover threshold is a parameter calibrated by the `route_cost_model` observer fed
from the `IO_TRACE` task-local accumulator (ADR-030). Planning reads the *calibrated
threshold*; it does not read live meters mid-plan. This closes the estimate→measure loop
while keeping metering off the planning path.

== Non-goals (explicit disclaimers)

* **This ADR does NOT address typed-vector-search scan cost (the #634 regression).** The
  typed `POST /api/v2/collections/{c}/search` path never enters DataFusion — it runs the
  hand-rolled `run_unified_search_v1` → `execute_unified_plan` core, shared with the hybrid
  vector leg. Its concurrency behavior is governed by the ADR-011 `AnnFilteringMode`
  **default `PostFilter`** (`legacy.rs:2958`), the SST block-skip / object-store-GET cost
  (TD-096, "≈ full scan on diffuse data"), and index-policy routing (ADR-028) — plus the
  fail-open short-read (TD-064) and deferred per-collection filtering policy (TD-073).
  Fixing it is ADR-011 / ADR-028 + TD-064 / TD-073 work. **Framing it as a DataFusion
  problem mis-diagnoses the code**; this ADR names the boundary so that mistake is not made.
* **Expression / predicate-eval correctness is ADR-043's**, not re-decided here (the four
  cast mechanisms, silent-drop-on-eval-error, one-function-per-binding). D2 supplies
  *statistics*; ADR-043 owns *evaluation*.
* **ANN-as-a-first-class relational `ExecutionPlan`** (promoting `src/datafusion/cross_modal.rs`'s
  `vector_search()` UDTF from an ad-hoc materializing table-function to a decided
  composition contract with pushed-down k / filter / affinity) is a **related but separate**
  decision, deferred to a future ADR. This ADR keeps ANN outside the relational cost model.
* **Engine choice is unchanged.** ADR-039 keeps Polars/DuckDB/native-PAX swappable; this
  ADR activates and instruments the *DataFusion* arm specifically, it does not re-open the
  backend selection.

== Consequences

=== Positive

* Analytical SQL finally reaches the OLAP engine it was built for; TPC-H's 22/22 green
  DataFusion arm (ADR-033) becomes the *served* path for analytical shapes, not a dormant one.
* Cost-based routing becomes real, and the ADR-042 statistics substrate earns a **second
  consumer** (the query planner) beyond the ADR-037 agent-catalog envelope — one spine, two
  readers, no new scan.
* The swap invariant (ADR-039) is preserved: statistics lower our-IR→DataFusion, and the
  Volcano-only build still plans on row/byte counts.

=== Negative / risks

* **Routing regressions.** A mis-estimated crossover could send a point read to DataFusion.
  Mitigated by: conservative default (Volcano unless clearly analytical + Parquet-backed),
  the `SET compute_engine` override, and observed-cost calibration (D4).
* **Statistics staleness.** SegmentStatistics lags the WAL tail; D3 makes this degrade the
  *estimate*, not correctness, and strong-freshness routes avoid the Parquet arm.
* **Added surface behind `datafusion-integration`.** All of the above lives behind the
  existing default-off-capable feature; the Volcano-only build is unaffected (ADR-039 ratchet).

=== Follow-ups

* File **TD-DFR-1** for D2 (SegmentStatistics → `ColumnStatistics` projection) under the
  ADR-042 spine; keep TD-115 for D1.
* A future ADR for ANN-as-relational-`ExecutionPlan` (the deferred `cross_modal` promotion).
