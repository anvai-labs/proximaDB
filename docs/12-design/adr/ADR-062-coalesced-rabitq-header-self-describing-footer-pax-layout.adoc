== Context

=== The measured ceiling this ADR dissolves

The WS8 VOE centroid-prune gate (TD-WLP-9) is **fail-closed**: pruned recall@10 = 0.8087 < 0.9
while the serving cascade is 0.9891 (unaffected). The 2026-07-15 SIFT1M eval
(link:../../_internal/status/SIFT1M_VOE_COMPACTED_RECALL_PARETO_2026_07_15.adoc[evidence])
measured block-centroid pruning to its structural limit and found a ceiling that is **not a
tuning gap**:

[cols="1,1,1,1,1", options="header"]
|===
| block geometry | keep=0.5 recall | GETs/query | GETs/kept-block | verdict

| default (~28 vec/block) | 0.867 |    220 | 0.13 (coalesced) | GETs OK, recall capped
| 8 vec/block             | 0.991 | 62 530 | ~10 (fragmented) | recall OK, GETs shattered
| 64 vec/block            | 0.991 |  7 870 | ~10             | recall OK, GETs shattered
|===

No block size gives both high recall and low GETs.

=== Root cause (the cost term that matters)

PAX is **block-major**: each block interleaves its `[RaBitQ | SQ8 | fp32 | metadata]` stripes,
so the read path (`segment_format.rs` cascade, ~L636-767) issues **~4-5 separate `read_range`
GETs per selected block** — the RaBitQ binary tier is read *per block*. The binary→SQ8→fp32
cascade cuts **bytes** (cheap tier first), but it does **not** cut **block-count GETs**, and on
object storage GET round-trips dominate the cost model (`per_get=20.0 ≫ per_mib_read=5.0`,
`src/query/route_cost_model.rs`). Block-centroid pruning tries to cut GETs by skipping blocks,
but it pays recall for it — and the sweep proves it cannot reach both. This is the
link:../CODESIGN_DIMENSIONAL_ARCHITECTURE_2026_06_19.adoc[co-design mandate P5] in negative:
the dominant term (round-trips) is unreachable through the block-prune lever.

=== The article of faith, tested

The unblock chain (TD-WLP-4 `cluster_order_pca_ivf`, TD-WLP-6 calibrated defaults, TD-RDSTRAT-5
directory activation) assumed PCA/IVF clustering would lift prune recall to ≥0.9. The eval
confirmed PCA/IVF **is** the right clustering (tightens radii −18% @ 128/block; recall +0.11 at
fixed keep) — but it clears 0.9 only at keep=0.7 (0.929), not at keep=0.5 (0.867), and the
block-size sweep shows block-prune is GET-capped regardless. So the article of faith is
*partially* confirmed for clustering and *refuted* for block-pruning as the end-state.

== Decision

Adopt a **scan-then-rerank** PAX layout over the **logical-file unit**, modelled on Parquet's
"data first, metadata footer last" pattern, with the RaBitQ binary tier hoisted to a coalesced
file-level header region. Six decisions:

=== D1 — The file is the atomic logical unit (no sidecar)

One self-contained object per segment: RaBitQ region + data blocks + footer-index + magic.
Object-store mechanisms (DR replication, lifecycle tiering, point-in-time versioning, lifecycle
delete) all operate per-object, so a single logical file is operationally simpler than a 2-object
RaBitQ sidecar and makes compaction/delete a single-object operation (atomicity mechanics in D6).
A collection accumulates 3-5 files LSM-style.

=== D2 — RaBitQ hoisted to a coalesced header region at offset 0; scan at keep=100%

```
 FILE — Parquet-style (data first, metadata footer last); RaBitQ hot-scan pinned at head
 ┌──────────────────────────────────────────────────────────────────────┐
 │ 0   HEADER-PREFIX ~32B: magic|version|rabitq_off|rabitq_len|          │ ◄ 1 GET (coalesces with
 │                             footer_off|footer_len                     │   the RaBitQ scan below)
 │     RaBitQ region (cluster-ordered IVF▸Hilbert/PC1; code+side/row)    │ ◄ HOT SCAN, 1 GET/file, cached
 │       [RaBitQ col header: centroid+subspace meta once]                │
 ├──────────────────────────────────────────────────────────────────────┤
 │     Block0 [PBLK|OID|tenant|ts|props|labels|text|SQ8|fp32|footer]     │  UNCHANGED block decoder
 │     Block1 … BlockK                                                    │  (RaBitQ stripe removed)
 ├──────────────────────────────────────────────────────────────────────┤
 │     FOOTER-INDEX (metadata hub, tail): schema, block table, stats,    │ ◄ tail GET, cached
 │       encoding map, rabitq_off/len mirror, row_count                  │
 │     FOOTER-LEN (8B) ; SEGMENT_MAGIC                                   │
 └──────────────────────────────────────────────────────────────────────┘
```

RaBitQ at offset 0 so the hot scan is **one GET at a known offset with zero metadata
dependency**; the ~32 B header-prefix (offsets) coalesces into that same GET. Scan all codes
(keep=100%) → ~0.99 recall, **zero prune loss**. The `PaxBlockWriter`/block decoder for
SQ8/fp32/metadata/text is reused verbatim; only the RaBitQ stripe leaves the block.

=== D3 — Rerank does the candidate reduction (vector-level), reusing existing infra

After the RaBitQ scan, select top-M survivors and fetch their SQ8(+metadata) block-stripes.
Because survivors are **cluster-adjacent** — the row order is the compaction-grade PCA/IVF
re-cluster `cluster_order_pca_ivf` (`src/storage/engines/sst/block_cluster.rs:198`, shipped
#995; reachable at *flush* via the `PROXIMADB_PAX_FLUSH_CLUSTER=ivf` opt-in, `block_cluster.rs:54`
+ the `write_pax_segment_full` branch at `segment_format.rs:183`, shipped #1015; measured in
the 2026-07-15 eval) — they fall in a handful of adjacent blocks. D3's rerank-coalescing GET-win
**depends on this clustered ordering being in effect**; PR1 therefore measures GETs *with the
flush opt-in ON* (the shipped `cluster_order_pca_ivf`), and names S4 (calibrated IVF
nlist/nprobe) a co-requisite if PR1's survivor locality is insufficient.

The GET reduction itself comes from the **existing cross-block range planner**
`plan_selected_block_ranges` (`sst_query_engine.rs:733`) + `ObjectRangeCoalescePolicy`
(`sst_query_engine.rs:289`), which *plan* merged/coalesced ranges (fewer, larger reads) before
any fetch. `FileSystem::read_ranges` (`filesystem-types/lib.rs:507`) only *executes* those
planned ranges — its default impl is a sequential `for range { read_range }` loop, so the
coalescing win is the policy's, not `read_ranges`' (a backend may override `read_ranges` to
true batched/multipart as a follow-on). fp32 finalized for top-k only. Net: ~1 RaBitQ GET/file
(cached) + a few coalesced survivor GETs, vs today's ~4-5 × every selected block.

=== D4 — Parquet-style self-describing footer-index; one pre-GA footer version

The footer-index is the metadata hub: the physical vector-schema summary needed
to decode the current file (with a full schema snapshot remaining the target),
block offset table, per-block **stats**, per-stripe **encoding map**, region
extents, and row count. The catalog stays the logical write authority.
**Encoding control lives in the footer** (Parquet-style), not in segment magic —
magic stays format-family-only.

**As-built pre-GA reconciliation (2026-07-28).** No released footer population
required a second compatibility version. #1064/#1069 therefore evolved the
unreleased footer in place and retained `FOOTER_V1 = 1`. A sectionless footer
stays byte-identical to the original form; typed additions use the existing
optional-section envelope:

```
[footer_version:u8 = 1]
[row_count | Region-A/B extents | SQ8 decode parameters | embed_dim/count]
[legacy embed_quant_tag | f32-presence | required block table/stats]
[section_count:u16][typed sections]
section = { tag:u8, version:u8, len:u32, payload }
```

Implemented optional sections include the `StripeEncodingMap`, the Region-A0
extent mirror, and the OID-position-resolver extent mirror. The existing footer
tail supplies total footer length, so no nested length/magic or footer-version
bump is needed. Readers validate lengths, parse recognized section versions,
and skip unknown optional section tags. A malformed recognized section fails
closed. A new data encoding is a registered descriptor/tag in the encoding map,
not a footer or segment magic bump.

The implemented base footer carries the physical vector summary needed by the
current PAX reader (`embed_dim`, `embed_count`, representation presence and
decode parameters), not the originally proposed full catalog-schema snapshot.
Tier stripes (RaBitQ index, SQ8 rerank projection, exact f32) are physical
representations of one logical vector field and belong in the encoding map, not
as duplicate logical fields. Full schema snapshot/evolution remains TD-TBL-4 /
ADR-047; catalog `object_id`, defaults, comments, indexes, and mutable properties
remain catalog-only.

The footer encoding map is a descriptor table, not one file-global codec choice. It declares
`{ descriptor_id, logical_field_id, physical_column_id, tier_role, value_codec_tag/version,
transform_tag/version, compression_tag/version, compression_flags, parameter_scope,
vector_transform, auxiliary_flags, source_role, source_fidelity, rebuild_source_id,
projection_generation }`. Each footer block entry carries the compact
descriptor ID selected for each physical tier. This is required because one segment may mix a
losslessly compressed rerank stripe with a raw SQ8 fallback block. It also lets footer-only ranged
planning determine row stride and required parameters without first fetching every block
footer. The tags name three independent layers: semantic value representation, reversible
statistical transform, and lossless byte compressor. Stable tags come from the shared codec
registry; they do not couple PAX to the ProximaBlocks wire format.

Codec parameters needed to decode one PAX block remain in that block's
`VectorParamBlock`, so a fetched block is self-sufficient and the segment footer does not
duplicate parameters. The descriptor records semantics and parameter scope; it does not carry
block-local bases, bit widths, dictionaries, or compressor payloads.
`rebuild_source_id=0xffff` is reserved for a projection-only object whose canonical authority is
cataloged outside the file (for example WAL lineage). It is not a stripe descriptor and cannot
be used to claim exact reconstruction from that object; `0` remains reserved for an in-file
canonical descriptor itself.

**Unimplemented descriptor tail.** The accepted target also records the vector
field's `metric_epoch`, the metric under which estimator-specific tiers were
built, and its normalization contract (`none` or enforced unit-L2). Those fields
are not serialized by `StripeEncodingDescriptor` as of 2026-07-28 and remain
TD-RDSTRAT-7 work. Runtime metric support must be derived from the registered
`(value_codec_tag, value_codec_version, vector_transform)` implementation rather than trusting a serialized
"supported metrics" claim. A catalog distance-metric change advances the metric epoch and
requires compatibility validation or a rebuild before the file can serve the new estimator
path.

Compatibility distinguishes an absent encoding-map section from unknown data
bytes. A sectionless footer uses the legacy SQ8 interpretation. When an encoding
map is present, an explicitly unknown value codec/version is never
reinterpreted as SQ8. An unknown transform or compressor on a canonical stripe
fails closed; an unknown optional projection may be bypassed only when a
declared canonical source can satisfy the request. Unknown optional metadata
sections may be ignored.

=== D5 — Per-block stats: typed slot in v1; optional OID Bloom activation in PR3

The footer block-table carries an optional, tagged, per-block per-column stats entry:

```
 stats: [ per-column: { col_id, stats_kind: StatsKind, payload } ]
 enum StatsKind { None, BloomOid, MinMax, BloomOid_MinMax, … }   // extensible, no format change
```

PR1 emits `StatsKind::None` and zero payload length; it reserves the typed slot. PR3 activates
`BloomOid` (per-block OID Bloom, no false negatives → `vector_by_id`/edge-by-oid skips to the
one positive block — the *point-lookup* index, complementary to the RaBitQ *vector-search*
index). `MinMax` zone-map pushdown and Bloom on other columns are deferred, added as new
`StatsKind` values.

The segment-level stats directory is keyed by `{block_ordinal, stable column_id}` and is lifted
from the existing PAX block `ColumnMeta`; it does not run a second stats producer. Large Bloom
and statistics payloads live in a contiguous auxiliary metadata region referenced by
`{region_id, offset, length}`, analogous to Parquet's optional column-chunk Bloom
offset+length. This bounds the cache-hot footer control plane. Bloom payloads carry their own
version, hash algorithm/seed, hash count, bit count, inserted count, and bits. Start sizing at
approximately 10 bits/key (~1% target false-positive rate), then measure by block cardinality.
Unknown/missing/corrupt optional Bloom metadata degrades conservatively to "may contain"; it
must never create a false-negative skip. TD-RDSTRAT-7 lands the directory/envelope; PR3 owns
population and point-lookup routing.

=== D6 — Self-derived block geometry; GET-budget compaction (file-count = GET-count knob)

Block geometry **emerges** from dim × tier-composition × backend IOPS, not a static constant:

```
 per_row_survivor_bytes = sq8(if present)·dim + fp32(if present)·4·dim + fixed_metadata   (RaBitQ excluded — it's in the header)
 block_bytes_target     = iops_budget.target ∈ [iops_budget.min, iops_budget.max]         (backend-derived; see below)
 rows_per_block         = clamp( iops_target / per_row_bytes, ceil(iops_min/per_row), floor(iops_max/per_row) )
```

The IOPS budgets (`iops_min ≈ 512 KB`, `iops_target ≈ 2 MB`, `iops_max ≈ 8 MB`; S3/ABFS lean
to 4 MB, MinIO/local to 512 KB-1 MB) are a **NEW per-backend `IopsBudget` property** on the
object-store/storage configuration — **not** the `StorageProfile` enum (`{AppendBulk, Churn}`,
`storage_profile.rs:33`, which is a per-collection *workload* tag, ADR-061). PR1 introduces
`IopsBudget` (the storage-profile crate is a reasonable home) keyed by backend; it is distinct
from and does not modify the workload enum.

A collection accumulates files LSM-style; **compaction triggers on a query GET-budget**
(projected RaBitQ-GETs/query = file count, or file-count threshold 3-5). Compaction merges N→1:
reads each file's RaBitQ (cheap), **re-clusters** the union, rewrites one file — **double duty**:
fewer files (fewer GETs) AND tighter survivor locality. This reframes the WLP-7 compaction
scheduler as *the* vector-query GET-cost lever. **Atomicity:** the object-store abstraction
exposes only create-only `put_if_absent` today (`proximadb-object-store/src/lib.rs:247`; no
`if-match`/`if-none-match` conditional replace yet), so compaction uses the **Iceberg-style
fresh-name + atomic pointer/manifest advance** — write the new file under a fresh
content-addressed name via `put_if_absent`, then atomically advance the WAL-authoritative
manifest/pointer (ADR-020: the segment/footer is advisory, the WAL is authority). Native S3/ABFS
conditional-replace (`if-match`) is a future optimization once the abstraction gains it.
Block-centroid pruning (TD-RDSTRAT-4/5) is retained only as an optional coarse pre-filter for
monster collections where a cached RaBitQ scan would exceed RAM.

=== D7 — Workload-profile applicability + write path (AppendBulk-optimal; Churn/graph scoped)

This layout is the **durable PAX-LSM segment format** — AppendBulk-optimal, applied
per-workload-profile (ADR-061), so it never lands on a hot high-churn write path or a graph-edge
path:

* **AppendBulk** (bulk vector loads, RAG corpora) — direct fit: large-batch flushes → few,
  well-sized files → RaBitQ header amortized; compaction merges occasionally.
* **Churn** (agent code-RAG, high trickle-write churn) — the HOT read/write path is the
  in-memory mutable AXIS index (ADR-061 D4) for immediate freshness; this layout is Churn's
  **durable tier only**, fed batched. It does not touch the hot write path.
* **Graph / ORION** — graph EDGES are CSR, epoch-rebuilt (not this layout); node EMBEDDINGS use
  the vector layout under AppendBulk/Churn rules.

**Write-path churn-tolerance:** the layout sits behind the existing **WAL → memtable → flush**
seam (ADR-020: WAL is durable authority; the memtable buffers before flush). Trickling writes
(agent codegraph, Churn) are absorbed by the in-memory memtable; a PAX file flushes only when
the memtable crosses a threshold. That threshold is **co-designed with the file-count/GET-count
knob** (D6): flush at a size that amortizes the RaBitQ header and bounds file count — *not* on
every small write. This prevents per-trickle file explosion + compaction thrash; the GET-budget
compaction (D6) then merges accumulated files. Graph-edge churn is ORION epoch-rebuild, separate.

**Net:** SEARCH is served identically across profiles (the layout helps reads everywhere); the
WRITE path is churn-tolerant via the memtable buffer + GET-budget compaction, and the layout is
scoped so it is never on a per-trickle-write or per-graph-edge path.

=== D8 — Lossless clustered statistical encoding moves bytes; clustering alone does not

PR1 (#1019) validates the separation of levers: SIFT1M N=100k, single-file, IVF-ON measured
recall@10 `0.984`, `20` range GETs/query (18.5x fewer), but `31.7 MB` read/query. Reordering
near-max-entropy SQ8/RaBitQ codes makes survivors contiguous but does not by itself compress
them. The bytes term moves through
link:../../10-quality/td/TD-RDSTRAT-7-lossless-clustered-pax-bytes.adoc[TD-RDSTRAT-7]: reusable,
reversible transforms over contiguous IVF cluster-runs followed by an existing lossless byte
compressor, consumed first by PAX.

The precision boundary and storage encoding are separate. SQ8 and RaBitQ remain declared lossy
query projections; the lossless wrapper must reproduce every input code byte. A canonical f32
stripe must reproduce every IEEE-754 bit. Compaction may only regenerate projections from a
declared canonical source; it never treats SQ8, RaBitQ, TurboQuant, or PQ bytes as canonical and
never performs lossy-to-lossy transcode. Therefore the lossless wrapper is metric-neutral: it
does not restrict L2, squared L2, cosine, dot product, or L1 beyond the value codec's existing
contract.

The shared codec exposes two initial reversible transform families without importing PAX or
ProximaBlocks layout types:

* `ClusteredForBitpackU8/v1`: within a cluster-run microchunk, logically transpose SQ8 codes by
  dimension, store each lane's minimum and bit width, and bit-pack exact unsigned deltas.
* `ClusteredExactBaseXor/v1`: select an exact f32 reference per run, XOR raw IEEE words, apply a
  reversible byte/bit-plane arrangement, then losslessly compress the result. Floating
  `x - centroid` arithmetic is forbidden because it cannot guarantee bit-for-bit reconstruction.

This follows the Parquet separation of value encoding, reversible encoding, and compression.
PAX and ProximaBlocks remain independent envelopes over the same codec engine. Granularity is a
microchunk contained by a cluster-run and range-read block: the cluster supplies the statistical
model, the block remains the IOPS unit, and the microchunk bounds independent decode and
over-read. Each unit falls back to raw bytes unless its complete encoded representation—header,
parameters, padding, and compressed payload—is smaller. The default-OFF gate is
`PROXIMADB_PAX_LOSSLESS_CLUSTERED=1`.

The 2026-07-16 bake-off produced no lossy winner. At N=100k residual SQ6 reached recall `0.981`
but saved only 7.0% query bytes and was 3.4x slower; TurboQuant4 and multi-bit RaBitQ4 reached
recall `0.921` and `0.917`. At genuine N=1M the flat control itself fell to recall `0.968` and
`61` GETs/query, while SQ6 reached `0.950` with the same GET count. No prototype receives a
durable tag. Its evidence sizes survivor and geometry prerequisites; it does not authorize
another lossy storage tier.

**Implementation reconciliation (2026-07-28).** #1064 shipped the single-version
footer's typed encoding-map section and shared-codec foundation plus an
independently gated, lossless scalar arm. Scalar
all-null elision and post-codec LZ4 reduced the same SIFT N=100k end-to-end
counter from `32,020,233` to `25,067,186` bytes/query (-21.7%) at recall `0.991`,
19 GETs/query, and unchanged p95. The clustered SQ8 transform also shipped
default OFF but has no accepted end-to-end win. ADR-065/#1069 subsequently
hoisted SQ8 into Region B on the default coalesced layout, so Region-B density
and selective probing supersede inline-block SQ8 compression there. D8 remains
applicable to scalar fields, non-coalesced layouts, and a future exact-f32
Region C only when their own evidence gates pass.

The N=1M result measures two prerequisites to D6/D8. Top-M is fixed at 1,000 for top-10
regardless of segment rows; it shrinks from 1% of N=100k to 0.1% of N=1M and must become a
measured segment-scale/confidence rule. `IopsBudget` exists, but PAX still cuts at a 3 MiB
threshold using a fixed 1 KiB/row estimate (about 3,072 rows/block), rather than realized
encoded bytes. Self-derived geometry is not implemented until that path is wired for
local/cloud targets.

An exact norm is metric auxiliary data, not an exact-vector tier. It can improve magnitude-
sensitive L2/dot estimates, is algebraically irrelevant to cosine after positive radial
rescaling, and supplies no L1-specific guarantee. `exact` remains reserved for original f32
values.

Canonical-f32 presence is a per-block physical fact and collection durability policy. A file
may omit canonical f32 only when its projection descriptor names a durable canonical rebuild
source outside that file; such a file cannot serve an exact read independently. Compaction and
re-clustering either decode exact canonical bits from every input, obtain them from the declared
authority, or preserve/defer the input. There is no `ApproximateOnly` escape hatch for
reconstructive database operations. Query guarantees follow the weakest live block, not whether
any one input file happens to contain f32.

== First principles / rationale

* **Move the dominant cost term.** On object storage GET round-trips dominate (`per_get=20 ≫
  per_mib=5`). Block-prune moved recall, not GETs. Scan-then-rerank moves GETs: one coalesced
  RaBitQ scan + few survivor GETs.
* **RaBitQ is the index; SQ8/fp32 is the data.** RaBitQ is small (≈ `dim/8 + 8 B`/row → 24 MB
  for 1 M×128d) → cacheable per-file, scanned fully. SQ8/fp32 are large (128 MB / 512 MB for
  1 M×128d) → fetched only for survivors. This is the FAISS IVF-ADC / DiskANN / ScaNN pattern
  realized over PAX (TD-RDSTRAT-3's rerank substrate already exists).
* **Clustering is doubly load-bearing.** PCA/IVF tightens centroids (if we prune) AND clusters
  survivors so the rerank fetch coalesces to few adjacent blocks. The clustering producer
  (`PROXIMADB_PAX_FLUSH_CLUSTER=ivf`, shipped) is the input.
* **File-count = GET-count.** The LSM shape *is* the query cost; compaction is the lever.
  Couples read cost to the storage LSM directly (a better coupling than classic LSM, where
  compaction is decoupled from read cost).
* **Standard outside.** One self-describing object per file → DR/lifecycle/versioning/conditional-write
  operate per-object (Parquet/Iceberg-native); internally we own the layout.
* **SPANN grounding.** SPANN's ~250-1000-vec balanced cells in *contiguous posting lists* +
  compact-code rerank are coarser than our ~28-64-vec blocks but *coalesced* — which is why
  SPANN's GETs win. D2 is the ProximaDB analog (coalesce the compact code = RaBitQ).

== Consequences

*Positive:* ~0.99 recall at keep=100% scan (no prune loss) with GETs/query collapsing from
~370 to the low tens (target: ~1/file + a few coalesced survivor GETs); self-describing
segments (DR, external-tool inspection, debugging); a point-lookup index (OID bloom) for free
in the same footer; block geometry self-tunes to dim/composition/backend; the compaction
scheduler becomes the query-cost knob.

*Negative / costs:* a format change behind an opt-in; the reader retains a footer
presence-field fallback for legacy RaBitQ-in-block segments, so on-disk *readability* is
preserved. Footer metadata grows with block/column count, hence large optional payloads use a
separate referenced auxiliary region. LSM file-merging adds write amplification. A cold query
may pay a footer-index GET to plan survivor data reads, but the fixed-offset RaBitQ scan never
depends on that footer GET and can proceed independently.

*Co-design cost-term note:* PR1 moved GETs (dominant). TD-RDSTRAT-7 is the separately gated
bytes lever; it reuses the same IVF producer for lossless per-cluster-run transforms while
leaving RaBitQ at the header.

== Alternatives considered

* **Block-centroid pruning (status quo, TD-RDSTRAT-4/5)** — measured GET-capped at ~0.87
  recall; no block size gives both recall and GETs. Retained only as optional coarse pre-filter.
* **Read-path cross-block coalescing only (no format change)** — collapses per-block GETs via
  `plan_selected_block_ranges`, but keeps keep<100% pruning (recall loss) and pays gap
  over-read. Cheaper; doesn't reach the keep=100% ~0.99-recall regime. Possible fast-follow.
* **Collection-level RaBitQ sidecar (A2)** — fewest RaBitQ GETs (1/collection) but splits one
  logical thing across two objects → breaks per-object DR/lifecycle/versioning/conditional-write
  atomicity. Rejected for the self-contained logical-file unit (D1).
* **RaBitQ in the footer** — read-the-footer-first serialises the hot scan on a metadata GET.
  Rejected; RaBitQ pinned at head (D2).
* **Per-encoding magic/version bumps** — rejected; encoding control lives in the footer's
  per-stripe encoding map + extensible `StatsKind` (Parquet-style).
* **Unknown encoding -> assume SQ8** — rejected. Absence of the new map means the legacy SQ8
  path; an explicit unknown codec describes bytes the reader cannot safely interpret and must
  fail closed (or use an independently declared exact tier).
* **Another lossy residual tier beside or replacing SQ8** — rejected. The measured candidates
  did not clear the end-to-end gate and would add a second precision/authority boundary. The
  accepted bytes lever wraps existing SQ8 or canonical f32 losslessly and adds no query tier.
* **Cap files at 1 (force compaction)** — rejected; LSM-accumulate 3-5, compact on a GET-budget
  (D6), so file-count = the GET-count knob without over-compacting.

== Initial open questions and resolution

. **Header-first write correctness — resolved by PR1.** Flush buffers the batch; #1019 shipped
  the fixed-offset header/RaBitQ writer and mixed reader.
. **Footer-index size at scale — structure resolved, measurement remains.** Keep typed
  descriptors in the cache-hot footer and place large Bloom/statistics bytes in referenced
  auxiliary regions (D4/D5). PR3 measures actual size/FPP.
. **Schema-footer vs catalog authority — resolved.** Catalog is logical/write authority;
  footer is the immutable physical snapshot keyed by `CatalogColumn.id`; block metadata owns
  local decode parameters. TD-TBL-4 owns evolution reconciliation.
. **GET-budget compaction — mechanism shipped, adaptive policy open.** #1012 wired execution and
  `l0_threshold:N` supplies the fixed-count trigger. It is not a measured collection cost
  controller. TD-RDSTRAT-9 owns the file/cache/GET band, write-amplification payback, observe-only
  decision trace, and independently gated actuation.
. **Compaction atomicity — resolved in design.** Use Iceberg fresh-name + manifest advance via
  create-only `put_if_absent` (ADR-020); native `if-match` remains an optimization.
. **Bloom sizing — initial policy resolved, activation evidence remains.** Per-block,
  approximately 10 bits/key and ~1% target FPP, deterministic versioned payload; PR3 ratchets
  it from measured cardinality and footer/aux bytes.
. **Readability — resolved by PR1 and D4.** New readers parse both footer v1 and v2; v2 writes
  stay default-OFF during reader rollout. Explicit unknown data encodings fail closed. Old PR1
  binaries reading v2 is not a pre-release requirement.

== Footer/bytes implementation amendment (2026-07-15)

After PR1 #1019 landed and measured recall `0.984`, `20` range GETs/query, and `31.7 MB`
read/query, link:../../10-quality/td/TD-RDSTRAT-7-lossless-clustered-pax-bytes.adoc[TD-RDSTRAT-7]
audited the shared codec, ProximaBlocks prior art, PAX `ColumnMeta`/`VectorParamBlock`, and Bloom
implementations. D4/D5/D8 now fix the implementation seams: one pre-GA footer
version with typed optional sections and a sectionless legacy interpretation;
stable physical field IDs with catalog/footer/block authority separation; skippable optional
metadata but fail-closed unknown data encodings; auxiliary-region Bloom references; and a
default-OFF lossless clustered transform/compression layer in the shared codec, consumed first
by PAX and available to ProximaBlocks through its independent envelope. The RaBitQ header
decision and precision of existing query projections are unchanged.

== Scale/bake-off amendment (2026-07-16)

The serialized release bake-off rejected residual SQ6, TurboQuant4, and
multi-bit RaBitQ4; no new lossy data encoding ships. A verified full TEXMEX
N=1M run then showed that the flat control also misses the recall and GET gates.
D6/D8 sequencing is amended accordingly: adaptive survivor M, realized-byte
`IopsBudget` geometry, and scalable deterministic cluster fitting precede any
new compact rerank tag. Higher-dimensional embeddings are evaluated, not
assumed to help: the mandatory RaBitQ scan grows as
`N * (ceil(dim/8)+8)`, as do rerank bytes and fitting cost. The header-first and
Parquet-style footer decisions remain unchanged.

== Lossless authority amendment (2026-07-16)

Database reconstruction requires canonical values to decode exactly. D4/D8 therefore separate
the existing lossy query projection from all subsequent storage transforms: SQ8/RaBitQ may be
quantized once under their declared value-codec contract, while clustered FOR/bit-pack, exact
base-XOR, byte/bit-plane rearrangement, and entropy compression are strictly reversible. This
supersedes the earlier residual-SQ4 implementation proposal. The codec-library transforms and
registry are layout-neutral; PAX is the first measured consumer and ProximaBlocks adoption is a
follow-on through its separate physical envelope and access granularity.
