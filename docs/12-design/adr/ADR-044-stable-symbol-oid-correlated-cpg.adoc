= ADR-044: Stable, line-independent symbol object_id — the correlated-CPG join key

[cols="1,3"]
|===
|Status|Accepted
|Date|2026-06-28
|Deciders|Vijaykumar Singh
|Relates to|ADR-031 (stable `object_id` as the physical *catalog* key — name is metadata; this ADR extends the same tenet to the *symbol/data-record* layer ADR-031 explicitly excluded), `CODE_GRAPH_CORRELATED_SUBSTRATE_2026_06_22.adoc` (one symbol = one row + node + vector, fused by shared oid with no join), ADR-029 (shared `victor-codegraph` chunker — the minter), `CODESIGN_DIMENSIONAL_ARCHITECTURE_2026_06_19.adoc` (incremental re-index is an I/O-round-trip cost term)

|Tracked under|TD-CG (correlated-substrate keystone)

== Context

The correlated-CPG thesis is that a code symbol is **one logical record with three
physical projections** — a relational row, an ORION graph node, and an ANN vector —
all keyed by the **same `oid`**, so a vector-seeded fusion search and a graph
expansion that reach the same symbol meet at the same key and fuse with *no join*
(`CODE_GRAPH_CORRELATED_SUBSTRATE_2026_06_22.adoc`, D1).

That property only holds if every producer that writes a projection agrees on the
`oid`. Today they do not. The 2026-06-28 audit found a **triple drift**:

* The substrate contract wants `graph/{repo_graph_id}/node/{symbol_oid}`.
* `victor-codegraph`'s adapter mints `sha256(path:name:line:col)[:16]`.
* The AnvaiOps connector **discards** that and re-mints plaintext `path:line:name`
  (`code_graph_sync/src/cpg.py`), because downstream name-matching expects the
  trailing `:name`.

Two structural problems follow:

. **Identity is line-coupled.** All three schemes fold the symbol's *line number*
  into its identity. Editing code *above* a function moves its line and therefore
  changes its `oid` — even though the function itself is unchanged. Its vector,
  graph node, and row all churn; cross-commit history breaks; and incremental
  re-index degrades to **full** re-index (every symbol below an edit is "new").
  This directly inflates the dominant cost term (I/O round-trips / re-embedding).
. **There is no single minter.** Three producers re-derive identity independently,
  so the join key the whole thesis depends on is unenforced at the only seams that
  populate it.

ADR-031 already settled the analogous problem one layer up: the *catalog* physical
key is a stable `object_id`, and the mutable *name* is metadata. ADR-031 line
302-308 **explicitly scopes itself to catalog objects** (namespace/table/column)
and leaves the data-record/symbol oid open. This ADR closes that gap with the same
tenet at the symbol layer: **stable identity, mutable coordinates are metadata.**

== Decision

. **One canonical symbol `oid`, minted exactly once** in `victor-codegraph`'s
  `adapter.to_proxima_records` (`symbol_to_record`), and **consumed verbatim** by
  the ProximaDB SDK, the AnvaiOps connector, and the DB substrate. No consumer
  re-derives identity. (Mirrors ADR-029: "vertical inside, standard outside" — the
  shared package is the one source of truth for id + record shape, not just AST.)

. **Identity is structural, not positional.** The stable symbol key is derived from
  coordinates that survive line/whitespace/body edits:
+
[source]
----
symbol_key = blake3(
    repo_id ‖ language ‖ module_path ‖ fully_qualified_name ‖ overload_discriminator
)[:16]
symbol_oid = "graph/{repo_graph_id}/node/{symbol_key}"
----
+
where `module_path` is the import path (not the filesystem path with line context),
`fully_qualified_name` is the dotted/`::` path to the symbol within the module, and
`overload_discriminator` is the parameter-arity/signature shape that distinguishes
same-name overloads. **Line and column are NOT in the key** — they are carried as
`SourceLocation` metadata for navigation/display only (the canonical 1-based
`LINE_BASE` contract, ADR-029, is unchanged). A symbol that moves lines keeps its
`oid`; only a rename / move-to-another-module / signature change / delete mints a
new identity — which is the correct semantics (those *are* different symbols).

. **Body content is a version, not identity.** A separate `content_version`
  (e.g. `blake3(source_text)`) is stored as a record attribute for staleness
  detection and dedup. Editing a function's body bumps `content_version` (re-embed,
  re-index its row) but **does not churn its `oid`** — so its graph edges and
  history survive the edit.

. **Migration is mixed-read-safe and additive.** The new structural `oid` ships
  behind a version marker; readers that encounter the legacy line-coupled id fall
  back to it (never assume the new form). Producers emit both a `legacy_oid` alias
  and the canonical `oid` during the bake window so existing collections keep
  resolving. Default-OFF (per-collection opt-in) until a recall/correlation
  ratchet confirms parity (per the storage-format-migration mandate, CLAUDE #8).

== Consequences

*Positive*

* The three-index fusion becomes real: vector ANN seed and graph expansion that
  reach the same symbol share the `oid` and fuse with no join, as documented.
* Incremental re-index becomes incremental: only renamed/moved/edited symbols
  churn; a line shift is free. Cross-commit / cross-branch diff and dedup become
  expressible (same `oid` ⇒ same symbol across history).
* Real code embeddings (the separate hollow-vector gap) attach a **durable** vector
  to a **durable** symbol, so the embedding survives line moves — making the vector
  seam worth lighting up.

*Costs / risks*

* Computing `module_path` + `fully_qualified_name` + `overload_discriminator`
  reliably is language-specific work in the parser (tree-sitter already yields the
  enclosing scope chain; the discriminator needs signature extraction).
* Same-name shadowing and anonymous/closure symbols need a deterministic
  discriminator (fallback: positional index *within the enclosing scope*, which is
  stable under edits outside that scope — strictly better than the global line).
* A two-id bake window (legacy alias + canonical) costs storage until cutover.

== Scope / non-goals

* Does **not** change the catalog `object_id` (ADR-031) — different layer.
* Does **not** mandate the code embedder (the hollow-vector gap is a separate item);
  it only makes a durable vector *possible*.
* Engine stays joint-free (ADR-037): this is about the *key*, not about computing
  cross-modal joints in the engine.

== Implementation (phased, owner: `victor-codegraph` as minter)

. **P0 — contract + minter.** Implement the structural `symbol_key` in
  `victor-codegraph/adapter.py`; expose `legacy_oid` alongside. Pin it with a
  contract test next to `test_line_base_contract.py`: "moving a symbol's lines does
  not change its `oid`; renaming it does."
. **P1 — consumers stop re-minting.** ProximaDB SDK `chunking_strategies/code.py`
  and the AnvaiOps connector (`code_graph_sync`) consume the adapter `oid` verbatim
  (delete the connector's `path:line:name` re-mint); resolve impact-analysis
  name-matching off `fully_qualified_name` metadata instead of the trailing `:name`.
. **P2 — substrate.** The DB substrate keys the vector + ORION node + relational row
  on the canonical `oid`; mixed-read fallback to `legacy_oid` during the bake.
. **P3 — cutover.** Flip default-ON per the recall/correlation ratchet; drop the
  legacy alias one release later.

== Implementation status (2026-06-28)

* **P0 minter — DONE** (victor PR #304): `victor_codegraph.stable_symbol_oid` +
  adapter dual-emit (`stable_oid`/`legacy_oid`/`content_version`) + edge endpoints via
  the id-map + tree-sitter signature extraction + the contract test (line move keeps the
  oid; rename/signature churns it; body edit bumps `content_version` not the oid).
* **P1 consumers — DONE** (anvaiops PR #273): the connector stops re-minting; readers
  are id-shape-independent (impact name-match off the `name` prop via `id_to_name`,
  editor line off the `start_line` prop); ProximaDB SDK already delegates and surfaces
  the canonical oid via the adapter (no change).
* **Cross-surface consistency — VERIFIED:** the same symbol yields the identical key from
  victor-codegraph and the anvaiops connector (`graph/{repo}/node/{key}` ⇔ `{key}`), and a
  line shift does not change it.
* All gated **default-OFF** (`VICTOR_CODEGRAPH_STABLE_OID` / `ANVAIOPS_CODEGRAPH_STABLE_OID`).
* **P2 cutover — TODO:** flip default-ON behind a correlation/recall parity ratchet.
