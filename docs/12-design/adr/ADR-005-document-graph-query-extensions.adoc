== Context

Gap implementation sprint added several extension modules that are not yet wired into production paths:

* **Document aggregation**: `aggregation_extensions.rs` has `AggregationExpression` evaluator, `StdDevAccumulator`, `LookupFetcher` trait — but none are connected to the proto-driven `AggregationExecutor` pipeline in `aggregation.rs`
* **Cypher parser**: `cypher_parser.rs` + `cypher_ast.rs` provide a recursive descent parser (21 tests) — but the active path still uses regex-based `PatternCompiler` in `pattern.rs`
* **Cypher functions**: No function library exists — `COUNT/SUM/AVG` are parsed but string/math/date functions like `toUpper()`, `abs()`, `substring()` are not

These extensions need formal architectural integration, not ad-hoc wiring.

== Decision

=== Document Aggregation: Proto-Driven Extension

The aggregation pipeline uses proto-generated `AggregationStage` with a `Stage` oneof. Extensions must follow this pattern.

==== $lookup Stage

[source,text]
----
Option A: Add LookupStage to proto AggregationStage oneof
  - Requires proto rebuild
  - Fully consistent with existing pipeline
  - Type-safe across all protocol surfaces

Option B: Handle via ExtensionStage wrapper (proto-compatible)
  - No proto changes needed
  - Uses an opaque JSON config field in a generic stage
  - Less type-safe but faster to ship

Decision: Option A (proto-first). ProximaDB is proto-first by design.
----

Proto addition:

[source,protobuf]
----

async fn process_lookup(
    &self,
    documents: &[SqlObject],
    stage: &LookupStage,

=== Cypher Parser Integration

The new parser (`cypher_parser.rs`) must be integrated without breaking existing graph queries.

==== Dispatch Architecture

[source,rust]
----
// In src/graph/query/mod.rs or a new dispatch.rs:

/// Parse a Cypher query using the best available parser.
/// Tries the full recursive descent parser first, falls back to regex
/// if the new parser cannot handle the query.
pub fn parse_cypher(input: &str) -> Result<ParsedCypher> {
    // Try new parser
    match cypher_parser::CypherParser::new(input).parse() {
        Ok(statement) => Ok(ParsedCypher::Full(statement)),
        Err(new_parser_err) => {
            // Fall back to regex-based pattern compiler
            tracing::debug!(
                error = %new_parser_err,
                "Full Cypher parser failed, falling back to pattern compiler"
            );
            let compiler = PatternCompiler::new();
            match compiler.compile_pattern(input) {
                Ok(pattern) => Ok(ParsedCypher::Pattern(pattern)),
                Err(pattern_err) => {
                    // Both parsers failed — return the more informative error
                    Err(anyhow!(
                        "Cypher parse error: {} (pattern fallback: {})",
                        new_parser_err, pattern_err
                    ))
                }
            }
        }
    }
}

pub enum ParsedCypher {
    /// Full AST from recursive descent parser
    Full(CypherStatement),
    /// Legacy pattern from regex compiler
    Pattern(CompiledPattern),
}
----

==== AST-to-Execution Bridge

[source,rust]
----
/// Convert CypherStatement to execution operations
pub async fn execute_cypher_statement(
    statement: &CypherStatement,
    graph_service: &GraphService,
    graph_id: &str,
) -> Result<CypherExecutionResult> {
    for clause in &statement.clauses {
        match clause {
            CypherClause::Match(m) => execute_match(m, graph_service, graph_id).await?,
            CypherClause::Create(c) => execute_create(c, graph_service, graph_id).await?,
            CypherClause::Return(r) => process_return(r, &working_set)?,
            CypherClause::Where(w) => filter_working_set(w, &mut working_set)?,
            CypherClause::OrderBy(o) => sort_working_set(o, &mut working_set)?,
            CypherClause::Limit(l) => truncate_working_set(l, &mut working_set)?,
            // ... other clauses
        }
    }
}

=== Cypher Function Library

[source,rust]
----
// src/graph/query/functions.rs

pub struct FunctionRegistry {
    functions: HashMap<String, Box<dyn CypherFunction>>,
}

pub trait CypherFunction: Send + Sync {
    fn name(&self) -> &str;
    fn evaluate(&self, args: &[CypherValue]) -> Result<CypherValue>;
    fn return_type(&self, arg_types: &[CypherValueType]) -> CypherValueType;
    fn min_args(&self) -> usize;
    fn max_args(&self) -> Option<usize>;
}

impl FunctionRegistry {
    pub fn with_builtins() -> Self {
        let mut reg = Self::new();
        // String functions
        reg.register(Box::new(ToUpperFn));
        reg.register(Box::new(ToLowerFn));
        reg.register(Box::new(TrimFn));
        reg.register(Box::new(SubstringFn));
        reg.register(Box::new(ReplaceFn));
        reg.register(Box::new(SplitFn));
        reg.register(Box::new(SizeFn));
        // Math functions
        reg.register(Box::new(AbsFn));
        reg.register(Box::new(RoundFn));
        reg.register(Box::new(SqrtFn));
        reg.register(Box::new(CeilFn));
        reg.register(Box::new(FloorFn));
        // Type functions
        reg.register(Box::new(ToStringFn));
        reg.register(Box::new(ToIntegerFn));
        reg.register(Box::new(ToFloatFn));
        reg.register(Box::new(TypeFn));
        reg.register(Box::new(LabelsFn));
        reg.register(Box::new(KeysFn));
        reg
    }
}

== Consequences

* Document aggregation follows proto-first pattern consistently
* $lookup is a first-class pipeline stage, not a bolt-on
* Cypher parser integration is graceful (new parser preferred, regex fallback)
* Function library is pluggable via trait (extensible for user-defined functions later)
* Expression evaluator wired into proto ProjectStage for computed fields
