== Context

PAX search issues ranged reads for immutable control, RaBitQ, SQ8, and OID
bytes. DRAM avoids repeat reads while an entry remains resident, but a process
restart or budget eviction loses that working set. Object-store request count is
a direct cost and latency term; local instance-store reads are not Blob GETs.

The implementation handoff proposed reusing
`src/storage/cache/backend/nvme_tier.rs`. Inspection found that type stores every
value in a `DashMap`: it creates shard directories but writes no entry bytes,
cannot rebuild after restart, and estimates capacity from `Debug` strings. It is
therefore a memory tier with an NVMe-shaped API, not a persistent backend.
`proximadb-cache` is also a foundation crate and cannot depend on that root-crate
module without violating the workspace layering contract.

== Decision

=== D1 — a real, rebuildable foundation L2

Add `PersistentByteStore` to `proximadb-cache`. It stores immutable values as
atomically renamed files under 16 hash shards and rebuilds its index on open.
Logical keys are stored in each entry and addressed by stable SHA-256 filenames;
the process-random Rust `Hash` output is never a disk identity.

The cache file is not an authority. Missing, truncated, malformed, or
checksum-failing data is deleted and treated as a miss; object storage remains
the correctness source.

Full values carry a whole-value CRC. Selective reads use a persisted CRC per
64 KiB local chunk and validate every touched chunk before returning bytes. The
touched chunks are fetched as one contiguous envelope. This avoids both
reading/checksumming a complete 128 MiB SQ8 parent and the measured
read-amplification from incorrectly reusing the 4 MiB cloud billing target as a
local integrity unit. The CRC table overhead is about 0.006%.

One byte budget is shared by both PAX caches. Survivor entries evict before
invariant entries, then least-recently touched within a class. Resident byte
counters are maintained per class in O(1); query-time metrics do not scan the
disk index.

=== D2 — DRAM then local L2 then object storage

`TenantCache<Arc<[u8]>>` receives an optional `L2ValueStore`:

----
DRAM hit
  or persistent-local hit -> admission-controlled DRAM promotion
  or authoritative loader -> write-through local L2 + DRAM admission
----

`SurvivorRangeCache` uses exact range entries for demand reads and a stable
parent-region entry for write-time SQ8 population. A parent hit reads only the
checksum chunks covering the requested range.

`SegmentInvariantsCache` persists control bytes separately from Region A, checks
local L2 after a DRAM miss, and promotes the reconstructed value. The
coarse-probe path retains header, A0, RaBitQ parameters, and footer by default;
the prior opt-in gate is now an explicit kill switch. This closes the measured
zero-hit population gap.

=== D3 — configuration and defaults

The persistent tier is optional:

----
[storage.sst_config]
cache_local_disk_path = "/var/lib/proximadb/cache" # unset => no persistent L2
cache_local_disk_max_gb = 100
cache_on_write = "invariant"                 # none | invariant | all
----

The corresponding `PROXIMADB_CACHE_*` config mirrors are registered in
`ENV_GATE_REGISTRY.adoc`. The path must be local; URLs are rejected. A zero
budget disables the persistent tier.

`cache_on_write = invariant` is the default because immutable control and
Region-A bytes are already writer-owned and bounded by the invariant-cache
policy. `all` additionally retains SQ8 and is the first-query-after-write
benchmark policy. Population is not described as free: it performs memory
retention, hashing, checksumming, and an optional local write, but no extra
encoding or object-store GET.

=== D4 — publication and invalidation order

Writer-owned bytes become cache-visible only after the atomic segment
publication succeeds at the final path. A staged or failed output is never
installed.

Compaction first publishes and seeds the output, then deletes each input. Only a
successfully deleted input path is purged from:

* invariants DRAM and persistent entries;
* survivor exact and parent entries in DRAM and persistent storage; and
* warm-replay tracking.

After a collection directory is successfully removed (or confirmed absent),
the same immutable-byte caches are purged by separator-aware directory prefix.
For example, retiring collection path `.../12` must not match sibling
`.../123`. This is capacity reclamation, not row-level coherence.

PAX segment paths are immutable and unique. An MVCC tombstone does not change
the bytes of an existing segment, so it does not invalidate these byte caches;
the canonical read merge and collection query-cache invalidation enforce
freshness. Cold deletion vectors are not yet a completed PAX read/compaction
surface: TD-DELVEC-1 WI-3a provides gated plumbing, while DV read application and
the compaction interlock remain later work. A future DV cache must key by
manifest generation/snapshot and must not masquerade as invalidation of the
immutable PAX bytes.

=== D5 — bounded prefix coalescing

Cold PAX reads fetch a bounded prefix (default 1 MiB, maximum 8 MiB) that always
covers the fixed header and may also cover adjacent A0/RaBitQ control and early
probed-cell bytes. This reduces operations only when physical adjacency is real.
The footer remains at the variable tail: moving it to the front would duplicate
or precompute data before blocks finish, and it is not adjacent to Region B
because optional resolver and Region-D blocks intervene.

== Consequences

* Warm local reads avoid Blob operations while preserving object storage as the
  authority.
* Local bytes and latency remain real costs even where Azure Hot has no separate
  per-GB retrieval fee. Instance-store capacity is bundled into the chosen VM,
  not economically free in isolation.
* Write-through increases local write amplification relative to eviction-only
  spill. It is deliberate: restart persistence and first-query-after-write
  behavior require the entry to reach L2 before DRAM eviction.
* The legacy root `NvmeBackend` remains a separate, memory-only abstraction. It
  must not be used as evidence of restart persistence.

== Verification contract

. Feature/config unset: historical DRAM-only route and recall are unchanged,
  except the corrected default-on invariant metadata population and bounded
  prefix read.
. Reopen, corrupt-entry fallback, cross-chunk selective read, tenant
  namespacing, priority eviction, post-compaction persistent purge, and
  separator-safe collection-prefix purge tests.
. SIFT1M after quiescent materialization: recall@10 >= 0.98.
. Persistent-local warm diverse queries: physical object GETs/query <= 10.
. First query after an `all`-policy write: physical object GETs/query <= 5.
. No performance claim is promoted to measured evidence until the corrected
  harness records materialized count, WAL residue, segment geometry, cache
  state, and physical reads in `BENCHMARK_EVIDENCE.toml`.
. Performance acceptance uses an optimized `release`/`release-server` binary;
  debug binaries are correctness-only.
