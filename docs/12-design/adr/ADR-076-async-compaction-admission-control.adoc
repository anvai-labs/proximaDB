== Context

SST compaction was **inline synchronous**: every flush awaited the full cycle (read all L0 →
merge → train PCA/IVF → write → delete inputs) — the opposite of RocksDB/HBase/Cassandra, which
compact asynchronously behind L0 admission watermarks and never block writes.

=== The measured pathology

The 2026-07-26 1M-SIFT ingest on Azurite showed the TD-COMPACT-5 training arm firing **every
~35 s** — 5–7 redundant cycles, each re-reading and re-training growing L0 segments (N GETs +
~35 s PCA CPU + 1 PUT + N DELETEs; ~7× the object-store I/O of one post-ingest pass). Three
intersecting gaps: (1) inline blocking gated ingest at ~1 flush/35 s; (2) no admission
control, so compaction fell behind; (3) no debounce — the arm fired on every flush while any
untrained L0 ≥ 32 MB existed, re-training segments still receiving flushes.

== Decision

Decouple the **write path** (flush → L0, fast, non-blocking) from the
**maintenance path** (compaction → train → promote, scheduled, overlaps
writes), gated by **L0 admission control watermarks**.

=== D1 — Async compaction (background workers, not inline)

The flush path calls `Compaction::enqueue_due_compaction` (non-blocking) instead
of the inline `run_due_compaction`. Flush creates the L0 file and returns ~1 s
later; compaction runs concurrently on the background worker pool. The inline
`run_due_compaction` is retained as the deterministic test primitive.

The existing `schedule_compaction` + `task_queue` + `worker_loop` provide the
machinery. Two corrections from the cross-model review shape the shipped form:

* **D0 (prerequisite, #1242):** two separate `Compaction` instances existed —
  the `SstEngine`'s (no workers) and the `StorageEngine`'s (with workers). The
  flush path uses the `SstEngine`'s instance, so D1 required starting workers on
  THAT instance (now wired to `background_thread_count`, was hardcoded 2).
* **Race fix:** the `active_compactions` dedup insert moved from worker-time to
  enqueue-time (`schedule_compaction`), under one write lock with the check —
  closing the TOCTOU where two rapid schedules for the same output both passed
  the read check before either worker inserted.
* **Atomic-coordinator preservation:** the `SstEngine`'s `Compaction` is built
  via `with_atomic_coordinator(Some(coord))` so the workers carry the ADR-046
  atomic-swap coordinator the inline path had (the default `Compaction::new`
  passes `None` → non-atomic publish on the async path).

=== D2 — L0 admission control (RocksDB-style watermarks)

Add two L0-file-count watermarks to `SstConfig` (TOML-controllable, env-overridable):

- **`l0_slowdown_trigger`** (default **6**): when the live L0 file count ≥ this,
  the flush yields ~1 ms before writing the next L0 (gives the async compaction
  workers headroom).
- **`l0_stop_trigger`** (default **10** = `max_files_per_level`): when the live L0
  file count ≥ this, the flush **defers** — returns `Err` so
  `materialize_collection`'s `?` returns before its `free_wal` block (the data
  stays durable in the WAL; the auto-flush driver retries next tick).

Defaults are 6/10 (not the 8/12 of the original Proposed text) per the
cross-model review: `stop_trigger` must be ≤ `max_files_per_level` (10) so the
stop boundary, not the level ceiling, is the active backpressure surface. Both
`0` disable. Armed only when a compaction manager exists.

This is the proven RocksDB model: flushes naturally slow down when compaction
can't keep up, preventing unbounded L0 backlog + compaction storms.

=== D3 — Training-arm debounce (state flag, not a timer)

The original Proposed text specified a **time debounce** (track last-flush
timestamp; skip the arm if a flush arrived in the last `training_debounce_secs`
= 120 s). The cross-model review (Kimi) replaced this with a **state flag**,
which is race-free and self-tunes to any ingest rate rather than guessing 120 s:

A per-collection `training_in_flight: Arc<Mutex<HashSet<String>>>` guard. The
flush path inserts the collection's `storage_url` before enqueuing a training
compaction; `should_trigger_compaction` arm 2 skips re-arming while it is
present; the guard is cleared when the compaction completes.

* **D3 (#1241):** the guard lived on `SstEngine`, set by the flush caller and
  cleared by the inline caller after `run_due_compaction`.
* **D1 evolution (#1253):** on the async path the inline caller can no longer
  clear the guard (enqueue returns before the compaction runs). The guard is now
  shared (same `Arc`) with the `Compaction`; the background `worker_loop` clears
  it via `release_task_state` on every exit path (Ok / Err / manager-construction
  failure), deriving the collection dir from `task.output_file.parent()`. The
  flush caller also clears it on the no-worker paths (`Ok(false)`, enqueue `Err`).

=== D4 — Separation of concerns (the boundary contract)

Each surface has a single, well-integrated responsibility:

[cols="2,4"]
|===
| Surface | Responsibility + boundary
| **Flush** | Memtable → L0 `.pax` file (atomic, non-blocking). Never awaits compaction. Returns in ~1 s. Owns: L0 file creation, filename, WAL append.
| **Compaction worker** | Reads L0 inputs → merge + dedup → train PCA/IVF → write L(n+1) output → delete L0 inputs. Runs on the background pool, concurrent with flushes. Owns: level promotion, segment training, input cleanup.
| **Admission control** | Monitors L0 file count per collection. Throttles (slowdown) or stalls (stop) writes when the backlog exceeds watermarks. Owns: the write-rate ↔ compaction-rate feedback loop.
| **Training debounce** | Guards the training arm: skip if the collection is actively receiving flushes. Owns: the "when to train" decision (post-ingest, not per-flush).
|===

The boundaries prevent the current pathology: flush never blocks on
compaction; compaction never re-trains an actively-growing segment; admission
control prevents backlog from outpacing compaction.

== Implementation history (re-sequencing + cross-model review)

The Proposed text sequenced D1 → D2 → D3 as one slice. Three independent
cross-model reviews (Opus 5, Kimi, DeepSeek) verified the 21 code-location
citations and corrected the sequence + four design points. Shipped in this
order:

1. **D3 (#1241)** — `training_in_flight` state flag (smallest diff, biggest
   COGS win: kills the redundant re-training loop). Independent of the async
   refactor; ships first.
2. **D0 (#1242)** — unify the two `Compaction` instances (the `SstEngine`'s
   flush-path instance must be the one with workers). Wiring prerequisite for D1.
3. **D1 + D2 (#1253)** — async compaction + L0 admission watermarks, shipped as
   ONE slice (Kimi's first-principles framing: they are halves of one
   producer/consumer rate-control loop, not separable decisions).

Cross-model corrections folded into the D1/D2/D3 text above: D0 added; D3
converted from a 120 s time-debounce to a state flag; D2 thresholds 8/12 →
6/10 (`stop ≤ max_files_per_level`); the `active_compactions` race fix moved to
enqueue-time; the atomic-coordinator must be threaded into the workers (else the
async path publishes non-atomically).

Test strategy (all three reviewers): the **async path is the default test
surface**, exercised via a quiescence barrier (`await_compaction_quiescence` —
await until the task queue and active-compaction set are both empty). The inline
`run_due_compaction` path is retained as a `#[cfg(test)]`-style deterministic
option, not the default — the prior "inline-only" coverage gap is what let the
metrics-panic + warm-manifest bugs ship.

== Consequences

* Flush is no longer gated by compaction/training wall time (projected ~30×: 1 flush/1 s vs
  1 flush/35 s) and ingest-time compaction I/O drops ~7× (one post-ingest training pass instead
  of 7 redundant cycles, each N GETs + 1 PUT + N DELETEs at ~50 ms/GET on cloud — the single
  largest streaming-ingest waste). Query latency during ingest improves (compaction CPU on
  worker threads).
* L0 watermarks bound the backlog, which also bounds per-query GETs (each un-compacted L0 file
  adds footer + data GETs).
* Correctness unchanged: compaction is idempotent; the atomic coordinator serializes publish
  (`finalize_atomic_operation`); segment-header `layout_version` is the mixed-read marker
  (v1 + v3 coexist). Cost: background-thread coordination; the inline path survives only as a
  deterministic test option.
* Later refinements: link:ADR-081-admission-first-flush-ownership.adoc[ADR-081] **amends D2's L0 admission placement** (metadata-only preflight before any clone/sort); byte-weighted memory admission (ADR-086) and deterministic local-spill
  compaction (ADR-088, Proposed) build on this async/admission model.

== Explicitly out of scope

* **Compaction strategy tuning** (leveled vs tiered vs FIFO): unchanged — the
  Cx L(n-1) → 1x Ln ratio and the `level_multiplier` stay as-is.
* **Compaction priority / scheduling policy**: the existing FIFO queue +
  `schedule_compaction` dedup suffice for the first cut. Priority-based
  scheduling (e.g., compact the largest L0 first) is a follow-up.
* **Per-collection compaction locks**: the atomic coordinator's operation-ID
  serialization suffices; a per-collection mutex is a follow-up if contention
  is observed.
* **Iceberg/Delta-style scheduled-batch maintenance**: the async-background
  model (D1) is the right first step; the scheduled-batch model (decouple
  compaction from the engine entirely, run as a job) is a larger follow-up.
