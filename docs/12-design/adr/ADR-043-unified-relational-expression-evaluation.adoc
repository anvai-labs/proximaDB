== Context

Relational scalar-expression and predicate evaluation in ProximaDB spans two
physical engines (the hand-rolled Volcano executor for OLTP/strong-freshness and
DataFusion for OLAP/MPP) over one logical plane
(`proximadb_relational_algebra::LogicalNode` + `proximadb_relational_types::Expr`).
ADR-039 establishes DataFusion as a *swappable binding*, and the function registry
(`proximadb-functions`) is documented as "one definition, many bindings". In
practice the implementation had drifted into **fragmentation on three axes**, which
the ADR-040 accuracy harness surfaced as the TD-183 JSON-path bug:

* **Casts are handled by four disagreeing mechanisms.** (1) The pgwire translator
  string-strips a *hard-coded* list of cast suffixes before parsing
  (`network/postgres/translator.rs`) — it forgot `::int` (only `::integer`) and
  over-eagerly deletes `::boolean`, destroying type information. (2) The shared
  relational frontend (`proximadb-relational-frontend` `lower_expr`) has **no
  `Cast` arm at all**, so any surviving cast declines the whole native pipeline.
  (3) Native `cast_value` (`proximadb-relational-types`) implements a partial type
  matrix (e.g. `String→Int64` but not `String→Int32`). (4) DataFusion lowering
  (`datafusion/logical_lowering.rs`) has a fuller matrix but is unreachable through
  the shared plane because the frontend never emits a cast node.

* **There are three function "registries".** The canonical
  `ProximaFunctionRegistry` / `builtins()`; an empty `NoFunctions` used at the
  storage-pushdown predicate boundary and in constant-folding; and a **separate,
  native-invisible** set of JSON functions defined *only* as DataFusion UDFs
  (`datafusion/udf.rs`). The "one definition" intent holds for ~8 builtins and is
  violated exactly where it caused TD-183: `json_extract*` exists for OLAP but not
  for the native engine, so every modality/engine path rediscovers the gap.

* **There are two error contracts.** Every Volcano *operator* (`FilterExec`,
  `ProjectExec`, joins, aggregates) evaluates through `builtins()` and **propagates**
  eval errors via `?`. But the single **storage-pushdown predicate boundary**
  crosses a `Fn(&[ProximaValue]) -> bool` closure that has no error channel, so it
  is structurally forced to coerce any `Err`/`Null`/non-bool to `false` — i.e. to
  **silently drop the row**. This is the load-bearing defect: a wrong answer that
  presents as a clean empty result.

Fragmentation is why one logical defect needed four fixes, and why each fix moved a
different subset of queries.

== Decision

Evaluation of casts, functions, and predicates is governed by **three invariants**.
They are normative for all current and future relational evaluation code.

=== Invariant 1 — Never silently drop a row on an eval error (fail-loud)

Every predicate-evaluation boundary, *including storage pushdown*, MUST carry a
`Result` error channel and surface evaluation failure as an error. Coercing an
eval `Err` (or `Null`, or a non-boolean) into `false` is prohibited. The
storage-scan row predicate changes from `Fn(&[ProximaValue]) -> bool` to
`Fn(&[ProximaValue]) -> Result<bool, ExprError>`, so `DmlTableReader::open`
propagates `ReaderError::PredicateEval` exactly as `FilterExec` does. A query the
native engine cannot evaluate fails loudly and (per ADR-039) the OLAP binding
serves it — it never returns a silently-wrong empty set.

=== Invariant 2 — One cast lowering, owned by the typed frontend

Cast semantics live in exactly one place: the relational frontend, which emits a
typed `Expr::Cast { ty }` from a single `sql_type → ProximaType` map. The pgwire
translator's `String::replace` cast-strip list is **deleted** — cast handling must
not be done by text surgery. `cast_value` (native) and `proxima_to_arrow`
(DataFusion) are the two *typed bindings* of that one frontend cast node and MUST
implement a consistent matrix (the native gaps, e.g. `String→Int32`, are filled).

=== Invariant 3 — One function definition, all engines (no engine-only scalars)

Every relational scalar/aggregate is defined **once** as an engine-neutral
`ProximaValue` kernel in `proximadb-functions`. Engine bindings are *adapters*: the
Volcano executor dispatches through the registry; the DataFusion F2 adapter
(`datafusion/registry_udf.rs`) wraps each registry scalar as a `ScalarUDF`.
Engine-only function definitions (a function registered for DataFusion but absent
from the registry, as the JSON UDFs were) are **prohibited**, except for a small,
explicitly-listed set of Arrow-vectorized specials that opt out via
`DATAFUSION_NATIVE_SCALARS` (so the untyped registry wrapper never shadows a typed
Arrow kernel — the failure mode observed when this was attempted naively). Once a
function is in the registry, the frontend MAY validate scalar names at lowering
time so unknown functions fail at planning, not at row evaluation.

== Consequences

* **Correctness** — the silent-drop class is eliminated; cross-engine cast/JSON
  behavior converges; ADR-040 differential + anchored checks have one consistent
  surface to verify.
* **SOLID** — Single Responsibility (cast lowering owned by the frontend; predicate
  eval owned by one validated seam), DRY (one function definition), Open/Closed
  (new functions/casts extend the registry/frontend map, not N call-sites).
* **Cost** — Invariant 1 is small and self-contained; Invariants 2 and 3 touch the
  frontend and the function crate respectively and are sequenced to ship
  independently.
* **Cloud-era posture** — fail-loud + single-definition are what make an OLTP+OLAP
  hybrid safe to scale: an engine that cannot serve a query escalates to the one
  that can (ADR-039) instead of returning a plausible wrong answer.

== Rollout (TD-186)

Incremental, each shippable on its own and gated by the ADR-040 document-accuracy
ratchet:

. **Invariant 1** — type the storage-pushdown predicate closure; propagate the
  error. Converts d06's silent 0-rows into a loud error → OLAP serves it →
  accurate. Subsumes the name-only pre-validation added in PR #496.
. **Invariant 2** — frontend `Cast` arm + delete the translator strip list +
  fill `cast_value` gaps. Fixes d06 (native computes) and d11 (`::boolean`
  preserved, no `Utf8 = Boolean` clash).
. **Invariant 3** — move the JSON kernels into `proximadb-functions`; F2 auto-binds
  DataFusion, native gains them; add the skip-list entries; tighten frontend scalar
  validation.

Each step removes its ids from `KNOWN_BAD_TD183` and raises `DOC_ACCURACY_RATCHET`
toward the full suite size.

== Alternatives considered

* **Keep patching per query/path** — rejected; this is what produced four fixes for
  one defect and left the silent-drop seam in place.
* **Make the OLAP engine authoritative and drop native scalar eval** — rejected;
  violates ADR-039 (engine is a swappable binding, not the source of truth) and the
  OLTP strong-freshness path needs native evaluation.
