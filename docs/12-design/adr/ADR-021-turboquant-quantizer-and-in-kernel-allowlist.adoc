= ADR-021: TurboQuant Quantizer and In-Kernel Allowlist
:toc: left
:toclevels: 3
:icons: font
:source-highlighter: rouge
:last-updated: 2026-05-30

== Status

Proposed

== Context

ProximaDB's existing quantization stack (`UnifiedQuantizationEngine`: Binary / INT8 / PQ4 / PQ8 / FP32 — see `src/compute/quantization/quantization_engine.rs:84-100` and `crates/modalities/proximadb-vector/src/quantization/internal_types.rs:14-23`) has three structural frictions that block locked-in work in `EMBEDDING_PRECISION_LLD_2026_05_22.adoc` and `COMPETITIVE_OLTP_OLAP_MPP_TRAJECTORY_2026_05_20.adoc`:

1. **PQ requires k-means codebook training.** Every precision-epoch bump (`EMBEDDING_PRECISION_LLD` Q12) marks codebooks stale and forces async retrain. New collections pay training latency before they can use compressed search; streaming/online ingest cannot keep up.

2. **AXIS adapters degrade recall under selective filters.** `src/index/axis/indexes/annoy_index.rs:672-676` and `src/index/axis/indexes/hnsw_index.rs:854-859` accept `filter: Option<&HashMap<String, String>>` but explicitly defer filtering to the storage layer, falling back to oversample-then-post-filter (`annoy_index.rs:714-721`). At small selectivity (1–10%) the oversample factor either explodes or recall collapses.

3. **Quantized scoring is downward-biased.** `Int8VectorData` (`src/compute/distance_computation/quantized.rs:170-178`) carries `scale`/`zero_point` correction but no per-vector length renormalization. The bias is largest at low bit-widths — exactly the regime where compression matters.

Google Research's TurboQuant (ICLR 2026, https://arxiv.org/abs/2504.19874[arXiv:2504.19874]) is a **data-oblivious scalar quantizer**: after random orthogonal rotation each coordinate of a unit vector on the (d-1)-sphere follows the same Beta((d-1)/2, (d-1)/2) marginal regardless of input data. Lloyd-Max quantization against that *theoretical* marginal needs no training and no per-collection codebook. Per-coordinate calibration (TQ+) closes the asymptotic gap at lower dimensions. RaBitQ-style length renormalization (SIGMOD 2024, https://arxiv.org/abs/2405.12497[arXiv:2405.12497]) turns the downward-biased inner-product estimator into an unbiased one at zero search-time cost.

Independently, a packed u64 slot-allowlist pushed into the SIMD scoring kernel lets selective filters skip entire 32-vector blocks before any LUT lookup or scoring work — collapsing the selective-filter recall problem without changing the index structure.

The reference implementation (RyanCodrai/turbovec, MIT, v0.8) demonstrates these techniques produce 16× compression with recall matching or beating FAISS `IndexPQ` 8-bit, and beats FAISS FastScan by 12–20% on ARM. ProximaDB does not lift turbovec's code; this ADR commits to a clean-room reimplementation from the published papers.

== Decision

Adopt TurboQuant + TQ+ + length-renormalization + in-kernel allowlist as a new variant within the existing `UnifiedQuantizationEngine`, and add a packed-bitmask `CandidateSet` impl that AXIS adapters can forward into their scoring kernels. Gated behind the `experimental-turboquant` feature flag until P9 (benchmark validation) closes.

=== Authority and route declaration

Per the "Reuse-First Architecture Rules" in `CLAUDE.md` and the route declaration mandate in `RELATIONAL_PGWIRE_DML_COMPUTE_BLUEPRINT_2026_05_20.adoc`:

[cols="1,3", options="header"]
|===
| Field | Value

| `authority_mode`
| `projection` — TurboQuant codes are a derived layout. `ProximaRecord` + canonical WAL remain authoritative.

| `policy_boundary`
| Per-collection rotation seed (NOT a global seed) so multi-tenant collections do not share rotation. Calibration scoped to collection epoch.

| `workload_profile`
| `ann_hot_read` — leaf scoring layer for already-narrowed candidate sets.

| `storage_specialization`
| `turboquant_2bit` / `turboquant_3bit` / `turboquant_4bit` depending on the chosen bit-width.

| `freshness_sla`
| `epoch_bounded` — codes invalidated on precision-epoch bump per `EMBEDDING_PRECISION_LLD` Q12.

| `compute_route`
| `simd_brute_force_with_mask` — runtime SIMD dispatch (NEON / AVX2 / AVX-512BW) with optional packed-bitmask allowlist.

| `partitioning`
| Inherited from the parent AXIS partitioning (HNSW shard, IVF list, etc.). TurboQuant does NOT introduce its own partitioning.

| `isolation_profile`
| Per-collection. No cross-collection sharing of rotation, calibration, or codebooks.

| `repair_source`
| Canonical `ProximaRecord` stream. Re-encode triggered by epoch bump or feature-flag re-enable.

| `support_maturity`
| Experimental until P9; Beta after recall and selective-filter benchmarks are locked in `TURBOQUANT_LLD_2026_05_30.adoc`.
|===

// src/core/search/filter_contract.rs (extension)
/// Packed-bitmask candidate set for kernel-level allowlist filtering.
/// One bit per slot; `bitmap[i >> 6] & (1 << (i & 63))` selects slot `i`.
///
/// SIMD kernels can early-exit 32-vector blocks (AVX2/NEON) or 64-vector
/// block pairs (AVX-512BW) when the relevant bitmap word is zero, avoiding
/// the cost of computing scores that would be discarded by post-filter.
pub struct CandidateMaskSet {
    bitmap: Vec<u64>,
    /// Set bits count, maintained on insert.
    n_set: usize,
    /// Slot index → external id resolution, owned by the calling adapter.
    id_resolver: Arc<dyn SlotIdResolver>,
}

=== AXIS adapter contract delta

AXIS adapters MUST inspect the `CandidateSet` they receive. When the concrete type is `CandidateMaskSet`, the adapter forwards the raw `&[u64]` bitmap into the scoring kernel. When the concrete type is anything else (`MemoryCandidateSet`, etc.), the adapter falls back to the existing oversample-then-post-filter path. This is dispatch by concrete type, not a new method on the trait — the trait shape is preserved.

[source,rust]
----
// src/index/axis/indexes/annoy_index.rs (delta)
async fn search(
    &self,
    query: &[f32],
    top_k: usize,
    filter: Option<&HashMap<String, String>>,
    candidate_set: Option<&dyn CandidateSet>,  // NEW parameter, defaulting to None for callers that haven't migrated
) -> Result<Vec<(String, f32)>> {
    if let Some(cs) = candidate_set {
        if let Some(mask) = cs.as_any().downcast_ref::<CandidateMaskSet>() {
            return self.search_with_kernel_mask(query, top_k, mask.bitmap()).await;
        }
    }
    // Fallback: existing path (filter HashMap, oversample-post-filter)
    self.search_legacy(query, top_k, filter).await
}
----

The new `candidate_set` parameter is additive. Existing callers compile unchanged.

=== Unified EXPLAIN integration (ADR-004)

Routes that select TurboQuant MUST surface the choice in `RoutedExecutionPlan` via the existing `ExplainOperator.hints` map. Required keys:

[cols="1,3", options="header"]
|===
| Key | Value

| `quantization`
| `"turboquant_2bit"` \| `"turboquant_3bit"` \| `"turboquant_4bit"`

| `calibration_mode`
| `"identity"` \| `"tq_plus"`

| `mask_pushed_to_kernel`
| `true` if `CandidateMaskSet` was forwarded into the SIMD kernel; `false` if the path fell back to oversample-post-filter.

| `kernel_arch`
| `"neon"` \| `"avx2"` \| `"avx512bw"` \| `"scalar"` — chosen by runtime dispatch.

| `blocks_skipped_by_mask`
| Integer count of 32-vector blocks short-circuited by the mask early-exit, sampled from the per-search counter.

| `length_renorm_applied`
| `true` if per-vector `scale = norm / <u, x_hat>` was applied at scoring (always `true` for TurboQuant; relevant for the P7 INT8/PQ8 retrofit).
|===

`required_capabilities` MUST include `{ subject: "compute.quantization", operation: "turboquant", tier: "experimental" }` while the feature flag is gated. Promotion to `tier: "beta"` happens after P9 closes.

`rejected_route` reasons that the planner MUST surface:

* `"dim_not_multiple_of_8"` — TurboQuant kernel requires `dim % 8 == 0`.
* `"bit_width_out_of_range"` — only {2, 3, 4} supported.
* `"non_finite_input"` — NaN / Inf / `|x| >= 1e16` rejected at the encode boundary.
* `"calibration_not_committed"` — search attempted on a collection whose first batch was below `TQPLUS_MIN_SAMPLES = 1000` AND `calibration_mode = TqPlus` was requested.
* `"epoch_mismatch"` — encoded epoch differs from the collection's current epoch; route through repair source.

=== Contract rules

1. TurboQuant is NEVER durable authority. The canonical `ProximaRecord` + WAL remain the source of truth. Quantized codes are a projection that the system can rebuild from authority on demand.
2. The rotation seed is per-collection, persisted in xCatalog. Two collections with the same data MUST encode to different code streams.
3. TQ+ calibration is frozen after the first qualifying batch (≥ `TQPLUS_MIN_SAMPLES = 1000` vectors). Subsequent batches re-use it. Re-fitting only happens on epoch bump.
4. `add()` / `search()` reject non-finite inputs and `|x| >= 1e16` at the boundary with typed `ProximaDBError`. No `unwrap`/`expect`/`panic` in production code paths (clippy lints in `src/lib.rs:22-31`).
5. The packed-bitmask `CandidateMaskSet` is recognized by AXIS adapters via concrete-type downcast. Adapters that do not migrate keep the existing oversample-post-filter path.
6. Unified EXPLAIN MUST expose every field in the table above for any plan that selects TurboQuant.

== Consequences

**Positive:**

* New collections can use quantized search immediately — no training step, no codebook drift, no separate train phase.
* Selective filters (tenant, ACL, time window) push directly into the scoring kernel; recall is preserved at small selectivity without inflating `top_k`.
* Per-vector length renormalization (extractable as a standalone fix in P7) eliminates the downward bias of existing INT8/PQ8 paths.
* Bit-identical scoring across NEON and AVX2/AVX-512BW kernels via periodic flush (`FLUSH_EVERY = 256`) — ARM-built indexes round identically to x86-built indexes.

**Negative / risks:**

* Adds a new SIMD code surface (three kernels) with attendant maintenance cost. Mitigated by feature flag and a portable scalar fallback covered by tests.
* TurboQuant is a flat scan — it does not replace HNSW/IVF coarse partitioning for billion-scale corpora. AXIS continues to do coarse filtering; TurboQuant only replaces the leaf scoring layer. The HLD makes this explicit as a non-goal.
* Per-collection rotation seed is a new xCatalog field. Mitigated by additive schema; existing collections default to a sentinel and fall through to the legacy quantizers.
* TQ+ calibration on small first batches (< 1000 vectors) silently falls back to identity calibration. Mitigated by EXPLAIN surfacing `calibration_mode = "identity"` so users can see the degradation.

**Migration path:**

* Phase 1 (this ADR): types, encode, calibration land behind `experimental-turboquant`. No collection picks it by default.
* Phase 2 (post-P9): default routing in xCatalog can prefer TurboQuant for new `ann_hot_read` collections that opt in via `quantization_policy: { prefer_training_free: true }`.
* Phase 3 (future ADR): consider promoting TurboQuant to a non-experimental quantization tier across the embedding-precision pipeline.

**Backwards compatibility:**

* All existing `QuantizationLevel` variants remain unchanged. `TurboQuant` is a strictly-additive enum variant gated by feature flag.
* The new `candidate_set` AXIS adapter parameter is additive (`Option<&dyn CandidateSet>`). Callers that don't migrate compile unchanged.
* `Int8VectorData` and `QuantizedDistanceResult` are unchanged. `TurboQuantVectorData` is a new sibling.
