= ADR-003: MultiModelPlan v1 Contract
:toc: left
:toclevels: 3
:icons: font
:source-highlighter: rouge
:last-updated: 2026-04-02

== Status

Accepted

Reconciliation (2026-10-15): implemented as `MultiModelPlan` in
`crates/query/proximadb-multimodel-plan` (no `V1` suffix; also carries resolved authority/storage/
projection context). Whether *every* public entry point lowers into it (the Decision's rule) is
not verified here — treat as open. File Plan paths below are historical. SQL routing is now
governed by ADR-064 (`ComputeScheduler::route_select`).

== Context

ProximaDB has multiple query entry points that produce different internal representations:

* **Federated SQL**: `src/query/federated/optimizer/mod.rs` produces `QueryPlan` with `PlanNode` tree (14 node types)
* **Unified facade**: `src/query/unified/` produces `QueryResult` via strategy dispatch
* **UQL**: `src/query/unified/uql.rs` has placeholder lowering (`convert_multimodal_to_query()`)
* **REST/gRPC**: Protocol adapters call into facade or federated paths independently

The current `PlanNode`/`QueryPlan` types are federated-optimizer-specific. They lack:

* Capability requirements per operator (ADR-001)
* Normalized filter attachments (ADR-002)
* Stable operator IDs for explain correlation
* Explicit bindings declaring what services/engines are needed
* A contract that all entry points must produce

The design resolution doc specifies that `MultiModelPlanV1` should wrap existing federated machinery (additive adapters, not invasive rewrite).

== Decision

Introduce `MultiModelPlanV1` as the **canonical logical-execution contract** that ALL public entry points must produce before execution. The existing `PlanNode`/`QueryPlan` system remains as the physical planner output, but it is wrapped in and validated against the canonical contract.

=== Contract Types

[source,rust]
----
/// Canonical multi-model plan contract.
/// Every supported public entrypoint must lower into this form.
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct MultiModelPlanV1 {
    /// Unique plan identifier for correlation
    pub plan_id: PlanId,
    /// Root operator in the execution DAG
    pub root: OperatorId,
    /// All operators in topological order
    pub operators: Vec<PlanOperator>,
    /// Capability requirements from all operators
    pub capabilities: Vec<CapabilityRequirement>,
    /// Service and engine bindings needed for execution
    pub bindings: PlanBindings,
    /// Diagnostics from lowering and optimization
    pub diagnostics: PlanDiagnostics,
}

pub type PlanId = String;
pub type OperatorId = usize;

/// Logical operator in the multi-model plan
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct PlanOperator {
    /// Stable operator ID (for explain, diagnostics)
    pub id: OperatorId,
    /// Operator kind
    pub kind: OperatorKind,
    /// Inputs (operator IDs this depends on)
    pub inputs: Vec<OperatorId>,
    /// Output column schema
    pub output_columns: Vec<String>,
    /// Estimated cost from optimizer
    pub estimated_cost: Option<f64>,
    /// Estimated output rows
    pub estimated_rows: Option<u64>,
    /// Capability requirements for this specific operator
    pub requirements: Vec<CapabilityRequirement>,
}

/// All supported operator kinds
#[derive(Debug, Clone, Serialize, Deserialize)]
pub enum OperatorKind {
    VectorSearch {
        collection: String,
        top_k: usize,
        query_vector_source: String,
        filter: Option<NormalizedFilterExpr>,
    },
    GraphQuery {
        cypher: String,
        start_nodes: Option<Vec<String>>,
    },
    DocumentQuery {
        collection: String,
        filter: Option<NormalizedFilterExpr>,
        aggregation: Option<Vec<String>>,
    },
    LogsQuery {
        namespace: String,
        time_range: Option<TimeRange>,
    },
    MetricsQuery {
        namespace: String,
        metric_name: Option<String>,
    },
    Filter {
        predicate: NormalizedFilterExpr,
    },
    Project {
        columns: Vec<String>,
        expressions: Vec<(String, String)>,
    },
    Join {
        join_type: String,
        keys: Vec<(String, String)>,
    },
    Aggregate {
        group_by: Vec<String>,
        aggregations: Vec<(String, String, String)>,
    },
    Scan {
        target: String,
        model_type: String,
    },
    Lateral {
        correlation_var: String,
    },
    Sort {
        keys: Vec<(String, bool)>,
    },
    Limit {
        count: usize,
        offset: Option<usize>,
    },
}

/// Service and engine bindings needed for execution
#[derive(Debug, Clone, Default, Serialize, Deserialize)]
pub struct PlanBindings {
    pub requires_vector_store: bool,
    pub requires_document_store: bool,
    pub requires_graph_store: bool,
    pub requires_observability_store: bool,
    pub requires_rdbms_store: bool,
    pub engine_preferences: Vec<(String, String)>,
}

/// Diagnostics from plan construction
#[derive(Debug, Clone, Default, Serialize, Deserialize)]
pub struct PlanDiagnostics {
    pub source_protocol: String,
    pub lowering_time_us: u64,
    pub optimization_rules_applied: Vec<String>,
    pub warnings: Vec<String>,
}

=== Lowering Flow

[source,text]
----
REST/gRPC request
  → Protocol adapter
  → Parse into protocol-specific AST

SQL extension (VECTOR_SEARCH, GRAPH_QUERY, etc.)
  → Federated parser extracts function calls
  → Federated optimizer produces QueryPlan (PlanNode tree)

UQL expression
  → UQL parser produces unified AST
  → MultiModelPlan lowering (replaces placeholder)

All paths converge:
  → MultiModelPlanV1 (canonical contract)
  → CapabilityRegistry.validate(plan.capabilities)
  → If valid: physical binding → canonical executor
  → If invalid: CapabilityError with ExplainPlan (valid=false)
----

=== Execution Entry Point

[source,rust]
----
/// Single canonical execution entry point (replaces multiple degraded paths)
pub async fn execute_validated_plan(
    plan: &MultiModelPlanV1,
    storage: &MultiModelStorageFacade,
    registry: &CapabilityRegistry,
) -> Result<ExecutionResult> {
    // 1. Validate capabilities
    let validation = registry.validate(&plan.capabilities);
    if !validation.valid {
        return Err(CapabilityError::from(validation).into());
    }

    // 2. Bind services
    let bound = bind_services(plan, storage)?;

    // 3. Execute through FederatedExecutor (existing)
    let physical_plan = plan.to_physical_plan()?;
    let executor = FederatedExecutor::new(storage.clone(), config);
    executor.execute(physical_plan).await
}
----

== Consequences

* All query paths produce the same logical plan format
* Capability validation happens once, before execution
* Explain uses the same operator graph (ADR-004)
* UQL placeholder lowering gets a real target format
* `execute_parallel` degraded paths can be safely removed (SB-18)
