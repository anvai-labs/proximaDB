= ADR-017: DR Engine Surface — OSS / Operator Boundary
:toc: left
:toclevels: 3
:icons: font
:last-updated: 2026-05-25

== Status

Accepted

== Context

The OSS DR engine implementation (P0..P6.1 + S14 + observability) is
now complete and lives entirely in the ProximaDB OSS repository. The
SaaS operationalization (concrete provider adapters, region-pair
eligibility, billing SKUs, failover runbook) lives in the private
AnvaiOps repository per the split decision recorded in
`docs/12-design/COLLECTION_DR_CRR_ENGINE_CONTRACT.adoc`.

New code is reaching the OSS surface every time a downstream
consumer asks "what's the actual `use` path for X?" or "what trait
do I impl when I write the S3 adapter?". This ADR is the
single-page answer — the canonical inventory of the engine's pub
surface, the bridge modules in the root crate, and the operator
responsibilities that sit on top.

Without this anchor, the surface drifts: each consumer rediscovers
it by grepping. With it, downstream implementations and integration
tests have one place to start.

== Decision

**The DR engine surface is the set of types and traits listed
below**, located in two crates:

* `proximadb-catalog` (this OSS workspace's catalog crate) — all
  abstract contracts. No `prometheus`, `aws-sdk-s3`, or
  `azure_storage_blobs` dependencies; this crate stays the
  lowest-layer surface that any operator can build against.
* `proximadb` (root crate) — concrete bridges to root-crate
  facilities (the prometheus registry, the WAL manifest service).
  Adds dependencies the catalog crate cannot take.

Operators (AnvaiOps and any future self-host integrator) provide
the rest: concrete provider adapters, real backends for the policy
store, and the server boot wiring that constructs the runner.

== The Public Engine Surface

=== Policy and contract types

Located in `proximadb_catalog::collection_dr_policy`:

* `CollectionDrPolicy` — the row that lives in
  `xcatalog_collection_dr_policies`. Carries every field listed in
  contract §"LLD: xCatalog Schema".
* `DrPlacement`, `DrReplicationBehavior`, `DrBillingBinding`,
  `ProviderReplicationBinding`, `DrHealth` — the sub-structs that
  compose a policy.
* `DrState` (Disabled / PendingBillingApproval /
  PendingProviderProvisioning / Active / SuspendedByOps /
  PendingRetirement / Retired) plus `can_transition_to` enforcing
  the state machine.
* `DrHealthState` (Unknown / Healthy / Degraded / Drifted /
  BillingBlocked / ProviderBlocked) — orthogonal to `DrState` per
  the contract S8 clarification.
* `ObjectProvider` (AwsS3, AzureBlob, AzureAdlsHns, GcsFuture
  reserved).
* `DrEventType` and `CollectionDrEvent` for the append-only event
  log.
* `ProviderError` taxonomy (Transient / Misconfiguration /
  QuotaExceeded / AuthDenied) with `is_retryable` and
  `requires_ops_ack` helpers.
* `ProviderObservedState` — what the adapter reports back to the
  reconciler.

DDL constants:

* `COLLECTION_DR_POLICIES_DDL`
* `COLLECTION_DR_EVENTS_DDL`

Both pinned by tests that assert every contract-locked column name
appears in the DDL string.

=== Adapter contract

Located in `proximadb_catalog::collection_dr_policy`:

* `DrProviderAdapter` async trait — the engine surface that
  concrete adapters implement. Three methods: `ensure_rule`,
  `fetch_state`, `retire_rule`. Idempotency contract documented on
  each method.
* `MockDrProviderAdapter` — reference test double, already public.
  Supports error injection across the full `ProviderError`
  taxonomy and idempotency-counter accessors.

=== Path layout

Located in `proximadb::storage::trait_components::path_resolver`:

* `DrPathBuilder` — pure construction. Validates IDs, enforces the
  contract path layout `data/{tenant_id}/{namespace_id}/{collection_id}/`.
* `DrResolvedPath` — typed wrapper with `root_prefix()`,
  `wal_subprefix()`, `manifests_subprefix()`, `snapshots_subprefix()`,
  `segments_subprefix()`, `indexes_subprefix()`,
  `restore_checkpoints_subprefix()`.
* `PathResolverError` (MissingTenantId / MissingNamespaceId /
  InvalidId / PoolClassMismatch).

=== Namespace extension

Located in `proximadb_catalog::CatalogNamespace`:

* `namespace_id: Option<String>`
* `tenant_id: Option<String>`
* `region_home: Option<String>`
* `default_dr_region_pair_id: Option<String>`
* `storage_pool_class: StoragePoolClass`
* Builder methods (`with_tenant`, `with_namespace_id`,
  `with_region_home`, `with_default_dr_region_pair`,
  `with_storage_pool_class`).
* `is_dr_addressable()` predicate (true iff both `namespace_id` and
  `tenant_id` are populated).
* `StoragePoolClass` enum (Pooled / Business / Enterprise /
  EnterpriseDedicated).

=== Customer-facing policy store

Located in `proximadb_catalog::dr_policy_store`:

* `CollectionDrPolicyStore` async trait — the contract §S14
  "single sanctioned mutation surface". 8 methods: `create`,
  `approve_billing`, `request_retire`, `suspend`, `resume`, `get`,
  `list_by_tenant`, `list_by_collection`.
* `CreatePolicyRequest`, `BillingApproval`, `RetirementAck` — input
  types with caller-provided `CatalogAuthorityMode` and
  `namespace_region_home` so the catalog crate doesn't have to
  resolve them.
* `InMemoryCollectionDrPolicyStore` reference impl enforcing every
  gate: D8 (ExternalAuthoritative refusal), S13 (UnsupportedProvider),
  G4 (region_home required), state-machine transitions, duplicate
  policy prevention, retirement acknowledgement, billing SKU
  validation.

=== Reconciler

Located in `proximadb_catalog::dr_reconciler`:

Decision layer (pure):

* `reconcile_step(policy, observed) -> ReconcileDecision` — pure
  decision function, every (state × observation) combination
  covered by tests.
* `ReconcileDecision` enum (Idle / EnsureRule / RetireRule /
  RepairDrift / MarkDrifted / MarkProviderBlocked /
  MarkBillingBlocked).
* `IdleReason`, `DriftReason`, `BlockReason` — bounded label enums
  so metric cardinality stays finite.
* `next_health_state(decision) -> DrHealthState` — pure mapping.

Driver layer (async):

* `DrPolicyStore` async trait — narrow store surface the reconciler
  needs (pending_reconcile, transition_state, set_provider_binding,
  update_health, record_event, acquire_lease, release_lease).
* `DrReconcilerDriver<S, A>` generic over store + adapter.
  `reconcile_one` and `reconcile_one_with_observation` methods.
* `ReconcileOutcome` enum (Idle / EnsuredRule / Retired /
  RepairedDrift / MarkedDrifted / MarkedProviderBlocked /
  MarkedBillingBlocked / AdapterTransient / AdapterEscalated).
* `DrApiError` taxonomy.

Backoff / rate-limit / pause primitives (pure):

* `BackoffPolicy` + `BackoffEntry` + `apply_backoff_signal`,
  `should_escalate`, `is_ready` helpers.
* `PerPolicyRateLimit::try_acquire`.
* `ShardPauseState::pause_for_quota`, `is_paused`.

Shard layer (async):

* `DrReconcilerShard<S, A>` — owns the per-policy gates, the
  per-shard pause state, and the metric sink. `with_holder_id`,
  `with_lease_ttl_ns`, `with_metrics` builder methods.
* `tick()` method — one async pass over the pending list.
* `TickOutcome` enum.

Metric sink:

* `DrMetrics` async-safe trait with `observe_tick`,
  `observe_shard_paused`, `observe_lag` methods. Default impls are
  no-ops so a future method addition stays source-compatible.
* `PolicyLabels` — bounded label set the shard hands to the sink.
* `NoopDrMetrics` — zero-cost default.

Async runner:

* `DrReconcilerRunner<S, A>` wrapping the shard in a
  `tokio::time::interval` loop with `tokio::sync::watch`-based
  shutdown.
* `RunnerConfig` (default 60s poll interval per contract).
* `RunnerStats` returned on shutdown.

Public testing surface (`proximadb_catalog::dr_reconciler::testing`):

* `MockDrPolicyStore` — in-memory store with mutation recording,
  error injection, and pending-list seeding.
* `RecordingDrMetrics` — captures `observe_tick`,
  `observe_shard_paused`, and `observe_lag` calls for assertions.

=== Restore readiness

Located in `proximadb_catalog::dr_restore`:

* `ManifestEntryRef` — engine-side projection of a manifest row.
  Bridge from `GlobalManifestEntry` lives in the root crate.
* `ManifestEntryStatus` (Active / Flushed / Archived / RolledBack)
  with `is_restorable()`.
* `RestoreReadiness` — the contract's exact result struct.
* `RestoreStatus` (Ready / Incomplete / Stale / KmsBlocked /
  NoReplicatedManifest) with precedence rules pinned by tests.
* `assemble_readiness(policy, target_lsn, entries, missing_objects,
  missing_metadata, kms_accessible, now_ms)` — pure assembler.
* `DrRestoreReadinessChecker` async trait — the operator-callable
  surface.

Reference checker plus its three pluggable concerns:

* `ManifestSource` async trait — `entries_for_collection(collection_id)`.
* `DestinationPresenceCheck` async trait — given candidate object
  keys, returns the subset not present at the destination.
* `KmsAccessibilityCheck` async trait — `is_accessible(policy)`.
* `EngineRestoreReadinessChecker<M, D, K>` generic struct wiring
  the three traits through `assemble_readiness`. Constructors
  `new` (system clock) and `with_clock` (test-injectable).

Public testing surface (`dr_restore::testing`):

* `StaticManifestSource`, `StaticDestinationPresence`,
  `StaticKmsCheck` — seeded reference impls for integration tests.

== Root-Crate Bridges

The root crate (`proximadb`) hosts the bridges that pull in deps the
catalog crate cannot take.

=== Manifest bridge

Located in `proximadb::storage::persistence::write_ahead_log::manifest::dr_bridge`:

* `wal_status_to_manifest(WalEntryStatus) -> ManifestEntryStatus`.
* `manifest_entry_to_ref(&GlobalManifestEntry) -> ManifestEntryRef`.
* `manifest_entries_to_refs(&[GlobalManifestEntry]) -> Vec<...>`.

Translates the engine's WAL types into the catalog-friendly
projection so `assemble_readiness` can consume them.

=== Prometheus bridge

Located in `proximadb::metrics::dr_metrics`:

* `PrometheusDrMetrics` — zero-sized impl of `DrMetrics`. All state
  lives in the global Prometheus registry.
* Metric families (every metric named in contract §"Observability"):
  - `proximadb_dr_ticks_total{tier, provider, outcome}`
  - `proximadb_dr_drift_total{provider, reason}`
  - `proximadb_dr_reconciler_errors_total{provider, reason}`
  - `proximadb_dr_reconciler_paused_total{reason}`
  - `proximadb_dr_provider_lag_seconds{provider, region_pair}`

== Operator Responsibilities

Everything not in the lists above is the operator's job. The
contract calls out the major pieces; this ADR names the integration
points each one slots into.

[cols="2,2,4"]
|===
| Operator responsibility | Engine surface it plugs into | Where it lives

| Concrete S3 / Azure / worker adapter
| `DrProviderAdapter` trait
| AnvaiOps or self-hoster's crate

| sqlx / filestore policy stores
| `CollectionDrPolicyStore` + `DrPolicyStore` traits
| AnvaiOps

| Customer HTTP/gRPC handlers
| `CollectionDrPolicyStore` trait (called server-side)
| AnvaiOps

| Server boot wiring (construct runner with real backends)
| `DrReconcilerRunner::new` + `tokio::spawn`
| AnvaiOps / root-crate server boot

| Region-pair eligibility curation
| The `region_pair_id` field on `CreatePolicyRequest`
| AnvaiOps config

| Tier-to-pool placement policy
| The `storage_pool_class` field on `CatalogNamespace`
| AnvaiOps namespace provisioning

| Billing SKUs / cost estimates / downgrade gates
| `DrBillingBinding` field + `BillingApproval` request
| AnvaiOps billing layer

| Failover runbook automation
| `DrRestoreReadinessChecker` trait + the
  `EngineRestoreReadinessChecker` reference impl
| AnvaiOps operations

| Manifest source bridge for the restore checker
| `ManifestSource` trait — wraps `GlobalManifestService` in the
  root crate via the existing `dr_bridge` helpers
| Root crate / AnvaiOps

| Destination-presence probe for the restore checker
| `DestinationPresenceCheck` trait — typically dispatches to HEAD
  requests or to a `DrProviderAdapter::fetch_state` derivative
| AnvaiOps

| KMS-accessibility probe for the restore checker
| `KmsAccessibilityCheck` trait — typically a `Decrypt` against a
  canary blob in the destination region
| AnvaiOps

| Grafana dashboards / PagerDuty wiring
| Scrape `/metrics/prometheus` for `proximadb_dr_*`
| AnvaiOps observability stack
|===

== Wiring Recipe

The minimum server boot looks like this:

[source,rust]
----
use proximadb_catalog::dr_policy_store::InMemoryCollectionDrPolicyStore;
use proximadb_catalog::dr_reconciler::{
    DrReconcilerDriver, DrReconcilerRunner, DrReconcilerShard,
    RunnerConfig,
};
use proximadb::metrics::dr_metrics::PrometheusDrMetrics;
use std::sync::Arc;

// Operator-provided pieces.
let store = Arc::new(my_sqlx_policy_store());          // operator
let adapter = Arc::new(my_aws_s3_adapter());          // operator

// Engine pieces.
let driver = Arc::new(DrReconcilerDriver::new(
    store.clone(),
    adapter.clone(),
    "reconciler",
));
let shard = Arc::new(
    DrReconcilerShard::with_clocks(
        driver,
        store,
        Default::default(),                            // BackoffPolicy
        Arc::new(|| /* now_ns */ 0),
        Arc::new(|| /* jitter u01 */ 0.5),
    )
    .with_holder_id(format!("shard-{pid}"))
    .with_metrics(Arc::new(PrometheusDrMetrics::new())),
);

let runner = DrReconcilerRunner::new(shard, RunnerConfig::default());
let (shutdown_tx, shutdown_rx) = tokio::sync::watch::channel(false);
let handle = tokio::spawn(runner.run(shutdown_rx));

// ... server lifecycle ...

// On graceful shutdown:
shutdown_tx.send(true).unwrap();
let _stats = handle.await.unwrap();
----

== Consequences

* The catalog crate is now a complete, self-contained DR contract
  surface. Self-hosters can build their own SaaS layer against it
  without reading anything but this ADR plus
  `COLLECTION_DR_CRR_ENGINE_CONTRACT.adoc`.
* The root crate adds two bridges and one Prometheus impl —
  ~600 lines, all in clearly-named modules.
* Operator-side work (sqlx store, S3 adapter, Azure adapter, HTTP
  API, runbook automation) is fully unblocked. Each integration
  point above names the exact trait or struct to implement.
* Adding a new engine method (e.g., a new `DrMetrics` method or a
  new `DrPolicyStore` method) is the contract author's call, not
  the operator's. The default-method pattern on `DrMetrics`
  ensures additions stay source-compatible.
