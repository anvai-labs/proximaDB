== Context

Consumers (notably AnvaiOps's connector SDK) cannot ingest through the official
`proximadb_sdk.ProximaDBClient`. Five verified root causes:

1. **Broken hand-written adapter.** `adapters/rest_adapter.py::insert_document` calls
   `self._client._session.post(...)` / `self._client._timeout`, but `ProximaDBClient` has neither
   (it uses `_http_client`). Always raises `AttributeError`, which `_call_document_adapter`
   *swallows* → silent in-memory `DocumentRepository`. Document operations never hit the server.
2. **No per-call headers.** Headers are baked into the `httpx.Client` at construction
   (`config.custom_headers`). `X-Tenant-ID` / `X-Ingest-Mode` / `X-Embed-Source` — load-bearing for
   tenant isolation, billing, and embedding control — cannot be injected per call.
3. **No fallback control.** `_prefer_local_fallback` auto-activates on any adapter error; no flag
   makes a server-backed client raise instead of silently going in-memory.
4. **Spec ↔ reality inversion.** The OpenAPI documents `POST /api/v2/document-collections/{c}/documents`
   (`insertDocument`, free-form body); the *working* ingest surface every consumer uses is
   `POST /api/v2/collections/{collection_id}/documents` (`ingest_documents`,
   `{records:[{id,text,metadata}]}` + `X-Embed-Source` → server-side embedding) — which was **not in
   the OpenAPI** because the route was wired as a plain `.route()` with no `#[utoipa::path]`.
5. **Drift.** A spec-correct generated transport (`clients/python/.../_generated/rest/api/documents/`)
   exists but is unused by the hand-written client.

== Decision

**The OpenAPI is the single source of truth for the document SDK surface, and it is generated from
Rust** (`#[utoipa::path]` + `#[derive(ToSchema)]`, checked by the `openapi_spec_gen` drift gate).
Generated transports are first-class and primary across all languages (Python/Rust/Go/Node from one
spec); hand-written surfaces are deprecated, then removed.

* **Canonical ingest surface** = `POST /api/v2/collections/{collection_id}/documents`
  (`operationId: ingestDocuments`), now documented **from Rust** (`src/network/rest/v2/documents.rs` —
  `#[utoipa::path]` on `ingest_documents` + `ToSchema` on the ingest DTOs; registered in
  `openapi.rs`). It is the only surface live-verified for native text→embedding, and it is what
  consumers already depend on. Hand-editing the generated YAML is explicitly NOT the path — the
  annotation is the source, the YAML is regenerated.
* **`insertDocument`** (`/api/v2/document-collections/{c}/documents`) stays as the legacy
  document-collection surface; the generated transport will expose both, with `ingestDocuments` as the
  primary ingest path the SDKs align to.
* **Generated transports become the primary client path** for documents; the hand-written
  `ProximaDBClient` document methods + the broken `rest_adapter` document methods are deprecated,
  then deleted.
* **Header passthrough + server-required mode** land on the generated path: per-call `headers=`
  (reuse the existing `kwargs["headers"]` seam in `protocols/rest_sync.py`) and an
  `allow_local_fallback=False` default so a server-backed client raises instead of silently going
  in-memory.

== Consequences

* Cross-language consistency: one Rust-annotated spec → generated clients for Python/Rust/Go/Node.
  No more per-language hand-rolled drift.
* Maintainability: the contract changes once (in Rust); clients regenerate; the drift gate enforces
  YAML↔code parity.
* Phased execution (P0–P5) so consumers migrate before the hand-rolled surface is removed. AnvaiOps's
  connector SDK (Phase 4) switches its `_rest_ingest` to the generated `ingest_documents`, retiring
  its hand-rolled REST + the documented blocker.

== Implementation history

deprecated (#462); P2 SDK `ingest_documents` delegates to the generated client (#532); P3
