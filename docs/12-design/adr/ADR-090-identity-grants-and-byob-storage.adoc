*Reconciled 2026-10-15 — L0/L1 largely landed:* L0.1 principal + API-key registry (#1514), L0.3 one gRPC port-identity construction (#1516), L1.1 Grant catalog object + admin surface (#1517, #1534), L1.2 grant enforcement at read admission default-OFF (#1529), item 3 escalation-safe cross-tenant open (#1562), L2.1 subject-parameterized row predicates (#1689). == Context — the target model

The security/tenancy architecture is re-derived from first principles against the
co-design spine (governance dimension, `CODESIGN_DIMENSIONAL_ARCHITECTURE_2026_06_19.adoc`
§2.5) and the standard marketplace model (Snowflake shares, Unity Catalog, S3 bucket
policy): storage placement and access control are *different concerns with different
mechanisms*.

The target model, in four claims:

. **Storage is bring-your-own.** A tenant may use an arbitrary S3 bucket / Azure storage
  account. Our path layout (`DrPathBuilder`) is *our convention for new files* — it serves
  billing attribution, DR/blast-radius, and residency. It is **not** the authorization
  mechanism.
. **Ownership is structural; access is granted.** A collection is *owned* by exactly one
  tenant (its path, its bill, its residency). *Access* can be granted cross-tenant.
  Authorization therefore lives on **catalog metadata** — namespace/collection — evaluated
  by ABAC at the catalog seam (open/plan time), not per row.
. **Row/vector-level access is read-time ABAC push-down.** The security predicate derives
  from policy over record metadata and **subject attributes**, AND-composed into the query
  plan (the existing ACORN push-down), never a bolted-on WHERE.
. **An API key authenticates a user.** Many users (keys) belong to one tenant/account; the
  ABAC subject is the *user*, with tenant as a server-resolved attribute of the credential
  — never a client-asserted header.

=== Reconciling with co-design P10 ("isolation at the I/O boundary, not per-query predicate")

P10 praises `DrPathBuilder` path isolation as "structural isolation in the object key, not
a WHERE clause that one missed predicate leaks." The audit (below) shows the codebase
*already* implements P10's spirit correctly: **no code derives authorization from a storage
key** — decisions are made upstream in catalog/tenant context and the path is *derived
from* the decision. This ADR keeps that: a cross-tenant grant is evaluated **once at the
catalog seam** and yields a capability to read the owner's path. The per-row
`record.tenant_id == ctx.tenant_id` predicate (the thing P10 actually warns against) is
retired per TD-TENANT-2 — and sharing *requires* retiring it, since a shared read is by
definition a foreign-tenant read.

== Current state — measured 2026-08-06

Three parallel audits (identity, authorization, storage) produced 53 file:line-evidenced
gaps. The load-bearing findings:

=== Identity (full inventory: appendix A)

* `ApiKeyInfo { user_id: String /*required*/, tenant_id: Option<String>, .. }`
  (`src/security/auth_service.rs:53`) — **key→user is already the data shape.** But there
  is no key store (config.toml, loaded once at boot, plaintext, no mint/revoke), **three
  competing key tables** with three validators, and **no user registry** — "many users per
  tenant" cannot be enumerated or provisioned.
* Tenant is a **parallel client-asserted channel** (`X-Tenant-ID`) reconciled against the
  credential; under the default `HeaderTrustPolicy::Open` a bare header with no credential
  is accepted (`config/config.toml:350`).
* **pgwire authenticates nothing** — unconditional `AuthenticationOk`
  (`postgres/protocol.rs:1043`); the ABAC subject is the client-supplied `user` param.
* Only **1 of 4 surfaces** uses the shared orchestrator `resolve_request_identity`
  (Arrow Flight, `arrow_ipc/service.rs:674`); REST/gRPC/pgwire re-implement the sequence.
* `account_id` (string tier "above tenant", `middleware/tenant.rs:73`) is **dead** — never
  set outside tests — while `tenant_stable_id` *is* the ADR-0083 account u32. Account ≡
  tenant in code today.
* The subject **never reaches the catalog**: catalog identity is tenant strings + u32s;
  no per-user catalog authorization or attribution exists.

=== Authorization (full inventory: appendix B)

* `PolicyBinding { object_id, tenant_stable_id, scope, effect, predicate_ref, field_mask }`
  (`fc_metamodel.rs:312`) has **no subject field and no action field** — a binding applies
  to every subject in the tenant; write-side authorization does not exist.
* **No catalog-open authorization**: `validate_tenant_collection_access`
  (`vectors/legacy.rs:806-856`) is tenant *scoping*; its RBAC branch **logs a TODO instead
  of enforcing** (`:838-845`). The written check `check_collection_access`
  (`governance/collection_rbac.rs:47`) has test-only callers. DDL/LIST are outside ABAC.
* Row predicates are **constants, not subject-parameterized**: `compile_security_filter`
  (`abac/compile.rs:277-302`) dereferences stored `FilterExpression`s;
  `SubjectAttributes::load_bearing()` (`fc_metamodel.rs:1094`) has zero production callers;
  the documented `dept == $subject.dept` (`compile.rs:128`) is unimplementable today.
* **Cross-tenant is impossible by construction at four layers** (binding filter
  `context.rs:158-164`, store partition, authority keying, catalog resolution), with two
  tests locking the impossibility in. Any grant model must extend the *type*.
* **Six client-facing read paths hardcode `System`** (graph hybrid, REST analytics,
  unified executor, streaming search, `VectorOpsPort::unified_search_native`, fusion's
  graph leg) — genuine bypasses.
* `permitted_principals` is a **second, fail-open** access channel ABAC never reads
  (empty ⇒ allow-all, `records/lib.rs:987`); `rls_policy_id` is a dead field; column
  masking (`FieldMask`) is dormant.
* **The predicate-object store is globally keyed** (`compile.rs:136-141`) — tenant A's
  binding can dereference tenant B's predicate `ObjectId`. The one non-structural spot in
  the tenant wall, contradicting the store's own trait contract (`compile.rs:62-64`).
* Two half-built models hold each other's missing piece: the live ABAC path lacks
  subject-parameterization, which the **unwired** legacy RLS
  (`CollectionRLS::build_filter(predicate, user_context)`, `rls/service.rs:294-470`)
  already implements; the missing grant vocabulary exists as **dead code** in
  `services/tenant_access/` (`CollectionSharing { collection_id, shared_with_tenant_id,
  permissions: {Read,Write,Admin} }`, feature-gated off, zero call sites).

=== Storage (full inventory: appendix C)

* **One credential identity per cloud scheme per process**, from env only
  (`filesystem/mod.rs:481-535`); the factory is keyed by *scheme*
  (`filesystems: HashMap<String, _>`, `mod.rs:263`), so **two accounts of one cloud
  structurally cannot coexist**. Many buckets under one account already work
  (`aws_s3.rs:104 store_for(bucket)`).
* Per-collection location half-exists, asymmetrically: reads honor an arbitrary
  `CatalogStorageLayout.location` URI verbatim
  (`object_store_parquet_reader.rs:557-560`), while writes **strip the scheme/authority**
  (`table_write_executor.rs:661-667 normalize_object_path_prefix`) and land in the one
  global bridge. The warehouse root is a hardcoded `format!("file://{}/warehouse", ..)`
  (`multi_server.rs:904`).
* `storage_config.storage_path` on collection create is accepted **verbatim, unvalidated**
  (`collection/manager.rs:1057-1073`) — currently unreachable from the network surface,
  but wiring it through as-is would ship an SSRF/exfiltration primitive.
* The external-table allowlist is the right *shape* but process-global env
  (`PROXIMADB_EXTERNAL_TABLE_ROOTS`, `ddl/mod.rs:2224-2240`) — cannot express "tenant A
  may use bucket A."
* Credential-carrying types exist and are **inert**: `FilesystemAuthConfig` (always
  `None`), `CatalogCredentials` (never consumed); `StoragePoolClass::Dedicated` is
  documented as "dedicated bucket/storage-account per tenant" and never selects a store.
* **Path is already not load-bearing for security** — no reader checks a key prefix
  against the caller; the tenant-path CI guard is a lint on literal formatting, not an
  enforcement of store routing.

== Decision — four layers

=== L0 — Identity becomes catalog-resident

* **User and API-key registries as catalog objects.** Keys are hashed (prefix + secret,
  constant-time compare), mintable/revocable/rotatable at runtime via admin API. A key
  **must** resolve to a user; a user **must** belong to a tenant (`tenant_id` stops being
  `Option`). mTLS/JWT credentials likewise must resolve a tenant or be rejected under
  `MultiTenant` mode.
* **Tenant derived from the credential.** `X-Tenant-ID` is demoted to an optional
  cross-check (mismatch ⇒ reject); the bare-assertion acceptance under
  `HeaderTrustPolicy::Open` is retired for authenticated deployments.
* **Account ≡ tenant, finalized.** Per ADR-0083 phase 5: delete the dead
  `MiddlewareTenantContext.account_id` string tier; `tenant_stable_id` is the account.
  (If a true multi-tenant-per-account tier is ever needed, it is a new ADR, not a dormant
  field.)
* **One orchestrator on all four surfaces.** `resolve_request_identity` becomes the only
  authenticate→tenant-gate→subject path (completes TD-ABAC-6 PR-B); the three duplicate
  key tables collapse to the catalog registry; pgwire gains real authentication (password
  messages mapped to API keys / SCRAM) or is explicitly a dev-only surface behind a
  registry-documented gate.
* Subject shape: `SubjectId` stays a string but is canonically `user_id`; subject
  attributes (roles, groups, department, …) are **server-resolved** into
  `SubjectAttributes` (the type exists) at resolution time.

=== L1 — Catalog-seam authorization and grants (sharing lives here)

* **Every catalog operation evaluates ABAC**: open-for-read/write, CREATE/DROP/ALTER,
  LIST (list results are filtered to authorized resources). This requires extending the
  policy model with **subject and action**:
  `Grant { resource: Scope, grantee: Grantee, actions: BitSet<Action>, predicate_ref:
  Option<ObjectId>, field_mask: Option<FieldMask>, expiry: Option<ts> }` where
  `Grantee ∈ { Tenant(tenant_stable_id), User(tenant_stable_id, SubjectId), Role(..) }`
  and `Action ∈ { Read, Write, Ddl, Grant }`. `PolicyBinding` remains the *constraint*
  layer (deny-biased, subjectless restrictions); `Grant` is the *entitlement* layer.
  Composition: deny > absence-of-grant > grant, fail-closed.
* **Cross-tenant sharing = a `Grant` whose grantee names a foreign tenant/user.**
  Evaluated once at the catalog seam; on admit, the plan receives a read capability for
  the *owner's* storage path with the grant's predicate/mask attached. The four
  hard-scoping layers are amended deliberately (type change), and the two
  impossibility-locking tests are rewritten to assert the new invariant: *foreign access
  only via an explicit grant, never via bindings*.
* **Resurrect, don't reinvent**: the dead `services/tenant_access::CollectionSharing`
  shape is the model for `Grant`; it moves into the catalog (durable, tenant-partitioned)
  and its in-memory fixture impl is deleted.
* Wire the collection-open gate: `validate_tenant_collection_access` calls the enforcer
  (subject now available per L0) instead of logging; `check_collection_access`'s fail-open
  empty-list semantics are inverted or the function is subsumed by `Grant` evaluation.

=== L2 — Row/vector level: one model, subject-parameterized

* **Implement `$subject.<attr>` substitution** in `compile_security_filter`, sourcing
  exclusively `SubjectAttributes::load_bearing()` (server-resolved attrs only — claims
  are advisory). One predicate object then serves all subjects; deny-biased composition
  stops needing per-subject binding fan-out. Harvest the parameterization logic from the
  unwired legacy RLS (`CollectionRLS::build_filter`), then delete that model.
* **Collapse the parallel channels**: retire fail-open `permitted_principals` enforcement
  (`is_accessible_by`, `RlsRecordPredicate`, fusion's graph leg) in favour of ABAC
  grants/predicates; drop the dead `rls_policy_id` field at the next record-schema
  revision; wire or delete column masking (`FieldMask` currently dormant).
* **Close the six `System` bypasses** (graph hybrid, analytics, unified executor,
  streaming, `VectorOpsPort::unified_search_native`, fusion graph leg) — each takes the
  same `ReadContext` threading the search seam already has.
* **Partition the predicate-object store by tenant** — the trait contract already
  promises it; make the filesystem store honor it.
* Vector-path namespace fix: `resolve_vector_read_context` passes the real namespace
  instead of the hardcoded `0` (`vectors/legacy.rs:683`), so `Scope::Namespace` policy
  applies uniformly across relational and vector paths.

=== L3 — BYOB: storage bindings in the catalog

* **`StorageBinding` catalog object**: `{ binding_id, tenant_stable_id, scheme, authority
  (bucket/account), credential_ref, pool_class, allowed_prefixes }`. Credentials live in
  a secret store (env-ref, file-ref, or cloud KMS/managed identity), **never** inline in
  the catalog; `CatalogCredentials`/`FilesystemAuthConfig` are the shapes to complete.
* **Factory re-keyed** from scheme to `(scheme, authority, credential_ref)` — the single
  chokepoint is `FilesystemFactory::get_filesystem(url)` (`filesystem/mod.rs:539`), so
  every engine read/write inherits routing without call-site changes. The DataFusion-side
  `ObjectStoreBridge` becomes a resolver (`bridge_for(tenant, collection)`).
* **Placement policy replaces random choice**: collection create resolves its
  `StorageAssignment.base_location` from the tenant's bindings (default pool → shared
  deployment bucket; `Dedicated` pool → tenant's own binding). `StoragePoolClass::
  Dedicated` finally routes. Path layout under the chosen root stays `DrPathBuilder`
  convention (billing/DR/residency).
* **Per-tenant location policy replaces the env allowlist**: `external_location_allowed`
  generalizes to `(tenant, location)` backed by the tenant's bindings; **read-time
  revalidation** is added so a layout injected by any path (materializer, import) is
  checked at open, closing today's read/write asymmetry.
* **Close the back door first**: `storage_config.storage_path` gets scheme/allowlist
  validation *before* any network surface exposes it; writes stop stripping
  scheme/authority (`normalize_object_path_prefix`) once the resolver exists; the
  hardcoded warehouse root becomes a `StorageLocation`.
* Commercial note (per co-design §2.5): BYOB/BYOK is the edition-gated enterprise margin
  surface. OSS ships the mechanism (bindings, resolver, validation); anvaiops ships the
  policy/entitlement (which tiers may bind their own storage), per the OSS boundary.

=== Sequencing

L1 depends on L0 (grants need real, catalog-resident subjects). L2 depends on L1
(predicates/masks attach to grants; bypass closure reuses the seam identity). L3 is
parallel to L1/L2 but gated on L0 (credential bindings need the catalog identity layer
and admin-API auth). Within each layer every slice lands independently green; enforcement
flips are default-OFF behind registry-documented gates until the corresponding e2e
ratchets exist (mandates #8-posture for authz: old behavior preserved until the gate
flips, ratchet tests only go up).

== Supersedes / amends

* **Amends the P10 reading** of `CODESIGN_DIMENSIONAL_ARCHITECTURE_2026_06_19.adoc` §2.5:
  the structural boundary is the *catalog decision + derived path*, not the path string
  itself; grants extend it to cross-tenant access without reintroducing per-row
  predicates.
* **TD-TENANT-2** gains a sharing addendum (same PR): retiring the per-row tenant
  predicate is *required* by sharing, and "access follows ownership" is corrected to
  "ownership is structural, access is granted."
* **ADR-0083** phase 5 (tenant ≡ account) is confirmed and finalized by L0.
* `services/tenant_access` (dead) is superseded by the L1 `Grant` object; the legacy RLS
  model (`rls/policy.rs`, `rls/service.rs`) is harvested then retired by L2.

== Consequences

* Positive: one identity, one authorization model, one credential story; sharing and BYOB
  become expressible (and sellable); six bypasses close; the fail-open channels die; the
  53-gap inventory becomes a burn-down list.
* Negative / cost: `Grant` is a durable catalog-schema addition (serde-compat shim +
  legacy round-trip per ADR-024 rollout doctrine); four surfaces must converge on one
  orchestrator (the seam work is the bulk of L0); BYOB credential handling adds a secret
  management dependency; the impossibility-locking tests are deliberately rewritten,
  which must be called out loudly in review.
* Risks: enforcement flips can break existing deployments that relied on open posture —
  hence default-OFF gates + ratchets; predicate substitution must be fail-closed on
  missing attributes (absent `$subject.dept` ⇒ deny, mirroring the existing missing-ref
  compile).

== Out of scope

* v1 wire surface changes (owned by TD-V1SUNSET-1/2); generated prost types.
* Data-plane encryption / BYOK key management beyond the credential-ref seam.
* Rate limiting / IP restrictions on keys (dead fields today; separate hardening TD).
