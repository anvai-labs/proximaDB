== Status

Accepted — Wired (verified 2026-05-26; source locations re-verified 2026-10-15). See

== Context

ProximaDB had Iceberg/Delta/Unity catalog *client* implementations but no way for external
compute engines (Spark, Trino, DuckDB, Flink, PyIceberg, Polaris) to treat ProximaDB as a catalog
authority without a custom connector. The Iceberg REST Catalog spec v1 is the lightweight HTTP
contract every major engine supports out of the box (XTable, 2401.09621, confirms it as the
open-format federation convergence point); Iceberg REST + Arrow Flight maps onto the Hadoop
`getSplits()` (metadata) / `createRecordReader()` (data I/O) split.

== Decision

Mount a full Iceberg REST Catalog v1 server at `/iceberg/v1` (port 5678).  It is always on — no feature gate.  External engines configure:

----
catalog URI: http://host:5678/iceberg/v1
----

This ADR is constrained by ADR-009. Iceberg REST is a schema-on-read catalog and split-planning
surface over xCatalog and `ProximaRecord` views. It must not make Iceberg metadata, Parquet files,
Arrow Flight tickets, or legacy vector-shaped DTOs the semantic record authority.

=== Endpoint Surface

----
GET  /iceberg/v1/config
GET/POST /iceberg/v1/namespaces
GET/HEAD/DELETE /iceberg/v1/namespaces/{ns}
POST /iceberg/v1/namespaces/{ns}/properties
GET/POST /iceberg/v1/namespaces/{ns}/tables
GET/HEAD/DELETE/POST /iceberg/v1/namespaces/{ns}/tables/{t}
POST /iceberg/v1/namespaces/{ns}/register
GET  /iceberg/v1/namespaces/{ns}/views   (empty stub, v2 placeholder)
POST /iceberg/v1/oauth/tokens            (501 when auth disabled)
----

=== ProximaRecord → Iceberg Canonical Schema (ADR-ICE-001)

Every ProximaDB collection exposed as an Iceberg table uses this fixed column prefix.
Cross-engine consistency depends on it — do not deviate.

[cols="3,3,2,3"]
|===
| ProximaRecord field | Iceberg column | Iceberg type | Notes

| `id` / `oid` | `id` | `string` required | partition candidate
| `tenant_id` | `tenant_id` | `string` required | default partition column
| `created_at_ns` | `created_at` | `timestamptz` | nanoseconds ÷ 1000
| `updated_at_ns` | `updated_at` | `timestamptz` |
| `valid_from_ns` | `valid_from` | `timestamptz` optional | bi-temporal lower bound
| `valid_to_ns` | `valid_to` | `timestamptz` optional | bi-temporal upper bound
| `actor` | `actor` | `string` optional | provenance
| `origin` | `origin` | `string` optional | provenance
| `props` | `props` | `map<string, binary>` | msgpack-encoded ProximaValues
| `labels` | `labels` | `list<string>` |
| `embeddings[i].values` | `embedding_{model_id}` | `list<float>` | dim in table properties
| `edge.source_id` | `edge_source_id` | `string` optional | graph edge
| `edge.target_id` | `edge_target_id` | `string` optional | graph edge
| `edge.edge_type` | `edge_type` | `string` optional |
| `edge.weight` | `edge_weight` | `float` optional |
|===

Table properties carry HNSW index metadata for engine-side discovery:

[source,json]
----
{
  "proximadb.collection": "my_collection",
  "proximadb.flight.endpoint": "grpc://localhost:5680",
  "proximadb.index.embedding_model_a.type": "hnsw",
  "proximadb.index.embedding_model_a.dim": "768",
  "proximadb.index.embedding_model_a.ef_construction": "200",
  "proximadb.record.envelope": "ProximaRecord/v1"
}
----

=== Synthetic Iceberg Snapshot

For existing ProximaDB collections, `load table` returns a synthetic snapshot:

* One current snapshot with a manifest-list URL (`/iceberg/v1/{ns}/{t}/manifests/current`)
* One manifest entry per VIPER/NOVA/HELIX storage shard: row count, size bytes, column stats
* Arrow Flight ticket embedded in `write-credentials` → workers exchange at port 5680

=== Hadoop Split Mapping

[source]
----
Coordinator: getSplits() / planInputPartitions()
  → GET /iceberg/v1/.../tables/{t}        (metadata-only, cheap)
  → parse partition spec + manifest entries
  → one split per ProximaDB storage shard

Worker: createRecordReader() / scan
  → exchange Arrow Flight ticket at port 5680
  → read Arrow IPC batches of ProximaRecord rows
----

This is Trino `ConnectorSplitSource` + `ConnectorPageSource` and Spark `DataSource V2` exactly.

For external Hadoop-style key/value or semi-structured files, xCatalog registration supplies the
`ProximaType` mapping: keys map to identity/partition/index columns and values map to `Map`, `Json`,
`Struct`, `Binary`, or declared typed columns. Readers project data into `ProximaRecord` before
query planning.

== Consequences

* External engines connect with no custom connector code; ProximaDB is a catalog authority and
  engines plan splits against its shards; index metadata in table properties advertises
  embedding dims/index types.
* Synthetic Iceberg manifests must stay consistent with engine shard topology across compaction.
* Endpoints are unconditional (no feature flag); the `/iceberg/v1` prefix avoids `/api/v1/*`.
* OAuth2 token exchange stays an intentional 501 (opt-in; header-auth/no-auth documented in the
  response body).
* Stale since filing: Arrow Flight is no longer a 501 stub and is multiplexed on port 5678
  (`multi_server.rs`); the `5680` endpoint/port in the table-property and split-mapping examples
  above is historical.
