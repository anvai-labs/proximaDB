= ADR-001: Capability Registry Architecture
:toc: left
:toclevels: 3
:icons: font
:source-highlighter: rouge
:last-updated: 2026-04-02

== Status

Accepted

Reconciliation (2026-10-15): implemented in a **reduced shape**. The registry lives in
`crates/query/proximadb-query-capability` (`CapabilityRegistry` over a `Capability` /
`CapabilitySet` model; errors in `src/errors/capability_error.rs`), not the tiered
`CapabilityDescriptor`/`CapabilityTier` model or the `src/query/capabilities/` paths in the File
Plan below. **Open:** `SUPPORTED_SURFACE.json` is not generated from the live registry —
`docs/SUPPORTED_SURFACE.adoc` is hand-maintained, guarded by `scripts/validate_capability_matrix.py`
and its status-as-of tag. The File Plan paths are historical.

== Context

ProximaDB has 6 storage engines (SST, VIPER, NOVA, HELIX, SWIFT, RAPTOR), 5 data models (Vector, Document, Graph, Observability, Relational), 4 protocol surfaces (REST, gRPC, SQL, PostgreSQL wire), and multiple query entry points (federated, unified, facade). There is no unified mechanism to:

1. Declare what each subsystem can and cannot do
2. Validate that a query plan can be executed before attempting it
3. Generate a machine-readable support matrix
4. Fail with structured errors when capabilities are missing

Capabilities are currently scattered across:

* `src/storage/trait_components/capabilities.rs` — per-engine `EngineCapabilities` trait (flush, compaction, scan)
* `src/storage/engine_capabilities.rs` — static search recommendation API
* `src/storage/multimodel/traits.rs` — `StoreCapabilities` struct (transactions, ACID, streaming)
* Implicit knowledge in executor code (e.g., federated executor silently returns empty on missing store)

== Decision

Introduce a **query-centric capability registry** in `src/query/capabilities/` that:

1. Owns the normalized capability model (`CapabilityDescriptor`, `CapabilityRequirement`, `CapabilityTier`)
2. Composes capabilities from adapters (not by replacing existing traits)
3. Validates plans at build-time and execution-bind-time
4. Generates serializable snapshots for support-surface documentation

=== Core Types

[source,rust]
----
/// Maturity tier for a capability
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash, Serialize, Deserialize)]
pub enum CapabilityTier {
    Supported,
    Beta,
    Experimental,
    Unsupported,
}

/// Domain subject for a capability
#[derive(Debug, Clone, PartialEq, Eq, Hash, Serialize, Deserialize)]
pub enum CapabilitySubject {
    Vector,
    Document,
    Graph,
    Observability,
    Scan,
    Join,
    Explain,
    Transaction,
    Protocol,
}

/// What a subsystem claims it can execute
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct CapabilityDescriptor {
    pub subject: CapabilitySubject,
    pub operation: String,
    pub engine: Option<String>,
    pub protocol: Option<String>,
    pub tier: CapabilityTier,
    pub predicates: Vec<String>,
    pub limits: Vec<CapabilityLimit>,
    pub evidence: CapabilityEvidence,
}

/// What a plan node requires to execute honestly
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct CapabilityRequirement {
    pub subject: CapabilitySubject,
    pub operation: String,
    pub mandatory: bool,
    pub acceptable_tiers: Vec<CapabilityTier>,
    pub disallow_fallback: bool,
    pub reason: String,
}

/// Evidence that a capability is backed by code and tests
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct CapabilityEvidence {
    pub test_suite: Option<String>,
    pub integration_verified: bool,
    pub benchmark_verified: bool,
    pub last_verified: Option<String>,
}

/// Quantitative limits on a capability
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct CapabilityLimit {
    pub name: String,
    pub max_value: Option<u64>,
    pub description: String,
}

/// Scope for grouping capabilities
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct CapabilityScope {
    pub engine: Option<String>,
    pub model: Option<CapabilitySubject>,
    pub protocol: Option<String>,
}
----

=== Registry Interface

[source,rust]
----
/// Central registry for all system capabilities
pub struct CapabilityRegistry {
    descriptors: Vec<CapabilityDescriptor>,
}

impl CapabilityRegistry {
    pub fn new() -> Self;

    /// Register capabilities from an adapter
    pub fn register(&mut self, descriptors: Vec<CapabilityDescriptor>);

    /// Check if a set of requirements can be satisfied
    pub fn validate(&self, requirements: &[CapabilityRequirement]) -> ValidationResult;

    /// Query capabilities by subject and operation
    pub fn query(&self, subject: &CapabilitySubject, operation: &str) -> Option<&CapabilityDescriptor>;

    /// Generate a serializable snapshot (for SUPPORTED_SURFACE.json)
    pub fn snapshot(&self) -> CapabilitySnapshot;

    /// Get all capabilities at or above a given tier
    pub fn at_tier(&self, tier: CapabilityTier) -> Vec<&CapabilityDescriptor>;
}

pub struct ValidationResult {
    pub valid: bool,
    pub satisfied: Vec<CapabilityRequirement>,
    pub unsatisfied: Vec<CapabilityRequirement>,
    pub warnings: Vec<String>,
}
----

=== Adapter Pattern

Existing capability types are bridged, not replaced:

[source,rust]
----
/// Bridge from storage engine capabilities
impl From<(&str, &dyn EngineCapabilities)> for Vec<CapabilityDescriptor> { ... }

/// Bridge from multi-model store capabilities
impl From<&StoreCapabilities> for Vec<CapabilityDescriptor> { ... }
----

Rules:

* A provider can only advertise `Supported` if the execution path exists and is test-backed
* If store and provider disagree, registry takes the lower tier and emits a warning
* Backend-specific capabilities (e.g., filtered ANN on HNSW) remain backend-scoped
* Incomplete adapters default to `Unsupported`, never `Supported`

=== Validation Flow

[source,text]
----
1. Plan build time:
   PlanBuilder attaches CapabilityRequirement to each PlanOperator
   → CapabilityRegistry.validate(requirements) → ValidationResult
   → If !valid: return structured CapabilityError (no execution)

2. Execution bind time:
   Executor checks engine/service availability
   → If engine missing: return CapabilityError::ServiceUnavailable
----

=== Error Model

[source,rust]
----
pub enum CapabilityError {
    UnsupportedOperation {
        subject: CapabilitySubject,
        operation: String,
        available_tier: CapabilityTier,
        required_tier: CapabilityTier,
    },
    ServiceUnavailable {
        subject: CapabilitySubject,
        reason: String,
    },
    FallbackDisallowed {
        subject: CapabilitySubject,
        operation: String,
        reason: String,
    },
}

impl From<CapabilityError> for ApiError { ... }  // HTTP 501/503
impl From<CapabilityError> for tonic::Status { ... }  // gRPC UNIMPLEMENTED/UNAVAILABLE
----

== Consequences

* Every supported operation has a machine-readable descriptor with evidence
* Unsupported operations fail with structured errors at plan time, not during execution
* `SUPPORTED_SURFACE.json` is generated from live registry, not hand-maintained docs
* New engines/models register capabilities via adapters without modifying existing code
