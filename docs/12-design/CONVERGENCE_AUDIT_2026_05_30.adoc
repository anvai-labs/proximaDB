[.lead]
Rapid AI-assisted ("vibe-coded") development produced parallel implementations across this codebase. Two
prior audits resolved most of them. This audit (a) confirms what is already converged or intentionally
separate, (b) catalogs the *live* divergent seams with a directionally-aligned reconcile direction each,
and (c) installs a **Convergence Gate** governance rule so future agentic edits stay aligned.

[IMPORTANT]
====
**Scope:** documentation + queued TD items only. No source files are reconciled in this pass. The point is
to make the seams explicit and pointable so they get fixed deliberately, not to churn code while documenting
how to reduce churn.

**Release target:** all reconcile recommendations below (TD-104…108) and the agent-memory items
(TD-100…103) target the **v0.2** release currently in development — none are deferred to a later release.
One item (S2 gRPC shims) carries existing code markers that say `0.3.0`; landing it in v0.2 means pulling
that removal forward and updating those markers (called out in the S2 row).
====

== Method & a lesson from prior audits

The 2026-05-25 audit found ~40% false positives when seams were identified by *symbol name* alone
(same-named structs that are actually different shapes, scoped test mocks, or re-export aliases). The
durable lesson: **verify the shape and the live caller chain before declaring a consolidation target.**
Every seam below is classified as one of:

* **LIVE** — genuine divergence; reconcile direction given.
* **BY-DESIGN** — looks like duplication, is intentional; documented so it is not "re-fixed".
* **RESOLVED** — already converged; listed for the record.

== Convergence invariant (what must never diverge)

Per `CLAUDE.md` and `RELATIONAL_DOCUMENT_GRAPH_CONVERGENCE_2026_05_14.adoc`: **durable authority is
single.** All protocol facades lower into one chain — `ProximaRecord` + canonical WAL + xCatalog (see
the convergence diagram in the apex map). Proliferation is tolerated at the *edge* (facades, adapters,
projections); it is a regression anywhere in the durable core. Every seam below is judged against this
invariant: edge-divergence is a cleanup; core-divergence is a defect.

| Clean layered specialization, not duplication. TurboQuant (ADR-021) is additive under `experimental-turboquant`.

P0 always selects `Native(Volcano)` (additive, observable via `EXPLAIN SELECT`); P1+ flip the OLAP arm to `DataFusionLocal` for Parquet-backed tables; §5.2 Phase 2 feeds the decision to the existing `RLPlanner`. Distinct physical engines are an intentional boundary, not duplication; the single decision point prevents fragmentation.

== Governance — the Convergence Gate

To keep agentic-AI / vibe-coded additions directionally aligned *without* a human re-auditing every PR,
adopt a lightweight, mandatory gate. This extends the "Reuse-First Architecture Rules" in `CLAUDE.md`.

[NOTE]
====
**Convergence Gate (landed in CLAUDE.md Architecture Mandates, v0.2).**

Any new `struct` / `enum` / endpoint / handler / planner / config / storage path MUST, in its PR
description or a doc comment, either:

. **Name the canonical surface it converges on** (the existing service, engine, router, cache, proto,
  record, or config it extends/reuses), OR
. **Cite the ADR** that justifies introducing a new seam (with `authority_mode`, `policy_boundary`, and
  `freshness` declared per the route-declaration mandate).

A new whole-system architecture diagram MUST live in `SYSTEM_MAP_2026_05_30.adoc` or a feeder linked
from it — never in a new competing top-level map.

Reviewers reject additions that do neither. Treat a duplicate abstraction as a regression.
====

The gate is the durable mechanism; this audit is a point-in-time snapshot. As seams are reconciled,
update the trackers below and the apex map's "Where the seams are" section.
