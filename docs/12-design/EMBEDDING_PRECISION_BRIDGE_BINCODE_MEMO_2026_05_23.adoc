== History

Decided how `EmbeddingCell.values` flips from `Vec<f32>` to `EmbeddingValues` without breaking v1
bincode WAL files. bincode is positional (no field tags), so a derived enum would make every v1 WAL
file unreadable.

* **Decision (Option A, custom `Serialize`/`Deserialize` on `EmbeddingCell`):** field order
  `model_id, modality, values, dim, precision, precision_epoch`; on the v1 path `values` is written as
  the fp32 view (`to_fp32_owned()`) at the same position and read back as `EmbeddingValues::Fp32`.
  Typed non-fp32 payloads ride only inside v2 (`PWAL`-header) segments. Rejected: a cluster-wide
  `schema_version` bump (breaks rolling deploy / old files) and a parallel `typed_values` field
  (old readers hit EOF on the appended field).
* **Lesson (2026-06-05 correction):** the shipped serializer once *skipped* `precision_epoch` when
  `None`; positional bincode then desynced every `None`-epoch record (`unexpected end of file`, ~16
  WAL/recovery tests broken). On binary wires `precision_epoch` is ALWAYS emitted (`None` = one `0x00`
  Option tag); only human-readable JSON omits the key.
* **Pin:** `embedding_cell_bincode_fixture_locks_pre_2_5b_layout` (`proximadb-records`) locks the v1 bytes.
