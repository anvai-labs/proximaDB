== History

*Capability:* the SQ8/PQ/RaBitQ encode/decode math, the codebook store and the in-memory
quantized-storage engine now live in their own crate. `src/compute/quantization` is a thin re-export
facade. The storage-coupled glue (`global_cache`, `selection`) lives in `storage::compute_bridge`.
`FlushParameters` deliberately stays a storage type.

*Decisive finding (measured correction):* step Q1 was a **no-op**. The "duplicated config types" that
the first draft planned to reconcile were not duplicates:

* `storage::traits::QuantizationType` was already a re-export of the canonical type.
* `ParsedQuantizationConfig` and `QuantizationLevel` are distinct progressive-search glue types. They
  moved as-is.
* The scattered engine enums are distinct domain types. Folding them onto the canonical tag would
  lose information.

The only real cleanup was deleting a dead `#[deprecated]` stub whose name collision made it *look*
like a duplicate.

*Lesson that still applies:* a name collision is not duplication. Re-measure against the code before
scheduling a cross-session "reconcile the types" rewrite.

*Evidence:* the Q2/Q3 PRs (#217, #229) were behaviour-neutral moves. The storage up-edge ratchet
dropped after #812.
