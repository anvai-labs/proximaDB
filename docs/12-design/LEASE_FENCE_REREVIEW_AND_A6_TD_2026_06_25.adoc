== History (shipped)

Re-reviewed the generation-fenced lease/manifest/catalog plane after PR #328 and scoped then landed
the A6 storage-write fence.

* *Re-verdicts after #328:* invariants 1/2/2-F7/6 (single-owner CAS, generation monotonicity,
  tombstone-not-delete, manifest fence) hold; `committer_for_key` totality, registry/pod-id
  unification, renew-loop wiring and REST v1 409 moved from AT-RISK/BROKEN to HOLDS.
* *Scenario 1 (vector-record split-brain):* routing half closed by lease-on-write
  (`RecordOpsService::ensure_collection_lease` → `PartitionLeaseManager::ensure_owned`) with Arrow
  `DoExchange` gated like `do_put` (#337); boundary half closed by the A6 fence.
* **Lesson — trace the binary, not the call graph:** static review predicted the live flush ran
  `engine.do_flush` from the serialization strategies; a runtime trace of the server binary showed
  those sites were DEAD (`_strategy` dropped), live inserts persisted only to WAL, and the only live
  `do_flush` boundary was the graceful-shutdown coordinator — so the fence went at
  `execute_coordinated_flush`, reversing the earlier "inert / misleading" rejection.
* *Decisions:* D1 one funnel (`engine.flush(params)`); D2 ownership check via `is_fenced_out` — no
  WAL/format change, coarser than token-carry (left open if it ever bites); D3 tenant carried on
  `BackgroundFlushContext.tenant_id` (not on the `Serialize` `FlushParameters`, ~120 literal
  constructors); D4 converge the coordinator, don't retire it; D5 default-OFF env gate, byte-identical
  ingest when off. `StorageWriteFence` trait keeps `storage` decoupled from `cluster`.
* *Still-valid rejections:* admission-only fencing is advisory (validate at write/commit time —
  Kleppmann/CockroachDB); the iceberg `ManifestCommitter` is not on the vector persistence path.
* *Evidence:* deterministic tests for cross-pod takeover, adapter-through-`evaluate_fence`
  (reject-when-ON / byte-identical-when-OFF), the `evaluate_fence` matrix and coordinator wiring.
