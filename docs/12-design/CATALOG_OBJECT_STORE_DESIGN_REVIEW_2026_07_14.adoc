== History

Reviewed the catalog-on-object-store design against Apache Polaris, Snowflake Horizon, the Iceberg
REST commit protocol, HadoopCatalog, Project Nessie, Delta `_delta_log`, Unity OSS / Gravitino, and the
conditional-PUT object-store-native catalogs (Boring Catalog, SlateDB, S3 Tables).

* **Verdict: the authority already matched the state of the art.** `SystemCatalog` (ADR-048) serves
  reads from RAM, fsyncs each DDL to a local WAL, and publishes snapshots via `ManifestCommitter`:
  immutable versioned manifests claimed by **create-only put (put-if-absent CAS)** plus an 8-byte
  **generation fence** — the Nessie/Delta commit kernel, stronger than Polaris' RDBMS entity-CAS for
  our shape (no DB sidecar). Per-tenant `DrPathBuilder`-prefixed commit logs never serialize on one
  global key (ahead of single-pointer catalogs).
* **Lesson: what was broken was wiring, not architecture** — a scheme allowlist missing
  `adls://`/`abfs://`/`azure://`/`gcs://` silently dropped Azure to temp-cache staging; the documented
  `adls://`/`gcs://` aliases were forwarded to an upstream parser that doesn't know them; `DeltaCatalog`
  staged all cloud metadata in `$TMPDIR`. Fixed by one scheme-generic `resolve_object_store_fs` (#960).
* **Deliberate decisions that still hold:** `latest_version` via LIST, no mutable tip pointer (a tip
  reintroduces lost-update/ABA; TD-MANIFEST-1 pruning bounds the LIST to ≈`keep_k` — revisit only if
  follower-poll LIST spend shows in the KRU/KOU trace). Iceberg REST change-based commits not adopted
  (single writer under the generation fence; note for a future multi-writer control plane). Do not
  retrofit CAS into `NativeCatalog` (superseded by the ADR-048 cutover). Rejected: RDBMS/FoundationDB
  sidecar (wrong dominant cost term), HadoopCatalog-style rename commits (rename is not atomic on our stores).
