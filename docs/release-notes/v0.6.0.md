# ProximaDB v0.6.0 Release Notes

**Metering and correctness release.** v0.6.0 ships per-collection survivor-cache
attribution (the meter the warm-rate tier prices from), restart cache warming that
actually finds its manifests, the retirement of the object-economy directory
sidecar write, and a sweep of configuration honesty fixes surfaced by a
post-merge smoke test (`git rev-list v0.5.1..v0.6.0` counts the range).
`docs/SUPPORTED_SURFACE.adoc`
stays the authoritative support contract and wins over any other claim.

## Observability and billing

* **Per-collection survivor-cache attribution (TD-CACHEC-1).** New family
  `proximadb_survivor_cache_collection_reads_total{tenant_stable_id, collection_id,
  outcome=hot|l2|cold}` — a bounded registry (200 series, day-idle eviction,
  overflow folds into `other`/`other`) so the warm-rate tier prices reads per
  collection, not only per tenant. First touches record `cold`; a warm deployment
  is served upstream of the meter (see TD-CACHEC-1 for the operational shape).
  Runnable check: `scripts/smoke/survivor_attribution_smoke.sh`.
* **gRPC v2 billing scope completed.** `search`, `search_stream`, `execute_query`
  and the write handlers (`insert`/`upsert`/`update`/`delete`) now open the
  io_trace scope, so their KRU / object-store meters and per-tenant consumption
  records are emitted. **Operator-visible change:** per-tenant cost dashboards
  over gRPC traffic WILL shift — gRPC writes previously emitted no meters.
* The in-parent survivor loader records the REAL hit outcome (concurrent-fill
  served lookups no longer hard-code a miss); this feeds the route cost model's
  Warm/Mixed/Cold classification.

## Storage

* **Object-economy directory sidecar write retired (TD-OEDIRWM-1 follow-up).**
  The unread per-flush sidecar write and its dead query-side wiring are gone;
  route-health/EXPLAIN reflect the retirement (`directory_format_present` false,
  `route_hint` null for SST collections).
* **Restart cache warming fixed (TD-CACHE-11).** Warm manifests were written
  under cache-scope labels (stable id / `shared`) but replay probed by catalog
  tenant NAME — no manifest was ever found and every restart served hot tenants
  cold. Boot now resolves names through the catalog stable-id authority and
  replays under the recorded request scope; the shared scope is covered too.
* The strict-search WAL delta-scan keeps develop's no-manifest skip; the
  pre-existing defects it surfaced (double WAL scan per strict query, exact-tie
  vector stripping) are filed as TD-DELTASCAN-1.

## Configuration honesty (post-merge smoke learnings)

* The public multiplexed port binds `[api].unified_port` — `[server].port` and
  the CLI `-p` flag (a documented no-op) bind nothing. config.toml now says so
  at every site.
* The ADR-069 auto-flush driver's keys live in `[storage.wal_config]`
  (`flush_interval_secs`, default 300s — the driver arms by default);
  `flush_interval_s` is the io_trace ETL sink's unrelated timer. Both are
  disambiguated in config.toml and the driver's docs.

## Verification

* Per-collection attribution carries a spawned-route + sequential-route ratchet
  (mutation-verified) and a smoke script
  (`scripts/smoke/survivor_attribution_smoke.sh`); the restart-warming fix
  carries its own DRAM-hit gate (mutation-verified).
