= ProximaDB v0.2.0 Release Notes
:toc: left
:toclevels: 2
:icons: font
:last-updated: 2026-05-30

[.lead]
**Narrow single-node release.** v0.2 ships the canonical REST/gRPC v2 record CRUD and vector
search path, plus diagnostic surfaces for filtered-ANN, freshness, write contract, object-economy
route, and recall probing. Broader multimodal, federated SQL, distributed, and external-format
surfaces remain Beta or Experimental and must not be marketed as production-ready.

The authoritative split lives in link:../SUPPORTED_SURFACE.adoc[`docs/SUPPORTED_SURFACE.adoc`] and
link:../_internal/status/MVP_RELEASE_READINESS_RECONCILIATION_2026_05_28.adoc[MVP Release Readiness
Reconciliation — 2026-05-28].

== Supported in v0.2

* Canonical REST/gRPC v2 record CRUD (insert, batch insert, upsert, get, delete-by-id).
* Vector search with typed filters, schema-aware records, per-request freshness modes
  (`Strong` / `BoundedStale{max_staleness_ms}` / `StaleOk`).
* Core WAL-backed write path with crash recovery.
* v1 compatibility adapters where they lower into the canonical write/search path.
* Prometheus metrics at `/metrics/prometheus`, including per-precision canonical-bytes accounting.
* Route-health diagnostic endpoint
  `GET /api/v2/_diagnostics/collections/{collection_id}/route-health` (schema marked
  `stability: experimental` — fields may change in v0.3).

== Beta in v0.2

These are usable but not part of the production positioning:

* Hybrid retrieval (BM25 + RRF/weighted fusion).
* Document / graph / observability stores (CRUD and query work; canonical-store WAL default
  varies — see `MASTER_FEATURE_DASHBOARD.adoc`).
* pgwire / federated SQL (basic DML and vector-distance syntax; ADR-018 Phase 2/3 incomplete).
* Object-economy vector route (SST sidecar directory + cache; opt-in, no published cost SLA).
* Filtered ANN routing (ADR-011 — Inline / PostFilter / PreFilter mechanics exist; per-collection
  catalog policy not wired; the deterministic recall-band harness exists in
  `tests/filtered_ann_recall_bands.rs` but remains ignored until TD-073 lands, so no recall SLA is
  claimed).
* Security runtime (JWT, API key, SSO hooks, mTLS, CRL revocation freshness).
* Time-series / event sourcing engine foundations.

== Not Supported in v0.2

The route-health `WriteContractHealth` block is the live source of truth. These are accepted by
SDKs only insofar as the field name passes deserialization; the server does not implement them:

* Optimistic versioning (compare-and-set on insert/upsert).
* Conditional writes (predicate-gated insert/upsert/delete).
* Update-by-filter / delete-by-filter.
* Patch / partial-record update.
* Collection-default freshness mode (per-request only; collection-level not catalog-persisted).
* `RecallProbeGate` enforced route selection (diagnostic only; route selection in `AxisManager`
  does not consult the gate).

== Experimental in v0.2 (do not market as implemented)

* Distributed cluster execution (Raft transport / remote execution placeholders).
* PULSAR and QUASAR graph engines.
* Full SQL parity (ADR-018 Phase 2/3).
* External-table execution (Iceberg / Delta / Hudi as Proxima-owned hot authority).
* Arrow Flight / gRPC multiplexing as a customer-facing transport.
* Trino / Spark compute adapters, including Spark shard-aware partitioning, JVM DataSource V2
  filter pushdown, and the Gradle/JUnit Spark JNI harness.
* Collection-default freshness, recall-gate route enforcement, filtered-ANN recall SLA, and
  object-economy benchmark/SLA claims.

== Notable Changes Since v0.1

=== Round-1 (foundational fixes — 2026-05-28)

* TD-064 (Predicate-Aware Vector Search) — AXIS HNSW now evaluates predicates during traversal with
  fallback-shortfall disclosure. Beta in v0.2.
* TD-072 (Graph branch-id WAL gap) — REST branch-merge endpoint end-to-end functional
  (commits 996626595, d44f5b1d7).
* Route-health diagnostic — adds filtered-ANN, write-contract, freshness, object-economy,
  recall-probe, pinning blocks (commits 1bc339161, 8f213b61d).
* v2 INSERT → v2 SEARCH wiring fix — closed a four-bug stack that hid the canonical write path
  from search: `should_scan_delta_with_time` returned false when the LSN tracker was at zero;
  relational schema validation rejected vector-shaped batches; `validate_records_for_insert`
  re-validated the resolved UUID with the user-facing name pattern; `search_unflushed_vectors`
  used `as_fp32_slice()` which returns empty for non-fp32 variants. The
  `fp16_v2_insert_search_e2e` integration test is no longer `#[ignore]`'d (commit ca4122cfa).
* Cluster-affinity cache routing registry wired through `SharedServices` (Phase 7.2.3 — commit
  2f770eed2).

=== Round-2 (release-readiness audit closures — 2026-05-28)

* **HTTP 404 for missing collection** — `POST /api/v2/collections/{missing}/records/batch`
  previously returned HTTP 200 with `BatchOperationResult::failure` in the body (the same
  silent-failure shape that hid the round-1 INSERT→SEARCH gap). Now maps `NOT_FOUND` →
  `ApiError::NotFound` → real HTTP 404 (commit a446b3964).
* **`top_k` cap** — v2 search now defaults to a 10 000-row cap; above-cap requests return HTTP
  400. Override via the `PROXIMADB_MAX_SEARCH_TOP_K` env var (commit a446b3964). +
  *Renamed in v0.3.0* (#1207): the override is now `PROXIMADB_SEARCH_MAX_TOP_K`, and the old
  name is no longer read — it applies to every search surface since TD-SECSCAN-1.
* **Arrow Flight precision-coercion parity** — `handle_record_insert_batch_for_tenant` (used by
  Arrow Flight DoPut) now applies the same fp16/bf16/int8 precision coercion as the REST/gRPC
  upsert handler. Previously Arrow Flight INSERT into an fp16 collection landed fp32 records
  silently (commit a446b3964).

=== TD-08x backlog closures — 2026-05-28 → 2026-05-30

* **TD-080** (default catalog bootstrap + handler-side metric emission) — `SharedServices::new`
  now explicitly calls `set_default_catalog("default")`. This was silently broken in production
  too (not just test harnesses); the `precision_resolver` was never wired anywhere. Per-precision
  `canonical_bytes` is now emitted from the handler boundary using the user-facing collection
  name, not the internal UUID. The fp16 metric regression test is no longer `#[ignore]`'d
  (commit 32cea5b85).
* **TD-081** (Python SDK live INSERT→SEARCH coverage) — `clients/python/tests/integration/test_v2_insert_search_e2e.py`
  exercises the v2 record path through the SDK against a live release server; auto-skips when
  no server is reachable. Uses the direct REST sync client (`proximadb_sdk.protocols.rest_sync`)
  rather than the unified client to bypass the latter's silent local-vector fallback (commit
  4ec40f79a).
* **TD-082** (handler parity by code-sharing) — extracted the v2 precision-coercion block into
  `UnifiedHandlers::coerce_records_to_canonical_precision`; both the upsert and insert-only
  handlers route through it so they cannot drift apart again (commit 32cea5b85).
* **TD-083** (Rust SDK v2 INSERT with `text_fields`) — `TextFieldInput` and chainable
  `text_field(name, content)` / `text_fields(Vec<...>)` builder methods on
  `InsertBuilderWithId`; `ProximaRecord` gained a `text_fields: Vec<TextFieldInput>` field
  mirroring the server-side wire shape (commit 40019ae79).
* **TD-084** (pgwire v2 record-typed INSERT) — new `docs/03-api-reference/postgres.adoc`
  documents the v0.2 SQL surface, the v2 record-typed INSERT pattern, and the cross-protocol
  contract (rows reachable via REST v2 record fetch). New `tests/pgwire_insert_props_e2e.rs`
  CREATE TABLE + INSERT INTO over the real tokio-postgres wire protocol with mixed-type
  columns and verifies via REST (commit 35bc86197).
* **TD-085** (internal marketing copy seal) — internal positioning files now carry an explicit
  "INTERNAL USE ONLY — DO NOT PUBLISH EXTERNALLY" banner; `make docs-claim-check` hard-fails
  if any customer-facing path references the sealed directories (commit 5efd3d0f5). Engineering
  side closed; product-owner scrub-or-cite work tracked in the Technical Debt Register.

=== Release gate

* New `make release-check` target chains `work-commit-check`, `proto-check`,
  `release-smoke`, and `build-server`. `work-commit-check` is the fast deterministic
  architecture guard: formatting, zero-retry nextest policy wiring, docs/support-claim
  checks, capability matrix, workspace boundaries, tenant-path guard, panic-policy guard,
  and tracked-artifact hygiene. `release-smoke` now runs the canonical lib unit battery
  plus three integration smokes: `release_smoke_v2` (REST v2 round trip + 404 + top_k cap),
  `graph_branch_merge_integration_test`, and `grpc_hybrid_integration_test`.

== Upgrade Notes

* Configuration: no breaking changes to `config/config.toml` schema since v0.1. The unified-port
  default remains `5678`.
* Data directory: clean `/tmp/proximadb*` between dev runs; on-disk WAL/manifest format is unchanged
  but recovery paths benefit from the manifest-service registration fix.
* Clients: v1 REST/gRPC vector-shaped flows continue to work as compatibility adapters. New clients
  should target v2 record APIs.
