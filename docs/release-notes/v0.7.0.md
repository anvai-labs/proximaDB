# ProximaDB v0.7.0 Release Notes

**Platform and packaging release.** v0.7.0 brings macOS Apple Silicon into the
supported-platform matrix (a native arm64 build shipping as a signed DMG),
moves the Linux packages' state-directory ownership to build time, completes
the TD-SEAM-14 S2 spill-manifest primitives, and closes the read-provisioning
graph semantics (`git rev-list v0.6.1..v0.7.0` counts the range).
`docs/SUPPORTED_SURFACE.adoc`
stays the authoritative support contract and wins over any other claim.

## New platform: macOS Apple Silicon (TD-PKG-4)

* **`aarch64-apple-darwin` DMG.** The release builds natively on arm64 macOS and
  ships `proximadb-{version}-aarch64-apple-darwin.dmg`: server/bench/migrate
  binaries, README/LICENSE and the config template in one drag-install volume.
  Binaries are ad-hoc codesigned; the DMG is NOT notarized — first launch needs
  `xattr -d com.apple.quarantine` (bare executables, not an .app bundle).
  `validate-artifacts` REQUIRES the dmg (missing = release blocked, same
  fail-closed shape as every other leg).
* Open (needs Apple credentials): Developer ID signing + notarization;
  prerelease-CI has no macOS leg yet, so the DMG builds inside the release run
  (~60-90 min) — a macOS-only break surfaces at release time, fail-closed
  (TD-PKG-4).

## Packaging: build-time attrs (TD-PKG-1)

* **The RPM payload ships the state directories' final owner/mode**
  (`fpm --rpm-attr 750,proximadb,proximadb:<dir>` per contract dir, driven from
  the shipped `chown_dirs.env`; the system user is created in `%pre` before
  extraction). The install-time chown mutation contract is retired: the
  pre-publish `rpm -V` gate now REQUIRES a clean verify (any deviation = foreign
  modification or a lost attr, caught at BUILD time by an `rpm -qp --dump`
  attr assertion before the container verify), and the installed dirs are
  stat-asserted directly — the same depth as the DEB leg. DEB keeps its
  postinst chown for root-owned upgrades (dpkg does not reset existing dir
  ownership).

## Graph semantics (TD-LANECOV-1)

* **Reads never provision a graph.** Reading a graph collection that was never
  created is now `NOT_FOUND` — previously a read silently CREATED an empty
  graph as a side effect (the leak behind "why does this collection exist").
  Exactly 9 creating-write call sites keep provisioning (`create`/`set`/batch
  writes/transactions); all 27 read/mutate-existing sites use the
  never-provisioning lookup. **Operator-visible change:** clients reading a
  graph before its first write now receive NOT_FOUND instead of an empty
  result. Tenant isolation semantics are unchanged (a tenant's first WRITE
  still auto-provisions its `{tenant}/{graph_id}` collection).
* The 5 TD-LANECOV-1 targets (counting filesystem, gRPC method surface,
  object-store segment-path guard, queue-adapter upgrade, TDD infrastructure)
  are wired into the CI burn-down lane and pass — the lane no longer carries
  known-failing integration targets.

## Spill placement primitives (TD-SEAM-14 S2)

* Manifest head (`_proximadb_spill_manifest.json`) with byte-exact CAS on the
  revision, ATOMICALLY conditioned on ownership: the owner marker's read-time
  bytes guard the `compare_exchange`, so ownership lost between check and write
  fails the write (native `compare_exchange` on the FileSystem trait — never
  GET-then-PUT). A fenced instance's write is a decisive error, not a retryable
  conflict. The manifest head is control metadata: a prefix holding only it
  stays adoptable/migratable. Storage-only this release — wiring is the S3
  scope; the digest/witness verification is carried there too.

## CI and packaging hygiene

* The Packaging Scripts Lint lane runs shellcheck + actionlint with the
  embedded shellcheck ENABLED — zero findings across the release/CI workflows
  (the 60-finding pre-existing debt is paid), and it gates: a red lane blocks
  CI Success. It also caught a real CI bug on day one: the `dup_ratchet`
  changes-output was never declared, so dup-gate-only PRs silently never ran
  Hygiene Guardrails.
* The SDK transports' `inserted_ids`/`vector_ids` channel is complete end to
  end (embedded numpy, REST, gRPC, unified sync/async) — server-assigned ids
  flow back on every transport; ships in the python wheel from this release.

## Verification

* macOS DMG + build-time attrs are exercised end-to-end by the release
  dispatch's dry run (container install on rockylinux:8, artifact validation,
  checksums) BEFORE anything publishes.
* The packaging scripts' selftests carry positive AND negative fixtures
  (dead-%post / lost-attrs / contract-subset / foreign-deviation mutations
  must all be rejected), wired into the release jobs.
* Guard ratchets updated BY HAND with the platform additions (release-matrix
  `features:` count 2→3; the archive-reuse mutation test follows the current
  gate).
