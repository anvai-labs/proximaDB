== 1. TD-007 Guidelines

=== 1.1 Core Principle

**NO panic-prone code in production paths:**
* `unwrap()` - Panics if Option/Result is None/Err
* `expect()` - Panics if Option/Result is None/Err (with custom message)
* `panic!()` - Explicit macro that causes program termination

=== 1.2 Acceptable Patterns

Production code MAY use these safe alternatives:

[source,rust]
----
// GOOD: unwrap_or() with safe default
let collection_id = obj.get("collection_id").and_then(|v| v.as_str()).unwrap_or("").to_string();

// GOOD: unwrap_or_default() with type's Default implementation
let vectors = obj.get("vectors").and_then(|v| v.as_array()).map(|arr| {
    arr.iter().filter_map(|v| v.as_f64().map(|f| f as f32)).collect()
}).unwrap_or_default();

// GOOD: unwrap_or_else() for lazy evaluation
let config = config.get("settings").unwrap_or_else(|| load_default_config());

// GOOD: unwrap_or() for NaN handling in comparisons
results.sort_by(|a, b| {
    b.score.partial_cmp(&a.score).unwrap_or(std::cmp::Ordering::Equal)
});
----

=== 1.3 Required Documentation

When using safe patterns, add TD-007 justification comments:

[source,rust]
----
// TD-007: unwrap_or with safe default - empty string for missing collection ID
let collection_id = obj.get("collection_id").and_then(|v| v.as_str())
    .unwrap_or("").to_string();

// TD-007: unwrap_or with safe defaults - max with NaN handling, default 0.0 for empty
features[5] = *all_scores.iter()
    .max_by(|a, b| a.partial_cmp(b).unwrap_or(std::cmp::Ordering::Equal))
    .unwrap_or(&0.0);

// TD-007: unwrap_or with safe default - 10 is reasonable default for result limit
let top_k = self.extract_limit(query).unwrap_or(10);
----

=== 1.4 Proper Error Handling

Use `Result<T, Error>` for error propagation:

[source,rust]
----
// GOOD: Proper error propagation
pub fn get_node(&self, id: &NodeId) -> Result<Option<Arc<Node>>> {
    self.nodes.get(id)
        .cloned()
        .ok_or_else(|| Error::NodeNotFound(id.clone()))
}

// GOOD: Early return with error
pub fn process_request(&self, req: &Request) -> Result<Response> {
    let collection = self.collections.get(&req.collection_id)
        .ok_or_else(|| Error::CollectionNotFound(req.collection_id.clone()))?;

    // Process request...
    Ok(response)
}
----

=== 1.5 Test Code Exemption

Test code MAY use `unwrap()`, `expect()`, and `panic!()` freely:

[source,rust]
----
#[cfg(test)]
mod tests {
    #[test]
    fn test_something() {
        let result = some_operation().expect("Test should succeed");
        assert_eq!(result.value, 42);
    }
}

pub fn generate_self_signed(&self) -> Result<GeneratedCertificate, TlsError> {

== 4. Best Practices Guide

=== 4.1 When to Use unwrap_or()

Use `unwrap_or()` for:
* Simple default values (empty string, zero, etc.)
* Non-critical optional fields
* User-provided input with sensible defaults

[source,rust]
----
// GOOD: Simple default for collection name
let collection = request.collection_id.unwrap_or("default".to_string());

// GOOD: Default for top_k parameter
let top_k = request.top_k.unwrap_or(10) as u32;

// GOOD: Empty string for missing field
let field_name = obj.get("name").and_then(|v| v.as_str()).unwrap_or("");
----

=== 4.2 When to Use unwrap_or_default()

Use `unwrap_or_default()` for:
* Types implementing `Default` trait
* Collections (Vec, HashMap, etc.)
* Optional struct fields

[source,rust]
----
// GOOD: Default for empty vector
let vectors = obj.get("vectors").and_then(|v| v.as_array()).map(|arr| {
    arr.iter().filter_map(|v| v.as_f64().map(|f| f as f32)).collect()
}).unwrap_or_default();

// GOOD: Default for empty filters
let filters = obj.get("filters").and_then(|v| {
    serde_json::from_value::<HashMap<String, SqlValue>>(v.clone()).ok()
}).unwrap_or_default();
----

=== 4.3 When to Use unwrap_or_else()

Use `unwrap_or_else()` for:
* Lazy evaluation (avoid computation if not needed)
* Expensive default values
* Complex initialization logic

[source,rust]
----
// GOOD: Lazy evaluation for expensive default
let config = match config_path {
    Some(path) => load_config(path)?,
    None => load_default_config()?,  // Only computed if needed
};

// GOOD: Complex initialization
let cache = config.cache_size.unwrap_or_else(|| {
    let system_memory = get_system_memory();
    system_memory / 4  // Use 25% of system memory
});
----

=== 4.4 Handling NaN in Comparisons

For floating-point comparisons, always handle NaN:

[source,rust]
----
// GOOD: NaN-safe sorting
results.sort_by(|a, b| {
    b.score
        .partial_cmp(&a.score)
        .unwrap_or(std::cmp::Ordering::Equal)
});

// GOOD: NaN-safe max/min
let max_value = scores.iter()
    .max_by(|a, b| a.partial_cmp(b).unwrap_or(std::cmp::Ordering::Equal))
    .unwrap_or(&0.0);

// GOOD: NaN propagation in comparisons
let ln = left.as_f64().unwrap_or(f64::NAN);
let rn = right.as_f64().unwrap_or(f64::NAN);
if ln > rn {
    // Handle comparison
}
----

=== 4.5 Error Propagation Patterns

Use proper error propagation with `Result<T, Error>`:

----
// GOOD: Early return with error
pub fn get_collection(&self, id: &str) -> Result<Arc<Collection>> {

== 5. Guidelines for New Code

=== 5.1 Code Review Checklist

When reviewing new code, check for:

* [ ] No `unwrap()` in production code (use `unwrap_or()` instead)
* [ ] No `expect()` in production code (use `Result<T, Error>` instead)
* [ ] No `panic!()` in production code (use `Result<T, Error>` instead)
* [ ] All safe patterns have TD-007 justification comments
* [ ] Error handling uses `Result<T, Error>` and `?` operator
* [ ] Floating-point comparisons handle NaN properly

=== 5.2 TD-007 Justification Comment Template

[source,rust]
----
// TD-007: unwrap_or/unwrap_or_default with safe default - [REASON]
[PATTERN_EXAMPLE]

[source,rust]

// After (safe)

    b.score
        .partial_cmp(&a.score)
        .unwrap_or(std::cmp::Ordering::Equal)
});
----

=== 9.2 TD-007 Fix Patterns

The fix patterns are defined once in the main body; this appendix pointed at them with
condensed re-statements, which drifted into a second copy of the same examples. The
canonical instances:

* **Simple default** (`unwrap_or("")`), **collection default** (`unwrap_or_default()` on the
  mapped collection, including the per-element `unwrap` the unsafe idiom carries) and
  **numeric default** (`unwrap_or(<sensible limit>)`): see
  <<_5_3_common_patterns,Section 5.3 Common Patterns>>.
* **Error propagation** (`?` on fallible calls instead of `unwrap()`): see
  <<_4_5_error_propagation_patterns,Section 4.5 Error Propagation Patterns>>, which shows the
  early-return, chained and context-adding forms.
