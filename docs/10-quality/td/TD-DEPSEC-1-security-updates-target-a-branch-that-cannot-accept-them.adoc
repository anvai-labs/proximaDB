== History

**The trap:** `target-branch: develop` in `dependabot.yml` governs *version* updates only. Dependabot *security* updates
always open against the default branch (`main`), and `main` accepts only the literal `qa -> main` promotion (two independent,
correct guards). Nine security PRs, including two `ui/` criticals, were closed unmerged (#1983–#1987, #1998–#2000, #2002) and
re-applied by hand (#1993, #2003). Because the remediation path was a human noticing, a day-old pair of advisories leaked.

* Rejected: exempting `dependabot[bot]` from the route guards. Content reaching `main` outside `develop -> qa -> main` caused the
  severed-ancestry failures (47 phantom conflicts) that `promotion-ancestry-guard` exists to catch.
* Chosen: default branch -> `develop` (root-cause fix). The user confirmed it on 2026-10-14: keep `develop` as default, promote at
  substantive checkpoints, and flip the default back to `main` at GA.
* **GA contingency (still actionable):** when the default returns to `main`, the defect returns. The recorded fallback is an
  automated re-router: a scheduled workflow cherry-picks each `base == main` Dependabot PR onto `deps/<slug>` off `develop`, opens
  the develop-targeted PR, and closes the original. Neither promotion guard may be weakened.
* **Evidence:** `gh pr list --author app/dependabot --json baseRefName` shows open Dependabot PRs on `develop` only (e.g. #2029, 2026-10-14).
