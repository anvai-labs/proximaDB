== History

* **Capability.** Eight executable invariants — totality, exactness, cap, non-empty, no-containment,
  batch/stream equivalence (randomised piece sizes), config safety, idempotence — run over every
  strategy × a shared corpus where each entry must record the real defect that earned its place
  (header-dense Markdown → zero chunks; CJK `。！？` never firing; 48× cap overrun; whitespace quadratic
  blowup; sub-minimum silent drop). A per-document, tenant-tagged trace (`units_in/covered/duplicated`,
  `spans_dropped`, `chunk_count`, `boundary_source` histogram, explicit `offset_basis`) makes loss auditable.
* **Lesson that still applies.** The prior 426-test suite caught none of the defects because it asserted
  execution, not invariants; a fix no test can see is indistinguishable from no fix. The kit ships
  *inside the package* (not `tests/`) so foreign consumers (anvaiops, victor-rag) can import the
  specification and run it against their own chunker via the `ChunkerAdapter` seam.
* **Design decisions.** Exactness *grades* failures (recoverable superset vs garbage span). The baseline
  is a bidirectional ratchet, not xfail: a new violation fails, and a fixed one fails until the baseline
  is updated in the same commit. Trace fields are `units_*` + `offset_basis`, not the filed `bytes_*`,
  because offsets are characters on text strategies and bytes on the code path.
* **Evidence.** Initial baseline: 60 cases, 38 violating, 67 violations (exactness 25, totality 20, cap 11);
  `sliding_window` pinned clean as the reference implementation.
