== History

* **Capability.** `PaxSplitReader::load_ranged` (default-OFF `PROXIMADB_DF_PAX_RANGED`, mixed-read-safe
  whole-file fallback) prunes whole blocks against the v2 index zone summary (Stage A) and, for
  predicates on shredded `props__<key>` columns the summary cannot evaluate, range-reads each survivor's
  footer into a `BlockLayout` and prunes on all columns before fetching the body (Stage B). It is general
  — every DataFusion PAX scan benefits, not just documents. The `documents()` UDTF serves
  `DocumentPaxPushdownProvider` when `pax_scan_inputs` resolves, else the `(id, props)` MemTable path.
* **Decisive lesson (still applies).** Delegating `documents()` to a raw `PaxTableProvider` is
  **incorrect**: `.pax` segments hold flushed data only (misses read-after-write) and the reader does no
  dead-filtering (surfaces tombstoned/expired docs). The correct read is flushed-pruned + raw unflushed
  delta (`RecordRoutePort::unflushed_records`, *including* tombstones so they can suppress a flushed
  live copy, #16d) + dedup-by-`oid` freshest-wins + `is_record_dead`; it never consults the query cache,
  so it is `Strong` by construction. `PaxTableProvider::reader()` passes empty filters, so a dedicated
  reader is built with the WHERE predicates lowered to `PhysicalExpr`.
* **Also.** An earlier spike reimplemented ranged reads inside the adapter and was discarded as a
  competing reader; and a `bytes_read` double-count was removed (the filesystem layer already records
  per `read_range`).
* **Evidence.** Selective predicates on a canonical column and a shredded user column read
  `bytes_read < whole segment` with `range_gets > 0` and rows identical to the whole-file path;
  `document_pax_provider::tests` pin read-after-write, tombstone, dedup-freshest and shredded-typed gates.
