= TD-SCANDEG-1: Concurrency back-off guards were dead on one entry each; peeked bytes were re-read
:status: Accepted
:date: 2026-11-06
:tags: [search, concurrency, cost, gets, survivor-cache]

== Problem

Two adaptive back-offs and one read path, each half-wired:

* **Morsel degree (intra-file rank).** `morsel_degree()` returns `cores` when
  `INFLIGHT_SCANS == 1`, else 1 — "total CPU workers ≈ cores". The only
  `ScanGuard::enter()` was on the legacy `&self` path; the production arc
  path never took it, so the degree was ALWAYS `cores`.
* **Inter-file degree (S2b).** The mirror image: `InFlightSearchGuard` was
  acquired only on the arc entry, so legacy-entry traffic never divided
  `resolve_search_parallelism` by concurrency (#2442 review F1).
* **Peek·discard·re-read.** The coalesced SQ8 survivor planner and the
  Region-D OID-chunk planner peeked residency, discarded the returned bytes,
  and re-read the identical range on consume — the full local-disk read
  stack (open + seek + read + CRC) paid twice per range.

== Decision

* Both entries now take both guards.
* A peeked-aware serve seam on each consume path
  (`get_or_fetch_in_parent_impl`, `get_or_fetch_impl`): an exact-length
  peeked buffer is served and promoted into L1 through ONE shared helper,
  accounted by the TIER the peek read (exact-L1 / parent-L2 / exact-L2); a
  different-length buffer is the parent DRAM slice and is ignored. Threading
  bytes through the loader would not have worked — the consume probes L2
  BEFORE the loader runs.
* Carried peeked buffers are bounded (`32 × 4 MiB` per arm, matching the D4
  wave bound); past the budget a range degrades to the pre-fix re-probe, so
  the worst case is the status quo ante, never worse.
* The legacy OID tail is untouched: its peek is DRAM-only, so there was no
  duplicated disk read to remove.

== Follow-up (filed, not fixed): TD-SCANDEG-2 — worker granularity

The guards count QUERIES, not rank workers. A lone query fanning out over
D files gives each per-file rank `morsel_degree() == cores`, so one query can
still run `D × cores` workers. Restoring "total workers ≈ cores" needs the
morsel degree to divide by the query's own inter-file degree as well. The
2026-07-25 sweep found every mid/high-concurrency posture inside the box's
±30% run-to-run variance, so the change must be MEASURED (QPS + p95 at
c=1/4/8 on a quiet box) before it ships — it is a posture change, not a
defect fix.
