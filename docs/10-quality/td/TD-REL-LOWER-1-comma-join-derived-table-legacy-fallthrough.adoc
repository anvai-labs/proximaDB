== History

The 2026-07-13 native ledger sweep showed 72 ERRs like `Table 'customer,' does not exist`: a relational lowering
decline fell through to the legacy single-table tokenizer, which took `customer,` and `(select` as table names.
The pgwire conformance ratchets ran the materialized/DataFusion route and never saw it.

Decisive findings (lessons that still apply):

* The decliner was **neither the join nor the comma**: the frontend already lowered comma-joins as cross joins.
  It was a **qualified ORDER BY key** (`ORDER BY t.col`) resolved against a post-projection scope with no
  qualifiers. A qualified key naming a projected output column now resolves by bare name.
* The legacy path now rejects multi-table / derived-table FROM with a specific `0A000`
  (`legacy_unsupported_from_shape`), so a residual decline reads "unsupported on this route", never a phantom table.
* Mixed numeric arithmetic (Q19 `1 - l_discount`) widens to f64 in `eval_arithmetic`.
* After the cross→equi rewrite (TD-REL-LOWER-2), the dominant blocker was again **not the join**: typed
  `DATE 'YYYY-MM-DD'` literals declined and surfaced the misleading comma-list `0A000` (a red herring). Lowering
  them to `ProximaValue::Date` took native TPC-H 4/22 → 12/22; the remaining 10 were distinct mechanisms, each filed separately.

Evidence: `tests/rel_lower_native_join_e2e.rs`; native TPC-H 22/22 (#1068).
