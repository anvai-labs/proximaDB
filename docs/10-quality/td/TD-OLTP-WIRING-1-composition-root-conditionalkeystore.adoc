== History

Before this, F2 fenced PK uniqueness and F5 FK-existence + delete-tombstone did nothing in a running server:
`with_conditional_key_store` was called only in tests. Now `SharedServices` opens
`LocalWalKeyStore` at `<data_dir>/oltp-cks.wal` (CRC-framed WAL, replayed on restart) and
`multi_server` threads the same `Arc` into pgwire.

Design decisions that still apply:

* **Exactly one store per process**, shared by every surface: two stores on one WAL path corrupt the log;
  two on two paths fence inconsistently, so a pgwire INSERT could commit a PK the gRPC store thinks unique.
* **Active only with the feature AND a `data_dir`.** Embedded/ephemeral ⇒ no CKS: an in-memory store would
  silently lose uniqueness across restart, worse than the honest legacy probe.
* Out of scope (not tracked here): multi-column PK fencing (TD-DML-2), a shared/HA (Redis) store backend
  (later ADR-0004/0005 item), HTAP delta-merge consistency.

Evidence: `tests/cross_surface_unification_e2e.rs` (cross-surface fence).
