== History (shipped)

D1 optional persistent L2 behind `TenantCache` (L2 hit promotes to DRAM; authoritative load writes
through); D2 persistent control/Region-A entries behind `SegmentInvariantsCache` with default-on
coarse metadata insertion; D3 TOML+env path/budget config (unset disables L2); D4 exact Prometheus
hit/miss/resident families with bounded `tier` labels; D5 env-gate registry + template; D6 writer
installs byte-identical PAX regions only after final publication (`none/invariant/all` policy);
SEARCH-3 physical GET counting corrected (filesystem `read_ranges` counts N, not 1) with bounded
prefix coalescing.

Verified gaps that drove the design and still apply as lessons: the pre-existing root `NvmeBackend`
was memory-only — reusing it would have made the restart acceptance test a false positive;
coarse-probe metadata insertion was effectively opt-in (the observed zero-hit invariants run); a
complete SQ8 seed cannot satisfy an exact subrange key without a parent lookup (persisted parent
entries now serve checksum-verified selective ranges); survivor purge and whole-collection deletion
previously reclaimed DRAM only (now both tiers, separator-aware so `12` never retires `123`).

== Correctness boundaries

Cache entries are immutable segment bytes, not query results. MVCC
tombstones/TTL state is applied by the canonical read merge and does not mutate
the cached bytes. Collection writes must continue invalidating query-serving
result caches post-commit.

TD-DELVEC-1's gated WI-3a plumbing and write-time resolver do not yet constitute
a PAX DV read path or compaction interlock. Those later slices need
generation-aware DV caching and their own snapshot/restart tests; they do not
require discarding valid immutable PAX byte entries until the segment path is
retired.

== Tests required before resolution

* persistent store reopen and malformed/truncated/checksum failure => miss;
* selective range crossing two checksum chunks;
* survivor and invariant L2 promotion after a new DRAM-cache instance;
* compaction-path purge removes DRAM, persistent exact/parent, and replay keys;
* collection deletion purges DRAM and persistent entries without prefix
  collision (`12` must not retire `123`);
* publication-order test: failed/staged output is never installed;
* env unset/config parsing and exact metric registration;
* corrected SIFT1M run with quiescence/materialization/segment-geometry gates,
  cold DRAM + cold L2, cold DRAM + warm L2, and post-write `all` policy.

=== Release acceptance iteration 1

The first clean `release-server` run at commit `acfb71dbe` validated the GET and
recall design but rejected the latency implementation:

* 1,000,000 live PAX rows, WAL zero, 2 L1 segments;
* post-write: recall 0.9855, 2.44 GET/query, p50 36.95 ms;
* local-disk warm: recall 0.9825, 2.00 GET/query, p50 57.76 ms (FAIL);
* object-cold local-file control: recall 0.9805, 42.91 GET/query, p50 38.55 ms.

The local phase served 7,874 parent-range hits across 200 queries. Its original
4 MiB checksum unit therefore read and hashed roughly 4 MiB for each typically
smaller survivor range. That cloud-I/O-sized integrity unit was a local-tier
co-design error. The pre-GA format now uses 64 KiB CRC chunks (about 0.006%
metadata overhead) and reads all touched chunks in one contiguous envelope.
There is no compatibility version bump for an unreleased, rebuildable cache.
Acceptance must be rerun; iteration 1 remains rejected evidence, not a promoted
benchmark result.

The acceptance driver is
`scripts/bench/sift1m_get_reduction.py`. It owns each measured server process,
accepts only `target/release` or `target/release-server` binaries, hashes the
binary, records the Git revision, and refuses a dirty source tree.
Unlike the historical `/tmp` harness, it streams ingest, persists the returned
collection ID, requires live PAX footer row counts to equal the requested
corpus, and requires geometry to remain stable with the collection's
unflushed-WAL gauge at zero before issuing queries. It never substitutes cache
misses for an absent physical-GET counter. Each owned process removes inherited
local-disk env mirrors before applying its phase configuration, so an operator
shell cannot accidentally make the object-cold control warm.

The three phases use fresh result/DRAM state:

. post-write `all`, before restart;
. DRAM-cold/local-disk-warm after restart; and
. DRAM-cold/local-disk-disabled diagnostic baseline.

The file-backed segment bed validates physical I/O-seam operation counts.
Latency is valid only for the declared local filesystem/hardware profile and
must not be presented as Azure WAN latency.

== Exit criteria

. recall@10 >= 0.98;
. warm-local physical object GETs/query <= 10;
. first query after write with `cache_on_write=all` <= 5 physical GETs/query;
. warm repeat invariants hit ratio >= 90%;
. cold p50 <= 50 ms on the declared benchmark bed;
. clippy, work-commit checks, and CI green;
. accepted measurements recorded in `BENCHMARK_EVIDENCE.toml`.
