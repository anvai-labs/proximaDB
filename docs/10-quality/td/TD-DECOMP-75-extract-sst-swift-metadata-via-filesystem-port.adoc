== History

`FilesystemPort` already existed in `proximadb-storage-ports` and root `FilesystemFactory` already implemented
it; the files were blocked only because their fields named the concrete type. The follow-ons it unblocked
(block_reader, sst_io_layer, footer_cache, nova/parquet metadata, common, utilities) all shipped in
link:TD-DECOMP-76-extract-factory-coupled-wave2.adoc[TD-DECOMP-76]–link:TD-DECOMP-80-extract-columnar-serialization-common.adoc[TD-DECOMP-80].

* Gotcha: `Arc<FilesystemFactory>` → `Arc<dyn FilesystemPort>` needs an explicit `as` cast at
  `Arc::clone` sites (unsized coercion is not applied through the generic).
* Caveat that still applies: swift's `extract_metadata` is a PLACEHOLDER (synthesizes a header, never reads
  the filesystem; still true 2026-10-15), so its tests inject a no-op port (`test_fs_port::noop_port`).
  When it gains a real read path, those tests must switch back to a real filesystem.
