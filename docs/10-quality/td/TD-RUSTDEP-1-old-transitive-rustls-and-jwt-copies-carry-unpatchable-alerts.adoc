== History

Two alerts had no Dependabot PR because the vulnerable copies were pinned to never-patched lines by a second subtree, while
the workspace already resolved safe copies alongside. **Lesson: the PR list is not the alert list** (found via the alerts API).

* **AWS half.** It was not the object-store path (S3/Azure are on `object_store`); it was the Glue catalog. A probed
  `cargo update -p aws-config` did *not* drop the old subtree: `aws-sdk-glue`'s own `default` features include `rustls`, which
  pulls the legacy `aws-smithy-http-client` path. Glue kept TLS via `rustls-aws-lc`. Duplicate crates 117 -> 113.
* **GCS half.** Kept the GCS SDK (not `object_store`) because fake-gcs-server only serves the JSON API; now a recorded decision.
  Two-plane split: data plane on the 1.x `client::Storage` (JSON); metadata (get/delete/list) on a small JSON-API client over
  `reqwest`, because the SDK's `StorageControl` is **gRPC-only** and fake-gcs has no gRPC (review catch: the first cut broke every
  emulator path). Closed TD-173 residual (a): per-write `ObjectAccessTier` storage class. `PROXIMADB_GCS_LIST_PAGE_SIZE`, formerly
  dead, is honored again.
* **Wire-gap lessons (caught only by the emulator lane, not review or compile):**
  ** The 1.x SDK appends a trailing `checksums` multipart part that fake-gcs **concatenates into the stored object**. Fix: every
     write passes `.with_known_crc32c(...)`, which moves the checksum into part-1 metadata; end-to-end validation is kept.
  ** The SDK sends a port-less `Host`; fake-gcs echoes it into the resumable `Location`, so `:8080` silently becomes `:80`. Fix:
     the emulator serves on **port 80**.
  ** Error `status.code` is parsed from the body's `status` string, which GCS bodies lack, so it is `Unknown`. Map
     `AlreadyExists` from the **HTTP status** (409/412). Not wire-exercised: fake-gcs runs non-strict, so this rests on SDK-source evidence.
  ** Missing `#[serde(rename_all = "camelCase")]` on `GcsListPage` silently truncated listing after page 1; the multi-page contract
     test (TD-OBJSTORE-4 S1) caught it.
* Recorded drift: the SDK switches writes >= 16 MiB to resumable upload (0.x used a simple PUT). This is latency only; revisit if flush traces show it.
* **Evidence:** `jsonwebtoken` single entry at 11.1.0; all four GCS contract tests pass against the pinned fake-gcs digest after the fixes; 0 backwards lock moves.
