== History (shipped)

*Finding (2026-07-12):* an external architecture analysis reproduced the Course Correction §4 audit table (a 2026-06-04
snapshot) as *current* state ("DataFusion UNWIRED", "`ComputeProvider` DEAD STUB", "no Parquet write"), and all three were false.
`SYSTEM_MAP`, the claimed "active baseline", also lagged, and stale module docs corroborated the wrong story. Root cause: the only
doc guard grepped marketing phrases, and nothing tied a status-of-record doc to a freshness contract. **In a repo developed by
many concurrent agent sessions, docs ARE the harness, so stale status docs poison every future session's static context.**

* Filing PR (#912): the `// status-as-of: YYYY-MM-DD` convention (bumped only after re-verifying, never mechanically);
  `scripts/check_status_as_of.py` (missing tag or older than `--max-age-days` 60 fails); `status-asof-check` in
  `work-commit-check`; tags on `SYSTEM_MAP` and `SUPPORTED_SURFACE` (the latter at its honest last-verified date); a supersession
  NOTE on Course Correction §4.
* 2026-07-21: the ADR README is tagged and allowlisted, and `check_design_status_index.py` requires every ADR/TD to expose a status
  and every ADR to appear exactly once with a matching lifecycle class.

== Remaining scope

1. **Allowlist extension.** The ADR README is now freshness-tagged and allowlisted, and
   `check_design_status_index.py` requires every ADR/TD to expose a status and every ADR to appear
   exactly once with a matching lifecycle class. Continue graduating other current-state tables
   (candidates: `docs/12-design/README.adoc`, capability-matrix source docs) as they are re-verified.
2. **Claim-level checking (stretch).** The tag is a freshness contract, not a truth
   contract. Consider tying specific greppable claims to code anchors (e.g. a claim
   registry mapping "DataFusionLocal routes live" → a grep that must hit
   `route_select_inner`), in the spirit of `capability-matrix-check`.
3. **Session hygiene.** When a PR materially changes routing/engine/format status,
   the same PR updates SYSTEM_MAP's status sections and bumps the tag (reviewers:
   treat a status-changing PR without a SYSTEM_MAP touch as suspect).
4. **Legacy validator rehabilitation (closed 2026-10-17 by deletion).** The validator was never wired
   into CI and was deleted with the other unused doc scripts. The history: `scripts/validate_docs.sh` assumed the retired
   `src/storage/engines/impls/` layout, exits on its first zero-to-one counter increment under
   `set -e`, scans archives as current link authority, and conflates multiple links on one line.
   A 2026-07-21 exploratory run reached 140 errors, many parser/archive false positives. It is not a
   CI authority. Rewrite its parser and scope before wiring it into a gate; do not treat a partial
   path substitution as validation.
