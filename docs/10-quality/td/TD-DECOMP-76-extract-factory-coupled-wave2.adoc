== History

* Layering decision: these landed in engine-core, not storage-common, because storage-ports already depends
  on storage-common (storage-common → storage-ports would be a cycle).
* Test-stub caveat (same as link:TD-DECOMP-75-extract-sst-swift-metadata-via-filesystem-port.adoc[TD-DECOMP-75]): nova/utilities/footer_cache tests inject no-op ports because their
  filesystem reads are placeholder or unused by those tests; `parquet_metadata` is the only serializer with a
  real read path and keeps it through the port. Swap stubs for real filesystems when placeholders gain reads.
