== History (shipped)

* **Capability.** `start_trace`/`get_trace`/search/tags/assessments/delete and logged-model
  create/search/get/patch/delete/params/tags/finalize work for the real MLflow 3.x client; both mount at
  both `server.rs` sites (before tenant/auth layers) and under the UI's `/mlflow-ui/ajax-api` nest. Runs
  gain `model_id`/dataset metrics (model-owned metrics never touch the run projection or freeze),
  `runs/outputs`, `runs/log-inputs`, legacy `runs/log-model`. The `RunStore` port grew traces,
  logged-model and run-link families; search grammar stays wire-owned (the port exposes persistence laws,
  not REST query syntax).
* **Lesson — the opening was reverted.** The first attempt introduced cross-layer query and artifact
  ports and was rolled back (#1891); this delivery keeps filtering in the wire and uses the
  capability-safe artifact backend. The ports were re-landed safely under TD-MLOPS-4.
* **Load-bearing client contracts (verified against pinned client 3.16.0 source).** The
  `mlflow.artifactLocation` trace tag is derived on every response and reserved from PATCH/DELETE (the
  client raises `MlflowTraceDataCorrupted` without it, and a caller-supplied tag must not redirect
  artifact access). NO `/version` and NO OTLP `/v1/traces` are served, so the client permanently uploads
  spans as `traces.json` through the existing artifacts proxy — server traces carry `spans: []` and never
  interpret span payloads. Our trace-404 message must NOT equal the reference server's literal (the client
  converts it to NotImplemented). Logged-model statuses are proto NAME strings (`LOGGED_MODEL_READY`, not
  `READY`); every logged-model RPC goes through the v2 route map.
* **Bug found in review (still a rule).** Metric seq counters are PER KEY, so substrate doc ids must
  embed the key (`mtr-{run}-{key}-{seq}`, `mtrm-{model}-{key}-{seq}`): a key-less id silently overwrote
  another key's sample via the id-keyed upsert — on the run side too. Readers locate history by indexed
  fields, never by parsing ids, so old `mtr-{run}-{seq}` docs stay readable.
* **Evidence.** Dual-generation ratchets: `mlflow_conformance_steps_2x.txt` (18, frozen) and
  `mlflow_conformance_steps_3x.txt` (30 = 18 + 12 gen-3 steps; `get_trace` proves span upload+download).

== Deferred (honest 404s, degrade as before)

`traces/metrics`, `traces/calculate-filter-correlation`,
`get-trace-artifact`, OTLP `/v1/traces` ingest, `/version`, and
prompts. Prompts need a design pass: MLflow prompts ARE
registered-models + model-versions carrying `mlflow.prompt.*` tags —
implementing them means relaxing the "registry is read-only from
MLflow" law (xCatalog versions are typed immutable contracts). Dataset
input tags are accepted on the wire but not surfaced. Dataset inputs are
embedded ONLY in `runs/get` (a per-run N+1 in search is documented as not-taken).

== Known limitation (review MINOR-3)

Wire-level read-modify-write cycles that span TWO port calls (`assessments_update` get→mask→upsert;
`runs_log_model` history-tag append) are atomic per store call but not across the handler — concurrent
writers can lose one update (last-writer-wins). Tracing/registry traffic is low-frequency control-plane;
a port-level compare-and-swap lands if contention is ever observed.
