= TD-IOBUDGET-3: DRAM-only residency peeks pay a billed GET for L2-resident ranges (legacy OID tail, Region-A coarse probe)
:status: Resolved
:date: 2026-11-06
:tags: [cost, billing, survivor-cache, object-store]

== Problem

TD-IOBUDGET-2 made the Region-D OID-chunk planner's residency peek
L2-aware. The legacy OID tail and its slot planner still peek DRAM only
(`peek_memory_exact`). An OID range evicted from L1 but still in the
exact-key L2 is therefore classified Cold and put in the
`read_ranges_prefetch_resident` wave — a BILLED object-store GET — and the
consume's `get_or_fetch` (whose `get_or_load` checks exact-key L2) then
serves the range from L2 without running the loader, discarding the wave
bytes. The tenant pays for a GET it did not need.

The same pattern is in `coarse_probe_survivors` (Region A, the
`peek_memory_exact` classification feeding its `Slot::Cold` wave, consumed by
`get_or_fetch`). Both sites live in `rabitq_search_segment_coalesced_allowed`,
the same function as the Region B / Region D planners, which production
search reaches.

== To close

Switch both sites' classification to the L2-aware `peek_exact_residency`, as
TD-IOBUDGET-2 did for Region D, each with a test that keeps the L2 entry
PRESENT and asserts no wave GET is issued for it.

Related: TD-IOBUDGET-2, TD-SCANDEG-3.

== Resolution (2026-11-06)

Both sites — and Region D, which TD-IOBUDGET-2 had moved to a byte-reading
L2 peek — now classify with `SurvivorRangeCache::is_exact_resident`: DRAM, or
the exact-key L2 INDEX (`PersistentByteStore::entry_len`). No bytes are read
to classify, so a resident range is read once (at consume), classification
costs map lookups rather than serial disk reads, and no L2 group-hit stats
are double-counted. The consume arms are unchanged; a classification that
goes stale before consume falls back to one ranged GET (the existing
fail-safe). The DRAM-only `peek_memory_exact` and the byte-reading
`peek_exact_residency` are gone from production builds. Regression
tests `l2_resident_oid_tail_ranges_are_not_refetched` and
`l2_resident_region_a_probe_ranges_are_not_refetched`
(`segment_format_tests.rs`) warm L2 through one cache, search again through a
fresh cache over the same store, and assert zero `ResultPayload` /
`ProbeIndex` GETs; each fails with the DRAM-only peek.

Reachability (traced from `search_vectors_unified` -> `direct_search_with`
-> `try_pax_cascade` -> `rabitq_search_segment_coalesced_allowed`): Region A
runs with default settings on two-level segments (probe ON); the legacy OID
tail is narrower (non-RG segments, plus deferral off or a deferred-resolve
retry, plus a hand-off over its fetch budget).

Accepted residual: an L2 entry evicted between classification and consume
(e.g. by an earlier slot's write-through on a near-full store) costs one
unbatched ranged GET instead of riding the wave — the same window the DRAM
race already had.
