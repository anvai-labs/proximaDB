== History (shipped)

* **Gap.** `TimeSeriesEngine` (time-partitioned columnar: `insert_record`, `query_time_range`,
  `query_ohlc`, `asof_join`, downsampling, retention, WAL + 2PC) sat on no trait and was unreachable; the
  SDK silently fell back to in-memory emulation. `engine:"tst"` on a normal collection was a *trap*:
  records flowed through stubbed vector-shaped trait methods (24h hardcoded window, `vector_by_id→None`,
  log-only flush). Principle that still applies: **each modality is exposed through its own native
  contract, never forced through the vector-record path.**
* **Fix (#651).** Process-global `TimeSeriesService` (under `<data_dir>/timeseries`) calls the TST-native
  methods only; REST v2 `POST /api/v2/timeseries/collections`, `…/{c}/ingest|query|aggregate`, list,
  delete; `"timeseries"` in `/_meta/capabilities`; aggregate buckets by `bucket_ms` with
  avg/sum/min/max/count/stddev. Later registered in the OpenAPI spec (TD-SPECRAT-1 wave 7).

== Remaining

* **gRPC + proto service** — a `.proto` time-series service + gRPC handlers on the
  multiplexed port (the deferred follow-on; REST-only for now). Tracked jointly with TD-CONN-1 C2.
* **Richer engine ops** — surface `insert_ohlc`/`query_ohlc` (OHLC), downsample, and
  `asof_join` endpoints so the REST surface reflects the full TST engine.
* **A Rust `TimeSeriesCollectionConfig`** mapping the full SDK shape
  (`value_columns`/`tag_columns`/`retention`/`downsampling`) for validation +
  round-trip; the MVP keeps a minimal resident config (`TsCollectionConfig` today carries
  value/tag columns + `retention_ms`, no downsampling).
* Retire the SDK's in-memory emulation fallback once the surface is complete.
