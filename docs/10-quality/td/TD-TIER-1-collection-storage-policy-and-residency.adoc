== Finding

The original handoff proposes economy/balanced/performance policies, but conflates desired class,
durable location, local cache priority, guaranteed capacity and provider access tier. There is
no per-collection admitted-residency lifecycle in the surveyed code. Existing cache and storage
primitives should be connected rather than duplicated.

== Premise corrections

* SST `CacheTier::evict_priority` is not the persistent store's reservation mechanism.
  `PersistentByteStore` has its own budget and evictable L2 classes.
* Write-time `all` warming does not cover every result/exact/control range.
* Zero total remote requests depends on coherent discovery (TD-PAXDIR-2), which remains
  separately owned; until then report data and control requests separately.
* GCS access-tier writes and `ProximaObjectStore::put_with_tier` already exist; verify callers.
* A PAX footer cannot have a different provider tier from its containing object.
* Query trace meters do not establish idle reservation time or physical object inventory.
* Additional EBS capacity does not replace the retained S3 bill. Original cost arithmetic,
  CPU attribution and namespace-size conversion require the corrections in the design.

== Acceptance

The design's SC-TE1–SC-TE16 are planned acceptance scenarios, not claims of existing tests.
SC1/SC2 landed acceptance (actual tests): SC-TE1 old-record decode + unknown-value rejection
across facades (REST string at the facade, raw number at the manager) + PATCH preservation;
SC-TE2's placement-shape half (performance requires object-backed SST/PAX; cross-prefix
selection stays with the existing tenant-scoped path machinery). Still planned: SC-TE3–TE16
(reservation/coverage/erasure/idle accounting scenarios belong to SC3–SC6).
Required invariants: balanced compatibility; authorized paths; no capacity overcommit;
truthful readiness; correct fallback after disk loss; publication/retirement ordering;
query freshness and deletes; idle reservation accounting; per-operation/tier usage;
recall and memory bounds.

No new manifest authority, distributed quota service, automatic lifecycle manager, object
location migration, global 40 MiB range default, or AnvaiOps rate-card implementation belongs
in this TD. Other modalities adopt the same contract only after their read-set and correctness
dependencies are proven; the initial implementation scope is object-backed SST/PAX.
