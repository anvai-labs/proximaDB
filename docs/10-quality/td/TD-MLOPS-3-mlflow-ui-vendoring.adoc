== History

* **Capability.** `GET /mlflow-ui[/]` serves the vendored `index.html`, `/mlflow-ui/static-files/<path>`
  the hashed assets, and `/mlflow-ui/ajax-api/2.0/mlflow[-artifacts]/…` nests the existing wire handlers;
  anything else falls back to `index.html` (hash-router SPA). The bundle is extracted reproducibly from
  the sha256-verified `mlflow==3.16.0` wheel with LICENSE + PROVENANCE committed. The feature is
  non-default (+26 MB), so the standard binary is unchanged.
* **Decision — the mount is the contract.** `/mlflow-ui` + the `ajax-api` alias is the stable seam; a
  future custom UI swaps in with the same auth. Statics and aliases mount on the same `base_router`
  before the tenant/auth layers, so a future OIDC/SSO middleware gates UI and API in one place — auth at
  the middleware layer, never inside the UI.
* **NEVER rules (still binding).** (1) NEVER implement MLflow's `users/*` or `roles/*` endpoints — a
  shadow password/identity system that would have to be unwound for OIDC; they 404 permanently and
  identity stays ours (Kanidm/SSO/TenantContext). (2) NEVER merge this bundle into the admin React app —
  it would fork off upstream updates permanently; serve standalone, iframe if visual integration is wanted.
* **Forward pointer (owned by TD-SSO-2).** Browsers send no `Authorization` header, so OIDC on this
  surface needs cookie-based browser sessions (OIDC redirect → cookie → same-origin SPA fetches).
* **Evidence.** Index, hashed JS/CSS and `ajax-api/…/experiments/search` all 200 through the SPA's exact
  paths; gate OFF mounts nothing; gate ON + feature OFF logs one pointer line. Verified at the DOM level.
