= TD-CI-4: Benches/Examples CI Gap (2026-08-23)

== Problem Statement

ProximaDB's CI does **not** compile the root crate's 50 bench files and 31 example files on every PR. These targets can rot without detection until develop→qa promotion.

== Evidence

=== Current CI Coverage

* **`rust-compile-benches` job** — runs `cargo check --workspace --benches` on `medium_tier` (develop→qa promotions **only**, not every PR)
* **No examples coverage** — examples are never compiled in CI
* **`--all-targets` OOM warning documented** — ci.yml comment states that `--all-targets` OOMs runners with benches/examples, citing evidence from a heavier clippy pass

=== Inventory

* **`benches/`** — 50 Rust files (criterion benchmarks)
* **`examples/`** — 31 Rust files (example programs)

```bash
$ find benches -name "*.rs" | wc -l
50
$ find examples -name "*.rs" | wc -l
31
```

=== CI Behavior

```yaml
# From .github/workflows/ci.yml
rust-compile-benches:
  if: needs.changes.outputs.compile == 'true' && needs.changes.outputs.medium_tier == 'true'
  steps:
    - name: cargo check --workspace --benches
      run: cargo check --workspace --benches
```

* **Gated on `medium_tier`** — only runs on develop→qa, not on feat→develop PRs
* **Examples unchecked** — no step runs `cargo check --workspace --examples`

== Impact

* **Silent rot** — benches or examples can break without failing CI
* **Delayed discovery** — breakage surfaces only at develop→qa promotion (late cycle)
* **Developer friction** — developers must manually run `cargo check --benches --examples` before PR (easy to forget)

== Proposed Solution: Option A (RECOMMENDED)

Add a PR-time CI job that compiles benches+examples with **constrained parallelism**:

```yaml
rust-compile-benches-examples:
  name: Rust Compile (benches + examples)
  runs-on: ubuntu-latest
  needs: [changes]
  if: needs.changes.outputs.compile == 'true' && needs.changes.outputs.test_tier == 'true'
  env:
    CARGO_BUILD_JOBS: 1  # Constrain to avoid OOM (not needed per measurement, but safe)
    RUSTC_WRAPPER: sccache
    SCCACHE_DIR: /home/runner/.cache/sccache
  steps:
    - uses: actions/checkout@v7
    - uses: dtolnay/rust-toolchain@1.95.0
    - uses: Swatinem/rust-cache@v2
      with:
        prefix-key: "v1-rust-compile-benches-examples"
        shared-key: "benches-examples"
    - uses: mozilla-actions/sccache-action@v0.0.11
    - uses: actions/cache@v6
      with:
        path: /home/runner/.cache/sccache
        key: sccache-${{ runner.os }}-${{ hashFiles('**/Cargo.lock') }}
        restore-keys: sccache-${{ runner.os }}-
    - name: Install Dependencies
      run: |
        sudo apt-get update
        sudo apt-get install -y libssl-dev pkg-config protobuf-compiler
    - name: cargo check --workspace --benches --examples
      run: cargo check --workspace --benches --examples
    - name: Show sccache stats
      if: always()
      run: sccache --show-stats || true
```

**Rationale:**
* ✅ **Catches rot early** on every PR (test_tier)
* ✅ **Low memory footprint** — the sibling `rust-compile-benches` job already compiles benches serially on the same runner class; this job is the same shape (`CARGO_BUILD_JOBS=1` + sccache)
* ✅ **Fast with sccache** — cached builds will be quick
* ✅ **Runs on test_tier** — same tier as other compile checks

**Why not Option B or C:**
* Option B (medium-tier-only) would allow rot to land on develop
* Option C (split jobs) adds complexity without benefit — memory is not a constraint

== Evidence (memory) — corrected 2026-09-01

An earlier draft cited "283 MB peak" from `/usr/bin/time -l cargo check …` on
macOS. That measurement is INVALID as evidence: `/usr/bin/time -l` reports the
cargo parent process's max RSS, not the `rustc`/sccache-server children that
actually consume the memory — it measured the coordinator, not the workload.
The load-bearing evidence instead: the existing `rust-compile-benches` job
(the benches half of this same check, serial compilation + sccache) already
runs green on the standard 7 GB runner, and this job adds only the
auto-discovered example targets to that shape. An adversarial review
(2026-09-01, PR Verification Regime) caught the bad measurement; also fixed
in that pass: the job is now wired into the `ci-success` aggregator's `needs`
list (a new job absent from the aggregator cannot gate a merge), and
`examples/**` was added to the `compile` path filter (examples-only diffs
previously skipped every Rust job).
