= TD-EXEC-CANCEL-1: Volcano ignores pgwire query-cancel mid-execution — a wedged query queues every subsequent query on the session

| Field | Value

== History

A PostgreSQL wire *CancelRequest* (psql Ctrl-C, driver timeouts) now stops a running native query.
Infra (#981): `ExecError::Cancelled`, a `CancellationExec` wrapper around every operator (poll mask 4095),
CancelRequest resolved by `(process_id, secret_key)`, per-query flag reset, `57014` on the wire; the same
change made native decline an unnormalized cross join fail-fast (`0A000`).

Decisive lesson (still applies): **the check alone was inert end-to-end.** Native operators are synchronous
CPU with no `.await` points, so a grinding query holds its worker thread and the out-of-band task that *sets*
the flag is never scheduled. `CancellationExec::next_row` now yields on its stride (runtime-agnostic
`YieldOnce`) (#984). A unit test that sets the flag by hand cannot catch this gap.

Evidence: `tests/pgwire_cancel_e2e.rs` — an 8×10⁹-row equi-join grind runs to the 540 s timeout without the
yield, and returns `57014` ~1 ms after `cancel_query` with it; the session answers a follow-up immediately.
Follow-up noted, not tracked here: DuckDB in-process cancellation (DataFusion streams already yield).
