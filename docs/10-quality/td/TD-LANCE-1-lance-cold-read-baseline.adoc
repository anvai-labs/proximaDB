== Problem

ADR-098 keeps PAX as the vector leaf format. Its reasoning is that the cost problems sit in the
metadata layers between the leaves and the catalog, not in the leaves. That reasoning rests on
the PAX trace alone. Lance is the obvious alternative for ANN on object storage, and it has
never been run on the same corpus, the same object store and the same cold-read protocol. So
the claim that the leaf format is right is asserted, not measured.

TD-091 asks whether ProximaDB can read or import Lance data. This TD asks a different question:
is PAX the better leaf for our cold-read cost terms?

== Fix

. Build a Lance (`lance` / `pylance`) arm of the SIFT1M object-cold protocol, outside the
  product. It uses the same corpus, the same MinIO + Toxiproxy bed, a comparable IVF-PQ index
  geometry, and recall@10 targeted to the PAX arm's.
. Measure the quantities the PAX trace records: requests per query (GET, LIST, HEAD), dependent
  waves p50, bytes per query, recall@10, and cold and warm p50/p95, on identical objects across
  repeated runs.
. Do not add a Lance dependency to the product crates for this.

== Acceptance

* A ledger entry (status `measured`, emulator-labelled) with the Lance arm and the PAX arm side
  by side, using the same protocol and hardware.
* A one-paragraph verdict recorded in ADR-098 (as a dated note) or in a superseding ADR: either
  the "no format pivot" conclusion stands on the evidence, or the gap is named with the cost
  term it moves.
