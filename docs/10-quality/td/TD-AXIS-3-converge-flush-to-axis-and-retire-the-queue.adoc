== History (shipped)

*Problem (full evidence in ADR-078 §Context).* Flush→AXIS had two implementations: SST indexed directly from
in-memory `FlushParameters.vector_records`, while VIPER/HELIX/NOVA published a queue event whose consumer
re-read the same vectors from storage — only because their `axis_manager` field was constructed `None` and
never set, not by design. The queue's compaction leg `rebuild_indexes_after_compaction` receives swapped
arguments (`(file_paths, &[])` into `(old_files, new_files)`), so its loop never runs yet it increments
`successful_migrations`; `EventType::Delete` is never emitted; `can_compact` fails open; queue state is PUT in
full per event and is stale after restart.

*S1 (#1281).* `storage::common::axis_flush_hook` holds one copy of the ADR-070 guard, the
`PROXIMADB_SKIP_AXIS_INDEXING` override and the `handle_flushed_vectors` call; `SharedServices` registers the
manager at boot (giving VIPER/HELIX/NOVA a handle) and all four engines call it. `handle_flushed_vectors`
itself is unchanged; S1 only changes how records reach it. *Evidence:* each engine was code-verified to derive
its flush input from `params.vector_records`; guard unit tests (absent config, empty `index_configs`,
`pax_vector_format:off` tag alone ⇒ no AXIS; explicit config ⇒ dispatch; missing manager ⇒ no-op); a
recording-`IndexEngine` spy pins dispatch via both the explicit handle and the boot-registered global fallback.

  cleanly deletable; extracting the shared types and retiring `EventLogManager` /
  the service adapter is the careful part. `rebuild_indexes_after_compaction` has a
  live caller — `rebuild_index` (itself a no-op today) — so redirect that to
  `Ok(())` before deleting.

**Explicitly not doing:** repairing `rebuild_indexes_after_compaction`. Fixing the
swapped arguments would resurrect a second compaction-indexing path beside the
working `update_indexes_after_compaction` and create a genuine double-index
hazard that does not exist today (ADR-078 D2).

== 4. Residual

A segment flushed but not indexed before an **unclean** restart is still never
re-indexed. That gap predates this TD and the queue never addressed it either;
tracked as **TD-AXIS-4**.
