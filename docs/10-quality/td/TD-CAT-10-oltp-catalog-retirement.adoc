== History

`OltpCatalog` is now an explicit opt-in module (`#[cfg(feature = "oltp-catalog")]`), retired rather than
rescued. Reviving SQL-backed catalog support would be new feature work starting from a working baseline.

Decisive findings (lessons that still apply):

* It was broken in *both* configurations: feature-off it was a silent in-memory no-op that logged
  "skipping DDL" and **reported success**; feature-on it did not compile (sqlx `SqlSafeStr` injection lint, 7× E0277).
  `oltp-catalog*` was in no CI workflow, so a green build was not evidence the feature worked.
* Adversarial review found the root `oltp-catalog` feature never forwarded to the catalog crate, so the module
  was unreachable from the server in every configuration; root features now forward
  `proximadb-catalog/oltp-catalog[-backend]`. The duplicated `InMemoryTestCatalog` double was deduped into `src/testing.rs`.
* The `oltp-catalog*` feature names stay in `Cargo.toml`; removing them is a separate breaking change.
  `check_compaction_needed_stamps_precision_hint_from_resolver`'s core assert never touches the catalog (pre-existing weak test).

Evidence: `cargo check -p proximadb-catalog --features oltp-catalog-sqlite` reproduced the E0277 failure before gating;
`clippy -p proximadb-catalog --all-targets -D warnings` passes after.
