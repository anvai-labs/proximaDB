== History (shipped)

* Finding: P-Shred (ADR-055) wrote typed user-column stripes as a **duplicated advisory index** — the msgpack `PROPS` tail stayed the source of truth — so every shredded value was written twice and typed columns could be trusted only for pruning. Target (aligned with Iceberg v3 Variant shredding): declared columns authoritative, `PROPS` tail carries only the residual.
* ROI caveat that still applies: ADR-034 ranks typed columns last because they buy < 2× on scans; this work is justified on one unified store, a real second router cost arm, uniform projection/pruning, and write-amplification removal — **not** as a scan-throughput win.
* Slice 1 (#1925): `header.rs` equality-rejected any non-`FORMAT_VERSION` block (a v3 block would have been a flag day), `BlockHeader` discarded the version, and `to_bytes` would relabel a v3 header as v2. Now `SUPPORTED_FORMAT_VERSIONS` dispatch, a retained `format_version`, version-preserving `to_bytes`; unknown versions fail closed.
* **Lesson — the block must be self-describing before the tail can become a residual** (slice 2a, #1926). Reconstruction took promoted keys from the caller's schema positionally; once a value lives only in the stripe, a drifted key list (routine schema evolution) silently drops props. `col_id::SHRED_DIRECTORY = 15` records the `(col_id, prop_key)` pairs written. The PAX block format had **no extensibility headroom left** (32-byte `BlockFooter` and 64-byte `ColumnMeta` fully consumed), so the directory is a stripe-less `ColumnMeta` entry borrowing `bloom_offset/bloom_len`, declared `ColumnRole::Props` (a new role byte would break older builds' mixed reads of v2 blocks).
* **Lesson — type fidelity needs the DECLARED type** (#1929): stripe typing was inferred from the first non-null value with silent `None` on non-conforming rows, and `shred_class` folds integers/temporals into one i64 class (`Int32` returns `Int64`); a variant tag cannot rebuild `Time(i64, TimeUnit)` etc. `ShredColumn { key, column_id, declared_type: Option<ProximaType> }`.
* Slice 2b (#1930): per row, per shred column, a key is dropped from the tail only if it has an exact declared type AND the stripe reproduces it identically (`shreds_losslessly`); otherwise it stays. Read merges stripes with **tail-wins** (`entry().or_insert()`), so a lossy stripe value never overwrites the true one. A block stamps `FORMAT_VERSION_V3` only when its tail actually became a residual. The filed "non-conforming value is a write error" rule was rejected: losslessness is a property of the encoding, not a requirement on the data.
* Measurement (#1931, `pax_residual_tail_write_amplification`): relational 310.97 → 182.97 bytes/row (−41.2%); vector/SST 0.0% by construction (asserted). Lesson: the first run showed 0.1% because `residual_tail_enabled()` reads the gate through a process-wide `OnceLock`, so toggling the env in one process measured one mode twice — unit tests had set the private field, never the configuration path. Fixed with `PaxBlockWriter::with_residual_tail(bool)`.
* Raw-`props` projection (#1934): `document_pax_provider.rs` projected `props` as an opaque blob, which under the gate would have returned the residual. `collect_flushed_rows` now reinstates shredded props under the same tail-wins rule (`residual_tail_props_projection_still_returns_the_whole_document`, through SQL, verified non-vacuous).
* Evidence: `residual_tail_round_trips_every_prop_exactly`, `residual_tail_is_smaller_than_the_complete_tail`, `residual_gate_off_keeps_a_complete_v2_tail`, `block_carries_its_own_shred_directory`, `directory_records_the_declared_type_when_the_caller_has_one`, `untyped_shim_records_no_declared_type`; recall@10 harness green.

== Open

=== Remaining before a default flip

* Recall/round-trip gating on real corpora (the evidence gate's losslessness ratchet incl. schema-evolved declared types, mixed v2/v3 segments in one collection, recall@10 ≥ 0.93), then decide the default flip of `PROXIMADB_PAX_RESIDUAL_TAIL`.
* Decide whether the block directory and the segment-level `shred_field_map` (TD-FPRUNE-1 P2) converge.

=== Consequence: "declared columns authoritative" cannot be uniform

ADR-094 spec §2.1 and this TD's headline both read as a global property. They cannot be. The
end-state is narrower, and the narrowing is structural rather than a matter of sequencing:

**Declared columns may become authoritative ONLY for columns carrying an exact declared type.
Everywhere else the typed stripe stays an advisory pruning index and the msgpack `PROPS` tail
stays complete — indefinitely, not "until a later slice".**

Which also means the write-amplification win this TD is justified on applies to the relational
arm, and *not* to the SST/vector arm, unless that arm later gains an exact per-column type.
That should be measured per-path rather than claimed globally.

This is recorded in the code too: `with_shred_spec` is retained as a shim that produces
`declared_type: None`, so a path that cannot declare exactly cannot accidentally be treated as
one that can. `untyped_shim_records_no_declared_type` pins that.

**Evidence:** `directory_records_the_declared_type_when_the_caller_has_one` (exact type
round-trips; absence is recorded rather than guessed) and `untyped_shim_records_no_declared_type`.
95/95 in the crate including the rabitq recall@10 ratchet.

=== Noted overlap, for whoever does 2b

A **segment-level** `shred_field_map` already exists in the PAX segment footer (TD-FPRUNE-1
P2), mapping field name → col-id for filtered reads. It overlaps in content with the
**block-level** shred directory added in slice 2a, but differs in scope and guarantee: the
footer map is gated behind `footer_stats_enabled()` and lives once per segment, whereas the
block directory is ungated and self-contained, which is what reconstruction requires. Worth a
deliberate decision in 2b whether the two should converge; they should not both grow
independently.

=== Evidence gate (mandate #6)

* **Losslessness ratchet:** declared columns + residual reconstruct the original
  `ProximaRecord` exactly, including nulls, type edge cases, and props whose declared type
  changed via schema evolution.
* Write-amplification delta (bytes written per row, before vs after) recorded in
  `BENCHMARK_EVIDENCE.toml`.
* Mixed-read test: a v2 segment and a v3 segment in the same collection both read correctly.
* Recall ratchet (recall@10 ≥ 0.93) stays green.
