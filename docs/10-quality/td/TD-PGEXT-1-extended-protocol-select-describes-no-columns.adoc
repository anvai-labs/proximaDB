= TD-PGEXT-1: extended-protocol clients fail on relational and parameterized queries

[cols="1,3", options="header"]
|===
| Field | Value
| Status | **Open** (filed 2026-10-18). Reproduced against the 0.4.1 image with asyncpg 0.31, psycopg 3 and psql `\bind`.
| Priority | **HIGH** — JDBC, asyncpg, psycopg 3 and most ORMs use the extended protocol, so most real clients fail; ADR-096 makes pgwire the front door.
| Component | pgwire extended protocol (`Describe` for portals and statements, `src/network/postgres/protocol.rs`)
| Relates to | ADR-096, TD-102 (extended protocol, Slice A), roadmap v0.5
|===

== Problem

The server's `Describe` reports zero result columns for relational SELECTs and describes every
`$N` parameter as `text`, whatever the column type. Observed on 0.4.1:

[cols="2,2,2,2", options="header"]
|===
| Client | Relational SELECT, no parameters | Relational SELECT with `$1` | Vector search with `$1`
| asyncpg 0.31 | fails (`the number of columns in the result row (2) is different from what was described (0)`) | fails (non-string arguments are rejected because every `$N` is described as text; a string argument hits the same column error whenever rows come back) | works
| psycopg 3 | works until psycopg auto-prepares the query (from the 6th execution, `prepare_threshold=5`), then fails | fails | fails (`unexpected field count in "D" message`)
| psql `\bind` | fails (`unexpected field count in "D" message`) | fails | fails
|===

JDBC and ORMs use the extended protocol and are expected to be affected; not yet tested. The
existing test (`tests/pgwire_extended_param_e2e.rs`, tokio-postgres) covers only parameterized
vector search, which is why this was not caught. The simple query protocol works (psql, psycopg 2).
Workarounds for psycopg 3: `prepare_threshold=None` keeps unparameterized queries working, and
`psycopg.ClientCursor` makes parameterized relational and vector queries work.

== Fix

Describe every SELECT with its real row description and parameter types. Add end-to-end tests with
tokio-postgres (`query` with and without parameters, relational and vector), and a driver smoke
with asyncpg, psycopg 3 and JDBC against the release image.
