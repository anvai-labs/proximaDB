== Defect

ADR-086 correctly refuses a compaction morsel that cannot fit the serving
process's byte-weighted RAM budget. The current executor has no alternate plan,
so the same pair remains ineligible forever on a small node. At 3.3M vectors the
5 GiB ceiling produced three segments, object-cold recall@10 0.981, and 58.63
GETs/query. A one-segment control at the same corpus scale measured 24.478
GETs/query at recall@10 0.980. Stability and query economy are therefore coupled
to serving-node RAM even when inexpensive local disk is available.

The current code cannot be fixed by adding a temporary `Vec` serialization:

* PAX inputs are whole-object decoded by the compaction route;
* MVCC sorts the complete `Vec<ProximaRecord>`;
* IVF planning projects and assigns every row into corpus-sized vectors;
* `PaxSegmentWriter` buffers Region D plus every f32 vector and builds complete
  Region A/B byte vectors; and
* the OID resolver retains every string plus a reverse hash map.

== Work items

=== S1 — Resource plan and scratch admission

* Add default-OFF spill configuration with a mandatory local path when enabled,
  bounded working memory, conservative scratch amplification, live-free-space
  fraction, and optional absolute scratch ceiling.
* Choose one complete execution plan before materialization.
* Reserve RAM and scratch process-wide with RAII release and metrics.
* Let discovery pack a spill-eligible whole-file morsel without relaxing the
  in-memory cap.
* Reserve at least 10x compressed input bytes by default: the 2026-08-03
  release/Azurite 3.3M task measured a 7.532x live-scratch peak and invalidated
  the initial 4x estimate.

=== S2 — Block-ranged canonical input stream

* Read coalesced PAX header/footer once and Region D one block at a time.
* Read only the matching Region B rows needed to reconstruct compaction vectors.
* Retain a mixed-read fallback for legacy PAX/SST inputs without loading every
  input concurrently.
* Apply versioned deletion vectors by source position before the record loses
  its segment/row identity.
* Persist canonical `u64 record_version` in an additive PAX stripe; treat absence
  as the legacy version-1 sentinel and corruption as an error.

=== S3 — Deterministic external MVCC and IVF order

* Length-frame and checksum scratch records.
* Generate bounded OID/version-sorted runs, k-way merge, and resolve one OID
  group at a time with semantics pinned to `MvccResolver`.
* Select the deterministic training sample from the survivor stream.
* Extract a reusable IVF fitted-model/row-key seam from `block_cluster`.
* Generate bounded cell-order runs and merge them with stable source ordinals.

=== S4 — Disk-backed PAX builder

* Add memory and local-spill backing modes behind one writer implementation.
* Stream Region D blocks, vector spool, Region A/B encodes, and OID resolver.
* Assemble the existing PAX layout sequentially and validate it through the
  existing scanner/read inverse.
* Keep the existing in-memory writer byte-identical.

=== S5 — Publication, invalidation, and recovery

* Upload the completed local output once to its unique final object key. Treat
  multipart completion as the remote visibility boundary; do not first upload
  an object-store `__compact` key and then GET/COPY/re-PUT it. Keep local
  staging plus atomic rename for `file://`.
* Fail spill closed when a remote backend/decorator cannot guarantee bounded
  local-file publication; Azure block upload, S3 multipart, and GCS resumable
  upload are qualified paths. Check this capability before compaction work.
* For `file://`/bare local paths, write a hidden sibling and atomically rename
  on the same filesystem; never use the configurable spill mount as the rename
  source.
* After publication, stream Region A/B from retained local staging into the
  rebuildable persistent cache without an object GET or segment-sized DRAM
  seed; degrade to bounded control-only admission when that tier is disabled.
* Retire inputs/DVs and purge cache entries only after publication.
* Cleanup scratch on every normal/error/cancellation path and at startup.
* Use advisory filesystem leases rather than PID liveness, and serialize owner
  creation/cleanup on a shared local or managed RWO scratch root.
* Add failure injection for ENOSPC, corrupt run, cancellation, upload failure,
  and stale task ownership.
* Retain the training rescan obligation across higher-level work so an L0
  published during a long spill cannot be stranded until a future write.

=== S6 — Release evidence

* Force spill on a small deterministic corpus and prove output/recall parity.
* Run release/Azurite at 3.3M with the same 5 GiB serving ceiling.
* Record peak RSS, scratch peak, local bytes, object GET/PUT/DELETE operations,
  segment geometry, GETs/query, latency, and recall in `BENCHMARK_EVIDENCE.toml`.

The 2026-08-03 exact-commit run completed the 3.3M functional/economic slice:
one 2.58M-row spill peaked at 7.492x live scratch inside its 10x reservation;
the settled two-segment corpus measured recall 0.985/0.987/0.983 and
4.98/1.17/48.69 GET/query after-write/disk-warm/object-cold. Whole-process RSS
and the injected-failure/determinism matrix remain open; this evidence does not
close the TD.

The subsequent 10M qualification reached one fully constructed
2,757,638,547-byte, 10,000,000-row PAX but exposed a publication defect before
source retirement: the Azure `move_file` compatibility path reread the whole
remote staging object and attempted a second PUT. The source segments remained
authoritative, proving the retirement ordering, but the run is not accepted as
10M query evidence. S5 now uses the already-admitted local spill file as the
only upload source and publishes it directly by bounded multipart commit; the
10M recall/GET/latency matrix must be rerun on that path.

== Exit criteria

TD-COMPACT-11 closes only when spill is default-OFF but fully wired, the failure
matrix and feature builds are green, and measured release evidence proves a
merge rejected by in-memory admission completes within its independent RAM and
scratch reservations without temporary object-store I/O or recall regression.
