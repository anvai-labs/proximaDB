== History

* Symptom: after a clean SIGTERM shutdown sequence the process never exited — `Runtime::drop` waited on a blocking-pool worker running a discovery pass. Root cause: `shared_services.rs` spawned background loops with `std::mem::forget(shutdown_tx)`, so their `watch`-based cooperative shutdown could never fire, and the discovery drain loop did not re-check shutdown between jobs. Supervisor SIGKILL masked it under systemd/K8s; on bare Spot it wastes the eviction window.
* Fix: all five leaked senders (discovery executor, recall observer, drift watcher, drift observer, AXIS EventLog consumer) `register(name, sender)` with `services::shutdown_registry`; `ProximaDB::shutdown` calls `fire_all()` first; the discovery drain loop re-checks its receiver between jobs. `shutdown_timeout(5s)` stays (durable state is persisted before it).
* Lesson that still applies: `std::mem::forget` of a shutdown sender creates a non-daemon background loop that outlives shutdown (mandate #11). A bounded teardown can also remove accidental grace that other subsystems relied on — see TD-FLUSH-4.
