= TD-SDKDOC-1: SDK guide examples are not executed

[cols="1,3", options="header"]
|===
| Field | Value
| Status | **Resolved (2026-10-24).** `clients/python/tests/unit/test_doc_examples.py` extracts every Python block from the SDK guide, the quick starts and the concept docs and runs three tiers: every block must compile; every `proximadb_sdk` name it imports or touches must exist; and, against a live server (`PROXIMADB_DOC_SMOKE_URL`, set by the `Python SDK round-trip` CI lane, which now also runs on docs-only changes via the `sdk_docs` filter), each document's blocks execute in order in one namespace. A block fails on an exception; on an un-awaited coroutine (a bare call or one held in a name); when the client falls back to its offline in-memory store (which fakes success on a transport error and logs only at DEBUG); after a 120 s per-block timeout; or when the SDK logs a WARNING or worse while it runs. Every python fence in a source file must be extracted, so a fence variant cannot silently drop a block. Blocks that cannot run against the smoke server (embedded mode, OAuth2, mTLS, two fragments) carry `# doc-smoke: skip <reason>`, which exempts them from execution only: they still compile and name real SDK symbols. A "complete example" carries `# doc-smoke: fresh-server`. The quick starts' embedding model is replaced by a deterministic stub only when `sentence-transformers` is absent. A deliberately re-broken example fails the gate.

Running the examples found more than review had: about 20 blocks failed as written, plus three SDK bugs, fixed in the same PR. `GraphAnalytics.shortest_path` raised `TypeError` on every real client and read the wrong response key. `ProximaDBClient.graph_shortest_path` dropped `graph_id`, so it always used the `default` graph. The multi-modal executor's vector leg called `search(collection=, filter=)` and failed silently. The executor's other legs are filed as TD-SDKMMQ-1, with the server's 500-on-duplicate-graph and the `Collection not found: unknown` message.

== Problem

Doc examples drifted from the SDK: `FilterBuilder().add`, `create_nodes`/`create_edges`/`traverse`,
`GraphAnalytics.semantic_traverse` (a duplicated keyword argument, which is a SyntaxError),
`knowledge_graph_search` arguments, `client.search(collection=...)`, AutoML parameters and
`create_graph(engine=...)`. Fixing them by review alone has taken several passes.

== Fix

Extract the Python blocks from the quick starts and the SDK guide and run them in CI against a
server started from the release image (a doc-smoke lane), so an example that fails as written fails
the build. Blocks that are illustrative are marked and skipped explicitly.
