|===
| Field | Value

== History

* **Bug.** Unlike the vector sibling (`execute_collection_query`, a real catalog lookup),
  `execute_graph_query` did no lookup and returned a placeholder `(table_name, "0", "0")` with a
  `SELECT 1` tag for an existing graph, an empty graph, or a nonexistent table alike. No test depended
  on it (the LDBC pgwire e2e models graphs as relational Parquet tables).
* **Fix.** Decline `0A000`, naming gRPC `proximadb.v2.ProximaGraphService` (incl. its openCypher
  `ExecuteQuery` subset) and REST `/api/v2/graphs/{graph_id}…` as the graph surfaces.
* **Lesson — the symmetric fix was unsafe.** Calling `GraphService::get_stats` resolves through
  `get_or_create_graph_engine` → `ensure_or_create_graph`, so a stray SELECT on a misspelled name would
  silently **provision a new empty graph**. A real-stats answer needs a side-effect-free catalog existence
  pre-check first; the honest decline is a complete resolution on its own (not filed separately).
* **Correction (2026-09-15).** This TD originally overclaimed that no graph SQL surface exists;
  `graph_traverse(...)` is a registered DataFusion UDTF with live pgwire wiring whose reachability is
  unverified — owned by TD-XMODAL-10.
