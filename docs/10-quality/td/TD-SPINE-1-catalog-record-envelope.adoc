== Implementation notes (2026-11-22)

* **No write gate.** The original Fix text proposed an opt-in write gate
  (default OFF) per CLAUDE.md #8. The owner decision of 2026-11-20 (pre-GA:
  no backward-compat gates — document breaks, don't gate them; see
  `feedback_prerelease_no_backward_compat`) overrides it: the writer emits the
  envelope unconditionally and readers sniff unconditionally. Mixed-read still
  works **by construction** — absent magic ⇒ legacy field-named MessagePack —
  so an upgraded binary reads every legacy record forever.
* **Breaking change (accepted pre-GA, 2026-11-22):** a pre-envelope binary
  cannot decode enveloped records (WAL payloads, snapshots, sidecars). There
  is no gate and no dual-write window.
* **Layout** (`src/services/catalog_record_envelope.rs`):
  `[magic "PXCATREC":8][format_version:u8 = 1][body_codec:u8 = 0][body]`,
  following the PMHEAD magic-prefix pattern. Body codec 0 = field-named
  MessagePack. Sniffing is unambiguous at the byte level: every legacy record
  is a MessagePack map (first byte `0x8n`/`0xDE`/`0xDF`), which can never
  begin with ASCII `P`. Unknown `format_version`/`body_codec` fails **closed**
  with a typed error naming the value; a torn header (magic present, header
  cut) fails closed; a short non-magic buffer is left to the MessagePack
  decoder.
* **Generation-prefixed payload:** the catalog snapshot bytes are enveloped
  at the record boundary (in `to_snapshot_bytes`) BEFORE
  `ManifestCommitter::commit_fenced` prefixes the 8-byte generation, so the
  fenced payload is `[generation:8][envelope]`. The committer itself stays
  codec-agnostic on purpose: it is shared with partition-lease manifests, and
  re-framing `encode_fenced` would envelope lease payloads too. A legacy
  `[generation:8][bare rmp]` manifest decodes unchanged (strip 8, sniff, no
  magic ⇒ legacy).

  `src/services/system_catalog.rs`) runs over a chain that contains legacy
  unframed records. The cross-pod suite runs over enveloped records only,
  because the current writer always emits the envelope.

* **Deferred decision, not a TD:** the protobuf body codec (ADR-098 D1.2)
  stays deferred. It is triggered by the first schema change that
  `#[serde(default)]` cannot carry.

== Problem

Catalog deltas, snapshots and the identity sidecar are bare field-named MessagePack
(`rmp_serde::to_vec_named`). The only version-like field, `writer_version`, sits inside the body.
The outer canonical WAL frame (`PXWAL001`) is versioned, but its catalog payload is not. A reader
cannot distinguish a future body codec or layout from today's, so any change needs every reader
upgraded first. Schema evolution relies only on `#[serde(default)]`; a rename silently breaks old
snapshots.

== Fix

. Frame every persisted catalog record as `{magic (4–8 B), format_version: u8, body_codec: u8, body}`,
  following PMHEAD's binary framing. Body codec 0 = field-named MessagePack.
. Decoders sniff the magic: present ⇒ dispatch on `format_version`/`body_codec`; **absent ⇒ legacy
  MessagePack** (forever). Unknown version ⇒ a typed error naming the version, never a panic.
. Readers sniff unconditionally and land first. The **writer** emits the envelope only behind an
  opt-in write gate (default OFF until baked, per CLAUDE.md #8), with an `ENV_GATE_REGISTRY.adoc`
  row named per the registry rules (e.g. `PROXIMADB_CATALOG_WRITE_RECORD_ENVELOPE`). Flipping the
  default is a separate, evidence-gated change.
. Do not change the body codec here (ADR-098 D1.2).

== Acceptance

* Round-trip tests for delta, snapshot and sidecar in both framings.
* A legacy (unframed) snapshot and WAL tail written by the current code open and replay unchanged
  (extend `identity_high_water_is_mixed_read_safe`-style tests).
* Cross-pod tests in `src/services/system_catalog.rs` (follower tail, superseded owner, fenced
  checkpoint) pass with a mixed legacy/enveloped chain.
* Truncated or corrupt envelope ⇒ fail closed with the existing torn-tail semantics.
