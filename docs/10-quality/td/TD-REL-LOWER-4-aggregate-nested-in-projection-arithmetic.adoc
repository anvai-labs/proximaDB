= TD-REL-LOWER-4: Aggregate nested in a projection arithmetic expression declines the native route (`aggregate function in non-aggregate position`)

[cols="1,3", options="header"]
|===
| Field | Value
| Status | **Partial: aggregates nested in projection *arithmetic* (`sum(x)/sum(y)`, `100.0*sum(case…)/sum(…)`) are hoisted into `Aggregate` slots (#1026, 2026-07-15); open: aggregates nested inside CASE or a scalar function at the projection top level still decline (`Unsupported("aggregate nested inside an unsupported projection expression")`, verified 2026-10-15).**
| Priority | P2 — the "aggregate ratio / market-share" shape is common ANSI SQL; broad TPC-DS fan-out
| Component | `crates/query/proximadb-relational-frontend` (`lower_projection_with_aggregates`, `lower_agg_projection_expr`, `remap_group_key_refs`)
| Relates to | link:TD-REL-LOWER-5-general-subquery-unnesting-pass.adoc[TD-REL-LOWER-5] (Q2/Q11/Q17/Q18/Q20 subquery shapes split out), link:TD-REL-LOWER-6-disjunction-shared-equi-key-cross-join.adoc[TD-REL-LOWER-6] / link:TD-REL-LOWER-7-nway-comma-join-connectivity-reorder.adoc[TD-REL-LOWER-7] (Q8/Q9/Q19 cross joins)
|===

== History (shipped)

`lower_projection_with_aggregates` handled only a bare top-level aggregate; `SUM(x)/SUM(y)` was lowered in
scalar position and rejected. Lesson: the pgwire client saw a misleading *legacy-fallback* message (`Column
'sum(case' does not exist` or the comma-list `0A000`) because a frontend decline silently fell through; the real
cause was the frontend, not routing.

Fix: a recursive pass over the arithmetic spine (`Nested`/`BinaryOp`/`UnaryOp`/`Cast`) extracts each aggregate
into a `NamedAggregate{name: "__agg_<slot>"}` and replaces it with a `ColumnRef` of the same name (so name-based
rebind resolves it); aggregate-free sub-expressions get group-key refs remapped to post-aggregate slots. One
`LogicalNode` feeds both native and DataFusion.

Evidence: `tests/rel_agg_arith_projection_e2e.rs`; frontend unit `select_aggregate_arithmetic_hoists_nested_aggregates`;
TPC-H Q14 native row-exact (native 13 → 14/22).

== Open

Anything else carrying an aggregate (CASE / scalar-function at the projection top level) → `Unsupported`, a
**graceful decline to legacy — no regression**, just not yet supported. Note also: division by zero is a hard
error (PostgreSQL semantics), not NULL.
