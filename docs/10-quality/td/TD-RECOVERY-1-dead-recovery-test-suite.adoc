== Finding

`tests/recovery/{recovery_test.rs, recovery_stress_test.rs,
write_buffer_corruption_recovery_test.rs}` exist in the tree but:

* Cargo.toml declares only `[[test]]` targets for `tests/rust/mod.rs` (integration)
  and three CDC tests — the recovery subdirectory is not listed.
* `tests/rust/mod.rs` does not `mod recovery;` — no module inclusion.
* No Makefile target, CI workflow, or script references them.
* Cargo's default test discovery picks only top-level `tests/*.rs`, never
  subdirectories.

Result: zero of these tests have run since they were placed there.

== Fix options

1. **Wire them**: add `[[test]]` entries to Cargo.toml with explicit paths, or
   restructure as a single `tests/recovery/mod.rs` target. Requires verifying
   they compile against the current API surface (they use dated types that
   may have been removed).
2. **Delete them**: if bit-rotted beyond reasonable revival, remove the files
   and record the loss of intent.

Either way, the current state (dead code that looks like coverage) is the
worst option.
