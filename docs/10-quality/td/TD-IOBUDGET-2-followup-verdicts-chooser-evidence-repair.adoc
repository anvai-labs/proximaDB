== History (shipped)

*Verdict 1 — destination URL plumbed (closes TD-IVF-4).* The live writer path is compaction, which always
knew its output object; `destination_url` now reaches `write_target_block_bytes`, so writer cell geometry
resolves the same per-location budget the reader does (ADR-065 "one cell ≈ one IOP" holds on both sides).
With an empty registry `file://` now derives LOCAL 1 MiB instead of hard-coded CLOUD 4 MiB (k ×4 on new
compaction segments; self-describing per segment, mixed-read-safe). *Measured (`iobudget2_file_geometry_sift1m`):*
object-cold bytes/q −51.1%, GETs/q −13.3%, recall 0.9835→0.9794; the product owner accepted the trade and the
recall floor dropped 0.98 → 0.975 repo-wide (2026-09-03). Rollback: `PROXIMADB_DISK_CLASS=hdd` or per-location `disk_class = "hdd"`.

*Verdict 2 — the original chooser A/B was invalid.* The harness popped `PROXIMADB_STORAGE_READ_STRATEGY_CHOOSER`
from the server env and the constructor parameter had no CLI flag, so the "ON" arm ran chooser-OFF (byte-identical
GET/q 20.05 in both arms). *Lesson:* an A/B whose arms produce byte-identical physical counters is not evidence;
attest engagement. `--adaptive-read-strategy` now exists and the OFF arm fails fast if the gate leaks into its env.
TD-RDSTRAT-13's Chooser A/B section (unmerged worktree commit 188787302) must NOT be cherry-picked as-is.
*Re-run (`read_strategy_chooser_sift1m_minio`, flip-checklist steps 1+2 DONE):* object-cold GETs 21.95 → 12.82
(−41.6%) at byte-identical recall; warm phase −29.3% GETs, −6.9% p50; the ON arm passes every gate the OFF arm fails.

== Consumers/interplay recorded for the flip decision

* With the chooser OFF, a registered per-location budget still applies — as the fixed
  default policy (`defaults` derives from `IopsBudget::for_path(path).target_block_bytes()`).
* The chooser only enumerates ADDITIONAL caps above that default
  (`read_range_cap_candidates` = multiples of budget.target up to scheme ceilings), so
  chooser-ON + a small registered budget can legitimately RAISE an effective cap — GET-count
  gates can move either direction and the flip A/B must run both budgets explicitly.
* The SST scan path (`sst_query_engine.rs`) is budget-blind (hard-coded
  `ObjectRangeCoalescePolicy::default()`) — a pre-existing divergence, out of scope here.
