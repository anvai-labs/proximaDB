== Problem

The xCatalog MLOps model registry is the durable authority for embedding
model contracts (implemented: typed contracts, immutable versions, command
mutations, tenant-scoped lifecycle APIs, generated SDKs), and its design
names MLflow compatibility as the next adapter slice. Without it:

* The ecosystem's standard experiment-tracking clients (`mlflow` Python SDK,
  MLflow REST) cannot drive the platform — every team wires bespoke tracking.
* Model registration happens through bespoke scripts instead of the MLflow
  registry workflow most ML engineers already know.
* The design's own standard pressure-test (MLflow / MLMD / OpenLineage /
  KServe / Unity Catalog mappings) remains unexercised — the mappings are
  prose, not conformance-tested code.

== Non-negotiable adapter laws (from the design authority)

0. **Scope note (review round 1):** the design authority's MLflow rows
   cover the REGISTRY only; extending the adapter to TRACKING (experiments/
   runs) is this TD's extension and requires an amendment note in the
   XCATALOG doc when slice 2 ships. To keep run identity ONE-HOME
   (mandate-19 twin risk): the RunStore document is the durable record of
   a run; when a model version registered from that run cites "source run
   identity" (the design's retained field), it MUST reference the
   RunStore's run_id verbatim — the catalog stores the reference, never a
   second copy of run state.
1. **Lower to xCatalog commands — never own another metadata database.**
   Registry operations lower to `CatalogModelRegistryService` commands
   (`RegisterVersion`, `SetAlias`, `AppendEvidence`, `RecordDecision`,
   `UpsertDeployment`) via `apply_mutation`. Tracking runs lower to a
   `RunStore` port whose FIRST implementation is the multimodal substrate
   (system-namespaced document collection under `DrPathBuilder` paths,
   tenant-scoped) — not a private table.
2. **Neither adapter owns persistence.** All durability flows through the
   substrate / catalog seams.
3. **Connectivity spine (mandate 18b):** the MLflow router is a thin
   wire-codec — auth/tenant from the shared `HeaderTrustPolicy` +
   `TenantContext` plane (never from MLflow body fields), errors through the
   shared error mapping, no hand-rolled auth.
4. **Default-OFF, fail-closed:** the wire surface is gated by
   `PROXIMADB_MLFLOW_COMPAT_ENABLE` (opt-in tier, default OFF; unset ⇒ every
   `/api/2.0/mlflow/*` route 404s). Registry row lands with slice 2.
5. **Mixed-read-safe by construction:** additive routes only; no existing
   surface changes; gate-off is indistinguishable from absent.

== Concept mapping (extends the design's standards table to TRACKING)

[cols="2,3,2", options="header"]
|===
| MLflow concept | Native mapping | Consequence
| Experiment | Tenant-scoped experiment record (RunStore) | Stable `experiment_id`; delete = soft (lifecycle marker), matching MLflow semantics.
| Run | Producer execution + typed lineage entry | Run identity retained on model versions (design: "source run identity is retained").
| Param / Metric / Tag | Substrate documents/columns | Metrics queryable (relational); params reject a DIFFERING second value but are idempotent on the same value (log-batch retries must succeed); tags mutable.
| Metric history | Append-only points `(step, value, timestamp)` | Time-ordered retrieval; no in-place edits.
| Artifact | OCI descriptor (URI, SHA-256, media type, size) | Content-addressed under DrPathBuilder paths; relocation-stable identity.
| Registered model / version | `CatalogEmbeddingModelRegistry` + immutable version | Duplicate versions fail; digest identity.
| Alias | Catalog alias transaction | No data-plane record stores an unresolved alias.
| Tag (registry) | Annotation outside versions | Mutable, never affects contracts.
| Stage transition | REJECTED with alias pointer | No built-in staging/production state machine (design); MLflow ≥2.5 aliases are the native path. NOTE: stage calls still function in current 2.x/3.x clients and `models:/name/Production` URIs will hard-fail — the slice-3 real-client workflow deliberately avoids stage calls, and the rejection message points at aliases.
| Dataset (run input) | Name + content digest in lineage | Reproducibility never depends on a mutable path.
| Signature | Typed input/output contract | Embedding semantics beyond tensor schemas.
|===

== Slices (TDD; each ships tests + docs; wire slices ship behind the gate)

=== Slice 1 — Tracking core (RunStore port + substrate impl) — no wire

* `RunStore` port: experiments CRUD (soft delete), runs lifecycle
  (create/get/update/delete/set-tag), params (immutable), metrics +
  history, tags. Tenant-scoped by construction.
* First implementation: system-namespaced document collection through the
  document substrate; keys under `data/{tenant}/{ns}/…` via `DrPathBuilder`
  only.
* Tests: red→green port conformance (round-trip, tenant isolation, metric
  ordering, param differing-value rejection + same-value idempotency,
  soft-delete visibility, CONCURRENT metric appends to one run from
  interleaved writers at the same step), positive shapes.

=== Slice 2 — MLflow tracking wire (gate OFF)

* Router under `/api/2.0/mlflow/*` (axum, mounted only when
  `PROXIMADB_MLFLOW_COMPAT_ENABLE` is set): experiments create/get/search/
  delete/restore, runs create/get/update/search/delete/restore,
  log-parameter, log-metric, log-batch, set-tag/delete-tag.
* MLflow-native error envelope (`{error_code, message}`) and REST shapes —
  MLflow's spec is the external contract (pgwire-class compatibility, not
  our OpenAPI); document this in ENV_GATE_REGISTRY + the surface docs.
* Search endpoints implement MLflow's filter language for the subset the
  canonical workflow exercises (`params.x = 'y'`, `metrics.k < v`,
  `tags.t = 'v'`, `LIKE`), plus `run_view_type` (ACTIVE_ONLY vs ALL —
  interacting with soft-deletes), `order_by`, and pagination. NEGATIVE
  CONTROLS REQUIRED: a non-matching filter returns empty (a ratchet that
  counts passing steps passes happily with an ignored filter).
* **Conformance ratchet:** a test lane drives the REAL `mlflow` Python
  client (`mlflow-skinny`, version PINNED in the lane's pip install —
  unpinned latest makes a counts-only-up ratchet drift with upstream)
  through the canonical workflow (create experiment → run →
  params/metrics/batch → search → artifacts). The lane counts passing
  workflow steps (only up). Lane + path-filter wiring named at slice-2
  time (the repeated repo failure: new test files matching no lane glob).
* **Cross-tenant wire negative:** foreign experiment_id/run_id returns a
  uniform MLflow-native `RESOURCE_DOES_NOT_EXIST` — never a distinguishing
  403 that confirms id existence; search silently excludes foreign tenants.
* Fail-closed: gate off ⇒ 404 on every route (negative control test).

=== Slice 3 — MLflow registry wire (gate OFF)

* registered-models create/get/search/delete; model-versions
  create/get/search/delete; aliases set/delete/get — lowering to
  `CatalogModelRegistryService` (create_registry / apply_mutation /
  resolve_alias_binding).
* Stage transitions rejected with the alias pointer (mapping table).
* Conformance: real-client registry workflow + the design's
  duplicate-version-fails / alias-history-preserved assertions.

=== Slice 4 — Artifacts + datasets

* Real MLflow clients do NOT fetch artifacts via `/api/2.0/mlflow/*`:
  the tracking server returns `artifact_location` (e.g.
  `mlflow-artifacts:/<exp>`) in experiment/run payloads and the client
  resolves it against the tracking host's *proxy* routes under
  `/api/2.0/mlflow-artifacts/*`. Slice 4 therefore mounts that route
  family too and populates `artifact_location`/`artifact_uri` in every
  experiment/run response — without it the slice-2 conformance step
  "artifacts listing" 404s by construction.
* `log-artifact` / list-download as OCI descriptors under DrPathBuilder;
  run dataset inputs recorded as name+digest lineage entries.
* Conformance: artifact round-trip digest-stable across relocation.

=== Later (separate TD if pulled forward)

* OpenLineage import/export over the same producer/input lineage.
* MLflow 3.x llm/datasets extensions; serving integrations (out of scope).

== Flip precondition (opt-in → default-ON)

The gate stays default-OFF until: (a) the real-client conformance lanes are
green in CI on two consecutive develop revisions, (b) load/footprint of the
tracking writes is measured on the SIFT bed (evidence ledger claim), and
(c) product signs off. Flip = its own PR (gate re-tier per the registry's
pre-GA rules).

== Out of scope

MLflow UI proxying; MLflow file-store emulation; model serving; training
execution; MLflow auth pass-through (tenant identity stays ours).

== Implementation log

* **Slice 2 (2026-09-07)**: the MLflow tracking wire at `/api/2.0/mlflow/*`
  (`src/network/rest/mlflow/`) — 16 endpoints over the RunStore port:
  experiments create/get/search/delete/restore, runs
  create/get/update/search/delete/restore, log-parameter, log-metric,
  log-batch, set-tag, delete-tag. MLflow REST 2.x shapes (string ids,
  info/data split, `mlflow.runName` tag) and the native error envelope
  (`{error_code, message}` — RESOURCE_DOES_NOT_EXIST / ALREADY_EXISTS /
  INVALID_PARAMETER_VALUE / INVALID_STATE / INTERNAL_ERROR). Tenant from
  the shared `Extension<TenantContext>` plane, never body fields;
  cross-tenant probes are byte-identical to missing-id probes. Search
  subset: params/tags = != LIKE, metrics < <= > >= = !=, ANDed;
  unparseable filters are INVALID_PARAMETER_VALUE (never silently
  ignored); non-matching filters return EMPTY (negative control pinned).
  Gate `PROXIMADB_MLFLOW_COMPAT_ENABLE` (opt-in, default OFF; registry
  row added) mounts the router in BOTH server modes. Wire tests in the
  unit lane: full workflow, tenant-uniformity, gate default. The
  real-client (mlflow-skinny, pinned) conformance lane follows as this
  slice's closing commit.
* **Slice 4 (2026-09-08)**: the artifacts PROXY family —
  /api/2.0/mlflow-artifacts/artifacts/{*path} PUT/GET/DELETE plus the
  bare-root LIST/DELETE via ?path= (listing a FILE path yields the empty
  list, the convention the client download flow relies on);
  artifact_location/artifact_uri populated (experiments default
  mlflow-artifacts:/<id>; runs mlflow-artifacts:/<exp>/<run>/artifacts);
  local-file storage under <data_dir>/mlflow_artifacts/<tenant>/...
  (traversal-sanitized, verbatim filenames, tenant-scoped; S3-backed
  repository is the tracked follow-up). Conformance 17 -> 18:
  log/list/download artifact round-trip through the real client. ALL
  FOUR SLICES IMPLEMENTED — the wave's remaining item is the flip
  assessment (conformance green across consecutive develop revisions +
  SIFT-bed load measurement + product sign-off).
* **Slice 3 (2026-09-08)**: the registry wire — registered-models
  create/get/get-by-name/search and model-versions get/search lowering to
  `CatalogModelRegistryService` (create_registry / get / list /
  apply_mutation with SetAlias); aliases set/get (`model-versions/create`
  REJECTED with the typed-contract pointer — version registration is a
  governance act through the native lifecycle API; `transition-stage`
  REJECTED with the alias pointer; registry tags/descriptions an explicit
  error, never fabricated success; alias DELETE honest-rejected pending a
  service-side RemoveAlias command). Real-client conformance extended to
  17 steps (ratchet raised): model create/get/search through the actual
  MLflow client, including the two documented rejections and the
  model-versions search (clients pass `name='...'` as a FILTER string —
  parsed; searches arrive GET+query like every read). Review round 1:
  `aliases` serialize as MLflow `RegisteredModelAlias {alias, version}`
  OBJECTS (bare strings parse into empty alias messages client-side) and
  the version projection rides the proto's `latest_versions` field;
  lowercase LIKE accepted; unsupported `order_by` explicitly rejected;
  the transition-stage message names the REQUESTED stage. KNOWN LIMIT:
  alias-set is a read-revision-then-mutate cycle — a concurrent registry
  mutation surfaces as a typed 400 "revision conflict" (no lost update)
  that MLflow clients do NOT auto-retry; one-shot failure is the
  documented behavior until a server-side compare-and-retry lands with
  the RemoveAlias command.
