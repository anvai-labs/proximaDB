== Problem

The xCatalog MLOps model registry is the durable authority for embedding
model contracts (implemented: typed contracts, immutable versions, command
mutations, tenant-scoped lifecycle APIs, generated SDKs), and its design
names MLflow compatibility as the next adapter slice. Without it:

* The ecosystem's standard experiment-tracking clients (`mlflow` Python SDK,
  MLflow REST) cannot drive the platform — every team wires bespoke tracking.
* Model registration happens through bespoke scripts instead of the MLflow
  registry workflow most ML engineers already know.
* The design's own standard pressure-test (MLflow / MLMD / OpenLineage /
  KServe / Unity Catalog mappings) remains unexercised — the mappings are
  prose, not conformance-tested code.

== Non-negotiable adapter laws (from the design authority)

0. **Scope note (review round 1):** the design authority's MLflow rows
   cover the REGISTRY only; extending the adapter to TRACKING (experiments/
   runs) is this TD's extension and requires an amendment note in the
   XCATALOG doc when slice 2 ships. To keep run identity ONE-HOME
   (mandate-19 twin risk): the RunStore document is the durable record of
   a run; when a model version registered from that run cites "source run
   identity" (the design's retained field), it MUST reference the
   RunStore's run_id verbatim — the catalog stores the reference, never a
   second copy of run state.
1. **Lower to xCatalog commands — never own another metadata database.**
   Registry operations lower to `CatalogModelRegistryService` commands
   (`RegisterVersion`, `SetAlias`, `AppendEvidence`, `RecordDecision`,
   `UpsertDeployment`) via `apply_mutation`. Tracking runs lower to a
   `RunStore` port whose FIRST implementation is the multimodal substrate
   (system-namespaced document collection under `DrPathBuilder` paths,
   tenant-scoped) — not a private table.
2. **Neither adapter owns persistence.** All durability flows through the
   substrate / catalog seams.
3. **Connectivity spine (mandate 18b):** the MLflow router is a thin
   wire-codec — auth/tenant from the shared `HeaderTrustPolicy` +
   `TenantContext` plane (never from MLflow body fields), errors through the
   shared error mapping, no hand-rolled auth.
4. **Default-OFF, fail-closed:** the wire surface is gated by
   `PROXIMADB_MLFLOW_COMPAT_ENABLE` (opt-in tier, default OFF; unset ⇒ every
   `/api/2.0/mlflow/*` route 404s). Registry row lands with slice 2.
5. **Mixed-read-safe by construction:** additive routes only; no existing
   surface changes; gate-off is indistinguishable from absent.

== Concept mapping (extends the design's standards table to TRACKING)

[cols="2,3,2", options="header"]
|===
| MLflow concept | Native mapping | Consequence
| Experiment | Tenant-scoped experiment record (RunStore) | Stable `experiment_id`; delete = soft (lifecycle marker), matching MLflow semantics.
| Run | Producer execution + typed lineage entry | Run identity retained on model versions (design: "source run identity is retained").
| Param / Metric / Tag | Substrate documents/columns | Metrics queryable (relational); params reject a DIFFERING second value but are idempotent on the same value (log-batch retries must succeed); tags mutable.
| Metric history | Append-only points `(step, value, timestamp)` | Time-ordered retrieval; no in-place edits.
| Artifact | OCI descriptor (URI, SHA-256, media type, size) | Content-addressed under DrPathBuilder paths; relocation-stable identity.
| Registered model / version | `CatalogEmbeddingModelRegistry` + immutable version | Duplicate versions fail; digest identity.
| Alias | Catalog alias transaction | No data-plane record stores an unresolved alias.
| Tag (registry) | Annotation outside versions | Mutable, never affects contracts.
| Stage transition | REJECTED with alias pointer | No built-in staging/production state machine (design); MLflow ≥2.5 aliases are the native path. NOTE: stage calls still function in current 2.x/3.x clients and `models:/name/Production` URIs will hard-fail — the slice-3 real-client workflow deliberately avoids stage calls, and the rejection message points at aliases.
| Dataset (run input) | Name + content digest in lineage | Reproducibility never depends on a mutable path.
| Signature | Typed input/output contract | Embedding semantics beyond tensor schemas.
|===

== History (shipped)

* **Slice 1 (#1847).** `RunStore` port + in-memory reference + `port_conformance` battery
  (`crates/control/proximadb-catalog/src/run_store.rs`); `SubstrateRunStore` over the document substrate
  (`src/services/mlflow_run_store.rs`) — one tenant-scoped collection, per-run seq counters for metric
  ordering; concurrent metric appends all retained. Adversarial review removed a production panic on a
  poisoned lock and made absent/non-string payloads fail as corruption instead of masquerading as unknown.
* **Slice 2 (#1850, #1851).** 16 tracking endpoints at `/api/2.0/mlflow/*` with MLflow 2.x shapes and the
  native `{error_code, message}` envelope; tenant from `Extension<TenantContext>`, cross-tenant probes
  byte-identical to missing-id probes; search subset with unparseable filters → INVALID_PARAMETER_VALUE
  (never silently ignored) and a pinned non-match negative control; `experiments/get-by-name` added
  because real clients resolve `set_experiment` by name. The `mlflow-conformance` lane drives the real
  pinned `mlflow-skinny==2.14.3` client against a ratchet (`mlflow_conformance_steps_2x.txt`, only up).
* **Slice 3 (#1854).** Registry wire lowering to `CatalogModelRegistryService`. Deliberate rejections:
  `model-versions/create` (version registration is a governance act via the native lifecycle API),
  `transition-stage` (alias pointer, names the requested stage), registry tags/descriptions (explicit
  error, never fabricated success). Lesson: `aliases` must serialize as `RegisteredModelAlias {alias,
  version}` objects — bare strings parse into empty messages client-side.
* **Slice 4 (#1855).** Real clients fetch artifacts via the `/api/2.0/mlflow-artifacts/*` proxy family,
  not `/api/2.0/mlflow/*`, so `artifact_location`/`artifact_uri` are populated in every response. Local
  storage under an injective, byte-encoded tenant root (`<data_dir>/mlflow_artifacts_v2/…`,
  traversal-sanitized). Conformance 17 → 18 steps.

== Open items

* **Alias DELETE + concurrency.** Alias DELETE is honest-rejected pending a service-side `RemoveAlias`
  command. KNOWN LIMIT: alias-set is a read-revision-then-mutate cycle — a concurrent registry
  mutation surfaces as a typed 400 "revision conflict" (no lost update) that MLflow clients do NOT
  auto-retry; one-shot failure is the documented behavior until a server-side compare-and-retry lands
  with the RemoveAlias command.
* **Legacy artifact bytes.** Legacy artifact bytes require an explicit offline ownership audit and
  migration/quarantine; an automatic read fallback is forbidden because the prior lossy tenant mapping
  cannot prove which tenant owns colliding bytes.
* **XCATALOG amendment.** Law 0 requires an amendment note in the XCATALOG design doc recording the
  TRACKING extension. Not present as of 2026-10-15: `XCATALOG_MLOPS_MODEL_REGISTRY_2026_08_12.adoc`
  still says "MLflow compatibility is the next adapter slice" and covers the registry only.
* **Later (separate TD if pulled forward).** OpenLineage import/export over the same producer/input
  lineage; MLflow 3.x llm/datasets extensions (traces + logged models are TD-MLOPS-2); serving
  integrations (out of scope).

== Flip precondition (opt-in → default-ON)

The gate stays default-OFF until: (a) the real-client conformance lanes are
green in CI on two consecutive develop revisions, (b) load/footprint of the
tracking writes is measured on the SIFT bed (evidence ledger claim), and
(c) product signs off. Flip = its own PR (gate re-tier per the registry's
pre-GA rules).

== Out of scope

MLflow UI proxying (later vendored separately under TD-MLOPS-3); MLflow file-store emulation; model serving; training
execution; MLflow auth pass-through (tenant identity stays ours).
