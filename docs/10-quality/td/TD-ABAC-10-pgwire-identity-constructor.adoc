== History (shipped)

* **10a** — `Session.identity: Option<ResolvedRequestIdentity>` is built once at the startup handshake
  by the pure `PostgresProtocol::startup_identity` (trust-asserted classification; empty/`anonymous`
  is no assertion); the catalog-backed `TenantStableIdResolver` stamps the ABAC key once per
  connection.
* **10b** — the whole canonical `PortIdentity` (not just the subject) is carried from
  `try_run_select` through `SnapshotCatalog`/`DmlTableReader` to `scan_table_relational`; REST and gRPC
  stopped flattening it and dropping `tenant_stable_id`/`auth_class`. Governed reads bypass the
  subject-agnostic result cache and the enforcement-blind in-memory/bare-Parquet shortcuts.
* **10c** — three distinct bypasses found by the 2026-08-02 live-path survey, closed differently:
  pgvector search (hardcoded `ReadContext::system(...)`) now resolves the client context through
  `records_read_context` and returns an empty set on deny; **legacy single-table SELECT fails closed**
  for a governed subject (deliberately *not* enforced in place — that would be a second
  implementation of the one rule, the drift ADR-087 removes); EXPLAIN/ANALYZE now threads the subject
  (severity: EXPLAIN ANALYZE *executes*, so it was returning rows the subject could not read).

Note that still applies: pgwire trust-auth subjects are spoofable by design (`AuthClass::TrustAsserted`);
deployments gate via `HeaderTrustPolicy`. Evidence: `abac_relational_transport_e2e` boots the real
server and proves live pgwire deny-before-provision → authenticated REST provision → hot permit →
unbound-subject deny → hot revoke, without reconnect or restart.

== 10c follow-on (open)

Grow relational-pipeline coverage so the legacy single-table fallback is unreachable for governed
subjects, then delete the fail-closed guard with it.

NOTE (verified 2026-10-15): the guard is still live — `src/network/postgres/protocol.rs` refuses with
"this query shape is not supported for a policy-governed subject … run it as an ungoverned
(no-subject) connection". TD-USUB-3 (#1919) widened the governed SQL surface (native table provider
under ABAC, with `query_has_table_function` as a fail-closed guard for UDTFs) but did not remove this
fallback guard.
