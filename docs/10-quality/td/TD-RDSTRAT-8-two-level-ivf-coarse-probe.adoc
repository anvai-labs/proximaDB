== Current serving contract (2026-07-28)

The normative state is:

* compaction emits v3/A0 by default when it has a trainable clustered plan;
* the reader probes A0 by default when a v3 segment declares a non-empty A0
  extent, otherwise it uses the v1/full-region path;
* unset configuration uses
  `nprobe = ceil(sqrt(ivf_cells_total) * nprobe_multiplier)`, with multiplier
  `2.0` (raised from `1.0` by TD-SEARCH-3 S5 to hold the recall ratchet), minimum `3`, and no configured maximum beyond the cell count;
* `PROXIMADB_PAX_WRITE_A0_TRAIN=0` and
  `PROXIMADB_PAX_READ_COARSE_PROBE=0` disable the write and read sides;
* unknown/legacy layout, missing A0, or a safe fallback condition never assumes
  probing; the durable `ivf_*`, region-byte, fetch-round, and fallback telemetry
  proves which route ran.

== History (shipped)

*Problem.* Compaction already computed `cells ≈ N·dim / IOP_target` (PCA → k-means → Hilbert-ordered) but used
them only to order rows and discarded the model, so Region A ranked every row and Region B planned from scattered
survivors. The real cliff was a chooser between more ranged GETs and O(N) whole-region bytes (SIFT128 single segment:
9 GETs/q at 100k, 51 at 1M); Region A itself is an unconditional O(N) cold fetch (~160–240 MB/query projected at 10M).
`M` (8→10 GETs over 100→10000) and `k` tuning (50–54) were measured and ruled out as fixes.

*Design decisions that still apply.*

* *Host = SST layout, not a new engine.* A code review falsified NOVA's claimed substrate (stub hierarchical stats,
  full-scan staged filtering, no region/coalescing machinery, engine choice immutable per collection); SWIFT is
  self-marked deprecated/incomplete. The feature needed a *layout*, not an *engine*.
* *Region A0 persists the compaction plan* (PCA model, centroids, per-cell A/B/D extents, rank params) inside the
  one atomic object; written only by compaction, so existing collections upgrade without migration. The cell count
  stays IOP-derived; `sqrt(N)` is rejected (an in-memory CPU balance, not cloud range economics).
  (Layout versions were later collapsed into one `SEG_LAYOUT_VERSION = 1` whose header declares the A0 extent —
  see TD-PAXRG-1.)
* *The adaptive radius rule is rejected as a correctness guard:* it compared a PCA-space lower bound with a RaBitQ
  approximate distance (different metric and error model; no cosine/dot generalization). `nprobe` comes from
  metric/dimension/distribution eval profiles; exact mode probes all cells.
* *Lesson — waves, not sums:* cold latency ≈ rounds × RTT + per-round ceil(GETs/pool) × RTT + compute; parallelism
  moves latency only, never GET billing.
* The budget is per segment; a collection with F live segments pays ~F times, so GET-budget compaction stays in the gate.

*Evidence:* ledgered `nprobe_sweep_trained_1m` held recall 0.986–0.987 with 81.4 vs 108.5 GETs/query and 92 vs 144 ms
against the unprobed control (#1210/#1234).

== Open

=== PR-C2 delta (controls default OFF) (trace-derived control and Region-A layout proof, rev 3.4)

PR-C1's full SIFT1M trace separated the v3 request budget into search control,
footer metadata, Region A, Region B, and Region D. It showed that the v3 probe
moved bytes but paid three small control reads per file and one Region-A read per
selected cell. PR-C2 tests three independently gated reader changes:

* a bounded prefix range supplies the prefix, A0, and RaBitQ parameters when
  their extents fit, without moving the fixed-offset header contract;
* small search-control/footer invariants may populate the byte-budgeted cache
  even though the probe never fetches the complete Region A; and
* `ObjectRangeCoalescePolicy` merges selected Region-A extents across a bounded
  gap, retaining exact selected slices so over-read cannot broaden ranking.

The release-profile 100-query SIFT1M proof retains the combined 64 KiB prefix +
split metadata cache + 1 MiB Region-A gap (4 MiB maximum range). Recall is
unchanged: `0.985` single-file (`nprobe=6`) and `0.982` four-file (`nprobe=3`).
GETs/query move `33→30` cold and `24→19` warm single-file; `75→65` cold and
`62→44` warm four-file. Under `20×GET + 5×MiB`, score improves 6.1–24.0%.
A 4 MiB gap is rejected as non-robust: it buys at most one additional four-file
warm GET while adding 3.59 MB/query and worsening the single-file cold tail.
See `RDSTRAT8_IVF2_LAYOUT_COALESCING_SIFT1M_2026_07_22.adoc` and evidence claim
`rdstrat8_ivf2_layout_coalescing_sift1m`.

The trace also identifies the next independent term: Region B still consumes
`22–42` GETs/query. Any successor work must optimize survivor-run geometry at
fixed recall/`nprobe`; file count remains the collection-level GET knob.

=== Deferred: spill

**Spill (deferred):** boundary rows with `d_2nd/d_1st < τ` could get their
   **Region-A code only** duplicated
   into the runner-up cell. A spilled code must carry its original global row ordinal so a
   hit addresses the one Region-B/D row; implicit code-position→row mapping is no longer
   valid for that cell. The mapping bytes and duplicate-candidate dedup are charged in the
   gate. B/C/D are never duplicated. No spill environment gate is currently
   registered; file one only with an implementation/evidence PR.


== Open questions (narrowed from rev 1)

1. Does the existing `k = N·dim/IOP` remain optimal when Region A and B have different
   bytes/row? Derive the default from the combined measured probed bytes, then sweep around it.
2. Which model fields are minimally sufficient for stable query projection and future reader
   compatibility? Version the numeric contract and checksum the directory.
3. Spill necessity: only if representative recall misses at a commercially acceptable fixed
   `nprobe`; duplication must be charged to persisted bytes and compaction cost.
4. At 100M, does a second directory level beat larger cached A0 plus SIMD centroid rank? File
   only after the one-directory design is measured; do not pre-commit a hierarchy.
