== History (shipped)

Finding: ProximaDB passed **6/43** ClickBench queries vs DuckDB 35/43, and **37/37 failures were the same error**
(`No field named advengineid. Valid fields are hits."AdvEngineID"`): unquoted identifiers kept their declared case
instead of folding per ANSI/PostgreSQL. They failed at plan time (~10 ms), so it was conformance, not perf.

Decision: **fold on miss at resolution, not a parser rewrite.** Exact/declared-case resolution always wins;
only a failing unquoted lookup falls back to a *unique* case-insensitive match (ambiguous variants stay strict
and error); quoted identifiers stay case-exact. So every previously working query is byte-identical. Pieces:
`InMemoryCatalog::lookup_table` + `Scope::resolve_*` (frontend); DataFusion scan lowering retries the folded
provider name and `RExpr::Column` lowers via `Column::new_unqualified` so the declared name is never re-folded;
`case_repair_sql_for_datafusion` rewrites unique-match unquoted identifiers into quoted declared form on the SQL
fallback path (all-lowercase schemas short-circuit).

Evidence: `tests/ident_case_fold_e2e.rs` (CamelCase Parquet fixture with ClickBench q02/q03/q05/q08 shapes,
native `CREATE TABLE CaseTbl (ColMine INT)` round-trip, kill-switch).

== Open: verification target

Re-run the ClickBench ledger (default config): ProximaDB **≥35/43** (DuckDB parity), with the 37 case-fold failures
gone; TPC-H (22) / TPC-DS pgwire ratchets unchanged. The one real passing scan query before the fix (q01) ran
706 ms (DF) vs 99 ms (DuckDB) — a separate, smaller perf item once conformance is confirmed.
