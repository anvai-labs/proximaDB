== The finding

The item-9 census DISSOLVED most of the quantization "duplication": the model/types crate pair is a
deliberate contract/model split (not twins), and the nova/optimizer/rl_planner enums are distinct
concepts (engine config vs RL action space). The REAL residual hazard is the NAME: two sibling
foundation crates export `QuantizationLevel` meaning different things, so a bare
`QuantizationLevel` at any import site is ambiguous, dual-import sites must alias, and a future
`use` fix can silently swap the vocabulary enum for the strategy enum (or vice versa) with no
compile error at sites that import via re-exports.

== Direction

1. **Rename the MODEL crate's enum** — EXECUTED as `QuantizationLevel` → `QuantizationScheme`
   (~166 token sites across 15 code files + this TD). Name selection was empirical: the TD's
   original proposal `QuantizationMethod` was abandoned (the types crate's dispatch trait,
   re-exported by the model crate); the second candidate `QuantizationStrategy` was abandoned
   after adversarial review found two pre-existing root-crate bindings of that name — and
   found the first attempt's justification ("unclaimed"; "the crate's own docstring already
   called it that") FALSE: the docstring line it cited was this rename's own edit. Correction
   recorded here deliberately: decision records must not carry manufactured evidence.
   `QuantizationScheme` was then verified unclaimed by workspace grep before adoption.
   "Level" stays with the types crate's precision ladder — the wire vocabulary, unchanged.
   The wrapper `UnifiedQuantizationLevel` and its field `level_type` are EXPLICITLY DEFERRED
   (no name collision once the enum is renamed; cosmetic churn).
2. **Clean break, no deprecated alias**: a `pub use QuantizationMethod as QuantizationLevel`
   alias would resurrect the exact collision this TD removes (both crates exporting the bare name
   again). Pre-GA renames in this repo are clean breaks (env-gate registry precedent); fix all
   consumer sites in the same, single-purpose PR.
3. **Mechanical-only PR**: rename + imports, zero behavior change, no variant reordering. Gate =
   `cargo check --workspace` + the feature lanes the census sites live behind
   (`experimental-turboquant` gates a variant) + `cargo check -p proximadb --tests` (test-file
   literals — the struct-field PR lesson).

== Non-goals

Merging the two enums (they are different concepts — precision ladder vs strategy config);
touching the nova/rl_planner enums; any behavior or serde-representation change.
