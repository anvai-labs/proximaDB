== History

Rate limiting is three separate things with different liveness: pgwire request limiting (live,
`PROXIMADB_PGWIRE_RATE_LIMIT_RPM`, keyed on the real peer), the auth failed-attempt budget (live,
per-principal), and REST request limiting — which was **certified dead code**: `[network.rate_limit]`
parsed into a field nothing read, `RateLimitConfig::default()` carried `enabled: true` with a green test
asserting "secure by default", and the doc example implied use. Mounting became sound only after
TD-TENANT-4: keyed on a client header it would have been evadable *and* weaponizable (spam a victim's
address to exhaust their bucket).

Shipped: mounted inside auth/tenant (accounting aligns with the authenticated principal), same
`production(rpm, rpm)` shape as pgwire, keyed on the observed client address; four tests drive the real
middleware (429 envelope, `/health` exemption negative-controlled, per-IP isolation, gate truth table).
`RateLimitLayer` implemented no tower `Layer` at all and was deleted.

Decision recorded: **`[network.rate_limit]` section KEPT, annotated** — removing it is a config-compat
break, and its parent `NetworkConfig` is itself unread by the boot path; if `NetworkConfig` is ever
resurrected, the section becomes the config rung beside the env gate and the annotation comes off.
