== Problem

The v1 proto package is NOT generated: `build.rs` regenerates only the
self-contained `proximadb.v2` package, and `proximadb.v1.rs` is hand-maintained
(the comment in build.rs says this is deliberate, to protect hand-maintained
serde impls on v1 types). Nothing in CI compiles the v1 `.proto` files against
the Rust mirror:

* `make proto-check` = `cargo check -p proximadb-proto` + Python contract
  tests — it checks the mirror *compiles*, not that it *matches* the `.proto`.
* The descriptor-byte-equality drift gate pairs only protos that have
  committed generated stubs — v1 has none.

Consequence: a field added to a v1 `.proto` but not to the mirror decodes
(binary wire) to `None`/default silently; a field added to the mirror but not
the proto is dead code. Both directions are invisible to every gate.

== Live instance (found by the #1724 fresh-agent review)

`proto/proximadb/v1/catalog.proto` declares `OltpCatalogConfig oltp = 17` in
the `CatalogConfig` oneof (fields 10-16 + 17) — while the hand-maintained
mirror's oneof covers tags 10-16 only and has no `OltpCatalogConfig` struct at
all. A binary-wire catalog config carrying field 17 decodes to
`config: None` today. (The live REST ingest path is JSON/serde, where the
mirror's serde derives are the authority, so the practical blast radius is a
binary-gRPC future — but that is exactly the direction the v2 push is going.)

The same review also corrected a mechanism claim this family had been making:
removing an enum value does NOT make prost reject the value on binary decode
(the `catalog_type` field is a raw `i32`; unknown values pass through), and
reserving a oneof field does NOT error on decode (unknown tags are skipped and
retained). Rejection for the retired Hive arm happens at the JSON/serde
boundary (unknown-variant hard error) — comments in
`proximadb.v1.rs` now say so.

== Candidate fix (pick one, measure maintainability first)

1. **Round-trip conformance test**: a small test that, when `protoc` is
   available, parses `proto/proximadb/v1/*.proto` descriptors and asserts the
   mirror's `#[prost]` tags/field names per message match (mirror→proto
   direction catches invented fields; proto→mirror direction catches missing
   ones). Skipped gracefully when protoc is absent (mirrors the v2 regen
   gate's env pattern).
2. **Generate the structural half**: keep hand-maintained serde, but generate
   the prost structure from the `.proto` into a check-in file and diff it in
   CI against the mirror's prost-derive surface (heavier; only if (1)
   proves insufficient).

== Implementation (2026-09-02)

Candidate fix **1** landed — option 2 (generating the structural half) was not
needed: the source-scan approach proved sufficient and stays hand-maintained
alongside the mirrors it guards.

* **Guard**: `crates/foundation/proximadb-proto/src/proto/v1_conformance.rs`
  (`#[cfg(test)]`, runs under CI's unit-test job which installs
  `protobuf-compiler`; skips gracefully when `protoc` is absent). It compiles
  `proto/proximadb/v1/*.proto` + `proto/proximadb/explain.proto` with `protoc
  --include_imports`, decodes the `FileDescriptorSet`, parses ALL five v1
  mirrors (`proximadb.v1`, `.cluster.v1`, `.streaming.v1`, `.explain.v1`,
  `.v1.ranking`) for their `#[prost]` attributes / derives / enum discriminants
  / name tables, and compares both directions per message: field names, tags,
  kinds, cardinality, map-ness, oneof member tags, enum wire-name →
  discriminant maps. Unparseable mirror syntax is a fail-loud anomaly, never a
  silent skip. Wire-compatible leniencies (documented in the file): a proto
  oneof may be modeled as same-tagged plain fields; message/enum Rust-name
  renames (RbacAuditEvent vs RBACAuditEvent) are not wire drift.
* **Ratchet**: current findings are diffed against the checked-in ledger
  `src/proto/v1_conformance_known_drift.json` — new drift fails, fixed drift
  fails until the ledger is shrunk (regen:
  `UPDATE_V1_DRIFT_SNAPSHOT=1 cargo test -p proximadb-proto --lib
  v1_conformance`). The ledger doubles as the burn-down backlog.
* **Live instances fixed in the same change**:
  ** `OltpCatalogConfig` message + `CatalogConfig` oneof arm `oltp = 17` +
    `CatalogType::{OltpPostgres,OltpMysql,OltpSqlite}` (10/11/12) — the filed
    instance. The REST construction arm declines loudly (TD-CAT-10 retirement)
    instead of constructing: the wire shape exists so binary configs decode
    losslessly, not to resurrect the adapter.
  ** `SqlValue` oneof arm `jsonb_value = 9` (bytes) + the custom serde
    (`serde_impls.rs`) round-trip + the ~20 exhaustive-match fan-out sites,
    each extending its local `BytesValue` convention.
* **First-run census**: the guard found 49 pre-existing findings; 8 were fixed
  above and the remaining **41 were burned down in the same change — the ledger
  now sits at zero** and any future finding is new drift:
  ** Never-mirrored messages/enums added to the mirror from their protos:
     the graph.proto PULSAR/QUASAR distributed-engine block (13 messages, 5
     enums incl. `GraphEngineType`), the collection_types.proto server-side
     embedding block (`EmbeddingConfig`/`EmbeddingRoute`/`ByoEndpoint`/
     `ByoAuth`/`MtlsCert`) plus `CollectionConfig.embedding_config` (tag 25)
     and `DocumentCollectionConfig.use_jsonb` (tag 8).
  ** `CollectionConfig.permitted_principals` was a real mirror bug: the prost
     attr said `message` over a `Vec<String>` (proto: `repeated string`) —
     fixed to `string`.
  ** The 6 mirror-only `assemble_*` messages (plus the whole generated
     `ContextService` client/server built on them) were **deleted**: absent
     from every proto, zero references anywhere in the workspace — dead wire
     types left behind when the protos dropped them (pre-GA no-back-compat
     applies). This is the guard's "invented types" direction doing its job.
  ** 3 of the "missing" messages were parser false-positives: one-line
     `pub struct X {}` units (prost's rendering of empty messages) — the
     guard now recognizes them.
* The guard caught a variant-name typo (`Polar` vs `Polaris`) introduced in
  this very PR before review did — the class of mistake it exists for.

A fresh-context adversarial review (2026-09-02) hardened the change; its
findings and dispositions:

**Round 2 (high effort, 2026-09-03) — 10 findings, all dispositioned:**

* **Writer emitted tag 8, not the declared tag 9** (MAJOR):
  `proxima_to_sql_value` encoded `ProximaValue::Jsonb` as `BytesValue`, so no
  write path ever produced the `JsonbValue` the canonical decode expects —
  the filter fix was unreachable. The writer now emits `JsonbValue`
  (mixed-read safe within the lineage: pre-PR segments carry tag-8 bytes that
  still decode via the legacy arm; the tag-9 variant did not exist before
  this PR). Pinned by `jsonb_writes_the_declared_tag9_variant`.
* **Six live wildcard fan-out misses** fixed (search-executor result metadata
  collapsed JSONB to `""`; nova string column, SST text-column support,
  document aggregation equality, document-block sort keys, timeseries tags
  dropped it) — each now decodes via the canonical representation.
* **Observability attribute filters**: the `JsonbValue` arm fed raw
  MessagePack through `from_utf8_lossy` (mojibake) into `key:value`
  matching, silently dropping matching logs — now decodes to compact JSON.
* **serde `jsonb_value` tagged form** now commits only for a SINGLE-KEY
  object whose value decodes — sibling keys can no longer vanish.
* **Guard: services were unguarded** — the exact drift class that motivated
  the TD (the deleted `ContextService` was found by luck, not by the gate).
  The guard now compares declared services (name + rpc set, snake-cased)
  against the tonic stubs, both directions. First run caught 7 real GraphService
  rpc gaps (the PULSAR/QUASAR messages were mirrored but their service
  methods were not) and the never-written `RankService` stub — all fixed by
  splicing in fresh `tonic-prost-build` output.
* **Guard: enum tables validated per-table** — a value must appear in every
  PRESENT name table; previously either table sufficed, letting a missing
  `from_str_name` arm hide behind a complete `as_str_name`.
* **One decode-or-binary helper** (`ProximaValue::from_jsonb_or_binary`)
  replaces the four copy-pasted match arms; the Arrow Flight codec renders
  compact JSON instead of a Debug byte dump; `MetadataValue` (which feeds
  equality) and its streaming.rs duplicate decode instead of emitting a
  `[jsonb]` placeholder.
* **Documented, not code** (mirror fidelity ≠ feature implementation):
  ** `CollectionConfig.embedding_config` (tag 25) and
     `DocumentCollectionConfig.use_jsonb` (tag 8) are contract-declared but
     feature-unimplemented — the proto fields pre-date this PR; the mirror
     now carries them faithfully. Wiring them is separate feature work.
  ** `permitted_principals`'s attr fix (`message` → `string`) changes the
     binary encoding of non-empty values — the OLD bytes were
     proto-nonconformant (prost wrapped each string in a StringValue
     submessage); JSON (the live REST authority) is unaffected, pre-GA
     no-back-compat applies.

**Round 19 (2026-09-05, entity-boundary review) — degradation contract
pinned + narrated:**

* The v2 entity boundary now routes through the canonical model
  (`TypedValue → ProximaValue → graph PropertyValue`, and reverse). The
  graph property model is deliberately neutral (string/int/double/bool/
  bytes/array/object/vector) — richer variants cannot carry their type
  marker through it without a graph-format change (which would require
  the #8 mixed-read migration discipline). The exact read-back
  degradation is therefore a CONTRACT, now pinned by
  `graph_boundary_degradation_table_is_pinned`: Uuid/Ulid → BinaryValue
  (value bytes survive), Timestamp/TimestampTz/Date/Time → IntegerValue,
  Decimal/Symbol/SparseVector → TextValue (canonical JSON for sparse).
  Mixed-read note: a 16-byte blob stored by v0.3.0 decoded as UuidValue
  under the old heuristic; it now decodes as BinaryValue.
* The write side now FAILS LOUD on genuinely-malformed input (UUID of
  ≠16 bytes, IsNull(false), out-of-range Int8/Uint8, undecodable JSONB)
  — requests v0.3.0 silently degraded now return invalid_argument. The
  old silent-drop behavior was the silent-Ok(failure) anti-pattern.
* SparseVector joins the canonical-text contract (sorted keys, round 18
  rule applied at the last unsorted seam).
* MapValue round-trips as StructValue (the graph model does not
  distinguish Map from Struct — the write-side lowering comment states
  this); nodes carrying present nulls are now emitted as IsNull(true)
  instead of omitted (rounds 11-12 rule at the read boundary).
