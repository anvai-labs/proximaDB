== History (shipped)

*Problem.* Region D's per-block framing (~1.2 KB fixed per block) amplified catastrophically at small block
targets: a 400-byte target produced ~400 micro-blocks whose *pruned* fetch was 1.25 MB for a 38 KB-Parquet-equivalent
dataset; even at 64 KiB blocks, per-granule framing, not stripe encoding, was the dominant byte term. Region C
(exact f32) was still an in-block stripe.

*Decision (shipped).* Parquet-style row groups for Region D plus a hoisted Region C, because the PAX segment serves
the vector+OLAP wedge (pure relational stays Parquet, ADR-033):

* An RG *is* an Olap-framed footer block entry (in-block rgdir suppressed, stats in the footer's `StatsKind::MinMax`
  payload with the per-RG OID chunk address) — zero schema change; old parsers skip stats wholesale.
* `RG_TARGET_MIN_BYTES = 256 KiB` floor makes the micro-block pathology structurally impossible.
* Region C = hoisted raw-f32 region in the A/B ordinal space; activation stays behind the `pax_f32_tier` opt-in.
* RowDirectory is gone from RGs — the OID resolver (TD-DELVEC-1) is the sole point-lookup authority, and
  `with_rg_layout(true)` auto-enables it (the resolver left the `cold-deletion-vectors` feature gate).
* ANN top-k fetches only per-RG OID chunks; A0 coarse cells never straddle RGs; DataFusion's ranged arm reuses the shared RG zone-prune.
* `finish_coalesced_spill` is a twin writer, pinned byte-identical by `spill_and_memory_rg_writers_produce_identical_footers`.

*Design decision that still applies (single-layout collapse):* nothing was released, so the v1/v3/v4 sprawl was
deleted for ONE `SEG_LAYOUT_VERSION = 1` whose header always serializes region extents (zero = absent) — region
presence is declared by the header/footer, never a version or flag. The version byte is RESERVED for the first
post-GA successor layout; reintroduce parse arms + freeze tests then, not before.
*Lesson:* the paired-evidence cohort gate rejected every `outcome=unknown` pair with caches disabled — a
pre-existing classification bug, fixed in closeout (`VectorCacheOutcome::from_snapshot` policy-aware Bypass).

*Evidence (Phase G):* SIFT1M N=100k recall@10 = **0.9896**, byte-identical to the legacy arm
(`tests/sift_pax_recall_ratchet_test.rs`, both arms); at-rest **80.3%** of legacy bytes
(`rg_layout_at_rest_is_not_larger_than_legacy_blocks`); `v4_floor_kills_microgranule_amplification`
(< ¼ of micro-block bytes); OID-chunk top-k fewer bytes at GET parity +2.

== Open

Still open (measure-then-decide or independent tracks): wedge-payload at-rest
promotion vs export-duplicate; RG target-size raise (post-flip traces);
RG-granular compaction rewrite; HELIX/SWIFT format ports (bespoke writers —
a per-engine format decision, not configuration); TD-CACHE-10.

`PROXIMADB_DF_PAX_READER` stays default-OFF with explicit attribution-poisoning
warnings on both gate definitions (the slice-2 route-dispatch design record lives in TD-OLAP-1).

== Per-collection config

`pax_rg_layout:on|off` (flush and compaction, via `resolve_pax_rg_layout`) —
precedence tag > env > default (now ON). Region C rides the existing
`pax_f32_tier:on` under rg_layout.
