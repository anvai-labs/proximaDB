== Problem

ADR-098 D4.1 assigns one encoding per metadata layer. Several persisted metadata formats sit
outside that table and have no owner. The SST JSON manifest (`src/storage/engines/sst/manifest.rs`)
was deleted in TD-PAXMETA-1 PR-A. The ones listed under Component remain. Each has its own
framing, its own version rule (or none) and its own recovery reading. The 2026-11-19
checkpoint's STOP list named them for retirement, but no TD carried them.

== Fix

. **Census.** Inventory every persisted metadata format, meaning anything that is written to
  disk or object storage and read back to decide what data exists or how to read it. Do not
  stop at the list above. For each format record the writer, the readers, the version or magic
  marker (if any), whether recovery depends on it, and its at-rest object count. Data formats
  (PAX, Parquet) and transport encodings are out of scope.
. **Target.** Map each format to one of the ADR-098 D4.1 layers: the L0 envelope (TD-SPINE-1)
  for catalog-like records, L1 PXCD for collection-level facts, or the Iceberg seam for
  interop. A format with no layer is either retired or the census explains why it is a cache
  and not authority (for example the warm-set manifest, which is a hint and may be lost).
. Migrations follow the pre-GA rule: a clean break with version bytes kept and fail-closed
  reads, documented in the PR that makes it.

== Acceptance

* The census is committed (in this TD or a linked doc), with one row per format and the fields
  above, verified against develop by file path.
* At GA, at most two persisted metadata formats exist besides the Iceberg export, counting the
  L0 envelope and L1 PXCD. Any exception is named, with the reason it is not authority.
* Each retired format has its decoder deleted, not left behind a flag.
