== History (shipped)

**Why delete:** a generic vector/graph SDK should not own a code-domain AST parser (ADR-029 D2). The defect was "dead AND
advertised", not duplication: of 23 registered languages, 12 raised `TypeError`, 10 were stubs and 1 worked, while the package
advertised "20+ languages". The neutral model (18 `CodeSymbolType` and 18 `CodeRelationType` members) already lived in victor
verbatim. **Co-design cost term:** the legacy path emitted class plus method bodies (2.0x the input chars) and ignored
`max_chunk_size` (10.6x over budget), so it inflated **KEU and KSU ~2x per indexed repo**. Compute is unchanged (same tree-sitter parse).

* **S0–S3:** the suite went green behind a declared skip, R1–R8 were written red-first, and the seam defects were fixed. R6:
  `include_tests` was never forwarded. R7: `.tsx` was forced to `typescript`, which halved its symbols. R8: fallback chunks were
  unlabelled; they are now `chunk_type="code_fallback"`. Two hidden defects also surfaced: unrecognised files were silently dropped,
  and relations were never surfaced, so the code knowledge graph had nodes and no edges. **Lesson: a config field read by nobody is
  indistinguishable from one left unset** (same as TD-CHUNK-5).
* **R5 offset basis:** the code path publishes UTF-8 **byte** offsets, while text strategies publish **character** offsets in the
  same field. An additive `metadata["offset_basis"]` marker fixes this; absence means legacy, with no flag day. Only a non-ASCII
  fixture can tell the two apart.
* **S4:** `code.py` went 4,589 -> 561 lines (~6,430 removed in total). The neutral model stays in-tree for import-safety (values
  verified 18/18). The extension map was derived (59 -> 27), then re-widened by 13 test-guarded aliases, ending at **40 extensions
  and 18 languages**. Without the extra, chunking now fails loudly. `tests/chunking/` reached 684 passed / 0 skipped / 0 failed.
* **S5:** `SUPPORTED_SURFACE` gained chunking rows (document chunking Supported, code chunking Beta, later Experimental). Three
  false docstring/`DeprecationWarning` claims were removed. `COVERED_WITHOUT_SYMBOLS` was conflating "symbol-less" with "not
  advertised", so the partition is now an **equality**, plus `WITHDRAWN_LANGUAGES`. **Lesson: a ratchet that only tightens in one
  direction records growth and misses retreat.**
* **Version gap (#1712):** no CI job installed `codegraph`, so the suite that authorised the delete had never run in CI. Without the
  extra it *failed* (50/52) rather than skipping, and on the published 0.8.1 it failed 30/54 (R1 failed for 15 of 16 languages). The
  fix: the extra pins `>=0.9.0`, a matching runtime guard, the suite skips while naming the installed version, and the tier dropped
  Beta -> Experimental. **Lesson: a capability claim inherits the trust level of the environment it was measured in.** Fixture lesson
  from filing the upstream bugs: a fixture that introduces a second variable (trailing `//` comments) produces a confident wrong number.

== Open residuals

* **Re-validate on a published package and gate it in CI.** The suite must pass against a released `victor-codegraph`. The filing
  required this before wiring the extra into the conformance job, because without it the job would only make the gap loud in a
  place that blocks everyone. Then revisit the code-chunking tier (Experimental) in `docs/SUPPORTED_SURFACE.adoc`.
* **ADR-029 → Accepted** is recommended in the ADR with its evidence, and deferred to the deciders.
* **Two upstream bug reports FILED 2026-08-19** against `victor-codegraph` 0.9.0 — **victor#916**
  (Rust `impl` overlap) and **victor#917** (class closing brace uncovered) — both pinned here as
  strict xfails so a fix cannot land unnoticed. Writing them re-measured both at **default** config
  rather than the tight budget the xfails use, and the defects are materially worse than the pins
  said: #916 emits **6,122 bytes for a 2,876-byte file (2.13x)** with 98% of bytes in more than one
  chunk, *and* leaves the struct's own field list in no chunk at all; #917 reproduces in
  javascript, typescript, tsx **and** java, at **any size** — a 62-byte class that fits the budget
  loses its brace too, so it is not large-symbol windowing. The xfails are `strict=True`, so they act
  as a **bidirectional ratchet**: an upstream fix makes the test xpass and *fail*, forcing the marker off.
* **`ruby` symbol extraction** is an upstream node-table gap. It sits in `COVERED_WITHOUT_SYMBOLS`
  honestly rather than being claimed. Deleting the legacy Ruby parser is a regression on paper; it was
  not one in practice, because the legacy parser raised `TypeError` on the pinned dependency. Either
  the upstream fix lands, or Ruby leaves the advertised set; do not choose silently.
* **Stored-contract note:** `document_processor.py` persists `start_pos`/`end_pos`. Readers must default to the legacy interpretation when `offset_basis` is absent.
* **Do not re-add `code.py` parsers "just for the languages victor lacks".** That reproduces the duplication ADR-029 removed. The
  languages in question (Haskell, Elixir) were stubs that returned nothing anyway.
