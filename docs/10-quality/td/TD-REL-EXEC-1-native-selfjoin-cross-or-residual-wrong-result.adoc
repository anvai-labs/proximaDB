= TD-REL-EXEC-1: Native route silently returns 0 rows for an OR-of-ANDs residual predicate spanning both sides of a (self-)join

[cols="1,3", options="header"]
|===
| Field | Value
| Status | **Done (2026-07-15).** The planner's `rebind_columns` preserves a column's existing ordinal, so self-join duplicate column names no longer collapse onto the first alias (#1011).
| Priority | **P1 (correctness)** — a *silent wrong result*
| Component | `crates/query/proximadb-relational-planner` (`push_projections` / `rebind_columns`); native route only
| Relates to | link:TD-REL-LOWER-3-pushdown-rebind-alias-sort-key.adoc[TD-REL-LOWER-3] (same fix closed its derived-table-alias case)
|===

== History

Surfaced by TPC-H **Q7** (native 0 rows vs DataFusion 4) once the typed-DATE-literal fix (#1003) let Q7 lower;
the bug was date-independent. Minimal repro: `edge ⋈ nation n1 ⋈ nation n2` plus a predicate on both
`n1.n_name` and `n2.n_name` returned 0 rows.

Decisive finding (lesson that still applies): the hypothesis (residual placement / ordinal rebase in
`push_predicates`) was **wrong**. Bisection showed any conjunct spanning both self-join aliases failed, even a
single AND, so the bug was self-join specific. `push_projections`' `rebind_columns` re-derived every
`Expr::Column` ordinal **by name** (`column_by_name` returns the first match), binding both `n_name` refs to
ordinal 3 → `col3='FRANCE' AND col3='GERMANY'` → always false. Fix: keep the ordinal when
`schema.columns[ordinal].name == name`; re-derive by name only when narrowing moved the column.

Evidence: `tests/rel_exec_1_selfjoin_e2e.rs` (Q7-shape residuals, minimal AND, Q15 derived-alias join); 112 planner unit tests unchanged.
