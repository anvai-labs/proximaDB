== History (shipped)

*Problem.* The `Catalog` trait had 40 methods, 18 with non-neutral default bodies (`max_object_id`,
`mint_collection_typed_identity`, `get_table_by_object_id` → `Ok(None)`), so "a catalog which does not mint
identity" was a representable state, and ABAC gates on `stable_namespace_id` AND `object_id`. The same gap
was fixed by hand three times (#1607, #1636, plus three live defects closed only *incidentally* by #1636).
Root cause: the trait demanded identity from HTTP shims and external metastores that structurally cannot
own an allocator, so every identity invariant was made optional until it constrained nobody.

*What shipped (#1680).*

* `CatalogAuthority`: every identity method required (`allocate_object_id` returns `u64`, not `Option`);
  implemented by `NativeCatalog` and `SystemCatalog`, not by federated adapters.
* `Catalog::identity_authority() -> Option<&dyn CatalogAuthority>` makes "federated" and "authority that
  forgot" different states; `Catalog`'s identity methods delegate through it.
* Sealed `create_table`: backends implement `create_table_inner`; the provided `create_table` rejects an
  authority returning `object_id: None`. Rust has no `final`, so `scripts/check_catalog_seal.py` (in
  `make work-commit-check` + CI layering job) is the seal. Call-site cost: zero.
* Forced-open defects: `SystemCatalog::get_namespace_by_object_id` did not exist (fourth instance of the
  omission, found by the compiler); `shared_services.rs` collapsed *no authority* / *nothing minted* /
  *authority failed* into one value, silently disabling the ADR-031 floor raise; the default backend minted
  no namespace `object_id` (filed and since closed as link:TD-CAT-9-system-catalog-namespace-object-ids.adoc[TD-CAT-9]).

Evidence: `authority_seal_tests.rs`, each test proven by neutering only its mechanism; 
`federated_catalog_without_object_id_is_accepted` guards the reverse direction.

== Still open

Item 4 of the proposed change — **collapsing the internal impls** (Native /
System / Oltp / Delta differ only in where bytes land) and retiring
`PROXIMADB_DISABLE_SYSTEM_CATALOG`, which has no stated exit criterion — is not
done. It is a persistence-strategy refactor with a different risk profile from
the trait contract, and bundling it here would have put a storage change in an
identity PR, which is the mistake this TD's sequencing note exists to prevent.

The `unwrap_or_default()` rendering at
`crates/binding/proximadb-catalog-introspection/src/lib.rs:424` also remains: it
turns a missing `object_id` into an empty string. The post-condition now makes
that state unreachable through `create_table`, so the rendering is a
defence-in-depth gap rather than a live defect.

== Related but deliberately separate

* The `unwrap_or_default()` rendering (see *Still open*) is indistinguishable from a legitimately empty
  column. Hardening it belongs with this TD's post-condition work, not with an identity PR.
* The configuration-reachable external adapters are [[TD-CAT-8]].

== Sequencing note

Do NOT bundle this with an authorization change. #1406 was an ABAC PR that carried identity
minting and caused a silent cross-tier recall collapse (`mean=0.000`) that took a bisect and a
revert to unwind (see [[TD-RECALL-2]]). Identity changes ship on their own, gated on
`vector_ann_recall_e2e`.
