= TD-SIFTCOMPACT-1: the SIFT recall ratchets measured an L0-only layout, because a swallowed compaction error made the id defect invisible

[cols="1,3", options="header"]
|===
| Field | Value
| Status | **Open.** Filed 2026-10-08, found by adversarial review of the TD-IVF2ENGAGE-1 change.
| Severity | Medium-High — no incorrect query results, but published recall/GET evidence may describe a layout the tests were not meant to exercise.
| Component | `tests/sift_pax_recall_ratchet_test.rs` (shared `collection()` helper), `src/storage/engines/sst/flush/mod.rs`, `crates/storage/proximadb-storage-common/src/compaction_override.rs`
| Related | TD-IVF2ENGAGE-1 (the sibling fix), TD-WLP-4 / ADR-061 (armed-by-default compaction), TD-VECEVAL-1
|===

== The defect

The shared `collection()` helper passed the collection **name** where the flush
and compaction-admission boundaries are fail-closed on a decimal catalog object
id (`FlushParams::get_collection_object_id` and its compaction twin). Three
things then compose:

. Compaction is **armed by default** for these collections.
  `resolve_compaction_armed(&[])` is `true` under `GlobalCompactionGate::Default`,
  because `AppendBulk` is the default storage profile and the gate's own comment
  says so: *"profile default (TD-WLP-4: `AppendBulk` — including every untagged
  collection — armed)"*. There is an existing unit test pinning
  `resolve_compaction_armed(&[])`. No SIFT test sets
  `L0_COMPACTION_ENABLED_ENV`.
. The L0 threshold is 5 and the harness batches at 20 000, so any run inserting
  ≥100 000 vectors reaches it. The default arm inserts the **full 1M** — 50
  flushes.
. `flush/mod.rs` catches the admission error, logs it at `warn!`, assigns
  `compaction_error` and **continues**: *"a compaction failure is recorded on the
  result but never fails the flush."*

So the error fired, was logged where nothing was listening, and the flush
succeeded. The tests pass because none of them asserts `compaction_ran` — the
IVF2 ratchet is the only one that does, which is why it was the only one that
visibly broke.

== Why it matters more than the bug it hid

If compaction never ran, these ratchets measured an **L0-only, uncompacted,
un-reclustered** layout — not the clustered PAX-LSM layout they appear to
exercise. That affects `sift_pax_cascade_recall_at_10_ratchet`,
its `_rg_layout` sibling, and `sift_pax_filtered_cascade_recall_ratchet`, which
are the source of the recall and GET/byte figures published in
`docs/02-guides/vector-index-selection-and-benchmarking.md` and carried by the
qa-gate `sift-pax-recall` job.

=== Confirmed by execution, and the fix is NOT one line

Minting an id in the shared helper was the obvious fix. I made that change and
ran `sift_pax_cascade_recall_at_10_ratchet_rg_layout` at N=100 000:

[source]
----
flushed 100000 base vectors
ground truth rows=50: provided/filterable=33, brute-force=17
thread 'sift_pax_cascade_recall_at_10_ratchet_rg_layout' panicked at
  tests/sift_pax_recall_ratchet_test.rs:505:5:
assertion `left == right` failed: each ratchet query must report one physical
  vector access
----

It inserted and flushed all 100 000 vectors, built ground truth, then died on the
**first query**. That is the confirmation: with a valid id, compaction actually
runs, the physical layout changes, and a query no longer reports exactly one
vector access. Before the fix the same run completes and reports
`ANN 53.97/53.97/25297445/20.90` — the published numbers.

So the defect is real AND the remediation is larger than an id: these ratchets
encode a **single-physical-access assumption** (`assert_single_vector_access`)
that a compacted, multi-segment layout breaks. Fixing the id without deciding
what the ratchets should measure converts three passing tests into three failing
ones.

The helper is therefore left as-is in that change, with the defect documented at
the site, and the decision belongs here.

== Why it was invisible

Three independently reasonable decisions compose into silence:

* **arming is implicit** — untagged means armed, so no test opts in and none
  opts out;
* **the failure is best-effort by design** — a compaction failure must not fail a
  flush, which is correct for production and fatal for a test's intent;
* **`warn!` goes nowhere** — the SIFT test file initialises no tracing
  subscriber, so `RUST_LOG=warn` prints nothing. I attempted to confirm this
  defect by grepping a run's output for the error and got zero matches, which
  looked like a refutation and was simply an invisible log.

== How to apply

. **Decide what these ratchets should measure, first.** That is the actual
  blocker, not the id. Either (a) they are meant to pin the single-segment
  cascade, in which case compaction should be explicitly DISARMED
  (`compaction:off` tag or `L0_COMPACTION_ENABLED_ENV`) so the intent is stated
  rather than achieved by an admission failure; or (b) they are meant to pin the
  compacted layout, in which case `assert_single_vector_access` must become a
  per-segment assertion and every published figure sourced from them needs
  re-baselining — the guide's table and any `BENCHMARK_EVIDENCE.toml` entry that
  cites them.
+
Option (a) is cheap and makes today's numbers honest. Option (b) is what the test
names imply and is the real work. Do not do (b) by accident, which is what
minting the id alone amounts to.
. **Then measure the delta** under whichever shape is chosen, at N=100 000, and
  record recall, GETs/query and bytes/query.
. **Assert the intent.** Each ratchet that means to exercise a compacted layout
  should assert `compaction_ran`, as the IVF2 test already does. A test whose
  premise is silently unmet is worse than a missing test.
. **Make the swallow observable in tests.** The production behaviour is right,
  but a test harness should fail loudly. Either initialise a subscriber in the
  SIFT file, or have the ratchets read `compaction_error` off the flush result
  and fail on it.
. Do not treat the id as cosmetic: `get_collection_object_id`'s own doc comment
  warns that hashing the name at that boundary would create "a second,
  collision-prone identity domain that cannot be joined reliably with catalog,
  MVCC, deletion-vector, or compaction state". Mint an id
  (`next_object_id()`), keep the human name in `CollectionConfig.name`.
