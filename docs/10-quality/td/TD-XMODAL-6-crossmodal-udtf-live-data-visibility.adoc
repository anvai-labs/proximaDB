== History

* **Symptom.** After the reachability fix, `wh JOIN vector_search(…)` and `CROSS JOIN timeseries_range(…)`
  executed over pgwire but returned 0 rows for data REST read back fine — even though the timeseries UDTF
  and REST shared the same process-global `timeseries_service()`.
* **Root cause.** Per-modality tenant scoping was not threaded into the UDTFs: timeseries REST folded
  the tenant into the collection key while the UDTF passed the raw name; the vector UDTF hardcoded
  `tenant_id = None`. Lesson: **freshness was a red herring** — the UDTFs call the same service methods as
  REST and inherit its freshness once the tenant scope matches. A second requirement: the pgwire read
  tenant must equal the REST write tenant (then `""` vs `"default"`; unified by #681).
* **Fix.** Tenant threaded pgwire → `QueryExecutionContext.tenant_id` → `prepare_dataframe` →
  `create_session_context_with_ports(…, tenant)` → UDTF constructors (`with_tenant`,
  `from_service_with_tenant`). `graph_traverse` later gained the same structural `{tenant}/{graph_id}`
  scope as the graph write path.
* **Evidence.** `tests/pgwire_crossmodal_join_e2e.rs::crossmodal_timeseries_join_returns_rest_seeded_rows`
  (REST-seeded under `X-Tenant-ID`, asserts rows and values over pgwire with matching `dbname`); unit
  tests `timeseries_range_udtf_folds_tenant_into_collection`, `vector_search_udtf_forwards_tenant_to_search`.
