== History

The default-ON OLAP delta merge called `changed_oids_since` (a canonical-WAL change-feed scan since the
snapshot LSN, twice for ADR-031 dual-keyed tables) for every table on every DataFusion query. For read-mostly
tables the delta is empty, but the scan scaled with WAL size: `open_ms ≈ wall_ms`, ~99% of every query.
The fix (#890) keeps a per-collection high-water, bumped atomically on append, so an unadvanced table returns
empty in O(1); #893 seeds it from recovered entries on `FramedTableWalAppender::open`. Worst case = the original scan.

Decisive finding (still applies): the long-assumed "single-threaded join build" gap was a **misattribution**:
the join was 8–23 ms (<1% of wall) even at SF=0.1. Only a per-query trace (`open_ms` vs `compute_ms`) found it;
`table_open_cache` could not help because it caches footer discovery on a path the merge runs *after*.
A2 NDV (#886) stays: correct, just not the lever.

Evidence (TPC perf ledger, default config): DF median 604 ms → 7 ms at SF=0.01 and 5762 ms → 12 ms at SF=0.1,
faster than DuckDB (10/15 ms); `open_ms` ~1780 ms → 0–1 ms.
