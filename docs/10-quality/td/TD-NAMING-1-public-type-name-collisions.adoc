= TD-NAMING-1: Public Rust type names are defined many times — ratchet now, burn down in batches
:status: Open
:date: 2026-11-06
:tags: [code-health, naming, solid, duplication]

== Problem

Baseline 2026-11-06 (`scripts/count_type_name_collisions.py`): 792 redundant definitions across 591 names.

The same `pub struct` / `enum` / `union` / `trait` name defined at several
sites causes two harms:

* **Silent duplication of a primitive** — a fix lands in one copy while the
  others keep the bug (mandate #12: "silent duplication of an existing
  primitive").
* **Wrong-type footgun** — once two same-named types are reachable from one
  module, an obvious-looking signature compiles against the wrong one. Found
  in #2443: `trait_components::path_resolver` re-exports the storage-ports
  `StorageAssignment` while call sites needed the PROTO `StorageAssignment`;
  a helper typed `&StorageAssignment` failed with "expected
  `StorageAssignment`, found a different `StorageAssignment`".

== Counting rules

* Bare `pub` only — `pub(crate)` / `pub(super)` types cannot collide across
  a crate boundary or be re-exported.
* Sites are MODULE SCOPES: same-named types in different modules (even of one
  file) collide; same-named items in ONE scope count once — rustc only allows
  that for mutually exclusive cfg alternatives, so the collapse is sound and
  an always-true `#[cfg(all())]` cannot hide a collision across modules.
  Same-named cfg'd `mod imp { .. }` alternatives share a scope path.
* Not counted: `type` aliases; generated protobuf; test code (`tests/`,
  `benches/`, `examples/`, `*_test(s).rs`, `tests.rs`, out-of-line
  `#[cfg(test)] mod x;` files, `#[cfg(test)]` / `#[cfg(all(test, ..))]`
  modules and items — `cfg(any(test, ..))` ships and is counted); comments and
  string/char literal contents (masked before matching, using the
  capability-facade ratchet's lexical rules).
* `git ls-files` enumeration; deleted-but-indexed files skipped; an
  unreadable tracked file fails closed.

== Known gaps (deliberate — see Follow-ups)

* **Re-exports are not measured.** The #2443 `StorageAssignment` case is a
  RE-EXPORT collision (proto definition vs a storage-ports definition
  surfaced by `pub use`); the guard does not see it. A regex re-export metric
  was built and dropped in #2445 review: glob re-exports, `as` renames,
  proto mirrors that are legitimately re-exported, and module-level `cfg`
  all need real path resolution.
* Macro-generated definitions are not seen.
* Out-of-line module handling is one level deep: a `#[cfg(test)] mod x;`
  file is excluded, but not modules it declares in turn, nor a `#[path]`
  target; out-of-line cfg alternatives (`#[cfg(unix)] mod unix;` /
  `#[cfg(windows)] mod windows;`) each count.
* Concurrent burn-downs of the SAME name in two PRs can leave develop red
  (both lower the same baseline line identically; the merged tree is lower
  still) — the same property as the capability-facade ratchet; re-baseline
  in a follow-up.
* Local runs see only tracked files (`git ls-files`); a not-yet-added file
  is checked in CI.

== Decision

1. **Ratchet first, per name, both ways.** CI fails if any name's count rises
   above its baseline, and if the total falls without the baseline being
   lowered in the same PR. `--mode baseline` refuses to RAISE any name. No
   big-bang rename (it would conflict with every open PR).
2. **Naming rule for new types:** a type that crosses a crate boundary or is
   re-exported carries a qualifying name — `ProtoStorageAssignment`,
   `SstCompactionConfig` — never a bare name already taken elsewhere.
3. **Burn down in themed batches**, lowering the baseline in each PR, largest
   clusters first (`OperationType`, `FilterOperator`, `TransactionState`,
   `JoinType`, `BloomFilter`): CONSOLIDATE where the copies are one concept,
   RENAME where they only share a word.
