= TD-NAMING-1: Public Rust type names collide across crates — ratchet now, burn down in batches
:status: Open
:date: 2026-11-06
:tags: [code-health, naming, solid, duplication]

== Problem

Baseline 2026-11-06 (`scripts/count_type_name_collisions.py`): 798 redundant definitions across 597 names; 987 re-export collisions across 501 names.

Two metrics, two harms:

* **Re-export collisions — the wrong-type footgun.** A `pub use` exporting a
  name that is defined at more than one site. Once two same-named types are
  reachable from one module, an obvious-looking signature compiles against
  the wrong one. Found in #2443: `trait_components::path_resolver`
  re-exports the storage-ports `StorageAssignment` while call sites need the
  PROTO `StorageAssignment`; a new helper typed `&StorageAssignment` failed
  with "expected `StorageAssignment`, found a different `StorageAssignment`".
  (The ports crate disambiguates internally as `ProtoStorageAssignment`; the
  re-export loses that.)
* **Redundant definitions — silent duplication of a primitive.** The same
  name defined at several sites; a fix lands in one copy while the others
  keep the bug (mandate #12).

== Counting rules

* Sites, not files: two same-named types in different modules of one file
  collide. Mutually exclusive `#[cfg(...)]` alternatives of one type in one
  file are one definition.
* Not counted: `type` aliases (per-crate `pub type Result<T>` is idiomatic);
  generated protobuf, for the DEFINITIONS metric only (v1/v2 mirror domain
  names by design — proto definitions DO count when something re-exports a
  same-named type); test code (`tests/` / `benches/` / `examples/`,
  `*_test(s).rs`, `tests.rs`, `#[cfg(test)]` and `#[cfg(all(test, ..))]`
  modules and items — but not `cfg(any(test, ..))`, which ships); comments.
* Files come from `git ls-files`, so a local baseline equals CI's.

== Decision

1. **Ratchet first, per name, both ways.** CI fails if any name's count rises
   above its baseline (a fix elsewhere cannot pay for a new collision), and
   if a total falls without the baseline being lowered in the same PR. No
   big-bang rename — that would conflict with every open PR across
   concurrent sessions.
2. **Naming rule for new types:** a type that crosses a crate boundary or is
   re-exported carries a qualifying name — `ProtoStorageAssignment`,
   `SstCompactionConfig` — never a bare name already taken elsewhere.
3. **Burn down in themed batches**, lowering the baseline in each PR:
   a. re-export collisions first, they actively mislead — start with
      `StorageAssignment` in `path_resolver`, then the most-re-exported
      (`DistanceMetric`, `MetadataFilter`, `StorageEngineType`);
   b. then the redundant-definition clusters (`OperationType`,
      `FilterOperator`, `TransactionState`, `JoinType`, `BloomFilter`):
      CONSOLIDATE where the copies are one concept, RENAME where they only
      share a word.

== To close

The re-export metric is zero and every remaining redundant definition is
documented as intentional.
