== History (shipped)
The root-crate decomposition stranded **duplicate config structs**: a type extracted to `crates/foundation/proximadb-config`
kept a separately authored core twin, and the two drifted (while wiring ADR-069 S1 `wal_local_dir`, we nearly edited the DEAD
twin). WAL was the lone genuine duplicate. Lesson: **the dead twin is usually the foundation extract, not the core struct**.

* **S1 (#1314):** retired the dead `WalStorageConfig` + `WalDistributionStrategy` and their test-only `From` impl. The canonical
  WAL config is `WriteBufferUserConfig` (TOML `[storage.wal_config]`).
* **S2 (#1323):** folded the two drifted WAL converters. `to_engine_config` is the single conversion, and
  `convert_toml_to_wal_config` delegates. This fixed a latent embedded-path bug (sync_mode/memtable/flush thresholds were ignored).
* **S3 so far:** a two-agent audit cut ~200 naive candidates to a verified inventory. Retired: the 2 `// MARKED FOR REMOVAL` WAL
  module files (#1326, finishes #1270), and the `MetadataBackendConfig` cluster (#1330). `SstEntry` is also gone.

== Tripwire — ASSESSED + DECLINED
A name-collision guard (`pub struct` defined in BOTH
`src/core/config.rs` and `crates/foundation/proximadb-config/`) was prototyped + tested
(zero false positives on the current tree) but is too NARROW: the original incident was two
*differently-named* structs (`WalStorageConfig` vs `WriteBufferUserConfig`) for the same concept,
which a name check cannot catch. The signal that *would* catch it — a foundation struct whose
only consumers are `#[cfg(test)]` — is a heuristic with false-positive risk unsuitable as a hard
`work-commit-check` gate. Per mandate #12 (keep the harness lean; avoid low-value CI creep), the
rule (Core Directive #19, reviewed every PR) + the RETIRED site notes + this TD remain the
primary defense against concept-drift. Do NOT re-attempt a name-collision tripwire without
addressing this gap.

== Guardrails
Trace the live path before deleting (the dead twin is usually the *foundation extract*, not the core
struct); build the **server binary**, not just `--lib`. Retiring a test-only *struct* is safe; retiring
a *field* obeys the format-migration discipline (Core Directive #8). See Core Directive #19.
