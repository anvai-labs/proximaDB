== History (shipped)

* **Gap.** Variable-length and multi-hop Cypher resolved only the first hop: the parser recognised
  `*min..max` but the `EdgePattern` AST had no field for it (`-[:r*1..4]->` compiled as `-[:r]->`), the
  executor did one expansion per edge pattern, a `contains("[*")` reject missed the common `[:type*..]`
  form and silently degraded to one hop, and anonymous `()` nodes failed to parse.
* **Fix (#658).** `EdgePattern.var_length: Option<(u32, u32)>`; anonymous/label-only nodes get a
  deterministic synthesized variable; the executor runs a **bounded BFS** over `min..=max` with
  *reachability* semantics (one binding per distinct terminal node), each node expanded at most once —
  **O(V + E) per source regardless of `max`**, with `MAX_VARIABLE_LENGTH_DEPTH` (64) so a user `max` is
  non-weaponisable. Traversal cost is adjacency round-trips, not CPU.
* **Evidence.** `graph_runtime` ratchets `variable_length_path_expands_every_depth_in_range`
  (`*1..3`, `*1..1`, `*2..4`) and `anonymous_chained_pattern_traverses_two_explicit_hops`.

== Remaining (follow-ups)

* Per-path multiplicity + relationship-list binding (`RETURN r` where `r` is a var-length rel
  list) — currently a var-length edge does not bind an edge variable; only `RETURN <node>` is
  supported. Reachability semantics are the intended default; strict per-path is opt-in later.
* Emit the query-scoped traversal I/O trace (nodes/edges visited per depth) so the
  `ComputeScheduler` can cost multi-hop routes from measured quantities.
* `*0..N` (zero-length paths, i.e. include the start node) is not handled.
