== History

* Finding: training happens only at compaction ("train-at-compaction, assign-at-flush"), but the gate fired on L0 count ≥ 5 while the TD-FLUSH-3 predicted-bytes floor produces 2–3 large L0 segments at 1M — so training never ran. Untrained cold queries paid 179.7 GETs / 104.3 MB vs the trained 20–51 GET band.
* Mechanism: the TRAINING arm reads one 72-byte header prefix per L0 candidate (`layout_version != 3 || a0_len == 0` and size ≥ `PROXIMADB_TRAINING_COMPACTION_MIN_MB`, default 32). It self-clears because the output is trained, and checks `ivf_probe_enabled()` first — without the A0 trainer outputs stay v1 and the arm would loop.
* Rejected alternative (still relevant): targeting via `proximadb_ivf_whole_region_fallback_total` — the counter is process-global and unlabeled, so it cannot say which segment is untrained.
* Lesson: the probe-armed run first measured recall@10 0.9780 < the 0.984 ratchet; the nprobe sweep showed that was slice noise (default nprobe=8 measures 0.9860 on a fixed 100-query slice), and the reader gate went default-ON (#1210). Historical 20–51 GET bands assumed single-file beds.
* Evidence: 1M all-trained bed with probe armed — 82.9 GETs / 77.5 MB per query, mean 76 ms / p95 90 ms (vs 179.7 GETs untrained).
