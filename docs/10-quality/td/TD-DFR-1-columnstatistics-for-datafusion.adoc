== History (shipped)

`ObjectStoreParquetTable` (the provider serving `route_select → DataFusionLocal`) implements
`TableProvider::statistics()` from Parquet footer `ColumnBounds` already read for pruning (zero new scan),
merged into a **schema-width** `Statistics`, all `Precision::Inexact` (ADR-050 D3: hints, not truth), and
feeds post-prune projected stats into `ProximaScanExec`. Where the ADR-037 registry has an HLL
`distinct_estimate`, it fills `distinct_count` (footers rarely carry NDV).

Lessons that still apply: DataFusion 54 indexes `column_statistics[col.index()]`, so a short vector
**panics** under `AggregateExec`; `extract_statistics` had silently dropped min/max.

Evidence: `schema_inference` + `object_store_parquet_reader` unit tests; TPC-H/TPC-DS pgwire ratchets unchanged.

== Open: value-bounds gate (default OFF)

Typed min/max projection is opt-in via `PROXIMADB_DF_STATS_VALUE_BOUNDS=1` (`df_stats_value_bounds_enabled`).
Bounds feed DataFusion's recursive interval/selectivity analysis, deepening plan-time recursion on
join+subquery-heavy shapes (TPC-H Q2 class) whose debug-build stack use is already environment-borderline
(a Q2 debug stack overflow reproduces on WSL2 *without* bounds; `RUST_MIN_STACK=16777216` clears it).
Rows/bytes/nulls/NDV — the join-ordering inputs — always flow; flipping the gate on is a follow-up once
the recursion depth is characterized (default-OFF-until-baked posture). See also
link:TD-EXEC-1-iterative-planner-stack-sizing.adoc[TD-EXEC-1] and link:TD-ROUTE-2-override-eval-stack-overflow-dev-profile.adoc[TD-ROUTE-2] (overlap: plan-time stack depth).

== Not in this slice (tracked under TD-OLAP-2)

* Cardinality estimation in the native/federated planner; histograms.
* Stats invalidation on compaction / DV application (TD-OLAP-2 step 2); freshness-stamped staleness flag in EXPLAIN.
