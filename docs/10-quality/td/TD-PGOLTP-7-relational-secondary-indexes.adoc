== Premise (to re-verify at start)

`CREATE INDEX` is parsed (`sql_frontend/parser.rs`, `query/ddl_dml`). The record store has a
UNIQUE index. Whether a non-unique relational secondary index exists **and is used by the
planner** has not been verified. Check callers before building anything (filing rule 7).

== Design

* An index is an LSM index table `(index_key, pk) → ∅`. Entries are written inside `TxnCommit`
  and flushed with the base, so the index is never stale. Reads apply the same snapshot
  visibility as the base and re-check the base row (`is_dead`).
* The planner chooses an index for equality and range predicates when the estimated selectivity
  is below a measured crossover. The decision and the cost go into the route trace (ADR-064).
* Composite-PK point lookup extends `point_lookup_relational` beyond `primary_key.first()`.

== Acceptance

* pgbench-style point UPDATE by a non-PK unique column touches O(1) segments, measured in the
  I/O trace (requests and bytes), not by microbenchmark.
* No index-only read ever returns a row that is dead in the base.
