== History (shipped)

* Symptom: on a **clean** Azurite container every flush failed (`Failed to commit atomic flush operation`), the memtable never drained, backpressure never lifted, `record_count` stayed 0. Same binary succeeded on a warm container ⇒ state-dependent, not a code regression.
* Root cause: `FilesystemFactory::resolve_path` reduced cloud URLs to `Url::parse(url).path()`, **dropping the container**; cloud backends parse container+blob from the full URL. The SST `.pax` write bypassed the factory and worked; the coordinator's staging-dir `list`/`move` went through it and failed (`not an azure path: /1/data/__flush`). A warm container's pre-existing staging prefix had masked it.
* **Lesson — capture the full error chain first.** The `move_atomic` suspect and the adjacent `warm_cache.json: Invalid path` log line (best-effort, TD-CACHE-5) were both wrong; the proximate cause had been lost in every report because `anyhow::anyhow!("…{e}")` consumed `e` via `Display` and dropped `.source()`. Now `anyhow::Error::from(e).context(...)` and consumers log `{:#}`.
* Fix (#1216): cloud-scheme URLs pass through `resolve_path` verbatim (`file://` still reduces to a local path); the trailing staging-prefix `delete` is best-effort (on object stores the prefix has no blob of its own, so NotFound is the expected end state). Test: `test_resolve_path_cloud_urls_pass_through_verbatim` (the old `test_path_extraction` asserted the broken strip and was corrected).
* Verified 2026-07-26 on a clean Azurite container: `.pax` lands at the final prefix, zero `auto-flush failed`, search returns ingested vectors. `record_count` reading 0 is a separate catalog-stat issue (ADR-074 / TD-NS-1).

== Open

Why it escaped CI: the recall/flush ratchet (#1208) flushes in-process (`do_flush`),
bypassing REST → WAL → flush, and the object-store-emulator suite does not run a full
ingest to flush against a freshly created container. A regression test belongs on
the clean-container axis specifically — a warm container masks it.

* Add the clean-container ingest→flush case to the object-store-emulator job.
* The same run against a container holding prior-session state must still succeed —
  the fix must not trade one state for the other.
