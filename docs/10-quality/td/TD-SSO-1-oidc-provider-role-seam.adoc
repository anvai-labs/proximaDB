== History

**Decision:** ProximaDB is an OIDC *resource server*, not a relying party — clients obtain tokens
themselves (client-credentials / PKCE) and present them on the existing bearer surfaces; no redirect
flows or engine session state. **Role seam:** `gateway`/`operator` pass only when
`allow_delegation_roles` (default **false** for the IdP path — IdP groups are an external directory
where those are ordinary names), any other string only if listed in `role_allowlist` (default empty =
fail-closed); everything else is dropped with a capped audit warn. The seam is retrofitted onto
local-JWT conversion **only when OIDC is configured** (opt-in-complete: with OIDC on, every bearer
path sanitizes; locally minted gateway markers are stripped — a deliberate fail-closed break for
gateway topologies). **Zero `UnifiedPermission` is ever derived from IdP claims.** `user_id` is
`oidc:{sub}` so an issuer-scoped sub cannot join local role assignments. An OIDC token whose tenant
claim lands in `system_tenants` is excluded from the REST compat fallback (no gateway class by claim
value). Confusion defenses: header `alg` only *selects* a verifier; HMAC and ES* rejected at config
load; `alg:none` rejected; https-pinned issuer, JWKS and discovered `jwks_uri`, no redirects;
single-flight, debounced JWKS refresh; an unreachable IdP fails the request, never the boot. Enabling
OIDC should pair with `default_deny = true`. Revocation propagates at ≤1 h TTL / ≤5 s rotation.

Non-goals recorded (not silently dropped): browser/PKCE flows and RP sessions; pgwire bearer auth;
aws_iam/azure_ad enterprise variants (later deleted as dead code, TD-SSO-3); mTLS role stamping
(still open under TD-TENANT-1).

Lesson: the first adversarial review's critical finding (F5) was that the seam invariant was pinned
only at the *helper* — deleting the call in the production conversion left all 11 module tests green.
Pin invariants at the production seam (`oidc_seam_is_enforced_at_the_production_conversion`,
`local_jwt_roles_sanitize_when_oidc_is_configured`).

**Process rule established here (user directive 2026-09-01):** fresh-agent adversarial review is the
first reviewer of record for every PR — a zero-author-context agent enumerates every consumer of each
touched invariant, verifies negative-controlled tests, and hunts silent-failure shapes and
trust-boundary crossings; findings are fixed and regression-pinned or refuted with evidence.
