== History

The whole `clients/python/tests/unit` suite was `medium_tier`-only, so it never ran on the PR that introduced a Python change. On
#1679, five Python gates ran and the one that executes the tests was SKIPPED. A real incident surfaced it: tests that built
`EmbeddedProximaDB` via `__new__` broke when `__init__` grew `_shared_http_client`, and sat red on `develop`. Fix: scope by
*what changed*, not by promotion stage. The cost term is engineering latency: a regression caught on its own PR costs the author a
re-push, while one caught at promotion costs a stranger a bisect.

* **Correction to #1707's reasoning:** the local/CI divergence was not a pytest 9.1 upgrade. A locally installed, unrelated plugin
  (`pytest-astropy`) supplies `--run-slow`, and `tests/unit/conftest.py` auto-marked tests `slow` by **name substring** ("large",
  "stress", "compaction"). Those tests were skipped locally and failing in CI the whole time. The auto-marking was removed.
  **Lesson: a marker whose semantics are supplied by whatever is installed is worse than no marker.** Ask what your environment has that CI does not.
