== History

* **Capability.** Heading hierarchy paths annotated by lookup on every chunk (default-ON, metadata-only);
  lexical near-duplicate dedup before embedding (`ProcessorConfig.deduplicate_chunks`, **default-OFF**:
  it removes stored chunks, so flipping it is a product decision); `NativeSentenceBoundarySource`; structural
  (not generated) context enrichment; small-to-big parents with window derived as 2× `chunk_size`. The
  three later items unified as one `ChunkPass` port because each is a divergence between a chunk's three
  faces (span, embedded text, returned text) — four boolean flags would have had 24 orderings and no rule.
* **Lesson — a named stage is not an implementation.** The filing claimed the Rust SDP pipeline already
  had three of these; reading the code showed all four SDP stages were placeholders (`split("\n\n")`,
  a first-line prefix, a `.!?` flag, a 100-char merge) and `use_sdp` was never true. "Stranded" vs
  "absent" implies opposite plans.
* **Eval design that still applies.** `conformance/evals.py` scores output (containment, density) and
  trajectory (structure, attributability) and deliberately does **not** score the embedding model, so a
  red gate is always attributable to chunking. Score at a tight budget (at 512 every chunker saturates at
  1.00; a guard fails if the rubric flattens). Recall ratchets must be **deltas** (dedup's 6/8 was
  `paragraph`'s own limit); small-to-big must score the *returned unit* (parent-if-linked-else-child).
  Enrichment (+4% KEU) is unscoreable here by design — its recall gate belongs in the ANN harnesses.
* **Evidence.** Dedup −24% (paragraph) / −31% (semantic) chunks with zero answers lost, almost all at
  threshold 1.0; small-to-big containment 0.75 → 0.875 at ~1.74× KSU (flat across windows). SEMANTIC
  scored best on every axis — filed as evidence only, not a default flip.
