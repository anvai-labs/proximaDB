== History

`push_projections` re-derived `Expr::Column` ordinals **by name** against a narrowed child schema, so an alias
name absent at that level errored: an ORDER-BY output alias (q3/q52 `brand_id`) or a derived-table column alias
(Q15 `supplier_no`).

Decisive finding (still applies): the q3/q52 root cause was **upstream of the planner, in the frontend**. For
`SELECT g AS a … GROUP BY g`, the Project built `NamedExpr{name:"a", expr: Column{name:"a", …}}`: the inner
`ColumnRef` wrongly adopted the alias, while the Aggregate slot it indexes is named by the key `g`. Now the inner
ref names the group key's source (slot) name and the alias lives only on the enclosing `NamedExpr`, mirroring
the aggregate-slot path. Join-subtree rebind disambiguation remains a documented Phase-3 restriction of the pass.

Evidence: `tests/rel_lower_3_orderby_e2e.rs` (`GROUP BY brand ORDER BY total DESC, b` returns correct rows + order);
`tests/rel_exec_1_selfjoin_e2e.rs` (Q15 derived alias).
