== Reuse decision and gaps

* `proximadb-object-store` already owns conditional create. Extend it only for
  the proven missing conditional replacement/versioned-read capability, preserving
  typed precondition, unavailable and unsupported outcomes.
* Pinned `object_store` 0.13.2 has conditional update in memory; its LocalFileSystem
  explicitly does not implement Update. Do not mistake emulator success for local
  filesystem or cloud deployment certification.
* `proximadb-runtime-common::file_lock` supplies existing Unix advisory locks
  used by the embedded runtime. Reuse/certify it for local exclusion rather than
  cloning flock. Its non-Unix success-without-locking branch is not strict-capable.
  Advisory exclusion still needs durable publication, stable lock inode and
  cooperation from every writer. Old writers must be drained/fenced on cutover.
* `ManifestCommitter` currently lives in Iceberg and pulls storage dependencies
  above horizontal queue. Extract generic mechanics downward with re-exports;
  extract ownership once only after dependency audit, without copied state machines.
* Unmarked legacy generation headers and arbitrary plain payloads are ambiguous.
  A JSON heuristic cannot provide universal mixed-read-safe decoding. Explicit
  codec/authority migration is required before promising automatic upgrades.

== P1 opt-in head/retention prototype

This section records the earlier prototype checkpoint. Its legacy-write refusal and
unresolved-counterexample statements are superseded by the approved policy below.

The existing `ManifestCommitter` now has explicit `create_versioned` / `open_versioned`
entry points. No existing serving caller opts in, no environment gate was enabled,
and no legacy authority is automatically converted. The default constructor reads
the detected format but rejects versioned writes/pruning without explicit opt-in.

The checksum/version-marked head embeds its current payload, version, generation,
authority incarnation and per-invocation operation ID. A conditional replacement
publishes it using the native validator from one body/metadata GET. The previous
committed head is archived first; history deletion cannot invalidate an in-flight
candidate because the candidate is inside the head PUT, not an external GC target.
Delayed history recreation is eligible for a later pass and cannot publish a lease.
Neither the head nor immutable format marker is pruned. A marker-only provisioning
failure deliberately stays closed; recovery is explicit operator repair, not reset.

The codec uses existing bincode and SHA-256 dependency versions with a 64 MiB body
limit, explicit magic/version and checksum. Plain payload bytes no longer double as
a generation header in this format. Legacy decoding remains unchanged and ambiguous.
Retention age conversion overflow now errors rather than treating the age as zero,
including in the legacy implementation.

Conditional errors are reconciled against the operation ID in the current or retained
historical record. A matching receipt proves committed; a different receipt at that
version proves conflict. Missing/corrupt/unavailable receipt evidence after a possible
commit returns indeterminate, including after a native conditional error. This is not
an external idempotency API or a substitute for P2 progress receipts.

== Approved fail-closed policy and local acquisition checkpoint

The human approved disabling legacy pruning and blocking ownership writes to presently
gapped legacy logs until explicit migration. All legacy prune calls now fail without
deleting objects, including empty logs. Exact parent, current continuity and generation
are validated from one observed tip. Continuity is not historical proof: already-refilled
pruned slots cannot be detected. Old writers AND pruners, including suspended calls,
must be externally excluded before this policy or migration can provide its guarantee.

`LegacyEncoding::{Plain,GenerationPrefixed}` declares historical interpretation; there
is no payload sniffing. Lease/catalog serving callers declare the prefixed codec.
Wrong legacy write operations and truncated declared headers fail closed. Warehouse
plain payloads retain every byte and read with generation zero.

`migrate_versioned(expected_tip)` preserves original source objects, records source
identity/encoding/checksums, archives retained history before publishing authority, and
rechecks the source inventory/tip. Completed retries open the current advanced head,
never reset it. Marker-only failures stay closed pending operator reconciliation.
Updated serving handles detect/pin persisted versioned authority for reads AND writes;
constructing a handle never initializes/migrates a log. No deployment was migrated.

The existing runtime `FileLockManager` now supplies whole-operation byte-conditioned
local replacement: stable advisory lock, exact observed bytes, same-directory temporary
file, file sync, rename, directory sync. Async callers retain the whole operation in a
single blocking task. Symlink/hardlink lock targets are rejected before mutation and
diagnostics use the locked descriptor, not a reopened path. Byte equality is NOT an
ABA-proof ownership token. All writers must cooperate; a post-rename error is uncertain.

Queue acquisition/renewal uses that existing primitive through `QueueFs` and the canonical
`FileSystem` adapter. Typed NotFound is the only absence result; other read failures and
empty/corrupt metadata propagate. Renew cannot reacquire missing/expired/superseded state.
Existing traits advertise conditional replacement, unsupported by default; queue roots
reject unsupported adapters before accepting data. Counting/fault decorators forward it;
encrypted/transforming adapters do not bypass their semantics to claim support. Native
local ObjectStore Update remains unsupported; these are different existing contracts.

TDD reproduced linked-lock corruption and unsupported queue startup before their fixes.
The new subprocess test proves cross-process exclusion and recovery after killing a lock
holder; it does NOT certify power loss or a kill during publication. Post-publication
error and renewal negatives exercise the queue port. Cancellation while the blocking
operation is executing and crash injection around rename remain qualification gates.
At this P1 checkpoint consumer ownership-conditioned ACK, release and incarnation remained
pending; see the subsequent P2 queue checkpoint below. Sink fencing is still not delivered.
Passing acquisition tests must not be called end-to-end connector correctness.

Fresh adversarial review found that versioned retention ranked recursively listed

Both new tests failed before the exact full-path filter and pass after it. An independent
