== History

Approximate search via `AxisManager::query` skipped the HMGI/HNSW path and fell to an empty IVF route, so
every query returned 0 ANN results and fell back to a full SST/memtable scan.

*Decisive finding:* `hmgi_enabled_collections` was populated with one identifier at insert (UUID) and probed
with another at query (the collection name), so `HashSet::contains` missed. #557 made the query entry pass
`&collection.id`. After ADR-031 (#559/#566) changed `collection.id` to the decimal `object_id`, both sides
still key on the same value. *Lesson that still applies:* the invariant is keying *consistency* between
enable and query paths, not the id type; any future id migration must keep both sides on one value.

*Evidence:* `bench_24` recall@{1,10,100} = 100%; CI guard
`test_hmgi_enablement_keyed_by_canonical_id_td_axis_1` (`tests/hmgi_integration_test.rs`) asserts a name
does not match an id-keyed enablement.
