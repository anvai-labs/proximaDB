== History (shipped)

* Capability (feature-gated): a cold delete resolves oid → segment → position and sets an MVCC-versioned DV bit at the delete generation instead of writing a cascading tombstone; the PAX cold scan applies bits with `gen ≤ reader snapshot`; flush publishes the DV before retiring the delete; compaction is DV-aware and interlocked.
* **The naïve design was not shippable** (3-agent red-team, 2026-07-27). Corrections that still apply:
** **MVCC-versioned DV, not a plain bitmap.** A plain bitmap drops rows a reader at snapshot T must still see; the scan must carry the reader snapshot LSN (it carried none). `OlapDeltaMerge.snapshot_lsn` is a base-materialization LSN, not a reader as-of. Format: `gen → RoaringBitmap` runs, `PDV2` magic, `is_deleted_as_of`.
** **Publish-before-retire.** If the flush frees the WAL entry before the DV bit is reader-visible, a concurrent read sees the row in neither suppressor → resurface. DV publish is the commit point; the DV "version" is the max-discharged LSN (one monotonic u64 makes the straddle check `snapshot_lsn > dv_version`), with bounded retry on straddle.
** **The lost-bit race.** A delete that sets a DV bit after compaction streamed the input but before it deletes the input is silently lost. Compaction re-reads all inputs' DVs under one atomic step (manifest-CAS) at commit, reduces position-keyed deletes to an OID set and re-applies them to the re-clustered output. On lease/CAS failure: retry/abort — never skip the interlock and delete.
* **Resolver vs DV: two artifacts, two stores.** The oid→position resolver is immutable write-time data, so it is a **footer region** (`opr_off/opr_len`, CRC32, `ORP1` magic) inside the single atomic segment PUT — not a `.opr` sidecar and not a global index file (one contention point, non-atomic with any PUT). The DV is post-write-mutable, so it lives in a CAS'd manifest keyed by segment id. Absent region (`opr_off == 0`) or bad CRC → fall back to the durable tombstone (mixed-read-safe). Setting the pre-existing in-block `row_flags::DELETED` bit was rejected: it mutates an immutable block and is unversioned.
* **Verification-first corrections:** the cited LSM `SstEntry::tombstone` path had zero live callers — the live cold delete is a `valid_to_ns = Some(0)` tombstone record through WAL → memtable → PAX flush. `OlapDeltaMerge` is the Parquet relational path, so the DV and it never co-apply on one scan (the straddle sub-piece is moot on PAX). An oid may live in several cold segments; the bit is set in every one. The delete LSN was being discarded at the WAL `Ok(_)` arm and had to be plumbed. There was no oid→segment index: the decision was an in-memory, byte-budgeted LRU `OidResolverCache` on the `SstEngine` (lazy footer-region load on miss; invalidated on compaction retire and collection drop), not a new index — the cold-tier bloom check is a stub and `SegmentRegistry` is a non-rehydrated metadata projection.
* WI-7 descoped (§7.2-5 decision): building a cold-data oldest-active-reader watermark is a subsystem larger than the DV itself; DV purge shares the existing 1 h tombstone-reclaim liveness rule, so **long-lived snapshots are not pinned** — a DV-deleted row is physically dropped at compaction, matching tombstone behavior.

== Open (deferred, non-blocking)

* The WAL `path_resolver` ROOT-vs-PREFIX DI is unwired (latent — the SstEngine resolver gives write/read agreement).
* A real cold-reader watermark (pinning long-lived snapshots across DV purge) is a later, separately-scoped item.
* `cold-deletion-vectors` remains default-OFF (not in the root `Cargo.toml` default features); no default-ON bake/flip decision is recorded.
* A greenfield O(1) oid→segment reverse index is deferred unless delete latency at scale demands it (deletes are O(segments) cache probes today).
* Forward invariant for any future past-T OLAP read: any change-feed-based suppress that co-applies with a past-T reader must be bounded by reader `T`.
