== Context

An architecture review characterized the "experimental / deprecated" storage engines
(RAPTOR ~22.7k LOC, SWIFT ~11.7k LOC, plus the CEDAR/CHRONO/SEQUOIA/TITAN stubs) as
**~35k LOC of dead weight** that could be deleted for a large maintenance win. A dependency
sweep before deletion proved that premise **wrong** for most of them: kept, production code
references the internals of SWIFT, RAPTOR, and SEQUOIA, and CEDAR backs the canonical
document-store test path. Only CHRONO and TITAN are genuinely dead.

== Findings (grep-verified)

[cols="1,1,4", options="header"]
|===
| Engine | LOC | Coupling that blocks a clean delete
| **RAPTOR** | 22,673 | `RaptorExtractor` is dispatched by the *production* extractor factory (`trait_components/extractor.rs`, `StorageEngineType::RAPTOR` arm); `raptor::progressive_stages` builds a *production* progressive-search pipeline (`engines/core/progressive/factory.rs::create_raptor_pipeline`).
| **SWIFT** | 11,721 | `SwiftExtractor` dispatched by the same production extractor factory; `swift::progressive_stages` builds `create_swift_pipeline`; `swift::progressive_search::BinarySketch` is used by NOVA.
| **SEQUOIA** | 1,010 | `sequoia::TypedRow` is the element type of the multimodel query router's `Relational` result variant (`query/multimodel_router.rs`) — a live public result shape.
| **CEDAR** | 689 | Implements `RecordStorage`; it is the backing engine for the `canonical-document-store` (default feature) document-service tests (`storage/document/service.rs::canonical_service_with_collection`).
| **CHRONO** | 673 | *No external consumers* — only the factory instantiated it. **Removed.**
| **TITAN** | 194 | *No external consumers*; its proto arm already fell back to SST. **Removed.**
|===

Structural note: the proto `StorageEngine` enum (generated) keeps the `Swift/Raptor/Cedar/Titan/Chrono`
variants regardless — deleting an engine only breaks code that names its **structs/modules**, never
code that names a proto variant. The factory maps removed variants to a hard error (no silent SST
substitution — consistent with the Wave-0 flush-materializer fix).

== History (shipped)

#702 deleted `src/storage/engines/{chrono,titan}`, their declarations and factory functions; the CHRONO factory arms now `bail!` and TITAN's proto arm keeps its pre-existing SST fallback.
Since then SWIFT has been cfg-gated behind `experimental-engines` exactly like RAPTOR (commit `e55df2325`), so default builds no longer compile it; the relocation work below still applies to both.
*Lesson:* an architecture review called ~35k LOC of "deprecated" engines dead weight; a dependency sweep proved that wrong for all but CHRONO/TITAN.

== What is deferred (and why it is a refactor, not a subtraction)

Removing SWIFT/RAPTOR/SEQUOIA is **not** a deletion — it requires *relocating shared code* out of the
engine directories into a kept module (e.g. `engines/core/`) before the dirs can go:

. `SwiftExtractor` / `RaptorExtractor` → a shared `extraction` module consumed by the extractor factory.
. `swift`/`raptor` `progressive_stages` and `BinarySketch` → shared progressive-search primitives.
. `sequoia::TypedRow` → a relational-result type owned by the query/relational layer, not an engine.

Each move touches a live path (vector extraction, progressive ANN search, relational query results)
and MUST be gated on the recall/relational conformance suites, not just compilation. CEDAR's removal
additionally requires providing (or re-pointing to) an alternative `RecordStorage` impl for the
canonical document-store tests. Track as a co-design-scoped refactor (engine/format convergence),
not a quick subtraction.

== Acceptance for the deferred work

* No `datafusion::`-style boundary violations introduced by the relocation (shared code lands in a
  layer the consumers already depend on).
* ANN recall ratchets and the multimodel relational suites stay green.
* `experimental-engines` feature is removed only once SWIFT/RAPTOR dirs are gone (their gated code is
  the last remaining user).
