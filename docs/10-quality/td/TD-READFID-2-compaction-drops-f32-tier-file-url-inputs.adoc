= TD-READFID-2: compaction drops the exact-f32 tier because its predicates cannot read `file://` input paths

[cols="1,3", options="header"]
|===
| Field | Value
| Status | **Resolved (fix/readfid2-compaction-f32-tier).** Reproduced end to end through the production compaction trigger, then fixed: compaction now reads its inputs' tier declarations through the filesystem port. See <<evidence>>.
| Priority | **HIGH** for TD-READFID-1's guarantee: an `fp32` collection's exact tier is silently dropped at the FIRST compaction, and the collection re-lossifies with no signal.
| Component | `src/storage/engines/sst/segment_format.rs`: formerly `pax_inputs_have_f32_tier` / `pax_inputs_rerank_quant` (both `std::fs::read` raw `PathBuf`s), now `pax_compaction_input_tiers`; input provenance: `src/storage/common/compaction_orchestrator.rs` (`GenericFileMetadata.path = entry.url`), `src/storage/persistence/filesystem/local.rs` (`file://{abs}` URLs), `src/storage/engines/sst/compaction.rs` (`task.input_files` → `PathBuf` unmodified).
| Relates to | TD-READFID-1 (this defect silently undoes its fix after one compaction); TD-RDSTRAT-7; the same defect also breaks `pax_inputs_rerank_quant`'s FP16-preservation claim.
| Found | 2026-10-15, adversarial review of PR #2048 (fix/readfid1-point-read-fidelity)
|===

== Mechanism

. `LocalFileSystem::list` returns entries whose `url` is `file://{abs}` (`src/storage/persistence/filesystem/local.rs`).
. The compaction orchestrator copies that URL verbatim into `GenericFileMetadata.path` (`src/storage/common/compaction_orchestrator.rs`).
. SST compaction converts `task.input_files` into `PathBuf`s without stripping the scheme (`src/storage/engines/sst/compaction.rs`; note that sibling code DOES strip `file://` for outputs and staging detection — the inconsistency is the tell).
. `pax_inputs_have_f32_tier` and `pax_inputs_rerank_quant` call `std::fs::read(f)`. `std::fs::read` cannot open `file://` paths (verified by one-off: `read_ok=false`).
. Both predicates fail closed (return `false` / continue), so the three live compaction write sites' intersection rule concludes "no input has the tier" and the merged segment is written WITHOUT it.

Net effect: flush writes the exact tier (TD-READFID-1) → compaction fires (L0 threshold or the >32 MB untrained-training arm) → merged segment has no tier → point reads fall back to SQ8 reconstructions again.

== Fix

`pax_inputs_have_f32_tier` and `pax_inputs_rerank_quant` are replaced by one async resolver, `segment_format::pax_compaction_input_tiers(port, inputs) -> PaxCompactionInputTiers { f32_tier, rerank_quant }`. All three live compaction write sites in `compaction.rs` (the local-spill executor and both canonical PAX arms) call it with `self.filesystem_port()`.

* **No string surgery.** Each input URL (`file://…`, `s3://…`/`az://…`/`gs://…`, or a bare path) is routed by `FilesystemPort::get_filesystem`, the same scheme routing compaction already uses to read the segment bytes.
* **Footer first (I/O round-trips).** A coalesced segment declares `has_f32_tier` in its footer. It is classified from two small ranged reads (the header prefix, which mirrors the footer extent, then the footer) with no whole-object GET. A legacy block-layout PAX segment, whose exactness is per block, or anything the ranged probe cannot classify, falls back to one whole read through `read_object_bytes`. That one read answers both the exactness and the rerank question; the old code would have read the object twice.
* **Encrypted local storage.** The port returns the `EncryptedFilesystem` wrapper. Its `read_range` decrypts the whole object and slices it, so the probe sees plaintext and is correct. The cost is a whole read+decrypt per ranged read, so 2 per coalesced input. This is tracked in TD-COMPACT-IO-1. (An earlier revision of this TD said encrypted ranged bytes were ciphertext and fell back to a whole read; that was wrong.)
* **Non-vector compactions skip the probe.** When the merged records carry no embeddings (relational or document), the probe is skipped with zero I/O.
* **The compaction base quant follows flush (review fix).** Compaction used to hardcode RaBitQ. Once the flush DTO carried `pax_vector_quant` / `pax_vector_format` (TD-READFID-1 residual, same PR), the first compaction would have silently re-encoded an sq8 collection as RaBitQ and a `pax_vector_format:off` (RawF32) collection as RaBitQ plus the tier. Task producers now resolve `SstCompactionTask.vector_quant` with flush's `resolve_pax_vector_quant`. The precedence and defaults are identical: kill-switch or `pax_vector_format:off` -> RawF32 > `pax_vector_quant` > env > RaBitQ. `SstCompactionTask::pax_output_encoding` applies it with two rules. A RawF32 output never adds the duplicate tier. A RawF32 output is written only when every input is exact; otherwise it falls back to RaBitQ, so lossy reconstructions are never relabelled as raw f32. See the second review round below for how follow-up tasks, the other producers and the spill executor carry it.
* **Second review round (delta review of `fcf9d7fca`).**
** **Follow-up tasks inherit the collection intent (blocker).** The worker builds its L1->L2 follow-up through the config-free `check_compaction_needed`. That follow-up copied `rg_layout` but not `vector_quant`, so an sq8 collection re-encoded as RaBitQ at L2, and RawF32 flipped to RaBitQ plus the tier. `SstCompactionTask::inherit_collection_intent` now copies every producer-resolved field: identity, `rg_layout`, `vector_quant`, precision hint, block size and compression. `check_compaction_needed` is the only other construction site. Its producer, `enqueue_due_compaction`, already sets them. Tests: `two_level_compaction_keeps_the_sq8_base_quant` and `two_level_compaction_keeps_the_raw_f32_base` (L0->L1->L2, checking the `L2_` segment).
** **Every producer resolves from the real catalog meta.** The background-maintenance context (`BackgroundFlushContext`) now keeps the fetched `Collection`, and `to_collection_proto` returns it, so `tags` and `pax_vector_quant` are no longer dropped. The background manager also sends a `collection_meta_complete` hint. SST `do_compact` declines a request without the catalog meta (a synthesized config, `collection_config: None` from the WAL `CompactionCoordinator`, or a bare `data_dir` hint) rather than guessing the encoding. A non-forced `do_compact` now honours `compaction:` / `l0_threshold:` like the flush trigger. Tests: `background_producer_resolves_the_same_quant_as_flush`, `meta_less_compaction_producer_defers_instead_of_guessing`, `meta_less_explicit_compaction_is_declined`.
** **Spill no longer stalls a collection.** The spill executor writes coalesced RaBitQ.
*** A RawF32 collection whose inputs are all exact is spilled to RaBitQ plus the exact tier. The values stay exact; only the encoding cost changes.
*** A RawF32 collection with a lossy input, or any other base quant such as SQ8, gets a typed `CompactionOutcome::Declined(reason)`. This is not an `Err`, and the inputs are untouched. Each decline is counted in `proximadb_compaction_declined_total{reason}` and logged by a warn rate-limited to once a minute. The worker schedules no follow-up after a decline.
*** The spill executor also now honours the task's `rg_layout`. The canonical arms do too: `write_pax_segment_compacted*` take it.
*** Tests: `spill_declines_an_sq8_collection_without_an_error`, `spill_keeps_the_exact_tier_for_a_raw_f32_collection` (bit-exact), `spill_declines_a_raw_f32_collection_with_lossy_inputs`.
** **A probe read error aborts (data loss, pre-existing).** A transient I/O error in the tier probe used to be classed as "not exact". Compaction then wrote a tierless output and **deleted the inputs**, the only exact copies. `pax_compaction_input_tiers` now returns `Err` for an unreadable input, and both executors abort before writing or retiring anything, so the compaction retries on the next trigger. Test: `tier_probe_read_error_aborts_and_keeps_exact_inputs`. It uses the new test-only `PROXIMADB_TEST_FS_READ_FAIL_AFTER_FIRST` fault, which lets the record read pass and fails the later probe read of the same input.
** Non-vector compactions no longer log the spurious "not every input is exact" warning (`PaxCompactionInputTiers.carries_vectors`).
* **Unreadable inputs abort.** An unreadable input is an `Err`, logged with its URL. The compaction aborts and keeps its inputs (second review round); treating it as "no exact tier" would lose data.
* **Semantics unchanged.** It is still the intersection rule: every `.pax` input must be exact, legacy `.sst` inputs are exact, unknown formats are not, and at least one PAX input is required. The rerank quant is still the first block-level `RERANK_BASE` kind found, defaulting to SQ8. A mixed tier'd plus lossy compaction still drops the tier by design (`mixed_exact_and_lossy_inputs_do_not_claim_exact_output`).

== Evidence

* **End to end, production path:** `tests/v2_post_flush_search_e2e.rs::v2_fp32_point_read_is_byte_exact_after_compaction`. It creates an fp32 SST collection over REST v2, does five insert + `force_flush_collection` rounds (the default L0 threshold of 5, so the flush itself enqueues compaction; there is no test-only compaction entry point), waits for the background worker to leave one merged `.pax`, then checks `pax_segment_has_exact_vector_authority` on it and does GET-by-id with `f32::to_bits` comparison for all 15 records.
** Unfixed code (`origin/develop` 65eb306f9): **FAIL**. Merged segment `L1_….pax` `has_exact_authority=false`; **15 of 15** records differ, e.g. `rec-0` got `[0.6145521, 0.6251966, …]`, written `[0.613, 0.62390834, …]`. That is the SQ8 grid, so the collection re-lossified at its first compaction exactly as described above.
** Fixed: **PASS**. The merged segment is exact and all 15 records are bit-exact.
* **Unit, `segment_format.rs` tests:** `file_url_compaction_inputs_keep_the_f32_tier` (Region C and in-block tier, `file://` and bare paths) and `file_url_compaction_inputs_keep_the_fp16_rerank`. Before the fix, the equivalent assertions against the old predicates failed: f32 tier `false` for a `file://` input, and rerank `Sq8` instead of `Fp16`.
* `object_store_inputs_resolve_through_the_port_footer_first` uses an in-memory `s3://` backend behind the port. A coalesced input is classified with **0 whole GETs and 3 ranged reads**; a legacy block-layout input costs exactly one whole read and keeps its FP16 rerank.
* `unreadable_compaction_input_is_an_error_not_lossy`: a missing input is an error, not "no tier".
* **Base-quant review fix, through the production flush -> enqueue -> compaction path** (`flush_materializer.rs` tests):
** `compaction_keeps_the_sq8_base_quant` and `compaction_keeps_the_raw_f32_base_for_pax_vector_format_off` both **FAILED on the first commit**: the merged segment was coalesced RaBitQ, block-0 `EMBED_BASE` was `None`, and the expected SQ8 / RawF32 kind was absent.
** Both pass after the fix.
** `untagged_compaction_still_writes_rabitq` shows the default is unchanged.
** `pax_output_encoding_follows_the_resolved_base_quant` pins the RawF32 rules.
