== History

The constructor set both caches to `None` and the `with_segment_invariants_cache` /
`with_survivor_cache` setters had zero production callers, so only byte-identical repeats (the
query-result cache) were cheap; every novel query paid ~36 GETs against warm segments. Found because
TD-METRICS-1's new counters scraped **0** for both caches across a 920-query 1M SIFT run while
`queries_total` advanced and repeats served at 2,455 QPS. Env overrides:
`PROXIMADB_SEGMENT_INVARIANTS_CACHE_MB` / `PROXIMADB_SURVIVOR_CACHE_BUDGET_MB`.

Lessons that still apply:

1. **A cache that exists only behind an unused builder setter is dead code** — arming belongs at
   construction with an env/config gate.
2. **The absent-vs-zero metrics distinction found this** (`touch()` at boot + counters at the lookup
   boundary): a scrape showing `0` after a real run is a wiring alarm; an absent family hides it.
3. Documented env vars need a grep-able read site.

Evidence: `survivor_cache_reduces_gets_on_hot_repeat_query` +
`invariants_cache_evicts_priority_then_recency`.
