== History

`utoipa` serialises the OpenAPI document through `serde_json`'s map type, which is `IndexMap` (insertion order)
only with `serde_json/preserve_order`, else `BTreeMap` (alphabetical). Nothing of ours requested it; it arrived
transitively from `datafusion-physical-plan 55.0`, and DataFusion 55.2 deliberately removed it. The drift gate then
saw a "wholesale rewrite" (9,248 spec lines + 8,606 TS SDK lines, all semantically identical) on #1989.

Lessons that still apply:

* **`utoipa`'s own `preserve_order` feature is an empty no-op** (`preserve_order = []` upstream): we had been
  declaring a no-op and believing it was the switch. The switch is `serde_json`.
* Five obvious hypotheses (serializer bump, stale base, branch edit, generator non-determinism, utoipa/indexmap feature
  drift) were killed before comparing **`serde_json`'s** feature set. Two unrelated changes (`datafusion 55.0→55.2`,
  declaring `sqlparser 0.62`) produced the **same** reordered hash — the fingerprint of a binary feature flip.

Evidence/guards: `check_serde_json_preserve_order` (with negative-control tests) in
`scripts/check_deterministic_commit_contract.py`; `tests/openapi_spec_gen.rs` reports a first top-level key other than
`openapi` as the TD-SPECORD-1 fingerprint instead of a 9k-line diff. The 68 members inheriting
`serde_json.workspace = true` now read the declared feature.
