== History (shipped)

`consensus` moved once the rpc client was in the runtime; its only rewrite was `super::rpc::` /
`super::super::rpc::` → `crate::cluster_rpc::` (5 sites). `cluster_rpc/mod.rs` gained glob re-exports
mirroring the root `rpc/mod.rs`. Runtime `uuid` became unconditional; the `cluster` feature is now `[]`
but still cfg-gates `ClusterServerConfig` in `bootstrap_config.rs`.

* Vein total (TD-DECOMP-3..6): 111 cluster tests out of the root lib binary.

== Open follow-ups

Root-side today (verified 2026-10-15): `src/cluster/{distributed_ops,partition_lease,primary_pod_registry,replication,routing}.rs`
and `src/cluster/rpc/grpc_server.rs`.

* `grpc_server` (root-side) is now the last piece coupling to a moved cluster module — it
  references `consensus::RaftConsensus` + `replication::EngineReplication` via the re-export.
  `grpc_server` itself moves once `replication` does (it's tangled with `distributed_ops`→
  `routing`→`crate::catalog`).
* The remaining cluster residue (`distributed_ops`/`replication` + climbers
  `partition_lease`/`routing`/`primary_pod_registry`) needs the structural enabler — extract
  `catalog`/`network`/`storage` to crates — before it can follow.
