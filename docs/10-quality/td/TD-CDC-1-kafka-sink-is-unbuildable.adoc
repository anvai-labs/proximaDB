== What

Two features named `cdc-kafka` exist and gate different things:

* Root: gates the three cdc `[[test]]` targets via `required-features`. Those tests compile
  and are now compiled by the `onnx-cdc-duckdb` feature-matrix leg. They do not touch rdkafka.
* `proximadb-cdc`: `cdc-kafka = []` with a comment saying rdkafka is used "when enabled" —
  but no manifest declares rdkafka, so enabling the feature opens `cfg` gates onto code that
  cannot resolve its imports. Unbuildable by construction; nothing in CI or out has ever
  compiled it.

== Options

. **Wire rdkafka in**: add the optional dep + `dep:rdkafka` forward, pick a version, satisfy
  its native build (librdkafka) in CI, and fix whatever API drift the 718 lines carry. Real
  integration work; gate on the cdc e2e tests actually running against a Kafka container.
. **Delete the sink**: if Kafka CDC is not on the near-term roadmap, 718 lines of unreachable
  code is exactly the "reads as coverage, compiled by nothing" disease of TD-ORPHAN-1. Delete
  `sinks/kafka.rs` and both shell features, and reopen when Kafka CDC is scheduled.

== Disposition

Deliberate decision needed (product: is Kafka CDC committed?). Until then the feature is
recorded here as a sanctioned gap so coverage sweeps stop reporting it as a fixable
forward.
