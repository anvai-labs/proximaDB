== History

* Why it existed: every TD-OBJSTORE-1 batch was found on a real object-store API, never by file:// suites. The matrix runs the same wire APIs on Azurite/MinIO/fake-gcs: PR tier (path-gated, azure-only build, strict); QA tier (one `cloud-full` build, Azure then S3 sequentially, restart proof per store, recall ratchet on Azure only — a backend must be recall-neutral, any delta is a read-path bug); nightly GCS best-effort. `make cloud-emulator-test` runs the identical script locally.
* Design rules that still apply: contract tests must exercise the **production root `FileSystem`** backends (`src/storage/persistence/filesystem/`), not only the `proximadb-object-store` wrapper — the wrapper could not have caught the GCS single-page LIST. Build the server **before** starting emulators. fake-gcs stays best-effort because it does not enforce `ifGenerationMatch=0`. The S1 gate was red-first on develop and flipped green with TD-OBJSTORE-4.
* Lesson — eviction is not timeout: QA-tier failures rendered as `The runner has received a shutdown signal` (memory cliff), not `exceeded the maximum execution time`, so raising the cap changed nothing. Cause: the MLflow seam test used `--lib` (the lib-test target, the largest codegen unit) in the same 16 GB runner; fix was a separate `--mlflow-s3` job, a 12 GiB swapfile and `CARGO_PROFILE_TEST_DEBUG=0`. `ubuntu-latest` has ~2 GiB swap, not none.
* Lesson — a cap set near the measured maximum does not fail loudly; it disarms whatever step runs last (Docker Build at 45 min cancelled `Test Container Health`). Job wall times from the Actions API include queue time, so they are upper bounds.
* Evidence (six green QA runs, 2026-10-11): `objstore-restart-qa-tier` 66–73 min (cap 130), `cloud-emulator-object-store` 54–66 (cap 120), `mlflow-s3-artifact-seam` 33–49.7 cold (cap 80) — all ≥1.6× headroom.
