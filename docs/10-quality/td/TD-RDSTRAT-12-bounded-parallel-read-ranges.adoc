== History (shipped)

_Section map for code comments citing the pre-consolidation numbering: §1 = INFLIGHT prefetch cap, §2 = general `fetch_rounds`/`max_inflight` io_trace metrics, §3 = the SIFT1M evidence rounds 1–4 and the RTT ladder, §5 = the S3/MinIO campaign; full per-round detail is in the dated `RDSTRAT12_SIFT1M_*` status artifacts and the ledger entries named below._

Cold latency follows a waves-not-sums model: `latency ≈ rounds × RTT + Σ ceil(GETs_in_round / pool) × RTT + compute`;
a bounded concurrent executor turns `GETs × RTT` into `rounds × RTT` without changing GET count. Two caps:
`PROXIMADB_FS_READ_RANGES_PARALLEL` (decode-bound) and `PROXIMADB_READ_RANGES_INFLIGHT` (pure prefetch,
`FileSystem::read_ranges_prefetch`). Cold tails classify every fetch against cache residency with side-effect-free
peeks, issue ONE bounded prefetch round for true-cold ranges, then consume through the original loader seams (cache
semantics, counters and rank order unchanged). Env-gate registry row exists (owner TD-RDSTRAT-12).

*Lessons that still apply.*

* Round 1 was a null result because nothing reached the gated function (`read_ranges_prefetch` had zero production
  callers); round 4 found the third certified-dead-code seam in this TD (wave metrics). Prove a gate fires with a
  positive control (`probe_cold_tail_records_read_ranges_metrics_when_inflight_armed`) before A/B-ing it.
* A ≈0-RTT `file://` bed cannot evaluate a round-trip lever (−4.3% p50); round 3's "wave of one" diagnosis was
  itself disproved by adversarial review — the true masks were RAM-hit probe tails and Region-B collapsing to one
  mega-GET (GET-optimal, RTT-terrible). TD-RDSTRAT-8 GET-economy vs RTT-economy is a real co-design tension.
* Record correction (TD-RDSTRAT-13 campaign): the RTT ladder's "~0.9 s compute floor" was inferred by latency
  subtraction and is contradicted by `ivf_probe_rank_us` (34–43 ms); the residual was byte transfer through the
  proxy. The ladder's GET-parity, identity and ratio facts stand.

*Evidence:* RTT ladder at exact GET parity, identical recall 0.9835 and identity hashes — 1.61× @50 ms,
**2.78× @100 ms, 2.81× @150 ms** (`rdstrat12_sift1m_rtt_ladder_crossover`); MinIO 1.17×–1.64×
(`rdstrat12_sift1m_minio_s3_wave_pairs`).

== Open

=== A2 wave-split identity divergence

The A2 split arm preserved identity on one quiet rep, but its second retained
same-binary/same-geometry rep changed both ordered and set identity for query
23 while aggregate recall stayed equal. A host load spike explains the timing
outlier, not the semantic divergence. A2 correctness therefore remains open
pending reproduction and root-cause analysis. Both gates stay opt-in
(defaults unchanged).

=== Default / arming decision

Both `PROXIMADB_READ_RANGES_INFLIGHT` and `PROXIMADB_READ_RANGES_WAVE_SPLIT_MB` remain opt-in. The Azurite ladder
supports arming INFLIGHT for high-RTT object-store deployments; the MinIO campaign did not reproduce ≥2×.
`WAVE_SPLIT_MB` trades +N−1 billed GETs for ceil(N/width)×RTT — the evidence campaign decides any default move.

=== Unwaved v1-layout cascade GETs

On MinIO, after the TD-PAXRG-1 single-layout collapse, roughly half the per-query GET cascade (~11 of ~22 GETs:
footer/index/OID/metadata) runs outside the waved regions. Follow-up lever: extend the wave to those GETs
(TD-RDSTRAT-13 C3/C4 since removed the HEAD and moved the footer into the probe wave; re-measure what remains).
Toxiproxy's latency toxic also couples RTT into bulk transfer, so re-run at real-cloud RTT before concluding.

* `INFLIGHT` is additive: when unset, behavior is unchanged (current `PARALLEL` cap still applies)
