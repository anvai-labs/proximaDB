== History (shipped)

* **Capability.** Documents written on either surface (REST v2, gRPC `ProximaDocumentService`) land in
  the one shared record/vector store by default. `doc_canonical_vector_enabled` is DEFAULT-ON with a
  global kill-switch `PROXIMADB_DOC_CANONICAL_VECTOR=off`; the legacy read-fallback is retained.
* **Decisive design point.** The flip was made mixed-write-safe by a capability check rather than a
  flag day: `canonical_route` routes canonical only when the collection actually EXISTS as a vector
  collection (`RecordRoutePort::collection_exists`), so pure-document collections stayed on the legacy
  path instead of hard-failing.
* **Bake (#718).** Four criteria measured before flipping, per mandate #8: per-tenant metering of
  object-store writes on flush (closed the previously-unmetered gRPC path), recall within f32 tolerance
  with vectorless docs excluded from ANN, single-copy GB-month, and restart recovery (500 unflushed docs
  fully recovered from vector-WAL replay in ~2 s). Evidence:
  `docs/_internal/status/TD_DOC_CONV_2_BAKE_RESULTS_2026_07_06.adoc`; harness
  `tests/documents_convergence_bake.rs`; ledger `doc_conv2_bake_*` in `BENCHMARK_EVIDENCE.toml`.

== Open follow-ups (from the bake results; not cutover blockers)

. *Tenant attribution audit before widening.* The write meter attributes to
  `proximadb_tenant::tenant_id_of(catalog_meta)`; confirm production catalogs carry the real owning
  tenant for canonical document collections (unset ⇒ "default").
. *100k-scale projection-cost test* against `CANONICAL_DOC_SCAN_LIMIT` (criterion 4 at real scale).
  `query_documents`/`aggregate_documents` still bounded-scan; the `DocumentService` DashMap/`IndexManager`
  is a hot projection — bound its rebuild-from-scan cost for large collections.
. *Access tier* is billed as `hot` (the write-time default); when tiered flush/compaction lands,
  thread the real `ObjectAccessTier` into the meter instead of the literal.
. *KOU/read-side billing* for document reads is unchanged here (reads served from memtable/cache in
  these tests emit no `fetch_pax`); covered where the object-store read path is exercised.
. *Production widen/watch*, then retire the legacy `document_wal` write path once all collections are
  converged — see TD-DOC-RETIRE-1.

== Constraints

* **Mixed-read-safe, no flag-day.** Old (legacy `document_wal`) and new (vector store) coexist,
  detected by presence + the `document` label; readers fall back to legacy when absent.
* **Quality ratchets.** ANN recall@k within f32 tolerance; conformance ratchets only go up.
* Keep net `proximadb_v1` references non-increasing (TD-123 ratchet).
