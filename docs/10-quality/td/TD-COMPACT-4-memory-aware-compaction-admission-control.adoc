== History (shipped)

* Before: compaction was per-collection with a thread-count cap only, so a small maintenance merge and a corpus-sized merge looked the same and independent collections could reserve the same free memory.
* S1: one atomic projected-byte reservation domain shared by every SST collection and worker, acquired before any record-proportional work (replaces a count semaphore — job sizes differ by orders of magnitude).
* S2: projection `input_bytes × 12.0` (headroom over the measured 9.85x; later max observed 10.75x). Budget = min(cgroup/host total × 0.25, live available × 0.50, optional `max_memory_mb`). Discovery packs oldest-first whole-file morsels and needs ≥ 2 files for fanout; the threshold-one L0 training signal may promote a single admitted file, and its reason stays attached to bounded L0 follow-up morsels until the untrained tail drains. An oversized file stays horizontal.
* Lesson: object-store discovery must reject staging components from the **full URL**, not only `DirEntry.name`, or a bounded follow-up consumes an unpublished `__flush` object mid-promotion.
* S3 (partial): live available-memory refresh makes admission yield to query/cache pressure; metrics `proximadb_compaction_queue_depth`, `_running`, `_memory_reserved_bytes`, `_memory_admission_waits_total`.
* Notes that still apply: queue depth alone is not sufficient (a depth-1 queue can admit a job too large for its pod) — the byte budget and whole-file morsel bound carry the correctness burden. A low budget can increase steady-state segments and GETs/query; that is the explicit memory-stability/read-cost trade-off (made observable by TD-COMPACT-12). CPU-side cap is #1164's cores-ratio compaction threads.

== Open

S3 remainder — Explicit CPU/I/O scheduler priority is not yet implemented and must not be inferred from these gauges.

S4 — **Interim mitigation available today — uniform fan-3 leveled geometry**:
`3× Lₙ₋₁ → 1× Lₙ` up to the existing `max_levels = 7`
(`compaction_threshold` 5 → 3 / `level_multiplier` → 3, or per-collection
`l0_threshold:` tag). Peak compaction memory scales superlinearly with input
size (measured: ~1 GB at 30k input vs 40-52 GB at 120k), so smaller L0/L1
quanta reduce peak disproportionately, and 3^7 ≈ 2,187 flush-units of
capacity is ample. Caveats: (a) the per-compaction bound is `3 × 3ⁿ`
flush-units — the geometry protects the shallow levels where today's pressure
is, but deep-level merges are large regardless of fan-in, so S2's byte budget
(or TD-COMPACT-2 S2 streaming) must still clamp the tail; (b) write amplification rises (~log₃ vs log₅
passes/record — more PUT/GET churn on object storage); (c) slower convergence to
the few-large-files state TD-FLUSH-3 wants for the read path. (Note: TD-COMPACT-10
later set `level_multiplier` 1.0 with `higher_level_file_threshold` 2 for vector
search; reconcile before applying this stopgap.)

S5 — **Next mechanism: explicit spill, not OS swap** — specified and tracked in
link:TD-COMPACT-11-deterministic-local-spill-compaction.adoc[TD-COMPACT-11] /
ADR-088 (independent local scratch-byte reservation, bounded sorted runs,
incremental MVCC/DV resolution, deterministic sampled training, cell-partition
streams; no output visible until one completed final object is uploaded and the
manifest generation is atomically replaced).
