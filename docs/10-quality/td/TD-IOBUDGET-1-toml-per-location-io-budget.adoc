== History

`IopsBudget` sizes every ranged GET. It used to come from hardcoded per-scheme constants plus the pod-wide `PROXIMADB_DISK_CLASS` hint, which could not express per-location devices (the ADR-073 SAS-HDD vs NVMe deployment) and left the effective geometry unauditable. Now `IopsBudget::for_path` consults the location registry first, then the unchanged scheme+env logic, with zero changes at consumer sites.

*Design decisions that still apply:* the leaf crate gains no dependencies (config types live in foundation `proximadb-config`; the root converts and seeds at boot). Precedence is specific-beats-general: explicit `*_bytes` > `disk_class` > scheme default, and the env var supplies the device class wherever `disk_class` is unset. Unknown keys/values, bad bounds, and duplicate URLs with conflicting budgets fail startup; boot seeding is authoritative-replace. PAX block byte geometry, the chooser default flip and hot reload are explicitly out of scope (restart-to-apply).

*Evidence:* leaf + root unit tests for profile mapping, overrides, fail-closed validation and longest-prefix semantics; the existing Azure `[4, 8, 12, 16, 24] MiB` cap ratchet is untouched and green.
