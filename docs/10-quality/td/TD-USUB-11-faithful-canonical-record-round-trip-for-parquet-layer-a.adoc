== History (shipped)

* Finding: `proxima_records_to_record_batch` materialized only declared schema columns from `props`, so `oid`, `tenant_id`, lifecycle timestamps, `variation_id` and — load-bearing — `valid_to_ns` were dropped. Not a live bug while the relational memtable hard-deleted and Parquet was only an export of live rows; but once Parquet is a **landing** format, segments are immutable, deletion must become a `valid_to_ns` tombstone, and a tombstone that does not round-trip is a resurrected row. Found before the spill path was written — the whole value of the finding.
* Decision: reserved, opt-in, additive system columns (`__proxima_oid`, `__proxima_tenant_id`, `__proxima_variation_id`, `__proxima_created_at_ns`, `__proxima_updated_at_ns`, `__proxima_valid_from_ns`, `__proxima_valid_to_ns`), convergent with Iceberg v3 row lineage / Delta metadata columns. Rejected: spilling relational data as PAX (contradicts ADR-094 "format follows modality") and always emitting the columns (would change every existing Parquet object, incl. `MATERIALIZE` output and the Iceberg interop copy).
* Mixed-read safety: **presence of the column is the version marker** — the legacy writer is untouched, the reader lifts a system column only when present, and a user column with a reserved name fails closed. `MATERIALIZE` deliberately keeps the legacy encoder (reserved columns would leak into an external Iceberg contract).
* Evidence: `tombstone_survives_the_round_trip_and_is_lost_without_system_columns` (pins both directions), `system_columns_restore_identity_and_stay_out_of_props`, `legacy_batches_decode_unchanged`, `legacy_encoder_output_is_unchanged_by_the_new_variant`, `reserved_name_collision_fails_closed`.

== Open

* **Projection hygiene.** `is_system_column` is exported so user-visible column lists
  (`SELECT *`, schema introspection) can exclude reserved names. Wiring that into the SQL
  surface belongs with the first consumer that can actually surface them.
