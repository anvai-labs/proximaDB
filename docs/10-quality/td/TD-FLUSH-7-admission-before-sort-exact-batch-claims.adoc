== History

* Defect (SIFT1M on `c4062103d`): ~592k unmaterialized records were cloned and sorted before every L0 STOP rejection, each attempt built a fresh SST engine/worker domain, and only the inline trigger had a (private) per-collection semaphore. `get_unflushed_batches` returned every batch with no ownership transition — so duplicate work, ambiguous cancellation ownership, and the possibility of clearing batches that arrived after the source snapshot.
* Now: gate + global permit → canonical engine → `preflight_flush` (SST counts only live `L0_` segments and rejects at the stop watermark before sort/cluster/train/encode/upload) → only then claim. A `WALFlushBatchClaim` owns the exact source batch-ID set; `Drop` rolls back on error or future cancellation; success retires only those IDs, so batches appended during encoding stay for the next epoch. Inline, periodic and shutdown triggers share one coordinator; periodic work runs concurrently across collections. PAX collections with no configured AXIS index no longer feed AXIS.
* Lesson that still applies: admission must precede materialization, and retirement must be by exact claimed IDs, never "everything unflushed".
* Evidence: `cargo test -p proximadb --lib adr081` (12 tests: zero sort calls on rejection, single publication per collection, rollback on error/cancel, exact retirement with a concurrent batch, engine reuse) + `axis_insert_gate_tests`.
