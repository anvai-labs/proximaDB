== History (shipped)

* The design (zero-padded hex sequence in the name, `seg-{seq:016x}.gcseg`, resumed past the max found) is right — TD-USUB-1 adopted it. Two implementation details were not: `seq + 1` on a filename-controlled `u64::MAX` panicked in debug and **wrapped to 0 in release** (re-issuing live names; this writer has no conditional create, so it would silently overwrite), and `parse_seg_seq` accepted names the writer never emits (any width, either case), breaking "lexicographic order == sequence order".
* **Lesson — require the allowed alphabet, never reject a list of bad classes.** "Reject other widths and uppercase" was insufficient: `from_str_radix` also accepts a leading `+`, so `seg-+0000000000000ff.gcseg` claimed another name's sequence. That half-fix shipped once in `parse_spill_seq` and had to be corrected. Fix: width exactly 16 and every byte in `[0-9a-f]`.
* **Lesson — `fetch_add` on an `AtomicU64` is not covered by `overflow-checks`** and wraps in both profiles; refusing only at resume was off by one. The write site uses `fetch_update` and requeues the pending batch on refusal.
* The same overflow class in `merge_segment_directory` (`TRAILER + dir_len`, both `offset + len`) wrapped in release, made the truncation guard pass and issued a reversed `get_range`; now checked.
* Tests assert properties, not a rejection list: `seg_name_maps_to_exactly_one_sequence_and_sorts_by_it` (mutation-kills every half-fix tried), `index_load_refuses_an_exhausted_sequence_rather_than_overflowing`, `write_refuses_at_sequence_exhaustion_and_requeues_the_batch`.

== Residual

The heal-from-tails resume site is not directly tested: the loop calls `merge_segment_directory`
first, so a max-named object with a garbage body fails on the trailer before reaching the resume.
Reaching it needs a hand-built valid segment body. The construct is byte-identical to the covered
sidecar site.
