= TD-LANECOV-1: integration targets that ran in no CI lane, and fail on develop

[cols="1,3", options="header"]
|===
| Field | Value
| Status | **Open (filed 2026-11-10).** Found by the item-7 lane burn-down (#2502). Each target here is still on `scripts/ci_lane_baseline.txt` and must stay off a lane until it passes.
| Evidence | All 75 default-feature, hermetic-looking baseline targets were run on develop `4f256e8b9` (`cargo nextest run -p proximadb --profile integration --retries 0 --test ...`). 64 passed and are wired into the new burn-down lane. == Triage

Classification key: **real** = the product violates the property the test pins
(verified by reading the code); **stale** = the test's expectation predates a
deliberate change; **investigate** = deterministic failure, cause not yet proven;
**contract** = the expected behaviour is a product decision.

| `objstore_segment_path_guard_test`
| `src/storage/engines/sst/compaction.rs` contains `strip_prefix("file://")`
| **fixed**
| Source guard from #1082 (TD-OBJSTORE-4 defect-6 class). Reintroduced at `compaction.rs:3262` and `:3298` by later PRs (#1325, #1417, TD-TIER-1 SC4 `cd46e4473`) because no lane ran the guard. Both sites are the post-publication cache-promotion **fallback** path: for a cloud URL the strip is a no-op, the fallback "path" is `az://...`, and promotion fails with a warning (a silently cold cache), not data loss. Fix: derive the fallback through `sst::staged_write` like the write path.

| `queue_adapter_upgrade_integration_test` (2 tests)
| A relative `file://` queue root makes LIST return entries "outside configured root": `.tmpX/queue/.tmpX/queue/events`
| **fixed** (real)
| The path is doubled when the root is relative (`file://.tmp1tZS1z/queue`, `file://./.tmpUVDUgf/queue`); absolute roots pass (3/5 tests green). Likely a relative-root join applied twice in the queue filesystem's LIST.

| `discovery_drift_watcher_e2e`
| Drift watcher did not auto-trigger a second recluster in 40 s
| **fixed** (real + stale)
| The test sets `PROXIMADB_DRIFT_THRESHOLD_WRITES=1` and `PROXIMADB_DRIFT_INTERVAL_SECS=1` itself (lines 100-101), so defaults (60 s / 10,000) are not the cause. Check whether the knobs are read into a static before `set_var`, or whether the watcher stopped re-arming.

| `documents_convergence_e2e`
| Consumption metric family not live on `/metrics/prometheus` after a metered write
| stale (likely)
| Not an export bug: `/metrics/prometheus` does append `prometheus::gather()` (`src/network/metrics_service.rs`). The asserted substring `proximadb_storage_bytes` matches the current family `proximadb_storage_bytes_seconds`, but that is a labelled `GaugeVec` set by the **periodic** storage snapshot (`src/database.rs:355`), and a vec with no observed label set exports nothing. Per-write billing is `proximadb_object_store_write_bytes_by_tier_total`, recorded **at flush** (#718); the test's `CreateDocument` lands in the memtable without flushing, so no consumption sample exists yet. The test asserts a family the write cannot produce. Confirm the intended "metered path" with the metering owner, then assert the right family (after a flush) or the snapshot. 4 of 5 tests pass.

| `route_cost_offline_eval`
| Controller should cut >= 75% of the static heuristic's regret; got ctrl=198,900 vs static=200,000
| **fixed** (stale; the eval measured nothing)
| An offline eval of the cost router (directive 13): the gated controller now barely beats the static heuristic. Either the router regressed or the eval's fixture drifted.

| `grpc_methods_test`
| `GraphOperationsService::get_node` on a non-existent graph does not error
| **fixed** (real; contract decided)
| The test expects `Err`; the service presumably returns `Ok(None)`. Decide the contract (not-found as `Err` vs `None`) with the graph owner, then fix the code or the test.

| `counting_filesystem`
| `batched_range_reads` is 2, test expects 1
| **fixed** (stale)
| `CountingFileSystem::read_ranges` deliberately counts *physical* GETs after the inner filesystem's coalescing plan ("count what the wire will see", `crates/storage/proximadb-storage-filesystem-types/src/counting.rs:220-224`). The test's fake filesystem does not coalesce, so its two adjacent ranges are correctly 2 GETs. Update the test to the physical-GET contract (or give the fake a coalescing plan).

| `tdd_infrastructure_test`
| Asserts `.git/hooks/pre-commit.tdd` exists
| **fixed** (stale)
| Depends on a developer-local git hook that no checkout or CI runner has. Delete the assertion (or the target, if it pins nothing else).

| `helix_prune_debug_test`
| Failed once in the 75-target batch; **passed 2/2 in isolation**
| flaky
| Load/timing-sensitive. Not wired; make it deterministic before adding it to a lane.

  real test under `#[cfg(feature = "gap-tests")]`, a feature that does not exist
  in `Cargo.toml`, and its 4 remaining tests have comment-only bodies;
  `test_record_store_route` is one empty placeholder. Wiring them would let the

  Owner decision: implement, or delete with sign-off.
* `abac_vector_pushdown_integration_test`, `abac_rest_record_search_integration_test`: their tests compile out without `abac-policy`; they belong in the feature-matrix lane.
* `cdc_rest_changefeed_e2e`: requires `cdc-kafka`.
* 43 targets that need external services, are cfg-gated or `#[ignore]`d.

== Progress

* **Fixed and wired into the burn-down lane** (#TBD):
** `objstore_segment_path_guard_test`: compaction's two cache-promotion fallbacks now use the new sanctioned `StagedSegmentWrite::local_path_of` (in `proximadb-sst-engine`'s `staged_write`), which returns `None` for an object-store output, and skip explicitly instead of building an `az://...` "path".
** `counting_filesystem`: the fake now has a coalescing plan, so the batched read is one physical GET and the test proves the physical-GET contract (it fails if the wrapper counts logical ranges).
** `tdd_infrastructure_test`: the developer-local hook assertion is removed; the repo-tracked checks remain.
** `queue_adapter_upgrade_integration_test`: regression from #2386 (`55141f6b3`), which made `LocalFileSystem::list` always return absolute `file:///...` entries; `FactoryQueueFs::relative_from_listed_url` still compared them with the relative root, so every LIST under a relative root failed. Fixed at that boundary only: a relative root is resolved against the working directory for the comparison (lexical, like the backend), confinement and `..` rejection unchanged, caller-facing paths still in caller coordinates. The doubled path in the dotted case is the documented existing mapping, not a bug. New unit test covers in-root, `./` callers, and out-of-root/traversal rejections.
** `grpc_methods_test`: a READ of a never-created graph went through `get_or_create_graph_engine`, so looking up a node in a mistyped graph silently **created and registered** that graph, then answered "no such node". Decided contract: reads and mutations of existing data (27 call sites) use a new non-provisioning `get_existing_graph_engine` and fail with "Graph collection '...' not found" (NOT_FOUND on the wire, same wording as `update_graph_schema`); only creating writes (create/batch-create, transactions, adding a constraint: 9 sites) still provision, preserving the TD-GRAPH-TENANT-1 first-write flow. A missing node in an existing graph stays `Ok(None)`. Visible change: reading a named tenant's graph before its first write is NOT_FOUND, not empty.

** `discovery_drift_watcher_e2e` (**real product bug** + stale test): since `076592ba1` (2026-10-17) the tenant-scoped `list_collections(None)` returns empty without a tenant, and `DriftWatcher::tick` (a background system caller) was never moved to the `list_collections_internal()` added for that case. Its name-to-id map therefore held only name-as-id, while the WAL manifest is keyed by internal object id, so `writes_since` was always 0: **the drift watcher never fired, for any collection, in any deployment**. Fixed in `drift.rs` (`sweep_targets()` uses the internal listing; listing errors logged, not dropped). Separately the test was stale: since #1384 the watcher is spawned only with the AXIS runtime on (`enable_axis_indexes`, default off per ADR-070); the test now enables it. Unit tests: name-to-internal-id pairing with a tenant-scoping mock (fails if the old call is restored) and re-arm after a completed recluster (with a coalescing negative control).
** `route_cost_offline_eval` (stale, high impact): the offline gate for flipping `PROXIMADB_ROUTE_COST_OVERRIDE` fed its simulated cost through `range_gets`, but since #1709 (`5d772a895`) the model scores the physical `get_ops`. Both arms scored 0 GETs, so the controller could never see an advantage and the eval measured nothing. The router itself is unaffected (real traces fill `get_ops`); the fixture now sets it.

== Exit criteria

Each row is closed by a PR that fixes the code (real), the test (stale), or the
contract (contract), **and** moves the target from the baseline into a lane in
the same PR, so it cannot silently rot again.

Evidence (all in the burn-down lane, slot ~51 of 620 sequential):

* Hung the lane **3 of 5 CI runs across three different trees** — #2506's
  original head (pre-#2505 Rust), #2509's head (current develop + graph
  changes), and the develop → qa promotion PR on **pure develop**
  (`c0610df0a`, no feature changes at all). Same signature every time: the
  `[sst]` leg prints PASSED, then silence to the full 360s (120s × 3
  terminate-after), while sibling all-engine tests in the same binary pass in
  ~3s concurrently.
* Passes in isolation **5/5 locally** — unrestricted (6-16s), 4-CPU-constrained
  via taskset, and under gdb with the same `--exact` invocation. A constrained
  run showed 5.1% CPU at 86s once (blocked, not slow), and per-thread wchans
  were futex_do_wait + an idle epoll reactor — lock/wait-shaped, but the
  user-space stacks were never captured (ptrace_scope=1; the CI-side stack is
  unavailable too — nextest kills the process).
* The distinguishing property vs the passing siblings: it is the only
  flush-heavy multi-engine test (3 insert+flush cycles per engine, WAL
  enabled) — the same post-flush territory as TD-HELIX-2, which is **open on
  pristine develop** with deterministic wrongness after a flush. The original
  triage already recorded the pattern: `helix_prune_debug_test` "failed once
  in the batch; passed 2/2 in isolation".

Disposition: excluded from the burn-down lane via `-E 'not
test(test_multiple_flush_cycles_all_engines)'` (the unit lane's rabitq
precedent) — the binary's all-engine search matrix keeps gating. Exit
criterion unchanged: root-cause the HELIX post-flush hang (with TD-HELIX-2's
fix), then remove the `-E` and re-wire the test in the same PR.
