== History (shipped)

The old patterns (`Dockerfile*`, `docker-compose*.yml`, `.dockerignore`) contain no `/`, so picomatch (what `dorny/paths-filter`
uses) matched **top-level paths only**. The filter was inverted relative to what `docker-build` builds (`deploy/docker/Dockerfile`,
shared with `publish-image.yml`): edits to `deploy/docker/**` skipped, while the root `Dockerfile` / `Dockerfile.prebuilt`, which
no CI job builds, triggered the build. #1977's two image fixes reached `docker-build` only because it also touched `ci.yml`.
Lesson: a gate that cannot see the change it validates is the same class `ci.yml` already calls out for its `rust` filter.
`publish-image.yml` already had the right pattern.

* Verified against picomatch 2.3.1 itself (the version dorny/paths-filter@v4 bundles, with `{dot: true}`), not retyped patterns.
  `deploy/docker/Dockerfile`, `entrypoint.sh` and a nested Dockerfile flip to RUNS; root `Dockerfile`, `Dockerfile.prebuilt` and
  `docker-compose*.yml` flip to SKIPS. `rust` stays in the `||`.
* The guard's matcher is a deliberate picomatch SUBSET (literals, `*`, whole-segment `**`), pinned by tests in
  `tests/scripts/test_deterministic_commit_contract.py`. Review round 2 caught that `*/**` must NOT match `Dockerfile`. Differentially
  fuzzed against real picomatch: 1,583,160 cases with **zero over-matches**, and 273 fail-closed under-matches (`./`-prefixed
  patterns and the `**/*a/**` family, which no filter here uses).

== Open residuals

* The filter does NOT watch `config/**`, yet `deploy/docker/Dockerfile` COPYs
  `config/` and bakes `/config/config.toml` — a config-only PR still skips
  docker-build. Pre-existing; the guard's declared scope is `file:` targets,
  and widening the filter is a cost decision (config edits would burn the
  ~38-minute build), so it is recorded, not silently closed.
* `.dockerignore` is watched but no such file exists in the repo — inert,
  inherited from the old filter.
