== History

* Finding (1M needle verification of #1234): `nprobe_multiplier = 1.5` in TOML had no effect, while the env `PROXIMADB_PAX_READ_COARSE_NPROBE` did. Defaults worked; only custom values were unreachable.
* Two root causes — lessons that still apply to any process-wide config:
** Every production `SstEngine::new()` constructs with `SstConfig::default()`, so the parsed config was dropped on the floor.
** `OnceLock` first-wins with `let _ = set(...)`: the first default-config engine seeded the value and the real config's `set` failed silently.
* Fix: `SHARED_COARSE_PROBE` is a `RwLock<Option<..>>` where a real (`Some`) config always wins regardless of construction order; `ProximaDB::start` seeds it from the server config; env vars still override at call time.
* Evidence: `toml_coarse_probe_config_wins_over_default_init` (multiplier reaches `geometric_nprobe`: sqrt(64)×1.5=12 vs 8).
