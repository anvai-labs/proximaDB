= TD-ANNPRUNE-1: Header-centroid file prune ranks unresolved files as closest — recall hazard on PAX
:status: Accepted
:date: 2026-11-06
:tags: [ann, recall, pax, pruning]

== Problem

`discover_sstable_files_with_centroid_pruning`
(`src/storage/engines/sst/search/mod.rs`) ranked the discovered segment set
by legacy SST1 header-centroid distance and kept the top `nprobe` files.
Every file that did not resolve a real centroid — the `.pax` fast path's
`Ok(None)` (deliberate: it avoids one paid ranged GET per PAX segment per
query), a dimension mismatch, or a header read error — was pushed at
distance `0.0`. The ascending sort reads `0.0` as closest-possible:

* **All-PAX collections** (> `MIN_FILES_FOR_PRUNING` = 10 live segments,
  Approximate or large-Adaptive search): every file ties at 0.0, the stable
  sort preserves input order, and `.take(nprobe)` keeps an arbitrary subset
  unrelated to the query. The segment holding the true nearest neighbours
  is excluded with probability `1 - nprobe/N` regardless of the query.
  `record_vector_ann_proof()` then recorded the arbitrary subset as a
  justified prune.
* **Mixed PAX + legacy collections** (the sharper case found while fixing):
  the PAX files' fake 0.0 beats every REAL distance, so PAX files
  monopolise the probe and the genuinely-ranked legacy files are evicted
  first — the prune inverts its own ranking exactly when it has real input.

== Decision

The prune requires **complete ranking input**: `resolved == all_files.len()`
(real, dimension-matched header distances). Anything less returns every
file. A partial ranking is not a weaker prune, it is an arbitrary one.

PAX probe selection belongs to the trained Region-A0 centroid directory
(`centroid_directory_nprobe_for`), which runs downstream of discovery and
has been default-ON since TD-PAXDIR-1 D1–D8. The legacy header-centroid
prune must not pretend to substitute for it.

`record_vector_ann_proof()` is unchanged: it is gated on
`selected_files.len() < all_files.len()`, which after the guard is
reachable only when the ranking was real.

== Cost note

GETs rise on unconsolidated all-PAX collections (the lottery becomes a full
scan). Mitigations, with their precise scope (#2439 review F3): the A0
directory prune downstream mitigates CASCADE-path queries only —
`centroid_directory_cells` returns no pruning when a filter expression is
present, under `force_exact`, for non-L2/Cosine/Dot metrics, or when either
read gate is off; on those paths this fix deliberately trades the (bogus)
bounded probe for an unmitigated full scan, because the bounded probe was a
recall lottery. `COMPACT TABLE … FULL` consolidation (#2418) collapsing
segment counts toward the target remains the structural mitigation for
every path. The cost claim is unmeasured per path (no
`BENCHMARK_EVIDENCE.toml` entry) — a measured per-query trace on a filtered
Approximate workload is the follow-up that would let the A0-for-filtered
gap itself be closed.

Observability note (#2439 review F4, filed not fixed): an Approximate query
that engages neither the cascade, nor AXIS, nor a real prune now records NO
VectorAccessPath, where the pre-fix code recorded a FALSE `Ann` proof. Per
the "never warm an ANN cell without an engagement proof" contract this is
the honest outcome, but such queries vanish from the vector access trace
(cache pattern tracking, ANN cost-cell warming) until a truthful proof
event is defined for the full-scan-on-unrankable path.

Review F1/F2/F5/F6 (all fixed in-PR): `load_sst_header_centroid` guarded
its 8-byte prefix slice (a crash-truncated 0-7 byte `.sst` panicked the
query task — mandate #4); the refuse-on-unrankable decision is now made
from URL suffixes BEFORE the header loop (a mixed collection was paying two
ranged reads per legacy file for a ranking the guard discarded); the
dimension-mismatch and read-error branches of the guard gained tests; and
the guard comment no longer reads backwards (a single unrankable file
always refuses the prune — the mixed case is only where the pre-fix
eviction was sharpest).

== Gates

Three unit tests beside the function: all-PAX never pruned; mixed
unresolved never pruned (the eviction case); fully-resolved still prunes to
nprobe (guards against overcorrection). The `sift_pax_recall_ratchet_test`
lane is the recall ratchet. Test SST1 fixtures are hand-built through the
real bincode `SstableHeader` path.
