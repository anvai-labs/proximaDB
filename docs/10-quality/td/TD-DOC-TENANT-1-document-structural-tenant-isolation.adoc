== History (shipped)

* **v2 gRPC core.** `scoped_document_collection(tenant, collection)` → `{tenant}/{collection}` (default
  tenant bare, fail-closed) is applied to BOTH the storage-key param and `record.collection_id`;
  `DocumentService::ensure_or_create_collection` (race-safe, WAL-logged `CreateCollection`) replaces the
  "Collection not found" hard-fail so a scoped first write auto-provisions; responses strip the scope
  (`record_to_v2_clean`). The `{tenant}::{collection}` fold (`effective_collection_id`) is gone.
* **Decisive finding.** The feared WAL-recovery risk was over-weighted: recovery replays each record by
  its embedded canonical OID (`document/{collection_id}/{doc_id}`), so scoping is recovery-safe
  *provided the storage key and `record.collection_id` are scoped together*. The real blocker was the
  collection-existence gate.
* **Store-split resolved (#698).** `DocumentService`'s canonical branch routes through the same
  tenant-scoped record/vector store REST v2 uses (now default-ON, TD-DOC-CONV-2); canonical-path
  isolation is structural via per-tenant collection resolution + `record.tenant_id`. The scoped fold is
  retained on the legacy read-fallback for pre-cutover docs.
* **Entity document leg (#692).** `entity_orchestrator` scopes its provenance document collection via
  `scoped_document_collection` (`/`, not `::`).
* **Evidence.** Two tenants, same clean collection + doc id, isolated via auto-provision; ratchet +0.

== Remaining follow-ons (open)

* **pgwire / REST v1 create + default uniformity.** Same shape as the graph follow-ons: those create
  paths are bare (pgwire `create_document_collection` still calls `document_service.create_collection(table_name, …)`
  with no tenant, re-verified 2026-10-15); once they scope, flip the default tenant to
  `default/{collection}` for uniformity.
* Make collection creation tenant-scoped in ONE place — pgwire `create_document_collection` and any
  REST/gRPC create compose `{tenant}/{collection}` via the shared `scoped_document_collection(tenant, collection)`
  (validating the tenant with `proximadb_tenant::validate_request_tenant`, path-style `/`, never `::`),
  so create and read agree.
* **Optional `TenantDocumentOps` scoped handle** over read/write (mirroring the graph `TenantGraphOps`
  facade — additive, raw methods untouched so internal callers are unaffected). Not built; the gRPC fold
  it was meant to replace is already gone.
* Gate with a documents isolation test across the create surfaces: two tenants, same clean collection
  name, no cross-read; no `::` in any composed key; recovery preserves scope.

== Constraints

* Keep net `proximadb_v1` references non-increasing (TD-123 ratchet, baseline 2917) — prefer v2
  proto types in any new code/tests.
* Mixed-read-safe / no flag-day for any on-disk key-shape change (document keys, WAL replay).
