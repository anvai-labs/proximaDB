= TD-CAT-9: the default catalog does not mint namespace object_ids
:status: Resolved
:dim: D5
:pillar: SEC

[cols="1,3", options="header"]
|===
| Field | Value
| Status | **Done.** `SystemCatalog` mints namespace `object_id`s from the shared system-wide sequence, and the recovery floor folds them (#1687).
| Severity | Medium — latent (no consumer), but a divergence between two backends that report the same `catalog_type`
| Component | `src/services/system_catalog.rs`, `src/services/system_catalog_state.rs`
| Relates to | link:TD-CAT-7-catalog-trait-split-unforgettable-minting.adoc[TD-CAT-7] (found it), ADR-031 / TD-181 P0

== History

The default backend (`SystemCatalog`) now mints a namespace `object_id` from the same sequence
`create_table` uses (ADR-031 amendment 1 — one sequence, not per-type), matching `NativeCatalog`.

Decisive design points (still apply):

* Both halves shipped together because either alone is worse than neither: minting without extending
  `SystemCatalogState::max_object_id`'s fold lets a restart recover a floor *below* a persisted namespace id
  and re-issue it — and object ids key grants, so a new table would inherit a live namespace's permissions.
* Legacy namespaces are **not backfilled**: `SystemCatalog` state is derived from the WAL, so an in-RAM
  backfill would be non-durable and mint a *different* id every restart. Old namespaces keep `object_id: None`;
  the floor folds whatever ids exist (mixed-read-safe).
* Test ordering is load-bearing: the last id minted before restart must belong to a namespace, or the
  test passes either way.

Evidence: `namespace_object_ids_are_never_reissued_across_a_restart` (neutering only the namespace fold →
"object id 5 was re-issued at or below the persisted namespace id 5"); sibling of TD-AUTHZ-2's
`object_ids_are_never_reissued_across_a_restart`.
