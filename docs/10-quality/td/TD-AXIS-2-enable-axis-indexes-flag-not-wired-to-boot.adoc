== History (shipped)

`enable_axis_indexes = false` used to parse but not control live AXIS registrations or maintenance loops; the
discovery drift watcher reclustered (materialized + k-means trained) a 3.3M-vector PAX-only collection with
`index_configs=[]`, and the RSS peak was misattributed to compaction until a per-component trace separated the
workloads. #1384 added fail-closed gates, cheapest first:

* *Compile:* without Cargo feature `axis`, AXIS-only drift/recluster code is not compiled; the PAX server still builds.
* *Process runtime:* `enable_axis_indexes=false` (default) ⇒ no SST/Orion/flush global registration, no EventLog
  consumer, recall observer, drift watcher or sweeper; vector ops and external-vector index paths do not feed or query AXIS.
* *Collection declaration:* absent config or empty `index_configs` ⇒ search, insert and flush share one
  `collection_declares_axis_index` predicate and use PAX. A format tag such as `pax_vector_format:off` cannot opt into AXIS.
* *Served-index maintenance:* with no published IVF/HNSW index, discovery recluster exits before listing records.
  Reclustering is maintenance of a served index, never an implicit bootstrap.

*Design decision that still applies:* `AxisManager::new` is lazy (no read, training or spawn), so the value is still
constructed; the contract is that it is never registered or touched while the runtime gate is false. Direct
`VectorOperationsService` construction defaults the gate to false; production boot must apply the resolved config.

*Evidence:* gate unit tests pass on the AXIS build; the no-AXIS `proximadb-server --no-default-features` CI-equivalent check passes.

== Open residual

* The 3.3M memory/compaction run must be repeated on a release binary to confirm
  the absence of the concurrent `Training clustering model ... 3300000 vectors`
  trace before updating the benchmark evidence ledger.
