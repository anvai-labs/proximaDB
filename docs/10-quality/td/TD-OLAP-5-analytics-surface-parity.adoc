== Why

Three gaps separate a fast engine from a *usable* warehouse surface, and each is table-stakes
vs Snowflake/Databricks:

. **Function library:** `proximadb-functions` ships 10 base scalars (+6 aliases) + one
  aggregate demonstrator (`register_builtin_scalars`/`register_builtin_aggregates`); window
  functions are absent. Mature systems ship 100+. Per ADR-039 invariant 4, each function is
  defined once as a `ProximaValue` kernel and bound to DataFusion — so coverage is additive,
  not a rewrite.
. **Relational late-materialization:** late materialization exists only on the vector path —
  the columnar module's selection-bitmap pipeline (`columnar_query_engine/pipeline.rs`,
  `vectorized_executor.rs`; lazy top-k materialization in `columnar_query_reader.rs`); the
  relational scan fully materializes projected columns. For selective OLAP scans this wastes
  the bytes-scan budget ADR-052 invariant 3 is trying to protect.
. **Result cache:** Snowflake's 24h→31d persisted result cache serves dashboard re-runs from
  the metadata layer with *no* compute charge. No competitor except the warehouses ships this;
  it is a large cloud-cost/UX lever for repetitive BI.

== Rollout (independent slices)

. **Functions:** grow `proximadb-functions` toward ANSI parity in tranches (date/time,
  conditional, casting, string, array/map, aggregate set); add window-function framing
  (`AggregateAccumulator` trait already exists — add partition/frame). Bind each through the
  DataFusion UDF wrapper; never redefine. Track ANSI-conformance coverage as a ratchet.
. **Late materialization (relational):** in the PAX-scan → Arrow path (TD-OLAP-1), defer
  wide-column decode for rows not surviving the filter/limit; reuse the vector-path selection
  bitmap idiom for the relational selection vector.
. **Result cache:** a query-result cache keyed **structurally on `(tenant_id, namespace_id)`
  first** (co-design mandate: isolation is structural, never a per-query predicate), then
  (canonical logical plan + LSN/bounded freshness watermark, per ADR-038/051 with ADR-046
  supplying WAL-tail LSN coherence); invalidated by write/DV **tenant-scoped**; serve hits
  without warehouse compute. Default-off, flag-gated; promote on measured dashboard hit-rate.

== Verification

* ANSI function-coverage ratchet rises monotonically; pgwire BI-tool smoke tests (psql,
  Metabase/Superset-class) pass against a representative TPC-DS workload.
* Late-materialization: a measured bytes-decoded reduction on selective scans in the TD-OLAP-4
  ledger, conformance unchanged.
* Result cache: repeat-query latency drops to metadata-fetch on the second run; invalidated
  correctly on write (reuse the ADR-051 LSN-pinning invariant; ADR-046 for WAL-tail
  coherence); a cross-tenant key-collision test proves structural isolation (tenant A's
  cached result is unreachable from tenant B's identical query).
