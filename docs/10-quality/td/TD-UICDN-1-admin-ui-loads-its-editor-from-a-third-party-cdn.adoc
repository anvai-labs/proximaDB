= TD-UICDN-1: the admin UI fetched its editor from a third-party CDN, so `npm audit` audited a version nobody ran

== History

`@monaco-editor/loader` does not bundle Monaco. It injected an un-SRI'd `<script>` from `cdn.jsdelivr.net/npm/monaco-editor@0.55.1`.
That gave two defects: unverified third-party code ran on the operator-session origin (plus an availability coupling), and
an **audit blind spot that manufactured false security progress**. `monaco-editor`/`dompurify` were lock-only peers, so #1993's
bumps (0.56->0.57, dompurify 3.4.8->3.4.15) changed `npm audit` output and **not one shipped byte**, while the executed 0.55.1 was
audited by nothing. Lesson: verify against the built artifact (bundle size, embedded URL), not the manifest.

* Chosen option: self-host, not CDN+SRI. SRI fixes only the first defect, and the loader has no integrity hook.
* **Loader guard bypass (review catch):** the first guard checked for the `loader.config` *substring*, which commenting the line out
  bypassed. The guard now requires a **statement-position** call, and it applies the override **through the shipped loader's own
  config-merge code** to prove the resolved script URL is `/vs/loader.js`. That executes the property on every build instead of
  asserting it once.
* Amended criterion: "no `cdn.jsdelivr.net` string in the bundle" is unachievable, because the loader's inert vendor default still
  bundles. The risk is reachability, not presence, and the executed-merge proof covers that.
* **Evidence:** the guard passes, and it fails closed on three negative controls (commented override, CDN override, missing
  `public/vs/loader.js`). Limitation: no network-blocked in-browser load test was run.

== Residual closed: `react-scripts` migration (2026-10-15, #2042)

`ui/` now builds with Vite 8 instead of Create React App. This closes the residual "the 101 remaining `ui/` advisories are all CRA transitives".

* `npm audit` went from **101 to 2** findings, and 22 of the 24 open Dependabot alerts closed.
* The self-host chain was re-verified on the Vite output:
** The guard runs unchanged in `prebuild` and prints `OK … loader resolves /vs/loader.js`.
** `vite preview` serves `/vs/loader.js` and `/vs/editor/editor.main.js` with 200.
** In the #2042 adversarial review's headless-Chrome (CDP) run, Monaco mounted with 18 requests to `/vs/` and zero CDN requests (recorded in a #2042 PR comment). That run was not network-blocked, so the History limitation above still holds for a blocked-network test.
* The two that remain are `dompurify` 3.4.15. `monaco-editor` 0.57.0 vendors its own copy, so an `overrides` pin would clear the alert without changing the shipped bytes; that is exactly the audit theatre this TD describes. Both alerts were dismissed as tolerable risk: they affect `IN_PLACE` mode only, which Monaco never uses. The fix is a `monaco-editor` release that bundles dompurify >= 3.4.16.
