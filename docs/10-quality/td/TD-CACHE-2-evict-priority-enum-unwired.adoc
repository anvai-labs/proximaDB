== History

The ADR-065 enum promised to drive both the per-tier GET trace and admission/eviction; only the trace
used it (`evict_priority` had zero callers and `put` evicted `map.keys().next()` — an arbitrary
victim that could shed a hot 24 MB Region A). Shipped: S1 priority-then-recency victim selection;
S2a 16-shard map with `AtomicU64` recency (hit = shard read lock + one relaxed store); S2b Region A
stored as its own entry so budget pressure sheds the region while the few-KB control plane keeps
serving; S2c `Other ≤ 0.3` kind ceiling on the survivor pool (`PROXIMADB_SURVIVOR_OID_CEILING_FRAC`)
so OID churn cannot flush SQ8 survivor ranges; S2d compactor input deletion calls
`invalidate(path)` + `SurvivorRangeCache::purge_path`. S3 (warming inserts with correct tiers) holds
by construction: the tier is derived from the entry's contents (`entry_tier`), so prefill puts are
tiered like any other.

Design decisions that still apply: **one shared byte pool with per-class floor/ceiling fractions,
never per-region static budgets**; physical structures split by *contention domain* (invariants vs
survivor), not by region; per-region policy via per-class keys. Sharding gotcha: DashMap is
sharded-LOCK, not lock-free — a recency stamp mutated on `get` must be an atomic in the entry, or every
hit takes a write lock. Cache correctness across re-clustering is structural (immutable, UUID-unique
segment paths); invalidation only reclaims budget.

Evidence: `invariants_cache_evicts_priority_then_recency`.
