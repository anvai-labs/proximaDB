== Problem

ADR-050 D2, amended 2026-11-19 under ADR-098, says plan-time statistics come from the metadata
spine: manifest per-file `ColumnFileStats` for Parquet/Iceberg and L1 directory entries for PAX.
Neither is built. Verified on develop @ `ea77dea50`:

* **Parquet/Iceberg.** `ObjectStoreParquetTable::statistics()` builds whole-table statistics
  from Parquet footers. On lazily opened, manifest-managed tables (TD-SPINE-4 Fix 4) it returns
  `None` until every footer has been resolved (`footers_complete()`). For a table whose filters
  always prune a file, that never happens, so DataFusion sees no table statistics for it. The
  manifest bounds are used only for file pruning.
* **PAX.** Both PAX table providers carry an `Option<Statistics>` set only by `with_statistics`,
  and `with_statistics` has no callers. So PAX tables expose no table statistics to DataFusion at
  all. The directory entries carry per-block prune statistics (`BlockPruneStatsTable`), which SST
  search uses for pruning, but nothing turns them into plan-time statistics.
* **Statistics envelope.** The registry in `src/core/statistics/` is fed by observing records on
  the write path (`observe_flush_into_statistics` in `src/storage/engines/sst/flush/mod.rs` at
  PAX flush, and the MATERIALIZE observer in `src/services/dml/mod.rs`, and the REST v2 collection-stats overlay in `src/network/rest/v2/collections.rs`, which overlays live counts, sizes and schema field facts and can create the summary before any flush). It never reads L1
  directory entries or manifests.

== Fix

. **Parquet/Iceberg.** At table open, derive whole-table statistics from the manifest's
  per-file `record_count`, `file_size_in_bytes` and `ColumnFileStats`: row count and byte size
  exact, column bounds and null counts `Inexact` per ADR-050 D3. Do this without reading
  footers. Follow the TD-SPINE-4 truncation rule: a string upper bound of 16 or more characters has no
  trusted upper bound, and a missing bound is unbounded. Footers stay the fallback for
  manifest-less tables.
. **PAX.** At table open, derive the same from the collection's directory entries (row counts
  and per-block bounds), trusting an entry only under the ADR-098 D2 `(size, ETag)` listing
  binding. Uncovered segments make the statistic unknown, never understated.
. Feed both into the existing `statistics()` path, so `ComputeScheduler` route decisions and
  DataFusion planning both see them.

== Acceptance

* A lazily opened, manifest-managed Parquet table returns non-`None` `statistics()` at open with
  zero footer reads (counted by the I/O trace's `parquet_footer_reads`). Row count equals the
  manifest's total, and bounds contain the eager footer-derived bounds.
* A directory-covered PAX table returns non-`None` `statistics()` at open with zero segment
  footer reads. A stale-ETag entry makes the affected statistic unknown (negative control).
* A route-decision test: a query on such a table makes the scheduler decision from these
  statistics (the route trace records the statistics source), where today it is made with none.
* The TPC-H/TPC-DS pgwire ratchets are unchanged.
