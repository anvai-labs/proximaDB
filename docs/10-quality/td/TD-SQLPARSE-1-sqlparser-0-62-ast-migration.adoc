== History (shipped)

DataFusion **55.0** already required `sqlparser ^0.62.0` while we declared 0.59, so the workspace compiled two
sqlparser copies with divergent ASTs (an earlier revision wrongly said 55.2 forced it). `arrow`/`parquet` were
**not** behind (an "arrow 58.3.0" in the lock was a duplicate pulled by `duckdb`).

The three semantic traps, each of which **compiles clean when wrong** (lessons for any future AST bump):

. **`PRIMARY KEY` demoted to `UNIQUE`.** 0.59 spelled a column-level PK `ColumnOption::Unique { is_primary: true }`;
  0.62 gave PRIMARY KEY its own variant, so the obvious port compiles and loses primary-keyness.
. **`Insert.columns` went `Vec<Ident>` → `Vec<ObjectName>`.** `ObjectName::to_string()` re-applies dialect quoting
  (`col` → `"col"`); port via `ObjectNamePart::as_ident()`.
. **`Values.rows` gained a `Parens` wrapper** — a named-field struct, payload `.content`, not `.0`; the compiler
  reports it as an iterator-trait problem.

Method lessons: do **not** drive a port from the compiler error list — port type by type against upstream
definitions. Two first-draft claims (constraint `columns` changed type; `ObjectName` restructured) were wrong and
retracted after diffing the vendored 0.59 source instead of reading error text that named the wrong type.
`Distinct::All` (`SELECT ALL`) is a no-op; `SelectItem::ExprWithAliases` and `FunctionArgExpr::WildcardWithOptions`
decline explicitly (folding the latter into bare wildcard would aggregate over excluded columns).

Evidence: baseline captured on develop first; TPC-H + TPC-DS ratchets identical after; the TPC suites exercise all
three traps (11 column-level PKs, 19 named-column INSERTs, 19 multi-row VALUES); `pgwire_fk_referential_actions_e2e` 4/4.

== Open: `PRIMARY KEY (c DESC)` yields column name "c DESC"

A **pre-existing** latent issue the migration deliberately preserved rather than fixed (changing it inside the
migration would be unattributable): `ddl_dml/mod.rs` (~L465) and `parser.rs` (~L3644) build a primary-key column
name with `col.column.to_string()`, where `col.column` is an `OrderByExpr`. For `PRIMARY KEY (c DESC)` that yields
`"c DESC"` as the column name, which then fails the column lookup. Predates 0.62.
