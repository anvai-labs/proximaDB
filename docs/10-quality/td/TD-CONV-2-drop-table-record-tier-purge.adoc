= TD-CONV-2: DROP TABLE left the record tier populated — a recreated table collided with (or served) the dropped rows

[cols="1,3", options="header"]
|===
| Field | Value
| Status | **Partial: DROP TABLE purges the DirectWal record partition + appends a `RecordPartitionDrop` WAL marker (#1900); open: Object-store/Iceberg-backed tables still take the warn-only trait default (`ObjectStoreIcebergRecordStore` has no `drop_table_records`, verified 2026-10-15).**
| Priority | **HIGH** at discovery — a recreated table's first re-INSERT failed with a false `INSERT_CONFLICT`, and scans could silently serve the dropped table's rows (wrong-data reads, not just errors).
| Component | `src/services/record_store.rs` (DirectWal record tier), `src/services/ddl/mod.rs` (DROP TABLE), `crates/storage/proximadb-storage-common/src/wal_entry.rs` (new canonical op).
| Relates to | link:TD-CONV-1-native-tpch-ddl-regression.adoc[TD-CONV-1] (same flake family — shared CWD catalog WAL), ADR-031 O2/O3 (oid-path cutover; a flipped gate masks this bug by giving recreated tables fresh partition keys), TD-064 (tenant-scoped partitions).
|===

== History (shipped)

*Bug.* SQL-row record oids are the PK text by design, and the DirectWal record partition was keyed by
the **bare table name**; `DROP TABLE` dropped only the catalog entry. So `DROP` → `CREATE` (same name) →
`INSERT` raised a false `Record '0' already exists`, and scans of the recreated table could silently
serve the dropped rows. A flipped ADR-031 O2/O3 oid-path gate would *mask* this by giving recreated
tables fresh partition keys. Found by `tpch_pgwire_e2e`'s accuracy phase (DROP + re-CREATE of the TPC-H schema).

*Fix (#1900).* New canonical WAL op `RecordPartitionDrop { collection_id }`: appended **before** the live
purge (a crash between them replays in the fail-safe direction), and replay voids the partition.
`TableRecordStore::drop_table_records` purges the `(tenant, collection_id)` partition, the legacy cutover
alias and lazily built UNIQUE/secondary index state; the trait default *warns* rather than silently keeping
rows. `DdlService` shares DML's record-store instance at every construction site. Shared-storage mode
(`DirectWalTableRecordStore::new`, unit tests only) cannot scope a purge and is skipped with a warning.

Evidence: `tpch_pgwire_e2e` 3/3 (deterministic failure before); unit test
`drop_table_records_purges_partition_and_wal_marker_replays_the_drop` (no resurrection on replay).

== Residual

* The new canonical op is an on-disk WAL format addition (serde-tagged enum variant). Per the
  pre-GA directive (internals replaced in place) no dual-format reader is shipped; old
  binaries reading NEW logs after a DROP will fail deserialization.
* Object-store/Iceberg-backed tables route the drop through the trait default (warn) until
  the Iceberg writer implements partition purge.
