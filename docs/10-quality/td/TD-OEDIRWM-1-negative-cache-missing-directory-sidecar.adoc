= TD-OEDIRWM-1: The directory-watermark reader never found the sidecar; fix the path, negative-cache genuine absence
:status: Accepted
:date: 2026-11-06
:tags: [cost, gets, voe-directory, freshness, correctness]

== Problem

Every Strong/BoundedStale vector query reads the object-economy directory's
freshness watermark (`cached_directory_watermark`), loading a per-collection
sidecar `{collection_root}/oedir/v0.bin` through a cache with a recheck TTL.

. **The reader looked in the wrong place.** It used the raw tenant
  `storage_assignment.base_location` as `collection_root`; the flush-side
  writer uses `collection_data_path_typed(base_location, collection_id,
  identity)` — the DrPath-scoped collection data directory. So the reader
  looked for `{base}/oedir/v0.bin` and never found the
  `{base}/accounts/{acct}/{ns}/{coll}/data/oedir/v0.bin` the writer wrote.
  The read-side watermark had therefore NEVER loaded a real sidecar: every
  strict query on every collection fell back to watermark (0, 0) after a
  404, and the delta-scan skip the feature exists for never fired.
. **Every 404 was retried after each idle gap.** A `Missing` result was
  cached like any other and dropped by the TTL.
. **Transient faults were indistinguishable from absence.** Any read error
  mapped to `Missing`.
. **The TTL was sliding.** `loaded_at` was re-stamped on every cache hit, so
  a collection queried at least once per TTL never expired, and the
  cross-pod staleness bound the TTL exists for never held.
. **A failed sidecar write skipped invalidation** (`?` returned before
  `invalidate`), leaving a stale entry over a sidecar that had committed.

== Decision

* Reader and writer resolve the root through ONE helper,
  `oedir_collection_root`, pinned by a parity assertion in the existing
  `flush_storage_path_matches_search_layout_policy` test.
* `load_with_status` maps only a backend `NotFound` to `Missing`; any other
  error is the new `DirectoryLoadStatus::Unavailable`, which keeps the
  ordinary TTL.
* `Missing` is negative-cached for `NEGATIVE_TTL_FACTOR` (10) x the recheck
  TTL — long enough to stop the repeated 404, bounded so a sidecar emitted by
  another pod is still picked up. Correctness-safe: `Missing` yields (0, 0),
  i.e. "always run the delta scan".
* `loaded_at` is stamped only on an actual load.
* `emit_after_flush` invalidates whether the write returned Ok or Err.
* A cached entry answers before the collection is resolved or a filesystem
  looked up.

== Rejected: removing the read-side fetch

The first cut of #2443 removed the fetch outright. That silently degraded
BoundedStale to Strong while route-health still advertised the bound, left
route-health's object-economy live status permanently `not_checked` (the
fetch was the cache's only production populator), and made EXPLAIN report a
fabricated watermark. It was reverted in favour of making the feature work.

== Not measured

The GET reduction and the newly-functional delta-scan skip are derived from
the mechanism (request counts by inspection), not from a per-query trace; no
`BENCHMARK_EVIDENCE.toml` entry is claimed.
