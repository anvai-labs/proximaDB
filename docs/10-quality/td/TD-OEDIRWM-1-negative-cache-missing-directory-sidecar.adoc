= TD-OEDIRWM-1: The query path read a directory watermark it could never soundly use — removed
:status: Accepted
:date: 2026-11-06
:tags: [cost, gets, voe-directory, freshness, correctness]

== Verified facts (#2443 review rounds 1–4)

* **Reachability.** Every REST record search reaches the delta merge:
  canonical handler → `RecordOpsService::handle_record_search_for_tenant` →
  `VectorOperationsService::search_records_with_tenant_context` →
  `run_unified_search_v1` → `unified_search_v1` → `unified_search_v1_inner` →
  `apply_delta_merge_with_explain`, which loaded the object-economy directory
  sidecar on every Strong / BoundedStale query.
* **The reader looked in the wrong place.** It used the raw tenant
  `base_location` as the sidecar root; the flush writer uses the collection
  DATA path. The reader never found a real sidecar, so every strict query
  paid a 404 (re-issued after each idle gap) and production NEVER skipped a
  delta scan on the watermark.
* **The watermark cannot soundly gate a skip.** It is stamped AFTER the flush
  commits (not at the flushed snapshot), so rows written during a flush sit
  behind it; and the sidecar is shared across pods while each memtable is
  per-pod, so pod A's sidecar would let pod B skip its own unflushed rows (and
  tombstones) of any age. Fixing the path alone would have ACTIVATED this.

== Decision

* **The query path no longer reads the directory.** `(0, 0)` → every
  Strong/BoundedStale query scans the delta, which is exactly what production
  already did. Zero sidecar GETs per query.
* **BoundedStale is served as Strong** (always correct, never stale);
  route-health reports `bounded_stale_time_bound_check: false` honestly, and
  EXPLAIN reports the watermark as `None` (not wired), not a fabricated 0.
* **Diagnostics load on request.** Route-health's live object-economy status
  loads the sidecar only when the endpoint is called
  (`object_economy_directory_status_for_diagnostics`), keyed by the canonical
  `collection.id` to match the writer.
* **One root composition** — `collection_data_path_for_assignment` — for the
  flush writer, the diagnostics loader and the record read-back (pinned by a
  parity assertion). Other hand-composed sites remain: the storage-traits
  `collection_storage_path`, `services/operations/vectors/read.rs`,
  `engines/nova/operations/search.rs`, `services/collection/manager.rs`
  (two sites) — migrate them to the helper.
* Load mapping: only a backend NotFound is `Missing` (negative-cached at 10x
  the recheck TTL); any other read error is `Unavailable` (ordinary TTL).
* Writer: refuses to overwrite a sidecar it could not read (a transient
  failure no longer truncates every earlier entry to "empty + one"). The
  refused flush's entry is not re-added later; since the sidecar now feeds
  diagnostics only, the gap is acceptable and visible as an `Unavailable`
  warning. `emit_after_flush` invalidates whether the write succeeded or not.

== To re-enable a delta-scan skip (future, not planned)

Needs a SOUND watermark: stamp the snapshot LSN/ns at flush START, and scope
it per pod (or fence it by memtable epoch) so a shared sidecar cannot vouch
for another pod's memtable. Then prove read-your-writes across pods before
any skip is allowed for Strong.

== Not measured

The GET reduction (one sidecar GET per strict query per idle gap → zero) is
derived from the code path, not a per-query trace; no
`BENCHMARK_EVIDENCE.toml` entry is claimed.
