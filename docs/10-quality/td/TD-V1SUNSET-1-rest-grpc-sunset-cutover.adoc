== History

* **Trap (name collision):** `crates/platform/proximadb-api/src/rest/v1/` looked like the deprecated surface but was **live
  `/api/v2` code** (port-backed graph/document/observability/multimodal/hybrid routers). The planned "Step 3 hard-delete" was
  INVALIDATED (2026-07-09) because it would have broken the build and removed `/api/v2` routes. The module was later renamed under
  TD-104 and now lives at `rest/canonical/`. Lesson: verify a deletion target's callers, not its path segment.
* **gRPC v1 completed as a hard removal**, not the documented flag-gated retirement. `enable_grpc_v1_compat` had zero references by
  the 2026-08-28 census, while `SUPPORTED_SURFACE` still described it as live.
* **The Step 5 gate was unobservable:** the REST metrics `route_layer` is post-routing, so unmatched `/api/v1/*` 410s were metered
  nowhere (same class as TD-TENANT-3 S4). A suspected "`.layer()` does not fire for unmatched paths" defect was **refuted
  empirically** and pinned (`unmatched_v1_path_still_gets_410_not_404`).
* **Live conflict:** `enterprise-catalogs` nested its API under `/api/v1/catalogs`, dead-on-arrival under the 410. It was moved to
  `/api/v2/catalogs` with no alias. Its feature-matrix lane compiled but never *served* the feature; it now runs the catalog tests.
* **Closure basis (recorded honestly):** not the counter window, which never accumulated because no release shipped. Instead:
  every known client was accounted for (the SDKs never called v1, and AnvaiOps makes zero `/api/v1` calls), there had been ~7 weeks
  of 410-by-default, and the migration affordance survives (`removed_v1_paths_404_with_the_v2_replacement_named`). Only the RFC
  8594 headers were lost.
