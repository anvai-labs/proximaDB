== History (shipped)

* Filed 2026-07-23 on SIFT 1M (6 L0 → 1 L1): 666 s compaction (expected ~10 s), `0.0 MB/s` throughput, recall 0.999→0.986.
* Lesson: the 666 s was **not** re-cluster CPU — it was the TD-COMPACT-2 phantom-embedding-column blow-up (compaction passed `records.len()` as `embedding_count` → 105k phantom columns → 40–52 GB RSS → swap). Root-caused by #1173/#1175 instrumentation, fixed by #1175. #1169 also scaled the IVF train sample with k.
* Lesson: `0.0 MB/s` was a silent size-probe failure plus a one-decimal display artifact; size probes now WARN instead of silently zeroing, and event-sourced counters exist (`proximadb_compactions_total`, `_bytes_{read,written}_total`, `_seconds`) (#1179).
* The recall dip does not reproduce: recall is identical pre/post compaction on disjoint query sets (0.9850==0.9850, 0.9815==0.9815).
* Evidence: 1M SIFT ratchet — 9 compactions in 19.7 s total (mean 2.2 s), peak RSS 7.4 GB (was 52 GB), 1M ingest 88 s with zero drain-pauses.

== Open

* **Absolute-recall observation (flagged to #1175):** absolute recall 0.985 vs the pre-storm 0.999 baseline (pre==post, so not compaction-caused; possibly the MAX_BLOCK_ROWS=16k bound re-cutting 21k-row flush cells — layout variance to confirm).

* **S3 — Preserve IVF model across compaction**: instead of re-clustering from scratch, carry the original IVF model (centroids + PCA) into the compacted segment. The flushed segments already have a consistent IVF model (same writer); merging them shouldn't require re-training. This eliminates the recall dip AND the re-cluster CPU cost.
+
Review note (2026-07-23 TD sweep): call-chain audit for TD-IVF-1 confirms S3's premise: the only reachable `AxisClusteringEngine::train_model` callers are the IVF `External` build path (`dual_store_ivf.rs`) and the poll-driven discovery recluster pass — the 666s re-cluster compaction re-enters the same k-means that TD-IVF-1 removes from restart. Fixing S3 (carry the persisted A0 model into the compacted segment) therefore addresses BOTH the compaction wall-clock and the recall dip (cell boundaries stay put), and it is the same mixed-read-safe persisted-model-reuse mechanism as TD-IVF-1 S1. Kept OUT of the 2026-07-23 TD-sweep PR deliberately: it is flush-path surgery that needs its own 1M-recall ratchet run before merging.

* S4 — Parallelize compaction (if CPU-bound): the re-encode of N vectors is embarrassingly parallel (per-vector RaBitQ encode). Use rayon or tokio::spawn for the encode phase. (Lower priority since the measured mean is 2.2 s per compaction.)

Impact on search latency (why compaction speed matters): 6 L0 files 504 ms mean (157 GETs) → 2 files 157 ms (86 GETs) → 1 file ~80 ms est (~43 GETs).
