== History

`build_kru` predated the `CountingFileSystem` → `IoTrace` composition (#553) and read only
`SearchPlanTrace.index_stats`, so the dominant cloud cost term (object-store GETs per query) never
reached the per-tenant metering event. Decision that still applies: the emitted GET count is aligned
to `range_gets` — the accurate single-source count after #1081 fixed a `range_gets`/`bytes_read`
double-count — **not** `get_ops`. The interim-$0 under-return rule for the physical KRU term can
retire downstream.
