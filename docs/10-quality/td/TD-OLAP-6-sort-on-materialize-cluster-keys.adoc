== Why (measured root-cause chain, 2026-07-04)

Zone-map pruning on the DataFusion/warehouse route skipped 0% in every
evidence configuration (`TPC_PERF_GATE_EVIDENCE_2026_07_04.adoc` and the v2
follow-up). Diagnosing link by link:

. Static predicates never reached `scan()` — **fixed** (#671, `supports_filters_pushdown`).
. `DATE` literals never translated into pruning predicates (TPC-H's filters
  are almost all date-ranged) — **fixed** (Date32/Date64/Timestamp arms in
  `physical_filter_translate::df_scalar_value`).
. The materializer wrote ONE row group regardless of table size (Arrow
  default: 1,048,576 rows) — one split, nothing to prune — **fixed**
  (`warehouse_writer_properties`, default 65,536 rows,
  `PROXIMADB_MATERIALIZE_ROW_GROUP_ROWS` override).
. **Remaining:** with 4096-row groups over 20k rows inserted strictly
  date-ordered, every row group STILL spans the full date domain
  (footer diagnostic: all five groups min=8766 max=9066) — the materialize
  snapshot scan does not preserve (or impose) any row order, so clustering
  in the source data is destroyed at publication.

== Rollout (design sketch; mixed-read-safe — ordering is not a format change)

. **Cluster-key metadata:** per-table optional cluster key (e.g.
  `CREATE TABLE ... WITH (cluster_key = 'l_shipdate')` or
  `ALTER TABLE ... CLUSTER BY (col)`), stored in the catalog schema.
. **Sort at MATERIALIZE:** the snapshot writer sorts the collected records by
  the cluster key before `write_records_to_parquet_with_schema` — one sort at
  publication time buys tight per-row-group min/max forever after (real TPC
  and telemetry data are time-keyed; this mirrors Snowflake clustering keys /
  Iceberg sort orders).
. **Default heuristic (optional):** when no key is declared, sort by the first
  DATE/TIMESTAMP column if one exists — the dominant analytical access shape.
. **Iceberg interop:** record the sort order in the published TableMetadata
  (Iceberg `sort_orders`) so external engines benefit too.
. **Evidence:** re-run the TD-OLAP-4 gate-promotion evidence (clustered
  generator + small row groups are already in place); TD-OLAP-3's runtime
  filter and static date pruning should finally show non-zero skip ratios —
  the promotion gate.
