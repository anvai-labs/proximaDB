= TD-MANIFEST-1: Unbounded manifest-log growth + O(n) tip scan on every lease op

[cols="1,3", options="header"]
|===
| Field | Value
| Status | **Partial: the core fix shipped (#565) — generic `ManifestCommitter::prune_retention`, an owner-only lease prune loop and catalog prune-on-write, all default ON; open: three deferred follow-ups (see below), none blocking.**
| Severity | High — unbounded object-store growth (562 MB / 144,546 files from one 3-day run) + O(n) per lease op → O(n²) over a pod's lifetime.
| Component | `crates/storage/proximadb-iceberg-engine/src/manifest.rs`; `src/cluster/partition_lease.rs`; `src/network/shared_services.rs`; `src/services/catalog_snapshot_store.rs`.
| Relates to | link:TD-LEASE-INFRA-1-ownership-publication-consolidation.adoc[TD-LEASE-INFRA-1] (overlap: its M1–M4 counterexamples show a delayed or stale `commit` can publish into a slot this retention pruned and return a false `Committed(_)`; the hardening of `prune_retention` and conditional publication is tracked there)
| Pillar | COST, PERF, REL
|===

== History (shipped)

* Symptom: an orphaned server accumulated ~48k `v{N}.manifest` per collection under `_operator/leases/…/_manifests/`; `latest_version()` LISTed every object then took the max on every `read`/`acquire`/`renew`/`commit_fenced`, driven by the 5 s renew loop. The same never-pruned log backs `catalog_snapshot_store.rs`.
* Decision that still applies: **cap the manifest count; do not add a mutable tip pointer** — bounding n makes the tip scan cheap, and a pointer would reintroduce the lost-update/ABA hazard the create-only `put_if_absent` protocol exists to avoid.
* Safety invariants: never delete the tip; eligible = ranked `keep_k`+ behind the tip (rank, not `tip - v`, so gapped logs work) **and** at least `min_age` old (protects the recent burst and release tombstones); `keep_k` ≥ 2 (`MIN_PRUNE_KEEP_K`); a future-dated `last_modified` is never reaped early; deletes are best-effort and idempotent.
* Wiring: `PartitionLeaseManager::prune_held` + `spawn_prune_loop` (prunes only logs this pod owns; knobs `PROXIMADB_LEASE_MANIFEST_*`); `CatalogSnapshotStore::prune_retention` prune-on-write in `write_atomic`, never failing the publish (knobs `PROXIMADB_CATALOG_SNAPSHOT_*`, `keep_k=3`).
* Evidence: 8 unit tests, load-bearing `prune_preserves_fenced_commit_after_prune` and `prune_then_stale_writer_still_fenced`.

== Follow-ups (out of scope)

* `_catalog/leases` manager (`shared_services.rs`, off-by-default, no renew
  loop) accumulates negligibly today; wire `spawn_prune_loop` there if its renew loop is
  ever enabled.
* Tip-pointer / probe-upward discovery to avoid the one O(n) `list` on cold start — not
  needed once `n` is bounded.
* Coalesce renewals (skip a write when expiry barely advanced) to cut the write rate.
