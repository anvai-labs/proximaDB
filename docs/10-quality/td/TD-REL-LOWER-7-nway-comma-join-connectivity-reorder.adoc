== History

`FROM a, b, c` lowered left-deep in *textual* order, so two adjacent tables connected only transitively (Q9
`part, supplier` via `lineitem`) stayed a raw cross product and declined. `comma_join_order` builds an equi-graph
from WHERE `col = col` conjuncts and greedily appends the lowest-index entry connected to the placed prefix, so
every level has a join key. Because it applies wherever a comma FROM is lowered, it also fixed Q8's 8-table comma
join inside a derived table with no separate derived-table work.

Correctness (still applies): comma/inner joins commute and associate and ordinals are assigned *after* the
reorder, so results never change; it is a no-op on an already-connected order, fewer than three entries, or no
WHERE; unresolvable columns drop their edge. Only a bare `SELECT *`'s column order can differ. Cost-based join
*ordering* remains out of scope.

Evidence: `tests/rel_join_reorder_e2e.rs`; frontend unit `comma_join_order_places_hub_between_disconnected_tables`;
TPC-H Q9 + Q8 native row-exact (14 → 16/22).
