== Context

The canonical spine (`TableRecordStore` + `TableWalAppender`, tenancy in every signature) is adopted on
a gradient; siloed modalities re-invent tiers/tenancy/WAL and drift on correctness/security (RFC-0002
§map). This TD is the build plan to consolidate the **contract surface** (ADR-072 D1) so modalities
stack on one foundation, with modality-specific impls behind the contracts where access diverges (D2).

=== The catalog governance metamodel (the seam that makes the primitive modality-agnostic)

`Container → Entity → Attribute → Identity/Uniqueness → Index → Constraint/Policy`, projected per
modality (relational `db/table/column/PK/btree`; vector `namespace/collection/field/oid/ANN`; document
`collection/path/_id/fulltext`; graph `graph/node·edge/property/(src,dst,type)/CSR`; observability
`namespace/stream/field/(series,ts)/Tantivy`). DDL/RBAC/schema-evolution written **once** against the
metamodel — this is the **naming/governance** unification, and it is real.

**Scope narrowed (P2).** The metamodel unifies *naming and governance*, **not** a universal uniqueness
primitive. The reviews correctly flagged that "uniqueness on the Identity key" is procrustean beyond
relational + document: a **vector `oid` is a system surrogate** (not a natural PK — it conflicts with the
"natural keys mandatory" rule); a **graph edge is identified by an `edge_id`** and is multigraph-capable
(`(src,dst,type)` is *not* its identity — verified in `orion-engine/.../memory_pool.rs`), and it is
itself an FK-pair; **time-series identity is monotonic-append `(series, ts)`, not a uniqueness
constraint.** The fenced `ConditionalKeyStore` therefore applies to **relational PK/UNIQUE (and document
`_id`)**; other modalities enforce identity through their own operators. Note this is a *doc* narrowing:
`ProximaRecord` already models `edge`/`sequence` first-class (ADR-072 D10), so no record change follows.

**Metamodel calibration (P3 — ADR-072 D12, grounded in U-Schema <<biblio-uschema>>).** The leading
unified metamodel confirms and sharpens this: (1) a **graph edge is a first-class `RelationshipType`
(peer of `EntityType`) + a `Reference`** — model edges as a first-class relationship construct, *not*
through the `Identity/Uniqueness` slot; (2) the identity slot is **family-parameterized** (graph omits
it, key-value detaches it, time-series is ordering-not-uniqueness) — carry a per-modality
"completeness-gap" list rather than one uniform semantics; (3) U-Schema **splits physical (Index) and
Constraint into a separate metamodel** — so split our governance-logical layer from the physical-index
layer rather than one `…→Index→Constraint` chain. **Open risk:** no unified-metamodel paper covers
**time-series or vector** identity — pressure-test these before finalizing D1.

== `ConditionalKeyStore` extraction

The ledger's proven CAS core (`crates/modalities/proximadb-ledger`: atomic conditional admit + WAL +
single-writer + CRC-framed torn-tail-tolerant replay) is the reference. Extract + generalize:

- **Generalize the key/value:** ledger CAS keys on `&str` → version `i64`; the shared primitive keys on
  the **typed composite `Identity`** (F0, below) → `Oid` (payload/row pointer). Crucially, **keep the
  fence:** the ledger CAS returns a `Version`; the shared contract must too.
- **Contract (fenced + capability-typed — ADR-072 D3/D11):**
  `put_if_absent(t, keyspace, key: &Identity, oid, fence) -> Result<Committed, Conflict{holder: Oid}>`
  + `get` + **append-only tombstone** (not a reclaiming delete). Three research-driven properties:
  * **Returns the current holder on conflict** (not a bare failure), so a loser resolves
    retry-vs-real-conflict — Cornus `LogOnce` returns the settled state (ADR-072 <<biblio-cornus>>).
  * **Append-only reclaim (D11):** a PK `UPDATE`/`DELETE` appends a tombstone + new version under the key
    (resolved by `version ≤ snapshot`), reclaimed behind an oldest-active-reader watermark — it never
    delete-then-reinserts a durable slot. This dissolves the reclaim race and largely subsumes the
    explicit fence into MVCC ordering (cMVBT; unanimous with BatchWeave/DSQL — ADR-072 §P3).
    **Tier-split physical delete (D14):** MVCC is the *visibility/uniqueness* model; its physical delete
    is row-level MVCC in the hot/local-WAL tier and **deletion vectors / merge-on-read** in the immutable
    cold columnar tier (a hot tombstone flushes to a DV, purged at compaction behind the same watermark).
    A DV encodes deletes but does **not** enforce uniqueness — that stays with MVCC + this index. Build
    split: hot MVCC = F1d; cold deletion vectors = F3v.
  * **Capability-typed scope:** each impl *declares* its atomic scope/granularity (ScalarDB Atomicity
    Unit; not a boolean), so callers never assume uniform atomicity.
- **Two impls behind it (ADR-072 D4/D5 — revised):**
  * *generation-fenced local-WAL CAS* — the ledger core generalized `Identity→oid`; sub-ms; **the hot,
    correctness-carrying default.**
  * *object-store `put_if_absent`* — the **scale-to-zero escape hatch**, not the default. Its existing
    proof (Iceberg manifest / partition lease) uses *fresh monotonically-versioned successor slots*, an
    append-only pattern that does **not** transfer to a reclaimable fixed PK slot; used only where its
    generation-fence + successor-slot discipline (per `partition_lease.rs`) is honored.
- The ledger's own CAS keyspace becomes a specialization of the same contract (str→version is a
  `bytes→scalar` case).

== The MVP — composite-natural-PK atomic uniqueness

**Goal:** a `PRIMARY KEY (a, b, c)` (composite, natural) insert is rejected on duplicate **atomically at
the storage layer**, serverless-capable — replacing the op-lock crutch.

**Seams (from the map):**
- Integrity checks today: `execute_insert` `src/services/dml/mod.rs:3004-3043` (PK), `:3045` (UNIQUE),
  guarded by the table op-lock `:2968`, then commit `write_mutations` `:3089`.
- Target (revised P2/P3): move the **primary-key** guarantee **into** `TableRecordStore::write_mutations`
  (`record_store.rs:502`) as a **fenced** `ConditionalKeyStore::put_if_absent` on the row's own
  PK-derived identity — recall `oid == primary_key_string` (`relational.rs:282`), so PK uniqueness is a
  **single row-keyed-by-PK** conditional write, not a separate index entry. **Only `UNIQUE` constraints
  take the coordinated path; non-unique secondary indexes are blind-writes keyed by the PK** (they cannot
  conflict independently of the base row — Aurora DSQL's CALM/blind-write result, ADR-072 <<biblio-dsql>>).
  Secondary `UNIQUE` (a real second durable write) and FK (a `get`) **remain inside the op-lock critical
  section** for the MVP.
- **The op-lock is retained, not demoted** — its docstring (`proximadb-catalog/src/manager.rs`) shows it
  orders `ON DELETE CASCADE` (child-scan → child-mutation → parent-tombstone); demoting it re-opens the
  cascade-orphan race. A concurrent-INSERT throughput win comes later, from narrowing the lock to the
  secondary-index critical section once F0's fenced primitive owns PK uniqueness — not from removing it.

**Acceptance:**
- Concurrent inserts of the same composite PK → exactly one succeeds; the fence lets the losing writer's
  idempotent retry be distinguished from a genuine conflict (no false-conflict livelock).
- PK-`UPDATE` / `DELETE` then re-insert of the same key leaves **no orphaned slot** (fenced tombstone,
  not unconditional delete).
- Local-WAL (default): fenced uniqueness holds across a crash/restart (torn-tail replay). Object-store
  (escape hatch): duplicate rejected across a compute restart **where the partition-lease generation
  fence is held** — not from a naked fixed-key create.
- Typed-identity codec (F0) passes property tests: no two distinct tuples collide, no tuple encodes two
  ways, byte order preserves column order incl. NULL/type-tag.
- `default` build + all existing tests unchanged (behind an `oltp-integrity` cfg feature).

**Scope:** composite-PK now (row-keyed-by-PK, fenced) + single/multi-column UNIQUE inside the op-lock.
**FK is phase 2** — a `get` on the same contract (parent-existence), different shape, cleanly deferred.

== Contract-adoption roadmap (leaf-first, additive, feature-gated)

|===
| Step | Work
| *F0* | **Typed composite `Identity` codec** (ADR-072 D9) — replace `oid: String` + `encode_primary_key_tuple` string-join with a length-delimited, order-preserving, NULL-explicit, type-tagged, tenant-scoped key; `oid`/`local_id` derive from it. Property-tested. Foundational prerequisite for F1.
| *F1* | Extract the **fenced** `ConditionalKeyStore` + the **generation-fenced local-WAL impl** (default) and the object-store escape-hatch impl; ledger CAS re-expressed as a consumer (proves the shared primitive, fence preserved).
| *F2* | **MVP:** composite-natural-PK uniqueness on the relational insert path via F0/F1 (row-keyed-by-PK); op-lock **retained** (secondary UNIQUE/FK stay in it); `oltp-integrity` feature.
| *F3* | Re-express ledger/queue/TS dedicated WALs as impls of the WAL contract (stop off-contract silos); siloed modalities consume the shared tiering contract instead of their own tiers; standardize the record-store substrate on columnar/PAX (D13).
| *F3v* | **Deletion vectors / merge-on-read (D14)** — cold-tier physical delete for immutable columnar objects (roaring-bitmap DV per data file, Iceberg-v3/Delta style); hot-tier MVCC tombstone → DV on flush; DV-purge at compaction behind the reader watermark; CoW fallback for read-heavy files. Parallel to the critical path. Depends on F1d + F3.
| *F4* | Finish document's canonical-store migration; onboard vector reads-side where the shared scan suffices (keep ANN as an extension operator). Depends on F3v (cold-tier delete path).
| *F5* | FK / referential integrity (phase 2, `get` on `ConditionalKeyStore`); then HTAP — native compute (Volcano/DataFusion) TPC-H over atomically-consistent data.
| *F6* | **Background plane (P6/D17)** — request-path-isolated services: compaction (merge-on-read rewrite), incremental index-optimize (fold unindexed fragments; brute-force until folded), version/DV GC behind the reader watermark, read-cache over object storage. Parallel. Depends on F3v.
| *F7* | **Hybrid/filter query planner (P6/D15)** — cost-based pre/post/exact by filter selectivity; structured predicate compiled to a global doc-id allow-list woven into ANN traversal; tenancy/RLS rides the same global filter (always ANDed); exact fallback for restrictive filters. Terminal of the multimodal chain (~16w). Depends on F4.

Each step: additive, `#[cfg]`-gated (compile-time composition, ADR-072 D7), one modality/contract at a
time, with reclaimed-footprint / latency / throughput evidence filed to `BENCHMARK_EVIDENCE.toml`
(measure-don't-assert).

== Cohesion / coupling / correctness

- *Cohesion:* a modality owns only its semantics + operators (ANN, CSR, PromQL, budgets) and its
  contract impl where access diverges.
- *Coupling:* modalities couple to the foundation **via contracts only, never to each other**; the
  storage⊥compute contract is the one deliberate seam (both swap). Coarse-grained dispatch (per
  batch/query) → zero per-row cost.
- *Correctness under security:* every contract carries `TenantContext` (fail-closed); the atomic
  primitive removes the TOCTOU race the op-lock papered over; the object-store impl makes it correct at
  serverless scale.

== Risks & non-goals

- *Risk:* moving uniqueness into `write_mutations` is on the hot write path + touches a central store —
  gated behind `oltp-integrity`, MVP-scoped, evidence-gated.
- *Risk:* object-store `put_if_absent` latency/cost + non-transferable reclaim semantics — it is the
  escape hatch, not the default; the generation-fenced local-WAL impl is the hot default (ADR-072 D5).
- *Non-goals:* multi-statement ACID transactions; one shared WAL for all modalities (rejected, ADR-072
  D2); changing any modality's semantics; a single god storage trait.

== Unresolved questions

- **Resolved (P2):** the shared composite-key encoding is **not** a reuse of `encode_primary_key_tuple`
  — that codec is documented-defective (unescaped `\u{1f}` separator collisions, non-order-preserving,
  type-lossy; `relational.rs:864`). F0 replaces it with a typed codec. Open: exact type-tag/collation
  table per `ProximaType`.
- **Resolved (P2):** object-store is the **escape hatch**, generation-fenced local-WAL is the default
  (ADR-072 D5) — reverses the earlier lean.
- The exact `Generation`/fence source for the local-WAL default (reuse the partition-lease generation, or
  a WAL-sequence epoch?) — F1 detail.
- Whether to later narrow the op-lock to a secondary-index-only latch (throughput) once F0/F1 own PK
  uniqueness — measure first.
- How far to widen `RecordStore` into observability/timeseries vs. keeping them contract-impl silos.
- The `ProximaRecord` union → composed `RecordCore` + `#[cfg]` modality-extension refactor (ADR-072 D10)
  — routed to the compile-time modality-composition track (#1180), not this MVP.
- **Key encoding — calibrated (R2 done):** the F0 codec is specified against the FoundationDB tuple layer
  + CockroachDB key encoding — see _Appendix A: F0 `Identity` codec_. Secondary-index maintenance remains
  thin in research; calibrate during F1.

== Appendix A — F0 `Identity` codec spec (R2 calibration)

Grounded in the FoundationDB tuple layer <<biblio-fdbtuple>> and CockroachDB key encoding
<<biblio-crdbenc>>. Three principles both systems share (and the current `encode_primary_key_tuple`
violates): **prefix-free / self-terminating** per column (concatenation is unambiguous → no two tuples
collide), **order-preserving** per type (`enc(x) ≤ enc(y) ⇔ x ≤ y`), and **type-tagged** (self-describing).

Layout: `tenant/keyspace prefix ‖ col₀ ‖ col₁ ‖ …`, each `colᵢ = <type-tag> <order-preserving payload>`.
The tenant/keyspace is a leading length-delimited string field → each tenant's keyspace is a contiguous,
isolated range (satisfies D6).

[cols="2,1,4", options="header"]
|===
| ProximaType | Tag | Payload (order-preserving)
| `Null` | `0x00` | empty (sorts first)
| `Boolean` | `0x01` | 1 byte `00`/`01` (false < true)
| `Int8/16/32/64`, `Date`(i32), `Time/Timestamp/TimestampTz`(i64) | `0x02` | big-endian, **high bit flipped** (`v XOR 2^(n-1)`) — maps signed onto monotonic unsigned
| `UInt8/16/32/64` | `0x03` | big-endian as-is (already monotonic)
| `Float16/32/64` | `0x04` | IEEE big-endian; **sign set → flip all bits, else flip sign bit** (total order incl. `-0<0`, NaN)
| `String`/`Symbol` | `0x06` | UTF-8, `0x00 → 0x00 0xFF`, terminate `0x00` (byte order = codepoint order)
| `Binary`/`BinaryVector` | `0x07` | bytes, `0x00 → 0x00 0xFF`, terminate `0x00`
| `Uuid`/`ULID` | `0x08` | 16 bytes big-endian as-is (ULID stays time-sortable)
| `Decimal` | `0x05` | order-preserving `(sign, exp, digits)` — **phase 2 / restricted**
| `Json/Jsonb/Array/Map/Struct/DenseVector/SparseVector` | — | **rejected as PK/UNIQUE component** at DDL
|===

Four semantic rules the codec must carry (beyond bytes):

1. **`UNIQUE` + NULL ≠ duplicate.** SQL `NULL != NULL` — two tuples differing only in a NULL column are
   *not* a violation. The codec encodes NULL (`0x00`); the **uniqueness enforcer skips the check when any
   UNIQUE column is NULL** (F1a/F2 concern, not the codec).
2. **TimeUnit normalization.** Normalize `Time/Timestamp/TimestampTz` to a canonical unit (nanos) before
   encoding, or `1s` and `1000ms` diverge.
3. **Structured types rejected at schema validation** (PK/UNIQUE columns must be scalar order-comparable).
4. **Descending columns = phase 2** (per-column byte-complement, CRDB technique); Decimal + locale-aware
   collation (ICU keys) likewise phase 2 — MVP is all-ascending, binary/UTF-8 collation.

F0 acceptance (property tests): no collisions; order-preserving per type + composite; round-trip decode;
NULL/type-tag correctness; TimeUnit-normalization idempotence; embedded-`0x00` escape.
