== History (shipped)

* Step 1 = link:TD-DFR-1-columnstatistics-for-datafusion.adoc[TD-DFR-1]: footer-derived `ColumnStatistics` + registry NDV overlay on the DataFusion provider.
* **A2 (#886).** The registry was designed but never *populated* in production: the overlay read an empty
  registry ⇒ `distinct_count = Absent` ⇒ `EnforceDistribution` fell back to a single-partition, single-core
  hash-join build — the measured 100–700× gap vs DuckDB at SF=0.1. `publish_ndv_statistics`
  (`src/services/dml/mod.rs`) now folds the materialized records into per-column HLL sketches at the write
  boundary (zero new scan), keyed by table name — the same key `ObjectStoreParquetTable::statistics()` reads.
  Lesson: the reverted A1 `num_rows`-as-NDV proxy overestimated low-cardinality columns (`l_returnflag` NDV=2
  → proxy 60K) and chose an exploding join plan at SF=0.01; the HLL carries the true count (±~2%).

== Why

ADR-037/038 specify a mergeable statistics envelope; `src/core/statistics/{summary,sketches}`
already implement min/max, NDV (HyperLogLog), TDigest quantiles, null-count, and a registry.
Its consumers today are the pgwire EXPLAIN selectivity surface (`relational_pipeline.rs` →
`statistics_registry().equality_selectivity`) and the federated optimizer
(`optimizer/{selectivity,plan_calibration}.rs`) — but none of it reaches **cost-based physical
planning**: `schema_inference.rs` returns `ColumnStatistics::new_unknown()` (its
`extract_statistics` has no call site; table providers default `statistics: None`), so the
DataFusion planner plans blind, and the native planner has no cardinality model. Snowflake's
signature posture is *"all statistics used for optimization are automatically maintained"* and
a no-indices Cascades CBO; Spark AQE/DPP depend on runtime stats. A competitive engine cannot
ship a statistics-blind planner.

== Rollout

. **[shipped — TD-DFR-1]** **Close ADR-050 D2 (= TD-DFR-1):** project the ADR-042 `SegmentStatistics`
  (min/max/distinct/null) into DataFusion `ColumnStatistics` in `schema_inference.rs`
  (replace `new_unknown()` and actually wire `extract_statistics` to the table providers) —
  zero new scan; the stats substrate's next consumer.
. **Persist + freshness:** stamp per-segment stats with the ADR-038 freshness watermark; merge
  up the segment→row-group→table hierarchy; invalidate on compaction / DV application.
. **Cardinality estimation:** feed NDV + TDigest histograms into the federated optimizer's
  selectivity/cardinality code (`src/query/federated/optimizer/`) so join ordering and filter
  costing use real distributions, not defaults.
. **Histograms for joins:** add equi-depth/equi-width histograms for join-column selectivity
  (today only TDigest quantiles exist).
. **Calibration:** wire the TD-158 observed-cost trace back as a cardinality correction ratio
  (infrastructure exists in the federated optimizer; tune it).

== Verification

* A plan-explain diff shows non-`unknown` cardinality on TPC-DS tables.
* Join-order changes measurably on skew-sensitive TPC-DS queries (Q72/Q95-class) once stats
  land, with conformance ratchets unchanged.
* Freshness: a write advances the watermark; a stale-stat query is flagged in EXPLAIN.
