This is the implementation spec for ADR-062; the ADR carries the *why* (measured GET ceiling, alternatives rejected).

== History (shipped)

*Capability.* A self-contained PAX segment = header prefix + coalesced RaBitQ head (one GET, cached) + blocks +
self-describing footer (block extents, per-stripe encoding map, typed optional sections, typed stats slot).
Reads are scan-then-rerank: rank the whole RaBitQ head, then coalesce survivor-block GETs; adaptive survivor M
expands until the next survivor would cost a new GET. Block geometry is self-derived from dim × tier composition
× backend `IopsBudget` (a per-backend property, not the `StorageProfile` workload enum). Readability is preserved
by a presence field (`rabitq_off` present ⇒ scan-then-rerank; absent ⇒ legacy in-block path); unknown data
encodings fail closed. Compaction atomicity is Iceberg-style fresh-name + WAL-authoritative manifest advance via
create-only `put_if_absent` (no `if-match` CAS yet).

*Decisive findings that still apply.*

* GETs/query is the billing-cost KPI (Azure read txns ~10–16× S3 GET price); GETs scale with fragmentation, not
  bytes. Byte-compression of encodings does not help GET coverage (same-AZ transfer is free). The downstream meter
  bills queries + physical bytes, never GETs.
* A segment-size-independent fixed candidate pool fails at scale (N=1M flat SQ8: recall 0.968, 61 GETs) — hence adaptive M.
* IVF ordering is *not* load-bearing for the coalesced layout (no-IVF run: recall 0.985, 40 GETs, ~80× faster
  flush); its only benefit was bytes, which ADR-065 Region B removes. Current order: SQ8-Morton at coalesced
  flush, PCA+IVF/Hilbert at compaction.

*Evidence:* PR1 SIFT1M N=100k recall@10 0.984 / 20 GETs / 31.7 MB per query; PR2 (#1060) recall 0.987/0.990 and
8/36 GETs per query at 100k/1M (46×/10.3× vs legacy) — clearing the downstream pricing gate.

== Open

=== Point lookup — per-block OID Bloom

* **Per-block per-column STATS** — optional, tagged, extensible:
+
```
stats: [ per-column: { col_id, stats_kind: StatsKind, payload } ]
enum StatsKind { None, BloomOid, MinMax, BloomOid_MinMax, … }   // add kinds, no format change
```
PR1/v1 emits `StatsKind::None` with an empty payload. PR3 activates `BloomOid` (per-block OID
Bloom, no false negatives → `vector_by_id`/edge-by-oid skips to the one positive block).
`MinMax` pushdown + Bloom on other columns remain deferred.

* **Point lookup — OPEN:** per-block OID bloom (`StatsKind::BloomOid`) + `vector_by_id` fast path.
* Measured Bloom sizing/FPP (Q6) remains here; footer-index sizing at scale (Q2) and the
  schema-footer vs catalog-authority invariant (Q3) are follow-ups. TD-RDSTRAT-7 owns remaining
  footer/schema/encoding work; full schema evolution is TD-TBL-4/ADR-047.

=== Downstream pricing — standing guard

The downstream coverage rule (AnvaiOps ADR-0041/0042) re-fires if the cost-control stack stalls a
quarter or at the first 10M-vector corpus (recall + coverage unmeasured past 1M).

=== Churn write path

**Write-path churn-tolerance (the key coupling):** the layout sits behind the existing
`WAL → memtable → flush` seam (ADR-020). Trickling writes (agent codegraph, Churn) are absorbed
by the in-memory memtable; a PAX file flushes only when the memtable crosses a threshold
**co-designed with the file-count/GET-count knob** — flush at a size that amortizes the RaBitQ
header and bounds file count, *not* on every small write. This prevents per-trickle file
explosion + compaction thrash; the GET-budget compaction then merges accumulated files.
PR1/PR2 must (a) confirm the flush threshold is sized for the new layout (not the old static
block size), and (b) measure write amplification under a Churn/codegraph trickle-write trace.
The evidence-gated flush-threshold lever is link:TD-WLP-10-churn-evidence-gated-flush-threshold.adoc[TD-WLP-10].
