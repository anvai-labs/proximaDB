== Finding (2026-07-13)

`cargo nextest run --test route_cost_override_pgwire_eval` **aborts with a stack
overflow** (`thread … has overflowed its stack` → SIGABRT) in
`override_on_preserves_materialized_query_results`:

* Reproduces on **clean `origin/develop` (a0fa74f95)** — pre-existing, NOT introduced
  by the TD-ROUTE-1 capability-gate change (verified by stash A/B on 2026-07-13).
* **Passes in 3s with `RUST_MIN_STACK=16777216`** (16 MiB) — a stack-*depth* margin
  problem in the dev profile, not an infinite recursion.

The test previously ran green in CI (#766, merged 2026-07-08), so the depth crossed
the default-stack line somewhere in the develop churn since — candidates: sqlparser
AST recursion, relational lowering, or DataFusion planning growing a stack frame tier
under `opt-level=0`.

== Next actions

1. **Bisect the depth**: `git bisect` develop between #766's merge and HEAD with the
   eval as the probe (fast — 3s per run with the big stack as the sanity arm).
2. Either fix the depth at the source (boxed recursion / iterative walk at the
   offending tier) or, if the depth is legitimate, pin the stack for the test tier
   the same way nextest slow-timeouts are pinned in `.config/nextest.toml`
   (e.g. `RUST_MIN_STACK` in the test-group env or a `#[tokio::main]`-style
   dedicated-thread wrapper with an explicit stack size in the harness).
3. Re-verify the eval runs at defaults; it is the TD-ROUTE-1 enable gate and must be
   runnable on a stock developer machine.

== Verify

`cargo nextest run --test route_cost_override_pgwire_eval` passes with no
`RUST_MIN_STACK` override.
