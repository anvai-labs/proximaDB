== Finding (grounded in a VOE wiring audit, 2026-07-12)

The VOE directory is **BUILT-BUT-DARK** — the schema, sidecar serialization (`{collection}/oedir/v{epoch}.bin`, magic `VECTOEDR`), read-side cache (`VectorObjectEconomyDirectoryCache` — DashMap + OnceCell, collection-keyed, invalidation-based), and emission hooks (`SstableWriterDirectoryHooks`) all exist, but three gaps keep it unused on the live PAX path:

1. **Emission never fires.** `flush/mod.rs` (~L321) sets `write_outcome = None` — the legacy ProximaBlocks path populated it, but the PAX writer (`write_pax_segment_full`) returns `SegmentMeta`, not an `SstableWriteOutcome` with `index_entries`. So `emit_after_flush()` (gated on `Some(outcome)`) is never called.
2. **Per-block centroids are never computed on the PAX path.** `ObjectEconomyBlockEntry.centroid_fp32/fp16` exist but stay `None` (`multi_stage_filter.rs:~700` writes `block_centroid: Vec::new()`). Only **SWIFT** computes them (`swift/mod.rs::compute_block_centroid`).
3. **The search/prune path ignores the directory.** `try_pax_cascade` reads segment bytes and runs the RaBitQ cascade over **every** block; it never loads the directory or calls the ready-made `readers/block_pruning.rs::select_blocks_by_centroid` (which today reads the *legacy embedded* `IndexEntry`, not the directory).

So the "across-block" gap TD-RDSTRAT-4 named already has a home — VOE — that just needs **centroids computed → emission restored → pruning wired**. This TD adds the co-design layer on top.

== The co-design value-add (first principles — why we beat the reference designs, not mimic them)

The competitive review (Lance/Turbopuffer/Vespa/Milvus/Qdrant/DiskANN/SPANN) treats block-identification metadata as something that must be **read** (a GET / page-fault), so their query floor is **≤2–3 GETs**. Three ProximaDB axioms dissolve that floor:

* **Segments are immutable/write-once (LSM)** ⇒ a segment-keyed cache entry is *never stale* ⇒ **zero read-path invalidation** (a new flush is a new key; the VOE freshness watermark + WAL delta handle recency per ADR-020).
* **We own the writer** ⇒ at flush we *computed* the centroids/extents — reading them back is waste ⇒ **write-through** the directory into the resident cache (VOE's `emit_after_flush` already invalidates; extend it to *populate*).
* **One multi-tenant process with a byte-budgeted, tenant-metered cache plane** (`proximadb-cache`, with `TenantLimits` floor/ceiling/weight already modelling **metered residency**) ⇒ residency amortizes across the fleet and is a **sellable tier**.

**The inversion:** make the **resident directory cache the primary block-identification surface**; the on-disk sidecar is the cold/durability backstop. Then the warm path is **≤1 GET** (one coalesced read of the chosen blocks' RaBitQ code stripes — extents + centroids resident), fp32 only for the final top-k. Concrete leapfrog moves beyond the references:

[cols="1,3", options="header"]
|===
| Move | Beyond-mimicry rationale
| **Write-through, not read-through** | Populate the directory/centroid cache at flush (we have the data). Freshly-hot segments = zero-GET metadata from birth. Competitors' write path ⊥ read cache.
| **Cache the _derived_ artifact** | Extend the existing `build_rotation_cached` pattern to per-block centroids + per-(query-cluster) ADC distance tables. A format-only competitor (Lance) caches bytes, not our decoded/rotated/table-built objects.
| **Cache _is_ the directory** | The resident VOE cache serves block-ID with 0 GET; the sidecar is the cold backstop. Reachable *before* any on-disk-format change.
| **Cache as _learned routing state_** | Track per-block query-affinity/hit-rate from the measured trace (the co-design mandate already costs routes from measured quantities) → drive eviction / prefetch / `nprobe` bias. **Recall-safe:** biases order, never drops a recall-required block. A static IVF can't adapt.
| **Negative / prune-verdict caching** | Cache "block B ∉ query-region R" + per-segment dead/tombstone bloom; immutability makes verdicts stable ⇒ repeat queries skip *both* prune compute and GET.
| **Fleet amortization + metered residency** | `TenantLimits` floor/ceiling/weight ⇒ sell a hot-residency SLA. An OSS format or a per-node warmer can't monetize/amortize the cache tier the same way.
|===

== Cache reconciliation (do NOT add a 4th cache)

Three overlapping caches exist today: (a) the **VOE directory cache** (DashMap+OnceCell, collection-keyed, no byte budget/TTL/metering); (b) **`proximadb-cache`** (`CacheKind::{Footer, SegmentIndex, QuantizedCodes, …}`, tenant-namespaced, moka byte-weigher, per-tenant elasticity); (c) **`RangedSegmentReader`**'s footer/BlockLayout + segment-index cache (built on `proximadb-cache`). **Mandate:** fold the VOE directory into `proximadb-cache` as first-class tenant-metered kinds rather than keep a standalone plane — add `CacheKind::{VoeDirectory, BlockCentroid}` (and optionally `AdcTable`, `PruneVerdict`), so the directory shares the byte budget, per-tenant elasticity, and metrics. The OnceCell collection-keyed cache becomes a thin façade over the metered plane (or is retired). One budget, one eviction policy, one metering surface.

== Slices (atomic, default-OFF, mixed-read-safe, recall-ratcheted; re-sequenced onto VOE)

[cols="1,3,2", options="header"]
|===
| Slice | Deliverable | Gate

| **S1 — PAX per-block centroid + sort-by-code** (flag `PROXIMADB_PAX_BLOCK_CLUSTER`, default-OFF) — *this TD's first code step*
| At PAX write (`write_pax_segment_full` / `PaxSegmentWriter`): reorder records by a cheap RaBitQ sign-code (Gray/space-filling) so blocks are spatially coherent, and **compute each block's centroid** — **reuse `swift::compute_block_centroid`**, do not re-implement. Return the per-block centroids (extend `SegmentMeta` or a returned outcome). No emission/search change yet.
| Round-trip parity (same record set back, reorder is result-preserving) + centroids present & decodable + server binary builds. No recall change (S1 only reorders + annotates).

| **S2 — restore `write_outcome` ⇒ VOE emission (write-through)** (opt-in hooks, default-OFF)
| Have the PAX writer return an `SstableWriteOutcome` (or adapter) carrying `index_entries` with the S1 centroids; capture it in `flush/mod.rs` (replace `= None`); `emit_after_flush()` now upserts the directory **and write-through-populates** the resident cache (not just invalidates).
| Emitting a segment produces a directory sidecar with non-empty per-block centroids; the resident cache is populated (0-GET on the next read). Default-OFF until S3's gate.

| **S3 — directory-aware centroid probe-prune at the cascade** (same flag; observe → gated)
| In `try_pax_cascade`, load the VOE directory **cache-first** (fall back to the sidecar, then to the legacy embedded index / whole-scan — mixed-read-safe, `route_degraded` per ADR-004), and call `select_blocks_by_centroid` (directory-fed) with the `(1+ε)` closure rule to select `nprobe` blocks; read only their code stripes via the TD-RDSTRAT-3 striped primitive.
| **SIFT1M recall ratchet ≥ floor** vs the f32 baseline at the chosen `nprobe` (load-bearing) **AND** measured `blocks_touched`/GET reduction on a cold-tier trace. Byte-identical within selected blocks.

| **S4 — cache reconciliation + metering** (cleanup)
| Fold the VOE directory into `proximadb-cache` (`CacheKind::{VoeDirectory, BlockCentroid}`), byte-budgeted + per-tenant elasticity + metrics; write-through on emission; unify with the footer/segment-index budget.
| One metered budget/eviction/metrics surface; no standalone directory cache. Residency metered per-tenant (co-design KRU/cache TAM).

| **S5 — learned residency** (trace-driven)
| Per-block query-affinity/hit-rate from the measured trace drives eviction/prefetch/`nprobe` bias; add `AdcTable`/`PruneVerdict` negative caching. Recall-safe (never drops a recall-required block).
| Measured warm-path GET reduction (target ≤1 GET) with recall ratchet green; a regression test asserts learning never lowers recall.

| **S6 — EXPLAIN/trace** (observability)
| Surface VOE route fields (route_kind, freshness_mode, selected/pruned blocks, estimated object GETs, cache hit/miss) per ADR-004.
| EXPLAIN shows the route + prune + cache decision; `route_degraded=true` when the directory is missing/stale.
|===

== Recall / eval gate & constraints

* Centroid pruning is **recall-affecting** (unlike the byte-identical striped read) — gate every pruning/learning slice against the **f32/SIFT1M recall ratchet within tolerance** (mandates #8/#10/#13). `nprobe`/`ε`/oversampling/eviction are calibrated, versioned eval thresholds.
* **Do not build a second directory or a fourth cache** — VOE + `proximadb-cache` are the vehicles.
* **Memory is the budget** (currently OOM-constrained): the byte-weighted per-tenant elasticity guards it; the working set must fit or **degrade gracefully to the cold sidecar / whole-scan path**.
* **Authority = WAL, not the directory** (ADR-020): the directory is advisory; strong reads merge the WAL/memtable delta above `freshness_watermark_lsn` and honour tombstones. Cold-start / new-node pays the reference budget until warm.
* **Reuse, don't re-implement:** `swift::compute_block_centroid`, `readers/block_pruning.rs::select_blocks_by_centroid`, `build_rotation_cached`, the VOE emission hooks, and `proximadb-cache` already exist — S1–S6 wire them together, they do not rebuild them.
