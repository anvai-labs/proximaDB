== History (shipped)

Observability answered "how much I/O / compute" but not "why this route" or "why this decline": the
route was one last-write-wins stamp, so a primary-then-floor fall-through attributed the floor's
measured quantities to the wrong cost cell (the ADR-050 mis-attribution), and frontend declines
vanished behind a generic message. Slice 1: `RouteReason{axis,detail}` on `SelectRouteDecision`
(ADR-058 eligibility→selection→trust) + `LoweringDecline{node,why}` via `FrontendError::decline()`,
surfaced in EXPLAIN JSON, with a cost-attribution regression test. Slice 2: per-operator
`exec:[{op, rows_in, rows_out, ms_self, bytes, spill}]` reconstructed from existing metered
`NodeMetric`s, surfaced under EXPLAIN ANALYZE and mirrored onto `IoTraceSnapshot.exec_ops` via a
neutral-tuple helper (no cross-crate type). Design rule that still applies: **default-lean** — verbose
detail materializes only on the already-opt-in metered path; a normal SELECT allocates nothing; billing
KRU still sums `compute_ms` (per-op is additive, zero double-count).
