== History (shipped)

* Root cause: **segment count is the GET multiplier** (~7–8 cold GETs per segment through the A0 → Region A → Region B → Region D cascade; Region D is inherently selective). With `level_multiplier = 2.0` (RocksDB default) the L2 threshold was 20 files, unreachable at 1M, so 5 L2 segments accumulated. The L0 early-return also starved the higher-level loop during sustained ingest.
* Fix: `level_multiplier: 1.0` plus `higher_level_file_threshold: 2` (L0 keeps its batching threshold; any L1+ pair consolidates; a single-file guard prevents pointless promotion/retraining). The default carries a co-design comment (ADR-080 D1) and the validator WARNs outside [1.0, 1.5]: below 1.0 over-compacts, above 1.5 accumulates segments; **2.0 is explicitly wrong for vector search.** The worker immediately enqueues the next due level after publication; `StorageConfig::effective_sst_config()` injects the common policy into every SST runtime (the TOML-parse/SST-default split is a regression test); the Flight action calls the real scheduler.
* Lesson: the 7.1 MB L0 segments in the benchmark were a test-config artifact (`flush_floor_predicted_mb = 4`); production uses 128 MB.
* Pre-pair baseline (`484d7da84`, hardened harness): 2 L1 segments, object-cold 42.02 GETs/query recall@10 0.9830; disk-warm 2.00 GETs/query. Historical input, not final evidence for the threshold-2 build.
