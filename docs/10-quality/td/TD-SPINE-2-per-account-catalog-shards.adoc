== Problem

* `CatalogSnapshot` holds every account, namespace, table and statistics row. In object-store mode
  `requires_snapshot_on_commit()` is true, so **every DDL publishes the full image**; in local mode it
  is rewritten every 1,000 mutations.
* Followers and superseded owners adopt a newer snapshot by swapping the whole image.
* Illustration (a model, not a measurement): 2,000 tenants × 50 tables × ~4 KB per table is
  ~400 MB per snapshot, written and redistributed for a single `CREATE TABLE`, and decoded in full
  at boot.
* The namespace stable-id floor is one global counter although the schema documents
  `stable_namespace_id` as per-account, so the 65,536-namespace bound is fleet-wide.

== Fix

. Snapshot = a small **root** (account registry, id high-waters, `account → shard generation`) plus
  one **shard per account**, each committed through `ManifestCommitter` (fenced, retention per
  TD-MANIFEST-1). Shard objects live **under the account's tenant prefix via `DrPathBuilder`**, so
  catalog isolation is structural (CLAUDE.md co-design mandate 3); this carries TD-CAT-2's goal.
. A DDL publishes its account's shard, then the root. Followers compare shard generations and fetch
  only changed shards.
. The namespace floor becomes per-account **for new allocations only**; existing ids are never
  renumbered.
. Migration: on first boot with the new code, an unsharded snapshot is read as legacy and re-published
  as root + shards (mixed-read-safe; the legacy chain stays readable).
. Read paths that iterate every account (`list_namespaces(None)` callers, `get_namespace_by_object_id`
  linear scan) are inventoried in the PR and either scoped to an account or explicitly marked as
  system-scope.

== Acceptance

* Bytes written per DDL scale with the account's catalog, not the fleet's (test with N accounts).
* All cross-pod catalog tests in `src/services/system_catalog.rs` and the embedded follower tests
  (`crates/binding/proximadb-embedded/src/catalog_follower.rs`) pass.
* Legacy unsharded snapshot → sharded migration round-trips and survives a crash between shard and
  root publish (idempotent).
* Per-account namespace floor: two accounts can each allocate namespace id 1; existing ids unchanged.
