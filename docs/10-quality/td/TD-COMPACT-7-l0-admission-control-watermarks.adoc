== History

* `l0_slowdown_trigger` (6: flush yields ~1 ms) and `l0_stop_trigger` (10: flush returns `Err` before `free_wal`, so data stays durable in the WAL and the auto-flush driver retries). Env: `PROXIMADB_L0_SLOWDOWN_TRIGGER` / `PROXIMADB_L0_STOP_TRIGGER`; 0 disables. Armed only when a compaction manager exists.
* Design decisions that still apply: `stop_trigger` must be ≤ `max_files_per_level` (10) so the stop, not the level ceiling, is the active backpressure boundary. The check lives in `flush_implementation` before the L0 write — the single chokepoint for every flush trigger (auto, shutdown, explicit).
* Lesson (#1294): the stop watermark initially blocked WAL recovery/restart flushes; recovery must bypass backpressure.
