= TD-COMPACT-7: L0 admission control watermarks (slowdown + stop triggers)
:status: Implemented
:dim: D1
:pillar: REL

[cols="1,3", options="header"]
|===
| Field | Value
| Status | **Implemented** (this PR). Defaults 6/10 (cross-model review: `stop ≤ max_files_per_level`); both env-overridable + TOML-controllable; armed only when a compaction manager exists.
| Priority | **P1** — prevents compaction storms + unbounded L0 backlog once compaction is async.
| Component | `src/core/config.rs` (`SstConfig` fields); `src/storage/engines/sst/flush/mod.rs` (the flush-path check).
| Evidence | 2026-07-26: no admission control exists — writes proceed at full speed regardless of L0 backlog. The only backpressure is memtable-level (`BACKPRESSURE: collection over memtable threshold`). RocksDB/HBase/Cassandra all have L0 watermarks; ProximaDB does not.
|===

== Mechanism

Two L0-file-count watermarks on `SstConfig` (TOML under
`[storage.sst_config]`, env-overridable via `PROXIMADB_L0_SLOWDOWN_TRIGGER` /
`PROXIMADB_L0_STOP_TRIGGER`):

- `l0_slowdown_trigger` (default **6**): when the live L0 file count ≥ this,
  the flush yields ~1 ms before writing the next L0 (gives the async
  compaction workers headroom).
- `l0_stop_trigger` (default **10** = `max_files_per_level`): when the live L0
  file count ≥ this, the flush defers — returns `Err` so
  `materialize_collection`'s `?` returns before its `free_wal` block (the data
  stays durable in the WAL; the auto-flush driver retries next tick).

Defaults are 6/10 (not 8/12) per the cross-model review: `stop_trigger` must
be ≤ `max_files_per_level` (10) so the stop, not the level ceiling, is the
active backpressure boundary. Both 0 disable.

== Placement (implemented)

The check lives in the SST flush path (`flush_implementation`, after the
storage URL resolves, before the L0 write) — the single chokepoint covering
EVERY flush trigger (auto-flush driver tick, shutdown flush, explicit flush),
using the same `discover_sstable_files` count `should_trigger_compaction`
reasons over. It is armed only when `compaction_manager().is_some()` (no point
bounding L0 for a collection that cannot compact it).

== Verification

* During a sustained ingest that outpaces compaction: flushes slow down (not
  crash/stall indefinitely); L0 count stays bounded (< stop_trigger).
* After compaction catches up: flushes resume full speed.
