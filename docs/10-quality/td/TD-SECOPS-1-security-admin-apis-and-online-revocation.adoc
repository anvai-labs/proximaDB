== Problem

mTLS is in place, but **certificate revocation is not checked at all in production**: `crl_path`
is declared in `src/network/auth/config.rs` and never read; the rustls client verifier is built
without CRLs; there is no distribution-point fetch and no OCSP; and the serial/fingerprint deny-list
middleware (`tls_client_cert_middleware`) is not installed in any router. Operators also have no
API to inspect or manage security state (certificates, keys, active identities).

== Acceptance

* Read-only security status APIs, tenant-scoped and authorized.
* Local CRL loading (`crl_path`) wired into the client verifier, with reload.
* Online revocation checking (CRL distribution points or OCSP) with a fail-closed option.
* Tests that present a revoked certificate for each mechanism.
