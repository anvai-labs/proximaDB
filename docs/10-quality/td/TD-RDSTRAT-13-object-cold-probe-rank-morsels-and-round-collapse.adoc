= TD-RDSTRAT-13: Object-cold probe-rank morsels + round collapse — beat turbopuffer's cold p50 at billed-read parity

:status: Open
:owner: perf
:created: 2026-08-31

== Working backwards: the persona and the bar

The buyer this TD serves is the *turbopuffer-class* tenant: a multi-tenant AI SaaS with
thousands of mostly-idle namespaces where the **cold query is the product** — every namespace's
first query (deploy, scale-out, idle eviction) hits object storage, and the buyer both bills users
for that latency and pays per byte read.

Competitor anchors (researched 2026-08-31):

* *turbopuffer*: object storage as source of truth + RAM/NVMe cache; cold query = 3–4 sequential
  ~100 ms object-store roundtrips; **p50 874 ms cold / 14 ms warm @1M docs**; billed **$1/PB
  queried** (bytes, steep marginal discounts). Their planner explicitly minimizes *roundtrip
  count* — everything knowable-ahead batches into the earliest round, and cluster fetches collapse
  into "one, massive roundtrip".
* *AWS S3 Vectors*: sub-second cold queries **by design**; ~$2.50/M queries + per-TB processed;
  the cheap cold tier behind a hot store. The market accepts sub-second cold — 874 ms is the
  competitive bar.

Both bill on **bytes**, not GETs — so latency wins that change neither GET count nor bytes are
billed-cost-free. That is this TD's prize.

== Acceptance

Object-cold SIFT1M (1M vectors, top-100) p50 **≤ ~870 ms over a 50–100 ms RTT object store at
GET/byte parity** (Σ bytes identical, GET ops equal-or-fewer, recall and result-identity hashes
identical) with today's sequential path.

Where we start (measured): the S3/MinIO campaign (#1795) put cold p50 at ≈1235 ms (real ~5.5 ms
RTT) to 3686 ms (150 ms RTT); the az ladder showed the waved arm saturating at ~1.8 s @100 ms =
compute + 1–2 waves. Decomposition of the residual:

* *Compute*: the single-threaded RaBitQ probe rank costs ~0.9–1.2 s at 370k–545k probed rows —
  the dominant term at every RTT.
* *Rounds*: 6 sequential IO rounds per segment — HEAD → header-prefix GET → probe wave → rank →
  **footer GET serialized after the rank** → Region-B wave → Region-D wave. The footer depends
  only on header bytes (ADR-062 guarantees the RaBitQ scan never depends on the footer);
  TD-RDSTRAT-8 §read-path prescribed this hoist and it was never implemented.

== Shipped (this PR)

=== C1 — observability instrument first

Always-on per-tier physical-GET ops/bytes counters (`tier_get_ops`/`tier_get_bytes`, indexed by
`CacheTier` declaration order — drift-guarded by test), a `metadata_ops` counter at the search
path's HEAD, and coarse-probe rank wall-time counters (`ivf_probe_rank_us`). `record_get_physical`
replaces the env-gated diagnostic at every physical-GET site (batch-time recording keeps the 1:1
invariant). These counters are the measurement instrument for C2–C4 and the ledger's
decomposition tool.

=== C2 — Phase A: morsel-parallel coarse-probe rank (the big term)

The probe rank runs chunked across `morsel_degree()` workers (`tokio::task::spawn_blocking`),
reusing the documented `PROXIMADB_SEARCH_MORSEL_DEGREE` gate (registry row widened, co-owner this
TD — no new gate). `PreparedProbeRank` hoists the per-query rotation/LUT build (~50 µs) so all
workers share it; `ProbedRun` moves fetch buffers zero-copy; `plan_rank_morsels` partitions runs
greedily by byte length, never splitting a run.

Determinism contract: each morsel keeps its local top-`pool` under the **sequential (score,
ordinal) total order**, and the parent re-applies the identical finalizer to their union —
byte-identical survivors to `rank_probed_rows_allowed` for any degree (the coalesced_rabitq
exactness argument applies because every chunk uses the same total order). Degree ≤ 1 and <65,536
rows route to the UNTOUCHED sequential function, so degree-1 identity is structural. A worker
panic degrades to a FULL sequential re-rank — never a partial pool (a partial pool would silently
change recall; this deliberately differs from `rank_region_morsels`, whose score-only merge and
partial-pool degrade are safe only for the approximate fallback path — its tie nondeterminism is
noted, not fixed here).

Oracle tests prove byte-identity across degrees {1,2,3,7,16,64} × metrics × allow-set on/off ×
pools, plus a tie-heavy fixture (duplicated rows → colliding scores → ordinal tie-break through
select_nth) and planner invariants. Moves **Compute only** (~0.9–1.2 s → cores-scaled); GETs,
bytes, rounds unchanged.

=== C3 — Phase B1: kill the HEAD

`discover_sstable_files` now returns `DiscoveredSstFile { url, size_bytes }` — object-store
listings already carry the size; the cascade consumes it as a *hint* and skips the HEAD (a billed
metadata op per segment per query). Failure semantics: unknown/zero listing size ⇒ HEAD exactly
as before; the header stays magic-validated; a listed size that cannot even contain the header's
footer extents fails closed to the generic scan path (segments are immutable, so a stale size
means a foreign object generation — never serve extents clamped against it). Moves **−1 GET op
and −1 round**.

=== C4 — Phase B2: the footer rides the earliest possible round

The cascade classifies the footer (`FooterPlan::Ready` on cache/prefix hit — check order
identical to the sequential arms; `Pending` otherwise) before the probe. A `Pending` footer
*joins the probe's Region-A wave at the front* of the cold queue (round growth only when
`n ≡ 0 (mod width)`), or — when every probe range is warm — overlaps the morsel rank via
`tokio::join!` (C2 freed the async worker; the GET hides under the compute instead of
serializing after it). Fetched bytes flow into the EXISTING `SegmentInvariants` cache entry —
same seam, same bytes, no double put; the footer never enters the survivor cache. Round
structure: **6 → 4** (HEAD and the post-rank footer round eliminated). Probe disarmed/missed ⇒
footer stays sequential (today's shape).

Teeth: `footer_rides_probe_wave_and_is_never_double_billed` pins `tier_get_ops[InvariantMeta]
== 1` per query (cold AND repeat), `metadata_ops == 1` on the cold path, and wave firing on the
cold query — through the real search wrapper on a real written segment.

== Cost-term ledger (co-design statement)

|===
|Change |GET ops |Bytes |Rounds |Compute
|C1 counters |0 |0 |0 |+ns
|C2 morsel rank |0 |0 |0 |0.9–1.2 s → cores-scaled
|C3 no-HEAD |−1/segment/query |0 |−1 |0

Bytes are NEVER traded: both competitors bill on bytes-queried, and TD-RDSTRAT-8's GET-economy
invariant is preserved (the wave changes only *when* GETs are issued, not how many).

== Campaign verdict (2026-08-31, 9 arms complete)

**Mechanisms verified; acceptance NOT MET on the campaign bed; the measured next lever is a
product defect bigger than everything this TD shipped.** Full numbers:
`docs/_internal/status/RDSTRAT13_SIFT1M_LADDER_2026_08_31.adoc` (ledger:
`rdstrat13_minio_s3_mechanisms`, `rdstrat13_l3l2_retirement_race`).

* **Verified at strict parity** (bytes delta +0.00%, result-identity IDENTICAL, GET/q equal
  within every pair): C3's HEAD elimination (`metadata_ops/q = 0.00` on the full binary — the
  direct end-to-end proof), C4's footer-in-wave (rounds 2.08–4.83, width 8), C2's parallel rank
  (byte-identical survivors; measured 33.7 ms mean at 882k rows vs 42.9 ms sequential at 370k).
* **Premise corrected on file**: the az ladder's "~0.9 s single-threaded rank" was inferred from
  latency subtraction; the direct measurement contradicts it. The rank was never the dominant
  cold term at this geometry — the residual was byte transfer. Phase A ships as correct,
  deterministic infrastructure, not as the ~1 s lever the premise claimed.
* **Acceptance blocked by two measured terms**: (a) the campaign bed is transfer-dominated
  (~98% of p50: 125.5 MB/query at ~14 MB/s effective through the window-limited 100 ms proxy;
  b0 p50 moved only +5% when RTT rose 50→150 ms); (b) the **L3/L2 retirement race** (below)
  doubled rows/bytes/GETs on most beds.
* **The L3/L2 retirement race (measured 3.03x p50, 2.1x bytes at identical code)**: two arms on
  byte-identical settled beds served different live sets at query time — clean L3-only
  (2977 ms @100 ms, 58.5 MB, 21.95 GETs) vs L2+L2+L3 overlap (9029 ms, 125.5 MB, 50.57 GETs).
  Superseded L2s stay live and serving after the L3 publishes; recall/identity stay correct
  (MVCC dedup at emit) but compute/bytes/GETs are paid twice. The settle gate's new
  compaction-quiescence check cannot catch it (the overlap appears after a quiet window and
  persists).

=== Follow-ups (in priority order, all measured)

== Measurement protocol (acceptance evidence — campaign pending in this PR)

Bed: the proven SIFT1M harness (`scripts/bench/sift1m_get_reduction.py --s3-endpoint`, MinIO on
dataserver2 + toxiproxy; IPs only — the hostname costs a 5 s DNS resolver timeout on the test
Mac), rows=1M, top-100, deterministic settle (`--explicit-flush-every-rows 250000
--flush-vector-threshold 250000 --max-segments 2`), `PROXIMADB_READ_RANGES_INFLIGHT=8`, RTT ∈
{real ~5.5, 50, 100, 150} ms. Arms: B0 baseline → B1 +C1 (must be neutral) → B2 +C2 (adaptive;
`=1` control) → B3 +C3 → B4 +C4. Record per arm×RTT: cold p50/p95, recall, result-identity,
GETs/q total + per tier, metadata_ops/q, bytes/q, fetch_rounds/q, rank_us.

Pre-registered arithmetic: ~1.8 s (B0-wave @100 ms) − ~0.8–1.0 s (C2) − ~2×100 ms (C3+C4) ≈
0.65–0.85 s ⇒ acceptance plausible with margin at 50 ms and borderline-to-good at 100 ms. If the
rung lands 870–1000 ms, the new per-tier counters name the residual (wave width vs rerank vs
transfer) — explicitly out of this TD's scope, recorded as follow-up.
