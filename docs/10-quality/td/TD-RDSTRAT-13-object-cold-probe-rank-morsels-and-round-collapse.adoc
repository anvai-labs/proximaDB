== Working backwards: the persona and the bar

The buyer this TD serves is the *turbopuffer-class* tenant: a multi-tenant AI SaaS with
thousands of mostly-idle namespaces where the **cold query is the product** — every namespace's
first query (deploy, scale-out, idle eviction) hits object storage, and the buyer both bills users
for that latency and pays per byte read.

Competitor anchors (researched 2026-08-31):

* *turbopuffer*: object storage as source of truth + RAM/NVMe cache; cold query = 3–4 sequential
  ~100 ms object-store roundtrips; **p50 874 ms cold / 14 ms warm @1M docs**; billed **$1/PB
  queried** (bytes, steep marginal discounts). Their planner explicitly minimizes *roundtrip
  count* — everything knowable-ahead batches into the earliest round, and cluster fetches collapse
  into "one, massive roundtrip".
* *AWS S3 Vectors*: sub-second cold queries **by design**; ~$2.50/M queries + per-TB processed;
  the cheap cold tier behind a hot store. The market accepts sub-second cold — 874 ms is the
  competitive bar.

Both bill on **bytes**, not GETs — so latency wins that change neither GET count nor bytes are
billed-cost-free. That is this TD's prize.

== Acceptance

Object-cold SIFT1M (1M vectors, top-100) p50 **≤ ~870 ms over a 50–100 ms RTT object store at
GET/byte parity** (Σ bytes identical, GET ops equal-or-fewer, recall and result-identity hashes
identical) with today's sequential path.

Where we start (measured): the S3/MinIO campaign (#1795) put cold p50 at ≈1235 ms (real ~5.5 ms
RTT) to 3686 ms (150 ms RTT); the az ladder showed the waved arm saturating at ~1.8 s @100 ms =
compute + 1–2 waves. Decomposition of the residual:

* *Compute*: the single-threaded RaBitQ probe rank costs ~0.9–1.2 s at 370k–545k probed rows —
  the dominant term at every RTT.
* *Rounds*: 6 sequential IO rounds per segment — HEAD → header-prefix GET → probe wave → rank →
  **footer GET serialized after the rank** → Region-B wave → Region-D wave. The footer depends
  only on header bytes (ADR-062 guarantees the RaBitQ scan never depends on the footer);
  TD-RDSTRAT-8 §read-path prescribed this hoist and it was never implemented.

== History (shipped)

* *C1 — instrument first:* always-on `tier_get_ops`/`tier_get_bytes` (indexed by `CacheTier`, drift-guarded),
  `metadata_ops` at the HEAD, `ivf_probe_rank_us`; `record_get_physical` at every physical-GET site.
* *C2 — morsel-parallel probe rank* via `spawn_blocking` under `PROXIMADB_SEARCH_MORSEL_DEGREE` (no new gate).
  Determinism contract: each morsel keeps its local top-`pool` under the sequential (score, ordinal) total order
  and the parent re-applies the same finalizer, so survivors are byte-identical for any degree; degree ≤ 1 or
  < 65,536 rows routes to the untouched sequential function; a worker panic degrades to a FULL sequential re-rank,
  never a partial pool (a partial pool silently changes recall).
* *C3 — kill the HEAD:* discovery returns listing sizes; size is a hint (magic + extents bounds-checked; a size that
  cannot contain the footer fails closed to the generic path).
* *C4 — footer rides the earliest round:* a pending footer joins the probe's Region-A wave (or overlaps the rank
  via `tokio::join!`) and lands in the existing `SegmentInvariants` entry; rounds 6 → 4. Pinned by
  `footer_rides_probe_wave_and_is_never_double_billed`.
* *PR-B:* 2a stage timers attributed ~92% of the tail (rehydrate 168 ms #1, Region-B 89 ms, Region-D 20 ms);
  2b cache-first rehydrate + waved Region-D removed serial-RTT terms (near-neutral on disk by design).

*Decisive findings (still apply).* Bytes are never traded (both competitors bill on bytes; the wave changes when
GETs issue, not how many). The "~0.9 s single-threaded rank" premise was inferred from latency subtraction and is
contradicted by direct measurement (33.7 ms at 882k rows parallel; 42.9 ms sequential at 370k) — the campaign bed
was ~98% byte-transfer-bound. The L3/L2 retirement race (superseded inputs still served after the output published)
cost 3.03× p50 and 2.1× bytes at identical code with correct recall — invisible to recall gates.

*Evidence:* mechanisms verified at strict parity (bytes +0.00%, identity identical); S3/MinIO localhost on the 2b
binary: object-cold p50 **586.1 ms**, 21.95 GETs/q, 58.5 MB/q, recall 0.9835 — sub-second at parity.

== Open

Acceptance (unchanged): object-cold SIFT1M (1M, top-100) p50 **≤ ~870 ms over a 50–100 ms RTT object store at

   turbopuffer's published 874 ms.
2. **Transfer efficiency** is the cold-query frontier on high-RTT paths (bytes/query and
   effective throughput — the overlap fix is itself 2.1x bytes).
3. **Correct the az-ladder ledger record** (`rdstrat12_sift1m_rtt_ladder_crossover`): its
   compute-attribution narrative was inferred and is contradicted by direct measurement; the
   GET-parity/identity facts stand.

Disk-bed residual after 2b (the next levers): region-B 83 ms (bytes-bound SQ8 survivor fetch — recall-gated pool-sizing
lever), rehydrate 166 ms (block fetch + full-record decode — wanted-rows decode lever), rank
48 ms, cascade/REST remainder ~46 ms.

=== Measurement protocol (acceptance evidence)

Bed: the proven SIFT1M harness (`scripts/bench/sift1m_get_reduction.py --s3-endpoint`, MinIO on
dataserver2 + toxiproxy; IPs only — the hostname costs a 5 s DNS resolver timeout on the test
Mac), rows=1M, top-100, deterministic settle (`--explicit-flush-every-rows 250000
--flush-vector-threshold 250000 --max-segments 2`), `PROXIMADB_READ_RANGES_INFLIGHT=8`, RTT ∈
{real ~5.5, 50, 100, 150} ms. Arms: B0 baseline → B1 +C1 (must be neutral) → B2 +C2 (adaptive;
`=1` control) → B3 +C3 → B4 +C4. Record per arm×RTT: cold p50/p95, recall, result-identity,
GETs/q total + per tier, metadata_ops/q, bytes/q, fetch_rounds/q, rank_us.

Pre-registered arithmetic: ~1.8 s (B0-wave @100 ms) − ~0.8–1.0 s (C2) − ~2×100 ms (C3+C4) ≈
0.65–0.85 s ⇒ acceptance plausible with margin at 50 ms and borderline-to-good at 100 ms. If the
rung lands 870–1000 ms, the new per-tier counters name the residual (wave width vs rerank vs
transfer) — explicitly out of this TD's scope, recorded as follow-up.

The 2026-09-03 chooser A/B that previously sat here ran its ON arm un-engaged and is superseded by
TD-IOBUDGET-2 (`read_strategy_chooser_sift1m_minio`); do not cite it as flip evidence.
