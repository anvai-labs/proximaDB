== Overview

ProximaDB provides native Arrow Flight support for exporting data to analytics tools. This enables zero-copy data transfer to PyArrow, Polars, DuckDB, and pandas.

=== Supported Formats

[cols="1,2,2"]
|===
|Format |Extension |Engines

|ArrowBlock
|`.arrow`
|SST (when configured)

|ProximaBlocks
|`.sst`
|SST

|Parquet
|`.parquet`
|NOVA (VIPER: deprecated, existing collections only)
|===

All formats are accessible via Arrow Flight on the multiplexed port 5678.

== Quick Start

=== Python SDK

[source,python]
----
from proximadb_sdk import connect_arrow

# Connect to Arrow Flight endpoint
with connect_arrow(host="localhost", port=5678) as client:
    # List available files
    files = client.list_files("my_collection")
    for f in files:
        print(f"{f.filename}: {f.total_records} records ({f.format.value})")

    # Read into PyArrow Table
    table = client.read_file("my_collection/data/block_0.arrow")
    print(f"Schema: {table.schema}")

    # Read into Polars DataFrame
    df = client.to_polars("my_collection/data/block_0.arrow")
    print(df.head())

    # Load into DuckDB for SQL analytics
    conn = client.to_duckdb("my_collection/data/block_0.arrow")
    result = conn.execute("SELECT * FROM vectors LIMIT 10").fetchdf()
----

=== Direct PyArrow Usage

[source,python]
----
import pyarrow.flight as flight

# Connect to Arrow Flight
client = flight.connect("grpc://localhost:5678")

# List files in a collection
for info in client.list_flights(b"my_collection"):
    print(f"Found: {info.descriptor.path}")

# Read file data
descriptor = flight.FlightDescriptor.for_path("my_collection", "data", "block_0.arrow")
info = client.get_flight_info(descriptor)
reader = client.do_get(info.endpoints[0].ticket)
table = reader.read_all()
----

== Batch Writes

Arrow Flight also accepts high-throughput record writes. The write boundary uses
the v2 rich-record shape: `id` or `oid` identifies the record, `vector` is
optional for dense-vector records, and additional supported Arrow scalar columns
are preserved as typed record properties.

=== Python SDK DoPut

Use `ArrowFlightClient.bulk_upsert()` for simple request/response writes and
`bulk_delete()` for tombstone deletes:

[source,python]
----
import pyarrow as pa
from proximadb_sdk.protocols.arrow_flight import ArrowFlightClient

client = ArrowFlightClient("grpc://localhost:5678")

records = pa.table({
    "id": ["r1", "r2"],
    "vector": [[0.1, 0.2, 0.3], [0.3, 0.2, 0.1]],
    "category": ["docs", "docs"],
})

upsert = client.bulk_upsert("my_collection", records)
print(upsert.records_processed, upsert.records_failed)

delete = client.bulk_delete("my_collection", ["r1"])
print(delete.records_processed, delete.records_failed)
----

DoPut descriptors may be command descriptors:

[source,json]
----
{
  "collection_id": "my_collection",
  "operation": "upsert",
  "write_mode": "wal",
  "trigger_compaction": false
}
----

The server also accepts operation-prefixed path descriptors such as
`["upsert", "my_collection"]` and `["delete", "my_collection"]`.

=== Python SDK DoExchange

Use DoExchange when the client needs progress metadata while streaming large
batches:

[source,python]
----
result = client.bulk_upsert_exchange("my_collection", records, batch_size=10_000)

for progress in result.progress:
    print(progress["batch"], progress["total_records"])

print(result.records_processed, result.records_failed)
----

DoExchange path descriptors are:

[cols="1,2"]
|===
|Operation |Descriptor path

|Insert
|`["bulk_insert", collection_id]`

|Upsert
|`["bulk_upsert", collection_id]`

|Delete
|`["bulk_delete", collection_id]`
|===

Command descriptors are also accepted for clients that cannot populate path
segments. `exchange_type`, `operation`, or `write_operation` may name the
operation, and `collection_id` or `collection` may name the collection. Plain
logical operations are normalized: `insert` -> `bulk_insert`, `upsert` ->
`bulk_upsert`, and `delete` -> `bulk_delete`.

`insert` is insert-only at the request boundary: duplicate IDs within the
streamed request, or IDs that already exist before the write is dispatched,
return a failed `BatchOperationResult` with `error_code` `INSERT_CONFLICT`.
Use `upsert`/`bulk_upsert` when replacing existing records is intended.

`write_mode` accepts `wal` and `direct`; `direct` is reserved for a future
WAL-bypass path and currently falls back to WAL-backed writes on the server.

=== Response Metadata

DoPut returns a `BatchOperationResult` JSON payload in `PutResult.app_metadata`:

[source,json]
----
{
  "success": true,
  "vector_ids": ["r1", "r2"],
  "metrics": {
    "total_processed": 2,
    "successful_count": 2,
    "failed_count": 0
  },
  "errors": [],
  "error_code": null
}
----

DoExchange emits progress metadata messages and a final completion message:

[source,json]
----
{"type":"progress","operation":"upsert","batch":1,"batch_rows":1000,"total_records":1000}
{"type":"complete","operation":"upsert","total_batches":1,"total_records":1000,"total_failed":0,"success":true}
----

When `trigger_compaction` is true, DoPut triggers collection compaction after
the batch write completes. The `compact_collection` action remains available
for explicit maintenance outside the write path.

For tenant-scoped writes, send the tenant as Flight call metadata using
`x-proximadb-tenant-id`. The Python `ArrowFlightClient` exposes this as the
optional `tenant_id` constructor argument.

When server authentication is enabled, Flight write streams are validated with
the shared security coordinator. API keys are sent as `authorization:
API-Key <key>` by the Python client; JWT callers may send `authorization:
Bearer <token>`. For mTLS deployments, Flight write streams can authenticate
with the verified client certificate exposed by Tonic on TLS connections.

=== DuckDB Direct Query

[source,sql]
----
-- Install Arrow extension
INSTALL arrow;
LOAD arrow;

-- Query ProximaDB files directly
SELECT * FROM arrow_scan('grpc://localhost:5678', 'my_collection/data/block_0.arrow');

-- Analytics on vectors
SELECT
    id,
    metadata->>'category' as category,
    array_length(vector) as dimension
FROM arrow_scan('grpc://localhost:5678', 'my_collection/data/block_0.arrow')
WHERE metadata->>'category' = 'tech';
----

=== Polars Direct Usage

[source,python]
----
import polars as pl
from pyarrow import flight

# Connect and read
client = flight.connect("grpc://localhost:5678")
flights = list(client.list_flights(b'my_collection'))
reader = client.do_get(flights[0].endpoints[0].ticket)
df = pl.from_arrow(reader.read_all())

# Analytics
result = df.filter(
    pl.col("metadata").struct.field("category") == "tech"
).select(["id", "vector"])
----

== ArrowExportClient API

=== Connection

[source,python]
----
from proximadb_sdk import ArrowExportClient, connect_arrow

# Using class directly
client = ArrowExportClient(
    host="localhost",
    port=5678,
    tls=False,
    auth_token="optional_token"
)

# Using convenience function
client = connect_arrow(host="localhost", port=5678)

# Context manager
with connect_arrow() as client:
    # Operations here
    pass
----

=== Listing Files

[source,python]
----
from proximadb_sdk import FileFormat

# List all files
files = client.list_files("my_collection")

# Filter by format
arrow_files = client.list_files("my_collection", format_filter=FileFormat.ARROW)
parquet_files = client.list_files("my_collection", format_filter=FileFormat.PARQUET)
sst_files = client.list_files("my_collection", format_filter=FileFormat.SST)

# Filter by pattern
block_files = client.list_files("my_collection", pattern="block_*.arrow")
----

=== Reading Data

[source,python]
----
# Read single file to PyArrow Table
table = client.read_file("my_collection/data/block_0.arrow")

# Read entire collection
full_table = client.read_collection("my_collection")

# Stream as batches (memory efficient)
for batch in client.read_batches("my_collection/data/large_file.arrow"):
    process(batch)

# Get schema only
schema = client.get_schema("my_collection/data/block_0.arrow")
----

=== Format Conversions

[source,python]
----
# To Polars DataFrame
df = client.to_polars("my_collection/data/block_0.arrow")

# To DuckDB (creates in-memory connection)
conn = client.to_duckdb("my_collection/data/block_0.arrow")
result = conn.execute("SELECT * FROM vectors").fetchdf()

# To pandas DataFrame
pdf = client.to_pandas("my_collection/data/block_0.arrow")

# Extract vectors as NumPy array
vectors = client.to_numpy("my_collection/data/block_0.arrow")
print(vectors.shape)  # (num_vectors, dimension)
----

== FileInfo Object

The `FileInfo` dataclass contains metadata about exportable files:

[source,python]
----
@dataclass
class FileInfo:
    path: str           # Full path
    filename: str       # File name only
    size_bytes: int     # File size
    num_batches: int    # Number of record batches
    total_records: int  # Total vector count
    dimension: int      # Vector dimension
    modified_at: int    # Unix timestamp
    format: FileFormat  # ARROW, PARQUET, or SST
----

== Performance Tips

=== Streaming Large Files

For large files, use batch streaming to avoid loading everything into memory:

[source,python]
----
# Memory-efficient processing
total_processed = 0
for batch in client.read_batches("large_collection/data/huge_file.arrow"):
    # Process batch
    total_processed += batch.num_rows

print(f"Processed {total_processed} vectors")
----

=== Parallel Processing with Polars

[source,python]
----
import polars as pl

# Polars automatically parallelizes operations
df = client.to_polars("my_collection/data/block_0.arrow")

# Fast parallel aggregations
stats = df.select([
    pl.col("vector").list.len().alias("dimension"),
    pl.len().alias("count"),
])
----

=== SQL Analytics with DuckDB

[source,python]
----
# Load multiple files
conn = duckdb.connect(":memory:")

for file in client.list_files("my_collection"):
    table = client.read_file(file.path)
    conn.register(f"file_{file.filename.replace('.', '_')}", table)

# Run analytics across all files
result = conn.execute("""
    SELECT COUNT(*) as total, AVG(array_length(vector)) as avg_dim
    FROM file_block_0_arrow
""").fetchdf()
----

== Troubleshooting

=== Connection Issues

[source,python]
----
# Check connectivity
try:
    with connect_arrow(host="localhost", port=5678) as client:
        files = client.list_files("test")
        print(f"Connected! Found {len(files)} files")
except Exception as e:
    print(f"Connection failed: {e}")
----

=== Format Not Supported

If you see "Format not supported" errors:

1. Check that the file exists and has a valid extension
2. Ensure the ProximaDB server is running with Arrow Flight enabled
3. Verify the collection uses an exportable engine (SST, or NOVA; VIPER only for existing collections)

=== Large File Timeouts

For very large files, increase the timeout:

[source,python]
----
import pyarrow.flight as flight

# Increase read timeout
options = flight.FlightCallOptions(timeout=300)  # 5 minutes
----

== Configuration

=== Server Configuration

Enable Arrow Flight in `config.toml`:

[source,toml]
----
[api]
rest_port = 5678
grpc_port = 5679
arrow_flight_port = 5678  # Arrow Flight endpoint

[storage.sst_config]
block_format = "ArrowBlock"  # Use Arrow format for new flushes
----

=== Block Format Selection

Choose the block format based on your use case:

[cols="1,2,2"]
|===
|Format |Best For |Trade-offs

|ProximaBlocks (default)
|Vector search workloads
|Optimal for search, accessible via Arrow Flight

|ArrowBlock
|Analytics/export workloads
|Native Arrow, fastest scans

|Parquet (NOVA; VIPER deprecated)
|Columnar analytics
|Best compression, excellent for batch processing
|===

=== Use Case Recommendations

**Real-time OLTP workloads:**

* SST/ProximaBlocks: Optimized for low-latency writes and point queries
* Three-stage filtering pipeline reduces unnecessary I/O

**Analytics with external tools (PyArrow, DuckDB, Polars):**

* SST/ArrowBlock: Native Arrow IPC format, zero-copy reads
* Direct integration without format conversion

**Production batch workloads:**

* Viper/Parquet: Best compression, optimized for large batch processing
* Cloud-optimized with footer caching and range reads

**Advanced analytics with progressive search:**

* Nova/Parquet: Hierarchical statistics for 70-90% I/O reduction
* SuperBlock metadata enables intelligent query pruning
