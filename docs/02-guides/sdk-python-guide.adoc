= ProximaDB Python SDK Guide
:toc: left
:toclevels: 3
:icons: font
:source-highlighter: rouge
:last-updated: December 2025

[.lead]
Comprehensive guide to using the ProximaDB Python SDK for record-native vector search, graph operations, document storage, and observability.

== Installation

[source,bash]
----
pip install proximadb
----

Optional features are extras, including `embedded`, `embeddings`, `embeddings-cloud`, `llm`,
`chunking`, `code-chunking`, `codegraph`, `performance` and framework integrations (`langchain`,
`llama-index`, `haystack`, `crewai`, `dspy`, `autogen`, `langgraph`). For example:

[source,bash]
----
pip install "proximadb[embeddings]"
----

== Quick Start

[source,python]
----
from proximadb_sdk import ProximaDBClient, ProximaRecord, DistanceMetric, Protocol

# Connect to ProximaDB
client = ProximaDBClient(url="http://localhost:5678", protocol=Protocol.REST)

# Create a collection
client.create_collection(
    name="my_vectors",
    dimension=768,
    distance_metric=DistanceMetric.COSINE
)

# Insert records with embedding cells
client.insert_records("my_vectors", [
    ProximaRecord(id="doc1", vector=[0.1] * 768).set_flexible("title", "Document 1"),
    ProximaRecord(id="doc2", vector=[0.2] * 768).set_flexible("title", "Document 2"),
])

# Search
results = client.search("my_vectors", vector=[0.15] * 768, top_k=10)
for r in results:
    print(f"{r.id}: {r.score:.4f}")
----

== Connection Options

=== REST Protocol (use this today)

[source,python]
----
from proximadb_sdk import ProximaDBClient, Protocol

client = ProximaDBClient(
    url="http://localhost:5678",
    protocol=Protocol.REST,
    timeout=60.0,
)
----

=== gRPC Protocol

Without a `protocol` argument the client prefers gRPC. Until TD-GRPCCREATE-1 is fixed, a
collection created over gRPC cannot store records, and the SDK reports the failed inserts with an
empty error list (TD-SDKERR-1), so pass `protocol=Protocol.REST` as the examples here do.

[source,python]
----
client = ProximaDBClient(
    url="localhost:5678",
    protocol=Protocol.GRPC,
)
----

=== Embedded Mode

[source,python]
----
# In-process engine (no server); requires the [embedded] extra
from proximadb_embedded import ProximaDB

db = ProximaDB(data_dirs="./data")
db.create_collection("vectors", dimension=4)
db.insert("vectors", ids=["v1"], vectors=[[0.1, 0.2, 0.3, 0.4]])
results = db.search("vectors", query=[0.1, 0.2, 0.3, 0.4], top_k=5)
----

== Storage Engine Selection

Choose the storage engine per collection with the `storage_engine` argument. The Python SDK sends
`storage_engine=SST` when you omit it, so SDK users get the Supported engine by default. REST and gRPC
creates that omit the engine also get SST (TD-ENGSEL-1); HELIX is an explicit opt-in. Note that
`create_collection` silently ignores an unknown `engine=` keyword (TD-SDKENG-1): use
`storage_engine=`.

[cols="1,2,2", options="header"]
|===
| Engine | Best For | Python Config

| SST (Supported)
| Vector and context search, real-time ingestion
| `storage_engine="sst"`

| HELIX (Beta)
| Locality-ordered high-dimensional embeddings (measure recall first)
| `storage_engine="helix"`

| NOVA (Beta)
| Mixed read/write workloads
| `storage_engine="nova"`
|===

VIPER is deprecated (new VIPER collections are rejected), and SWIFT/RAPTOR are experimental
engines a stock server rejects. For analytical SQL, use a relational table over pgwire and
`ALTER TABLE … MATERIALIZE` it.

[source,python]
----
from proximadb_sdk import StorageEngine

client.create_collection(
    name="knowledge_base",
    dimension=768,
    storage_engine=StorageEngine.SST,  # the SDK sends SST when this is omitted
)
----

== Vector Operations

Vector features are expressed as embedding fields inside `ProximaRecord` payloads.
`VectorRecord` and `insert_vectors()` remain compatibility aliases for older clients,
but new code should call `insert_records()`.

=== Insert Records With Embeddings

[source,python]
----
from proximadb_sdk import ProximaRecord, TypedValue

# Single insert
client.insert_records("my_collection", [
    ProximaRecord(
        id="vec_001",
        vector=[0.1, 0.2, 0.3, ...],
    )
    .set_typed("category", TypedValue.text("electronics"))
    .set_typed("price", TypedValue.float_(299.99))
])

# Batch insert
records = [
    ProximaRecord(id=f"vec_{i}", vector=embeddings[i], flexible_fields=data[i])
    for i in range(1000)
]
client.insert_records("my_collection", records)
----

=== Search Records By Vector

[source,python]
----
results = client.search("my_collection", vector=query_embedding, top_k=10)
for r in results:
    print(r.id, r.score)
----

For an equality filter on properties, pass `metadata_filter`. Do not pass `filter=` or any other
argument `search()` does not declare: today an unrecognised argument silently switches the client
to an empty local store (TD-SDKERR-1). For ranges and `in`, use the REST API's typed `filters`
(see the link:../03-api-reference/rest.adoc[REST reference]).

[source,python]
----
results = client.search(
    "my_collection", vector=query_embedding, top_k=10, metadata_filter={"category": "books"}
)
----

== Graph Operations

=== Basic Graph Operations

Graph methods exist on the REST client only (`protocol=Protocol.REST`).

[source,python]
----
client.create_graph("knowledge", name="Knowledge graph")

client.batch_create_nodes([
    {"id": "entity_1", "labels": ["Person"], "properties": {"name": "Alice"}},
    {"id": "entity_2", "labels": ["Company"], "properties": {"name": "TechCorp"}},
], graph_id="knowledge")

client.batch_create_edges([
    {"id": "e1", "from_node_id": "entity_1", "to_node_id": "entity_2",
     "edge_type": "WORKS_AT", "weight": 1.0},
], graph_id="knowledge")

result = client.traverse_graph(
    "entity_1", max_depth=2, edge_types=["WORKS_AT", "KNOWS"], graph_id="knowledge"
)
print(result)
----

=== Pattern Matching

[source,python]

from proximadb_sdk import GraphPattern, node, relationship

# Find triangles: A -> B -> C -> A
pattern = (GraphPattern()
    .node("a", label="Person")
    .relationship("r1", type="KNOWS")
    .node("b", label="Person")
    .relationship("r2", type="KNOWS")
    .node("c", label="Person")
    .relationship("r3", type="KNOWS", target="a"))

matches = analytics.pattern_match("knowledge", pattern)

== Multi-Modal Queries

Combine vector, graph, document, and observability queries:

[source,python]
----
from proximadb_sdk import (
    MultiModalQueryBuilder,
    MultiModalQueryExecutor,
    FusionStrategy,
    TimeDecayFunction,
)

# Build a multi-modal query
query = (MultiModalQueryBuilder()
    # Vector similarity search
    .vector("products", query_embedding, top_k=20)
    # Graph traversal from vector results
    .graph_from_vector_results("knowledge", edge_types=["RELATED_TO"])
    # Join by semantic similarity
    .join_semantic("vector.embedding", "graph.node.embedding", threshold=0.8)
    # Fuse with Reciprocal Rank Fusion
    .fuse(FusionStrategy.RRF)
    # Apply time decay
    .with_time_decay(TimeDecayFunction.EXPONENTIAL, halflife_hours=24)
    .limit(10)
    .build())

# Execute
executor = MultiModalQueryExecutor(client)
results = executor.execute(query)

for record in results:
    print(f"{record['id']}: score={record.get('_rrf_score', 0):.4f}")
----

== AutoML Features

A client-side heuristic that suggests an engine for a workload. It runs locally and does not
measure your data; treat it as a starting point and measure recall before committing. It can
name an engine the server rejects (VIPER is deprecated; SWIFT and RAPTOR are experimental), so
check the suggestion against the
link:../05-concepts/storage-engines.adoc[engine tiers].

[source,python]
----
from proximadb_sdk import AutoML, OptimizationGoal

automl = AutoML(client)

recommendation = automl.recommend_engine(
    vector_count=1_000_000,
    vector_dimension=768,
    read_ratio=0.9,
    target_latency_ms=10,
    memory_budget_mb=8192,
    goal=OptimizationGoal.LATENCY,
)

print(f"Recommended: {recommendation.engine}")
print(f"Confidence: {recommendation.confidence:.2f}")
print(f"Reasoning: {recommendation.reasoning}")

client.create_collection(
    "optimized_vectors",
    dimension=768,
    storage_engine=recommendation.engine,
)
----

== Observability

=== Metrics and Tracing

[source,python]
----
from proximadb_sdk import Observability, traced, metered

# Initialize observability
obs = Observability(client, enable_metrics=True, enable_tracing=True)

# Decorate functions for automatic instrumentation
@traced
@metered
def search_products(query):
    return client.search("products", vector=query, top_k=10)

# Export metrics (Prometheus format)
prometheus_metrics = obs.metrics.export_prometheus()

# Export traces (OpenTelemetry format)
traces = obs.tracer.export_otlp()
----

== Security

=== OAuth2 Authentication

[source,python]
----
from proximadb_sdk import OAuth2Config, OAuth2Provider, OAuth2TokenManager, ProximaDBClient, Protocol

# Configure OAuth2
oauth_config = OAuth2Config(
    provider=OAuth2Provider.OKTA,
    client_id="my-client-id",
    client_secret="my-client-secret",
    token_url="https://my-org.okta.com/oauth2/default/v1/token",
    scopes=["openid", "profile", "proximadb:read", "proximadb:write"],
    auto_refresh=True,
)

# Get token manager
token_manager = OAuth2TokenManager(oauth_config)

# Client credentials flow (for service accounts)
token = token_manager.client_credentials()

# Use with client
client = ProximaDBClient(
    url="http://localhost:5678",
    protocol=Protocol.REST,
    api_key=token.access_token,
)
----

=== RBAC Permissions

[source,python]
----
from proximadb_sdk import (
    RBACManager, SecurityManager, SecurityContext,
    security_context, Role
)

# Initialize RBAC
rbac = RBACManager()

# Check permissions
allowed = rbac.check_permission(
    roles=["developer"],
    required_permission="vector:search"
)

# Create security context
security = SecurityManager(rbac_manager=rbac)
ctx = security.create_context(
    user_id="user123",
    tenant_id="tenant_abc",
    roles=["analyst"]
)

# Use context for operations
with security_context(ctx):
    # Operations run with analyst permissions
    results = client.search("vectors", query, top_k=10)
----

== Filtering

=== Filter Builder

[WARNING]
====
`FilterBuilder().add` does not exist in the SDK; this block is illustrative until TD-SDKDOC-1.
Use `metadata_filter=` for equality filters.
====

[source,python]
----
from proximadb_sdk import FilterBuilder, eq, gt, lt, in_list, and_filters, or_filters

# Simple filters
filter1 = FilterBuilder().add(eq("category", "electronics")).build()
filter2 = FilterBuilder().add(gt("price", 100)).add(lt("price", 500)).build()

# IN operator
filter3 = FilterBuilder().add(in_list("status", ["active", "pending"])).build()

# Logical combinations
complex_filter = or_filters(
    and_filters(eq("category", "electronics"), gt("price", 200)),
    and_filters(eq("category", "books"), lt("price", 50))
)
----

== Batch Operations

[source,python]
----
from proximadb_sdk import RequestBatcher, BatchStrategy

# Create batcher
batcher = RequestBatcher(
    client=client,
    strategy=BatchStrategy.SIZE,
    batch_size=100,
    flush_interval_ms=1000,
)

# Queue operations
for record in records:
    batcher.queue_insert("my_collection", record)

# Flush remaining
batcher.flush()

# Get metrics
metrics = batcher.get_metrics()
print(f"Batches sent: {metrics.batches_sent}")
print(f"Average batch size: {metrics.avg_batch_size}")
----

== Error Handling

[source,python]
----
from proximadb_sdk import (
    ProximaDBError,
    CollectionNotFoundError,
    VectorDimensionError,
    AuthenticationError,
    RateLimitError,
    TimeoutError,
)

try:
    results = client.search("my_collection", query, top_k=10)
except CollectionNotFoundError:
    print("Collection does not exist")
except VectorDimensionError as e:
    print(f"Dimension mismatch: expected {e.expected}, got {e.actual}")
except AuthenticationError:
    print("Authentication failed - check API key")
except RateLimitError as e:
    print(f"Rate limited - retry after {e.retry_after}s")
except TimeoutError:
    print("Request timed out")
except ProximaDBError as e:
    print(f"ProximaDB error: {e}")
----

== Best Practices

=== Connection Management

[source,python]
----
from proximadb_sdk import ProximaDBClient, Protocol

# Use connection pooling for high throughput
client = ProximaDBClient(
    url="http://localhost:5678",
    protocol=Protocol.REST,
    pool_size=20,
    timeout=30.0,
)

# Reuse client instance across requests
# Don't create new clients for each operation
----

=== Batch Inserts

[source,python]
----
from proximadb_sdk import ProximaRecord

# Good: Batch inserts
records = [ProximaRecord(id=f"v{i}", vector=vecs[i]) for i in range(1000)]
client.insert_records("collection", records)

# Bad: Individual inserts
for i in range(1000):
    client.insert_records("collection", [ProximaRecord(id=f"v{i}", vector=vecs[i])])
----

=== Resource Cleanup

[source,python]
----
# Embedded mode - always flush before exit
from proximadb_embedded import ProximaDB

db = ProximaDB(data_dirs="./data")
try:
    # ... operations ...
finally:
    db.flush()
    db.close()
