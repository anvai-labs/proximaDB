= Unified Port Migration Guide
:toc: left
:toclevels: 3
:icons: font
:source-highlighter: highlight.js

== Overview

ProximaDB 0.2.0 introduces *Unified Port Mode*, which consolidates REST, gRPC, and Arrow Flight protocols onto a single port (default: 5678). This simplifies deployment by reducing the number of ports to manage.

=== Benefits

* *Simpler Firewall Rules*: One port instead of three (5678, 5679, 5680)
* *Easier Load Balancing*: Single endpoint for all protocols
* *Unified TLS*: Single certificate for all protocols
* *Reduced Complexity*: Simpler client configuration

=== How It Works

The unified port uses HTTP/2 protocol multiplexing with automatic protocol detection:

[source,mermaid]
----
%%{init: {"theme": "neutral"}}%%
flowchart LR
    subgraph "Client Requests"
        REST["REST (JSON)"]
        GRPC["gRPC (Protobuf)"]
        ARROW["Arrow Flight"]
    end

    subgraph "Unified Port 5678"
        DETECT["Protocol Detector"]
        REST --> DETECT
        GRPC --> DETECT
        ARROW --> DETECT
    end

    subgraph "Protocol Handlers"
        REST_H["REST Handler"]
        GRPC_H["gRPC Handler"]
        ARROW_H["Arrow Flight Handler"]
    end

    DETECT -->|"application/json"| REST_H
    DETECT -->|"application/grpc"| GRPC_H
    DETECT -->|"arrow.flight.*"| ARROW_H
----

== Migration Steps

=== Step 1: Update Server Configuration

Edit your `config.toml` to enable unified mode:

[source,toml]
----
[api]
# Enable unified port mode (recommended)
unified_mode = true
unified_port = 5678

# Legacy ports (used when unified_mode = false)
grpc_port = 5679
rest_port = 5678
arrow_flight_port = 5680

# Protocol-specific settings
[api.protocols.rest]
enabled = true
compression = false

[api.protocols.grpc]
enabled = true
max_message_size_mb = 64
compression = true
reflection = true

[api.protocols.arrow_flight]
enabled = true
max_message_size_mb = 512
----

=== Step 2: Update Firewall Rules

.Before (Multi-Port Mode)
[source,bash]
----
# Open ports for REST, gRPC, and Arrow Flight
ufw allow 5678/tcp  # REST
ufw allow 5679/tcp  # gRPC
ufw allow 5680/tcp  # Arrow Flight
----

.After (Unified Mode)
[source,bash]
----
# Only one port needed
ufw allow 5678/tcp  # All protocols
----

=== Step 3: Update Client Applications

==== Python SDK

.Before (Multi-Port Mode)
[source,python]
----
from proximadb_sdk import ProximaDBClient, PortMode

# Explicit protocol URLs
client = ProximaDBClient(
    url="http://localhost:5678",  # REST
    port_mode=PortMode.MULTI,
)

# For gRPC, connect to different port
grpc_client = ProximaDBClient(
    url="localhost:5679",
    protocol="grpc",
    port_mode=PortMode.MULTI,
)
----

.After (Unified Mode - Recommended)
[source,python]
----
from proximadb_sdk import ProximaDBClient, Protocol

# Single URL for all protocols. Pass the protocol explicitly: the automatic choice is gRPC, and a
# collection created over gRPC cannot store records yet (TD-GRPCCREATE-1).
client = ProximaDBClient(url="http://localhost:5678", protocol=Protocol.REST)

# gRPC on the same port (protocol multiplexed)
grpc_client = ProximaDBClient(
    url="http://localhost:5678",
    protocol="grpc",  # Same port, protocol multiplexed
)
----

==== Arrow Flight

.Before (Multi-Port Mode)
[source,python]
----
from proximadb_sdk.protocols.arrow_flight import ArrowFlightClient

# Connect to Arrow Flight port
client = ArrowFlightClient("localhost:5680")
----

.After (Unified Mode)
[source,python]
----
from proximadb_sdk.protocols.arrow_flight import ArrowFlightClient

# Connect to unified port
client = ArrowFlightClient("localhost:5678")
----

==== gRPC Clients (Any Language)

New gRPC clients should use `proximadb.v2.ProximaRecordService`. The
`proximadb.v1.*` services remain on the unified port only as deprecated
compatibility services and return deprecation metadata.

.Before
[source,bash]
----
# Connect to gRPC port
grpcurl localhost:5679 proximadb.v2.ProximaRecordService/Search
----

.After
[source,bash]
----
# Same unified port
grpcurl localhost:5678 proximadb.v2.ProximaRecordService/Search
----

=== Step 4: Update Load Balancer Configuration

==== NGINX

.Before (Multi-Port Mode)
[source,nginx]
----
upstream proximadb_rest {
    server proximadb-1:5678;
    server proximadb-2:5678;
}

upstream proximadb_grpc {
    server proximadb-1:5679;
    server proximadb-2:5679;
}

upstream proximadb_arrow {
    server proximadb-1:5680;
    server proximadb-2:5680;
}

server {
    listen 80;
    location /api/ {
        proxy_pass http://proximadb_rest;
    }
}

server {
    listen 9090 http2;
    location / {
        grpc_pass grpc://proximadb_grpc;
    }
}
----

.After (Unified Mode)
[source,nginx]
----
upstream proximadb {
    server proximadb-1:5678;
    server proximadb-2:5678;
}

server {
    listen 443 ssl http2;

    # All protocols through single upstream
    location / {
        grpc_pass grpc://proximadb;
        proxy_pass http://proximadb;
    }
}
----

==== AWS ALB / NLB

.Before
* 3 Target Groups (REST: 5678, gRPC: 5679, Arrow: 5680)
* 3 Listeners with path-based routing

.After
* 1 Target Group (Unified: 5678)
* 1 Listener (HTTP/2 enabled)

=== Step 5: Update Kubernetes Services

.Before (Multi-Port Mode)
[source,yaml]
----
apiVersion: v1
kind: Service
metadata:
  name: proximadb
spec:
  ports:
  - name: rest
    port: 5678
    targetPort: 5678
  - name: grpc
    port: 5679
    targetPort: 5679
  - name: arrow-flight
    port: 5680
    targetPort: 5680
----

.After (Unified Mode)
[source,yaml]
----
apiVersion: v1
kind: Service
metadata:
  name: proximadb
spec:
  ports:
  - name: unified
    port: 5678
    targetPort: 5678
    appProtocol: h2c  # HTTP/2 cleartext
----

== Backwards Compatibility

=== Gradual Migration

You can run both modes during migration:

[source,toml]
----
[api]
# Enable unified mode on new port
unified_mode = true
unified_port = 5688  # New unified port

# Keep legacy ports active during transition
grpc_port = 5679
rest_port = 5678
arrow_flight_port = 5680
----

=== Fallback to Multi-Port Mode

If you encounter issues, disable unified mode:

[source,toml]
----
[api]
unified_mode = false

# Original ports
grpc_port = 5679
rest_port = 5678
arrow_flight_port = 5680
----

== Protocol Detection Logic

The unified port detects protocols in priority order:

|===
| Priority | Protocol | Detection Method

| 110
| Arrow Flight
| Path starts with `/arrow.flight.protocol.`

| 100
| gRPC
| `Content-Type: application/grpc*` OR HTTP/2 with `grpc-timeout` header

| 10
| REST (fallback)
| `Content-Type: application/json`, `text/*`, or default
|===

== Performance Considerations

=== Latency Overhead

Protocol detection adds minimal overhead:

|===
| Metric | Impact

| Detection Latency
| +10-50μs per request (header inspection only)

| Memory
| -100KB (single listener vs. three)

| TLS Handshakes
| Reduced (single endpoint)

| Connection Overhead
| Reduced (HTTP/2 multiplexing)
|===

=== When to Use Multi-Port Mode

Consider keeping multi-port mode if:

* You need protocol-specific load balancing
* Your infrastructure requires separate ports
* You're using legacy clients that don't support HTTP/2

== Troubleshooting

=== Protocol Detection Issues

.Symptom: gRPC requests treated as REST
[source,bash]
----
# Ensure Content-Type header is correct
curl -H "Content-Type: application/grpc" http://localhost:5678/...
----

.Symptom: Arrow Flight connection fails
[source,bash]
----
# Ensure HTTP/2 is enabled in your client
# Arrow Flight requires HTTP/2
----

=== Connection Issues

.Check unified mode is active
[source,bash]
----
# Server logs should show:
# "Starting unified server on 0.0.0.0:5678"

# Test REST
curl http://localhost:5678/health

# Test gRPC
grpcurl -plaintext localhost:5678 list
----

== Reference

=== Configuration Options

|===
| Option | Type | Default | Description

| `api.unified_mode`
| bool
| `true`
| Enable unified port mode

| `api.unified_port`
| int
| `5678`
| Port for unified mode

| `api.grpc_port`
| int
| `5679`
| gRPC port (multi-port mode)

| `api.rest_port`
| int
| `5678`
| REST port (multi-port mode)

| `api.arrow_flight_port`
| int
| `5680`
| Arrow Flight port (multi-port mode)
|===

=== SDK Options

|===
| SDK | Option | Values | Default

| Python
| `port_mode`
| `PortMode.UNIFIED`, `PortMode.MULTI`
| `UNIFIED`

| Python
| `protocol`
| `Protocol.AUTO`, `GRPC`, `REST`, `ARROW_FLIGHT`
| `AUTO`
|===
