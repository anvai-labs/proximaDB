= RFC-0003 Open-table analytics and batch execution
:status: Planning baseline; qualification pending
:date: 2026-11-21
:toc:

== Recommendation

Use DataFusion for relational planning and as the reference physical executor for analytical SQL. Make an unmaterialized ProximaDB table, a published Iceberg snapshot and a supported external Delta version eligible inputs to the same join. A user should be able to run that join through pgwire without first copying each source to a preferred format. Eligibility requires a reader that can prove visibility, types and access policy for that particular read.

Invest first in getting fewer bytes to the operators and in bounding the cost of loading and opening tables. A native scan, join or fused operator earns a place under the DataFusion plan when it gives correct answers and a repeatable end-to-end gain over the best existing provider on identical input. Keep the legacy native route available for its current callers and as a diagnostic control. Evaluate Ballista first for remote execution after the local contracts pass. These requirements guide P3/P5/P6 and the later scale-out review. Release order remains with the link:../current/ROADMAP.adoc[roadmap].

== What the benchmark establishes

The retained console log (ledger-0.1b.log, November 20–21) covers synthetic TPC-shaped data at scale 0.1. The generator's roughly 866k estimate covers all eight TPC-H tables. It generates 150k orders with 1–7 lineitems each. The log supplies no exact lineitem count. The benchmark process failed creating the final ledger directory after both suites. The numbers below are successful-query repeat medians and completion counts, independent of value parity.

[cols="1,2,2",options="header"]
|===
| Workload | Before MATERIALIZE, native sweep | After MATERIALIZE, DataFusion sweep
| TPC-H | 21/22, 15,206 ms median. Q21 hit the 300 s deadline twice. | 22/22, 39 ms median. Q21 repeated in 60 ms.
| TPC-DS subset | 28/63. Of 35 failures, 34 returned 0A000 and q17 returned XX000. | 63/63, 20 ms median. q17 returned zero rows.
|===

TPC-H load consumed 17,730,719 ms for 4,334 INSERT batches at parallelism one. Publishing all eight tables then took 19,545 ms. TPC-DS load consumed 221,382 ms for 2,944 batches. Peak recorded process RSS across the phases was 14,749 MiB. The benchmark changed both storage representation and executor between sweeps. It measured neither an isolated join-kernel gain nor a comparison against Spark or Trino. Publication cost belongs in time-to-first-answer for a fresh load.

Two specific regressions belong in the evidence gate. For q17, minimize the native expression that expects Int32 and receives Float64 at ss_quantity ordinal 10. Exercise a nonempty result with known values and verify declared types, coercion and NULL behavior. For the reported SF1 stall, the 135,313 MiB estimate exceeds the 65,536 MiB envelope. In the reviewed harness the banner prints *after* validation. The guard checks acknowledgement, finite limit and host headroom but never compares estimated peak with that limit. At 0.1 the 8,192 MiB acknowledgement check runs before the finite-limit check, and the successful invocation reports Some(65536). The SF1 blocked operation remains unknown. Require an over-budget refusal before server startup, phase heartbeat and a bounded no-progress timeout. Verify the guard with synthetic limits.

== Prior art and resulting constraints

The design choice that matters across these systems is where a pipeline may block, spill, replay or publish. A lazy DAG can still need a wide shuffle. An MPP stage can use a durable exchange. The same query may benefit from both behaviors.

[cols="2,3,3",options="header"]
|===
| System | Mechanism and cost | Requirement for ProximaDB
| Hadoop MapReduce and Hive | Map outputs undergo partition, sort and shuffle. Chaining jobs can persist intermediate output. Hive metastore partitions can drift from files added out of band. https://hadoop.apache.org/docs/current/hadoop-mapreduce-client/hadoop-mapreduce-client-core/MapReduceTutorial.html[MapReduce tutorial], https://hive.apache.org/docs/latest/language/languagemanual-ddl/[Hive partition management]
| Pipeline local filters and projections. Introduce an exchange only for required distribution, ordering or recovery. Resolve table membership through the format's authority.
| Spark | Data Source V2 negotiates pushdown and supplies task inputs. Runtime statistics let adaptive execution coalesce small partitions, split skewed ones or change joins after a shuffle. https://spark.apache.org/docs/latest/sql-v2-data-sources.html[Data Source V2], https://spark.apache.org/docs/latest/sql-performance-tuning.html[adaptive execution]
| Keep connector capabilities explicit. Measure partition bytes, max-to-median skew and build-side size. Allow bounded replanning of unconsumed stages while preserving key distribution and results already emitted.
| Trino | Pipelined execution limits interactive latency. Task retry can reuse spooled exchanges, paying storage and I/O costs and requiring connector support. https://trino.io/docs/current/admin/fault-tolerant-execution.html[Fault-tolerant execution]
| Choose exchange durability by query class, replay cost and available budget. Require a retry-safe source and sink before enabling task replay.
| Impala | Concurrent queries can exhaust memory or saturate I/O. Admission pools bound concurrency, queue length and wait time. https://impala.apache.org/docs/build/html/topics/impala_admission.html[Admission control]
| Reserve coordinator and worker resources per tenant. Give interactive reads and backfills separate admission budgets and finite queue deadlines. Measure p95 under concurrent load.
| DataFusion and Ballista | A DataFusion memory pool covers participating operators. Process memory includes other allocations. Ballista divides plans into stages and sends tasks to executors that exchange Arrow data. Extensions must be understood at both ends. https://datafusion.apache.org/library-user-guide/securing-datafusion.html[Runtime limits], https://datafusion.apache.org/ballista/contributors-guide/architecture.html[Ballista architecture]
| Account separately for metadata, decoders, joins, network buffers and spill. Negotiate plan/extension versions before placement. Prove a custom scan can run on a worker with only its declared inputs.
| Airflow | A task may retry after upstream data changes or on a different machine. Tasks need stable partitions, durable outputs and idempotent effects. https://airflow.apache.org/docs/apache-airflow/stable/best-practices.html[Task best practices]
| Expose submit/status/cancel and a durable output receipt for retryable jobs. Leave calendars, backfill dependencies and cross-service orchestration with the workflow tool.
|===

=== Execution representations and Volcano

Trino supplies column blocks through its page-source SPI and negotiates split discovery and pushdown at the connector. Hive's vectorized operators consume `VectorizedRowBatch` and benefit from ORC stripe and row-group indexes. Impala's C++ runtime passes batches of tuple rows with attached memory, and can distribute runtime join filters to scan nodes. Redshift documents columnar storage, distributed slices and compiled query segments. This describes different execution and storage choices even where engines can all read Parquet. Redshift's published performance design leaves its internal batch ABI unspecified. https://trino.io/docs/current/develop/connectors.html[Trino connector SPI], https://github.com/apache/hive/blob/master/ql/src/java/org/apache/hadoop/hive/ql/exec/vector/VectorGroupByOperator.java[Hive vectorized aggregation], https://hive.apache.org/docs/latest/language/languagemanual-orc/[Hive ORC], https://github.com/apache/impala/blob/master/be/src/runtime/row-batch.h[Impala RowBatch], https://impala.apache.org/docs/build/html/topics/impala_runtime_filtering.html[Impala runtime filtering], https://docs.aws.amazon.com/redshift/latest/dg/c_challenges_achieving_high_performance_queries.html[Redshift performance]

Use *Volcano* as the working product name for the native executor. Keep the bound scan contract independent of a DataFusion `TableProvider` or `ExecutionPlan`. A format-specific binder owns version and feature negotiation. The resulting scan describes the visible schema, projections, exact and residual predicates, replayable splits, deletes and placement. Both executors consume that contract. Start with Arrow batches at the local source boundary. A Volcano operator may retain dictionaries, carry a selection vector, or fuse operators within one fragment if the boundary preserves values, order guarantees, cancellation and memory accounting. Count conversion and exchange bytes before adopting another representation.

Prioritize projection and physical pruning, then safe runtime filters, partitioned hash joins and bounded aggregation with spill. Keep the generic batch path available for every supported type. Gate specialization and compiled fragments on measured kernel and end-to-end wins that include cold setup and compilation. Measure shared scans before attributing a speedup to an executor. Carry the same visibility and split contracts to a distributed worker before adding a second scheduler. Reserve memory for batches and dictionaries still referenced by downstream operators, even after the producing stage yields.

== Pinned source design after the SF1 checkpoint

Catalog classification owns the authority and format decision for DDL, write
refusal and read routing. At statement setup, the binder requires one eligible
layout and resolves its exact snapshot, log version or manifest digest. Each
format reader owns protocol interpretation, schema mapping and delete
application. The local Arrow batch source exposes schema, a stable split
inventory and repeatable projected scans without optimizer types. DataFusion
plans against the bound source and opens each scan partition on first demand.
Unpushed filters stay in DataFusion. These boundaries let another executor
reuse the readers while keeping its plan, scheduling and SQL semantics above
the batch contract.

Pinned pgwire reads resolve SQL-folded unquoted names and preserve quoted

== Source and sink requirements

. *Bind the view once.* Resolve each relation to tenant, catalog identity, schema/field identities, supported format features, policy generation and immutable snapshot or file-set token. Managed fresh tables also pin a reconciled WAL visibility boundary. State the consistency level of a join across independently committed catalogs. A caller requiring atomic cross-table visibility receives a refusal unless the catalog can supply it. Record how long the source can serve the selected version and return snapshot-expired if it becomes unavailable. Reauthorize a resumed job.
. *Negotiate the scan.* Describe projection, predicates (exact, pruning-only, unsupported), splitability, ordering, partitioning, estimate confidence and freshness per source. SQL residuals run on all surviving rows. Apply LIMIT after visibility, policy and residuals unless equivalence is proved. Statistics may select join order, broadcast or repartition. Unknown estimates cannot authorize unbounded broadcast. Runtime filters must preserve outer/anti-join semantics and newer WAL versions.
. *Enumerate and execute.* A replayable split names an immutable source version, object identity, logical range, schema, partition transform and applicable deletes. An expiring opaque credential reference is scoped to the tenant and input. Page manifests under a coordinator byte limit and coalesce small files without losing per-file identity. A worker opens the split and yields byte-bounded Arrow RecordBatch streams under backpressure. Count decode, copies, range reads and cancellations. Arrow defines the in-process data representation. Transport encoding is negotiated separately. https://arrow.apache.org/docs/format/Columnar.html[Arrow columnar format]
. *Publish once.* A CTAS or INSERT SELECT job fixes its source versions, target parent and run key. Workers stage uniquely named files and report their checksums, partitions, schema and row counts. The target owner validates the winning attempts and fences a single metadata commit. Bind the run key and input digest to its outcome durably so a lost acknowledgement can return the prior receipt. A changed input under the same key conflicts. On abort, clean unreferenced files after checking outstanding leases. For native DML preserve canonical WAL ordering, constraints and recovery. Overwrite and MERGE each need independent conflict and crash proofs.

A raw-file listing becomes repeatable only with an immutable inventory and enforceable object versions or equivalent immutability. ADLS, S3 and local files may offer different guarantees. Raw-file exports return a manifest of completed objects. Atomic table replacement requires a transactional target. Test decimal precision, timestamp zones, NULLs, duplicate keys, empty input and nested values across every supported adapter.

The local NDJSON reader uses a declared flat SQL schema and one `.jsonl` file
beneath an operator-allowlisted directory. Register it through pgwire with
`format='json'`, `authority='external'`, a canonical `external_location` file
URI, and `ndjson_manifest_sha256`. The sibling `<file>.manifest.json` is capped
at 1 MiB. Version 1 stores the file size and a contiguous sequence of ranges,
each with an exclusive `end` byte offset and a hexadecimal `sha256`. Every
range ends at a newline and is capped at 8 MiB. Verify each accessed range before
decoding any of its records. A query with early termination may leave
unneeded ranges unread. Missing nullable fields become NULL. Undeclared
fields, invalid types and fixed-point decimals that require rounding fail
during decode. Both the manifest and data use confined local handles.
The DataFusion provider consumes the same Arrow split interface for Iceberg
and NDJSON, and can join pinned tables in either format.

Evaluate Delta Kernel for binding and scan planning. The published 0.30.1 manifest pairs its `arrow-60` feature with Arrow and Parquet 60 and object_store 0.14.2. Its default engine accepts a caller-supplied object store. Exercise that interface with confined log discovery and file reads, and carry query cancellation into snapshot replay and scans. The legacy local Delta connector defers checkpoint replay. Require successful checkpoint, feature and delete fixtures before exposing a direct Delta reader. https://docs.rs/crate/delta_kernel/0.30.1/source/Cargo.toml[Delta Kernel dependency manifest], https://docs.rs/delta_kernel_default_engine/0.30.1/delta_kernel_default_engine/struct.DefaultEngine.html[default engine], link:../../src/storage/formats/open/delta.rs[existing connector]

A standalone compatibility test compiled Delta Kernel 0.30.1 with Arrow 60.1
and object_store 0.14.2. It matched a delta-rs writer's four versions across an
append, overwrite, checkpoint and subsequent append. With the JSON commits
through the checkpoint removed from the fixture's log, versions 2 and 3
still returned the expected values and version 0 failed to bind. This
exercised the default local object store.

The read-only pgwire registration uses `format='delta'`, `authority='external'`,
a directory `external_location` and an explicit `delta_version`. The
directory must be within the operator's local allowlist. Delta Kernel
resolves the version, checks protocol features, replays checkpoints and
builds file transforms. Directory handles confine log listing, Parquet and
deletion-vector reads. File references cannot use remote or presigned URLs.
The provider streams Arrow batches with one queued batch per scan partition
and applies sparse deletion vectors to physical row positions. Positional
Kernel transforms and literal partition-value insertions push projection
into Parquet while preserving those positions. Other transforms apply
projection to the logical output.
Initial DV support
covers inline and table-relative files. The local adapter caps both log
directory entries and active data files at 16,384. Metadata or DV blobs
read in full are capped at 16 MiB, and a DV may represent at most 1,048,576
deleted rows. The reader relies on the producer's immutable data-file and
transaction-log contract at the registered root.

== Distribution and data engineering

Keep planning lazy until required properties are known. A scan/filter/local aggregate can run as one pipeline. A large fact-to-fact join may need hash repartition on both sides. A small dimension may be broadcast only within each worker's reservation. Preserve hash function/version, key coercion, NULL semantics and partition count across exchange. Mark partial aggregation states with a merge-compatible type and version. Global ordering, DISTINCT and windows require their SQL distribution/order guarantees.

The coordinator owns admission, tracks each input’s retention guarantee, renews available leases, and owns fragment attempts and the terminal outcome. Workers own cancellable split reads, bounded compute and staged exchange partitions. Use the same split and physical operator on one node without a network hop. Across nodes, negotiate protocol, Arrow schema and extension codecs. A node-local Layer A or WAL tail requires proven placement and retention for the full read, or a safe pinned alternative. Show the refusal reason in EXPLAIN if neither is available.

Interactive work may pipeline exchanges and fail promptly on loss. Restartable batch work may checkpoint selected wide exchanges on durable storage. Record bytes and lifetimes for each choice. Fence stale attempts and deduplicate partition completions. After worker loss, retry only deterministic input ranges with valid leases. After coordinator loss, recover ownership and reconcile target commit status before acknowledging a write. A query that already streamed rows needs a resumable output cursor or an explicit client-visible failure. Never replay a partial result transparently. Cap retries and clean up leases, buffers and exchange files on timeout. Bound coordinator state with paged split assignment and test cancellation while a consumer stalls.

For a backfill, the orchestrator submits an input manifest or version interval and stable run key. A bounded job reads CSV/Avro/JSON, conforms types, joins a pinned dimension and publishes partitioned output. Return row counts, rejected records under the selected error policy, input versions and output snapshot. For incremental loads persist the consumed offset with the commit, or reconcile it through the same receipt. Test duplicate delivery, late records, overlapping backfills, schema drift and restart after commit. Continuous streaming and watermark semantics need a separate contract.

Specification and tagged-source review, 2026-11-21. Iceberg format version, Delta library release, Delta minimum reader/writer protocols and Delta compatibility feature are independent numbers. *The shared bytes.* Eligible views can reference the same Parquet objects. For a portable on-disk deletion vector, Iceberg's Puffin blob uses the Delta-compatible length, magic, Roaring bitmap and checksum framing. Our existing reader fetches exactly the declared blob range and checks cardinality. This is a concrete reuse opportunity, subject to a cross-produced fixture. https://iceberg.apache.org/puffin-spec/#deletion-vector-v1-blob-type[Puffin blob specification], https://github.com/delta-io/delta/blob/v4.4.1/PROTOCOL.md#deletion-vector-file-storage-format[Delta framing], link:../../crates/storage/proximadb-iceberg-engine/src/snapshot_deletes.rs[ProximaDB range reader]

[[catalog-interoperability]]
== Proposed catalog contract for ProximaDB and Anvai Lake

Anvai Lake's reference catalog is Lakekeeper. Garage is an S3-compatible file store in its
cross-profile test bed. Keep catalog and object-store qualification independent.
ProximaDB's native catalog keeps its local identity and
recovery role under link:../12-design/adr/ADR-063-objstore-native-catalog-driven-restartability.adoc[ADR-063 D1].
Offer xCatalog as an optional Iceberg REST provider for Anvai Lake once its profile passes.
Both products can also connect directly to an enrolled external catalog. Anvai Lake keeps its
PostgreSQL roles, WAL, managed visibility and publication-attempt ledger. A second product or
catalog service is unnecessary for ProximaDB native operations. The optional REST endpoint
serves the same xCatalog authority as the owning ProximaDB deployment.

Distinguish three owners per table. The identity authority maps an authenticated principal into
the product's tenant and grants. The data writer owns local transaction semantics and publication
attempts. The catalog authority owns the published head for the bound table and ref. Native
ProximaDB may fill all three roles. A qualified Anvai Lake writer can keep its local roles and
delegate the published head to xCatalog or an external catalog. An attached external table uses
a locally enrolled alias and the provider's table identity, schema, snapshots and retention.
The alias grants no right to mutate the provider's state. First-class provider support means a
qualified operation and table profile, including explicitly authorized writes where qualified.

[cols="2,4,4",options="header"]
|===
| Boundary | Contract | First negative control
| Resolve and authorize
| Bind the authenticated issuer/subject or effective PostgreSQL role to the local tenant and grant generation, then the approved provider instance, warehouse, table UUID/incarnation, ref and object-store endpoint/root. Pin once per statement. Verify required capabilities before opening data files or attempting mutation. Bound retries, pagination, metadata bytes and deadlines.
| Two tenants use the same table name and snapshot number. Rotate a role mapping, drop and recreate a table, and change an approved endpoint. Reuse a warm cache and a prepared query. Refuse stale authorization or incarnation before forbidden object access.
| Read the exact publication
| Return a retained snapshot, schema/field mapping, immutable metadata locator and authorized read scope, or an explicit empty, expired, denied, unsupported or unavailable result. A metadata URI and its inline representation must describe the same persisted publication. Scope cache reuse to the approved storage identity/version and recheck grants. Use a qualified governed plan for row filters or masks, or refuse that profile.
| Move the head during a scan, omit a required delete file, break the persisted metadata pointer, and revoke access with warm metadata or byte caches. An empty table is a separate positive control. A raw-file route cannot satisfy a required row-policy boundary.
| Commit and find the outcome
| Pin the table UUID, ref, expected head, schema/spec preconditions, writer fence and exact attempt identity. Keep durable intent before sending. The catalog atomically advances the head under its supported preconditions. Reconcile ambiguous sends against authoritative, retained operation evidence. A receipt reports the original committed snapshot when proven. A verified rejection can replan under the attempt policy. Unknown remains lookup-only.
| Two writers race at one head, a fenced writer sends late, and the catalog accepts a commit whose reply is lost. Restart before and after acceptance. Demand one effect, a recoverable receipt and no second send on inconclusive lookup. Refuse a mixed unsupported update before any partial effect.
| Failover and retention
| A provider timeout preserves the existing authority and fails the operation where freshness cannot be proven. Catalog migration is an explicit fenced ownership transfer with verified head, retention and unresolved attempts. Require retained or revalidated authorization before reading any old pin. Retention and physical cleanup stay with the publication owner.
| Stop the external catalog, make a stale local mirror reachable, and expire the pinned inputs. Verify the mirror cannot take over authority and an expired pin cannot silently rebind to the latest version.
|===

Source blocker on `8765f65f6`. The Iceberg REST `commit_table` path can return success after
logging `AddSnapshot` without applying it and does not evaluate the request requirements.
`load_table` can fall back to synthesized metadata when the published lookup cannot establish
the publication. A qualified native read profile must expose the committed metadata or fail
explicitly. A qualified write profile must apply and check the requested transaction semantics
or decline the operation. link:../../crates/control/proximadb-catalog/src/iceberg_rest_service.rs[REST service]

First reuse the same profile fixtures, typed errors, capability receipts and object-request
accounting in both products. Preserve each product's internal catalog interfaces and WAL format.
Start with pinned read interchange through xCatalog and Lakekeeper, then repeat the same read
profile against Polaris on the same qualified storage. Add Glue, Horizon and Unity as separate
authentication, governance and table-capability profiles. Qualify commit and reconciliation per
provider after the read profile, with local-write acknowledgement and published visibility

outside the split/Parquet hot loop. Any shared client library must earn adoption from two

*Backfill expiry decision (owner-confirmed).* Managed Iceberg currently retains a clock-free generation window for data and metadata (default three). Binding a version identifies data but does not extend that window. For the first release, confirmed expiry of any still-required input version before publication ends the job with a terminal snapshot-expired outcome. Report the source and version to the authorized caller. Preserve the same terminal result on same-key retry and reclaim uncommitted staged output after reachability checks. The caller can start a new run with a new key and newly bound versions. A transient read error requires retry or an I/O failure. If publication was attempted, reconcile its outcome first so input expiry cannot mask an already committed write. A completion guarantee across source expiry requires either an enforceable upstream retention agreement or a fully staged, verified input manifest with all referenced data and deletes under job-owned retention. A list of URIs is insufficient. Pause a backfill mid-scan, advance one source beyond its retention window and resume. Assert that the target head stays fixed, same-key retry reproduces expiry and a new-key run reports its own input versions and result. Repeat with a lost target commit response to verify that committed work returns its receipt. link:../10-quality/td/TD-GCRETAIN-1-dv-generation-gc-keeps-two-generations-and-a-pinned-reader-loses-files-mid-scan.adoc[generation retention], link:../10-quality/td/TD-SPINE-3-iceberg-metadata-gc.adoc[metadata GC]

*Visibility example.* An owner commits an explicit tombstone after the last Iceberg publication. A fresh query can use Layer A or a proven merge against the WAL boundary. A remote worker holding only that older publication must decline the fresh placement. An explicitly requested historical snapshot may still contain the row. Test the same race with a deletion vector and a catalog flip delayed after commit. Preserve the fence's existing refusal for an unordered delta. Its current guarantee covers explicit tombstones, and a caller requiring exact TTL visibility needs a provider that can prove it. link:../12-design/PUBLICATION_WAL_VISIBILITY_FENCE_2026_10_27.adoc[publication/WAL fence]

[[retryable-writes]]
== Outcome of a retryable batch write

The first sink to qualify is a single managed target. Use pgwire as the SQL-write authority and the existing table-write and publication paths. A job API can observe and cancel authorized work when it exists. The design requires a persisted recovery record before promising retries across process loss. Neither a successful flush nor a planned route is a commit receipt. link:../current/PLATFORM_PLAN.adoc#embedded-cloud-lifecycle[platform lifecycle]

Scope the caller's run key to tenant and target incarnation. Bind it to the logical operation, normalized parameters, source versions, target precondition, schema and session semantics. Physical replanning and attempt numbers do not change that identity. Concurrent submissions of the same key and digest join the existing outcome. A different digest conflicts. Keep a durable target-side commit identifier or atomically recoverable association to the run key through the advertised retry window, even when snapshot metadata ages out. After that window a replay must return an explicit expiry under the key-reuse policy. Blind execution of an old key can duplicate a successful append.

[cols="2,3,3",options="header"]
|===
| Observable state | Recovery action | Acceptance case
| Staged, with positive evidence that publication did not land | The fenced owner may resume or abort. Clean only proven unreachable artifacts after accounting for competing attempts. | Kill one of two attempts after writing its files. Exactly one winning file set is visible.
| Commit outcome unknown | Return pending reconciliation, preserve the staged objects and query the authoritative history using the commit identity. Lost acknowledgement or a failed metadata read alone cannot authorize a second append. | Drop the commit response and temporarily deny the metadata read. A same-key retry produces one effect after recovery.
| Snapshot committed, catalog layout behind | Record the landed snapshot. Complete or reconcile the forward-only catalog update under the publication fence. Expose the intermediate state to status callers and withhold job-complete acknowledgement until its promised visibility holds. | Restart after Iceberg CAS and before catalog flip. A newer valid tip stays ahead, affected fresh reads agree or refuse, and retry does not append rows again.
| Completed, or cancelled racing with commit | Completed returns the same authorized receipt with target ID, snapshot, counts and input digest. Cancellation can abort before commit. If publication won the race, report its committed outcome. | Lose the final response, revoke access, then retry from another process. Recheck authorization before disclosing the receipt. A failed access check cannot trigger another write.
|===

The current publisher already distinguishes landed, not landed and unknown. Its proof is scoped to the existing MATERIALIZE operation. A durable backfill receipt additionally needs cross-process run identity and the retention rule above. Arbitrary opaque keys require a durable deduplication marker after the full receipt expires. An alternative is an issued, expiring run identity whose expiry can still be verified after collection. Pick one before allowing deletion of replay evidence. For ingestion from offsets, advance the source checkpoint only after recovering the matching target commit. Initially scope this guarantee to one target. Multi-target atomic publication requires a separate transaction contract. link:../../src/services/dml/materialize_stream.rs[commit reconciliation], link:../10-quality/td/TD-SPINE-3-iceberg-metadata-gc.adoc[catalog flip failure behavior]
