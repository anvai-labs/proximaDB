== Summary

Every ProximaDB modality — vector, graph, document, observability/metrics/timeseries/event, relational,
ledger, and the fusion orchestrator — is, at the level that matters for maintenance, the **same
shape**: a **storage plane** + a **compute plane** + a thin layer of **modality semantics**. Today
that shape is realized inconsistently: relational rides the shared canonical spine end-to-end, vector
shares it for durability but not reads, document is mid-migration onto it, and graph, observability,
timeseries, ledger, and queue each carry **their own WAL and re-implement their own tier storage and
tenancy plumbing**. The result is code proliferation and inconsistent correctness/security guarantees.

This RFC proposes consolidating the **contract surface** — not the implementations. A small family of
narrow, tenancy-carrying contracts (durability/WAL, a `ConditionalKeyStore` for atomic keyed writes, a
record store, a read IR, tiering, tenancy, catalog) becomes the **single foundation every modality
stacks on**. Where a modality's access pattern genuinely diverges (the ledger's hot counters, the
queue's offsets, observability's time-partitioned ingest), it keeps its **own implementation behind
the same contract** — cohesion and performance preserved — instead of a bespoke off-contract silo. The
flagship new contract, `ConditionalKeyStore` (atomic insert-if-absent on composite-key bytes), is
extracted from the just-shipped ledger's proven **version-fenced** CAS core and reused by the relational
OLTP insert path to move composite-natural **`PRIMARY KEY`** uniqueness into a storage-level, fenced
atomic write (`oid == primary_key_string`, so it is one row-keyed-by-PK write). The coarse table lock is
**retained** for secondary `UNIQUE`/FK and cascade ordering — see §Design-gate review reconciliation.

The outcome: **foundational consistency + reduced code (one contract, many impls), cohesion per
modality, decoupling via contracts (storage and compute swap at ease), and enterprise security carried
in the contracts (tenant context, fail-closed, at every I/O boundary).**

== Motivation

=== The map: a shared spine adopted on a gradient

The canonical spine already exists — `trait TableRecordStore` (`src/services/record_store.rs:500`) +
`trait TableWalAppender` (`src/services/canonical_wal.rs`), with `TenantContext` in *every* method
signature. But adoption is uneven:

[cols="1,2,2,2", options="header"]
|===
| Modality | Write / WAL | Read engine | On the shared spine?
| *Relational* | shared `DirectWalTableRecordStore` + `FramedTableWalAppender` | shared `LogicalNode` IR → Volcano/DataFusion | **fully**
| *Vector* | shared store (PAX layout route) | siloed ANN (HNSW/IVF) | durability only
| *Document* | HYBRID — own legacy `UnifiedWALWriter`; canonical route default-on (feature) | siloed JSON projection | mid-migration
| *Graph* | HYBRID — canonical edge records + own ORION engine-WAL (CSR) + own metadata file | siloed ORION traversal / Cypher | partial
| *Observability / TS / Event* | **own** `ObservabilityStoragePort` WAL; `TimeSeriesService` own partitions/WAL | siloed LOGS/METRICS/PromQL/Tantivy | no
| *Ledger* | **own** `DurableLedger` `ledger.wal` (ratified, ADR-071) | counter reads | no
| *Queue* | **own** `QueueFs` segments ("access patterns differ") | siloed | no
| *Fusion* | none (orchestrates) | cross-modal fan-out + rank | n/a (pure compute)
|===

**Two costs of the gradient.** (1) *Code proliferation* — the queue re-implements memory/disk/object
tiers (`proximadb-queue/src/{memory_tier,disk_tier,object_tier}.rs`), each siloed modality re-rolls WAL
framing, and tenancy is re-plumbed per silo. (2) *Inconsistent guarantees* — a modality off the shared
contracts does not automatically inherit the tenant-fail-closed isolation, the tiering, or the CDC feed
the spine provides; correctness and security drift per modality.

=== The commonality is a primitive, not a coincidence

The ledger (just shipped) and the relational OLTP insert path want the *same* atomic operation. A
composite-`PRIMARY KEY` insert reduces to **atomic insert-if-absent on the encoded key tuple**; the
ledger's `compare_and_swap(key, expected = None)` is that exact shape. Today the relational path fakes
it with a **coarse in-process table op-lock** (`src/services/dml/mod.rs:2968`) wrapped around a
`get_by_key` + a later `write_mutations` — a TOCTOU window closed by serializing *all* inserts to a
table. That lock is a throughput ceiling and a correctness crutch standing in for a storage-level
atomic write the store lacks (confirmed: no atomic conditional write in `write_mutations`).

=== The minimum bar: serverless, low-cost, composite natural keys

- **Serverless / scale-to-zero** forbids relying on an in-process single writer: the serialization
  point must live in the **storage layer**. _(Revised P2.)_ The codebase's storage-layer serialization
  authority is the **object-store generation fence** / per-partition lease (`partition_lease.rs`), which
  attains atomicity by claiming *fresh monotonically-versioned successor slots* — an **append-only**
  pattern. That pattern does **not** transfer to a *reclaimable fixed PK slot*: a bare create-only
  `put_if_absent` plus the unconditional `delete` cannot reclaim a key race-free, so it is **not** a
  coordination-node-free unique index for a mutable PK. The serverless-correct construction is a
  **generation-fenced** conditional write; object-store is the scale-to-zero *escape hatch*, and the
  generation-fenced local-WAL path is the correctness-carrying default (see ADR-072 D5 and §reconciliation).
- **Composite natural keys are a hard requirement:** the key is a **typed** byte-tuple — length-delimited,
  order-preserving, NULL-explicit, type-tagged. _(Revised P2: the existing `encode_primary_key_tuple` is
  **not** reused — its own docstring documents an unescaped-separator collision and it is neither
  order-preserving nor type-safe. A typed `Identity` codec replaces it; ADR-072 D9.)_ Never a surrogate.
- **Low cost to operate + use:** one substrate to run (fewer moving parts), scale-to-zero pay-per-use,
  object-store cold tier, and compile-time-lean profiles (link only the modalities you deploy, RFC-0001
  §4 / the modality-composition handoff).

== Detailed Design

=== The layer model

[source,text]
----
COMPUTE plane   Volcano · DataFusion · DuckDB · ANN · ORION traversal · PromQL · fusion/rank
                 ▲  depends ONLY on contracts (read IR + write ops), never on a storage impl
─── CONTRACT surface (the consolidation boundary) ─────────────────────────────────────────
   RecordStore · WAL/durability · ConditionalKeyStore · Scan/read-IR · Tiering · Tenancy · Catalog
                 ▼  many implementations, chosen by deployment/workload
STORAGE plane   canonical (WAL+memtable+object-store) · dedicated (ledger/queue/TS) · object-store CAS
─── FOUNDATION (shared, tenancy-carrying) ─────────────────────────────────────────────────
   TenantContext · DrPathBuilder · ObjectAccessTier · block-format/PAX · proximadb-catalog
─── MODALITIES (cohesive; implement the contracts + own their operators) ──────────────────
   Ledger · Relational-OLTP · Vector · Graph · Document · Observability · … · Fusion(compose)
----

=== The contract family

Some contracts exist and are widened; one is new. Each **carries `TenantContext`** so security is
structural, not per-modality.

[cols="1,1,3", options="header"]
|===
| Contract | Status | Surface (consolidation target)
| `RecordStore` | exists (`TableRecordStore`, record_store.rs:500) | `write_mutations` / `get_by_key` / `scan_records_filtered` / CDC `read_changes_since`. Widen adoption; keep per-layout routes.
| WAL / durability | exists (`TableWalAppender`, canonical_wal.rs) | `append_operations`. A modality with divergent access implements *its own* appender behind this contract (ledger/queue already do — legitimize it) rather than a non-contract WAL.
| **`ConditionalKeyStore`** | **NEW** | `put_if_absent(tenant, keyspace, key: &[u8], oid) -> Result<(), Conflict>` + `get` + `delete`. The atomic OLTP primitive. Extracted from the ledger CAS core; two impls (below).
| Scan / read IR | exists (`LogicalNode`, relational-algebra:466; ADR-039) | Read-only IR + swappable compute backend. Modality reads project into it (or extension operators).
| Tiering | exists (memtable→object-store→PAX; block-format) | Hot/cold contract siloed modalities *consume* instead of re-implementing their own tiers.
| Tenancy | exists (`TenantContext`/`DrPathBuilder`/`ObjectAccessTier`) | Threaded through every contract method — fail-closed, per-tenant paths.
| Catalog / governance | exists (`proximadb-catalog`, `CatalogTableSchema`) | The **governance seam** — one metamodel, N vocabularies (below).
|===

=== The catalog: one governance metamodel, N modality vocabularies

The catalog is not merely another contract — it is the **governance seam**. *All* modality data,
whatever its nomenclature, is governed by **one metamodel** — `Container → Entity → Attribute →
Identity/Uniqueness → Index → Constraint/Policy` — carrying schema, RBAC, tenancy, and
constraint/index declarations **uniformly**. Only the *vocabulary and index shapes* differ:

[cols="1,1,1,1,1,1", options="header"]
|===
| Metamodel level | Relational | Vector | Document | Graph | Observability / TS
| *Container* | database / schema | namespace | namespace | graph / namespace | namespace
| *Entity* | table | collection | collection | node type · edge type | stream / metric
| *Attribute* | column | field (vector + payload) | field · JSON path | property | field · label
| *Identity / uniqueness* | PRIMARY KEY · UNIQUE | id / oid | `_id` | node id · edge (src,dst,type) | (series, timestamp)
| *Index* | btree · bitmap | axis / ANN (HNSW·IVF) | path · fulltext · array · geo | adjacency (CSR) | Tantivy · PromQL
| *Constraint / policy* | PK·UNIQUE·FK·CHECK | dim · metric | schema-mode | edge cardinality | retention · rollup
|===

So DDL, RBAC, schema evolution, tenancy, and constraint/index enforcement are written **once** against
the metamodel; a modality plugs in its vocabulary (`namespace/collection/field` vs
`database/table/column`) and its index kinds (ANN/axis vs btree/bitmap vs CSR-adjacency vs
path/fulltext). This **naming + governance** unification is real and is the seam the consolidation banks.

_(Scope narrowed, P2.)_ The metamodel unifies *naming and governance* — **not** a universal uniqueness
primitive. "Uniqueness on the identity key" is procrustean beyond relational + document: a vector `oid`
is a **system surrogate** (not the mandated natural key); a graph edge is identified by an **`edge_id`**
and is multigraph-capable, so `(src,dst,type)` is *not* its identity and is itself an FK-pair; a
time-series identity `(series, ts)` is **monotonic-append, not a uniqueness constraint**. The fenced
`ConditionalKeyStore` therefore applies to **relational PK/UNIQUE and document `_id`**; other modalities
enforce identity via their own operators. This is a *documentation* narrowing only — `ProximaRecord`
already models `edge` (`EdgeShape`) and `sequence` (`TokenSequence`) as first-class fields, so no record
change is implied (see §reconciliation).

=== `ConditionalKeyStore` — the flagship, and its two impls (storage⊥compute, swappable)

[source,rust]
----
trait ConditionalKeyStore {                                   // the storage plane's OLTP primitive (fenced)
    fn put_if_absent(&self, t: &TenantContext, keyspace: KeyspaceId,
                     key: &Identity, oid: Oid, fence: Generation)   // typed key (D9) + fence (D3)
        -> Result<Committed, Conflict>;                       // PRIMARY KEY / UNIQUE
    fn get(&self, t: &TenantContext, keyspace: KeyspaceId, key: &Identity) -> Option<Oid>; // FK (phase 2)
    fn delete(&self, t: &TenantContext, keyspace: KeyspaceId,
              key: &Identity, fence: Generation);             // fenced tombstone, not unconditional
}
----

_(Revised P2.)_ The primitive is **generation-fenced** — modeled on the ledger's `compare_and_swap`,
which returns a `Version` (the token a bare `PutMode::Create` drops). For a composite natural `PRIMARY
KEY`, `oid == primary_key_string`, so uniqueness is a **single row-keyed-by-PK** fenced write — no
separate index write. Default and escape-hatch are reversed from the original draft:

[cols="1,2,1,2", options="header"]
|===
| Impl | Serialization point | Latency | Fit
| *generation-fenced local-WAL CAS* (the ledger core, generalized `Identity→oid`) | in-process writer + WAL, fenced | sub-ms | **the hot, correctness-carrying default**
| *object-store `put_if_absent`* | object-store generation fence (successor-slot discipline) | tens of ms + per-op cost | **scale-to-zero escape hatch** — not for the mutable-PK hot path (successor-slot proof does not transfer to a reclaimable fixed key)
|===

Compute (the insert executor; the Volcano/DataFusion readers) calls the contract and never learns
*how* uniqueness is enforced — so the storage impl swaps (serverless vs hot) and the compute engine
swaps (ADR-039) independently. The contract is invoked at a **coarse grain** (per insert-batch / per
query), so swappability costs **zero per-row dispatch** — the speed-vs-flexibility balance point.

=== The consolidation principle (cohesion + balanced coupling)

**Consume the shared contracts; implement modality-specific behavior behind them.** A modality does not
get to invent an off-contract WAL or re-roll tiers/tenancy; it either uses the canonical impl or ships
its *own impl of the shared contract*. This is the balance the mandate asks for:

- *Foundational consistency + reduced code:* one contract surface; siloed modalities stop re-inventing
  tiers/tenancy/WAL-framing and inherit CDC, tiering, and fail-closed isolation.
- *Cohesion:* each modality owns only its semantics + operators (ANN, CSR traversal, PromQL, budget
  counters) and its contract impl where access diverges.
- *Balanced decoupling:* modalities couple to the **foundation via contracts only, never to each
  other**; the storage⊥compute contract is the one deliberate seam, making both swappable.

Fusion is the proof the layering holds: it is **pure compute over the modality ports**, owns no
storage, and composes vector+graph+document — a modality that is nothing but composition over
contracts.

=== Enterprise security

`TenantContext` is already a parameter of every `TableRecordStore` method; the consolidation makes that
**universal** — it is in every contract signature, so tenant isolation is enforced at the contract
boundary for *every* modality (not re-implemented per silo). Per-tenant physical paths (`DrPathBuilder`),
at-rest tier control (`ObjectAccessTier`), and block-format RLS tenant-hash skipping are foundation
facilities every modality inherits. Neutral units only; no pricing crosses any contract.

== Design-gate review reconciliation (P2)

Before acceptance the design was pressure-tested by three independent adversarial reviews — Kimi, GLM-5.2,
and DeepSeek — each grounding its critique in the source. Their load-bearing claims were re-verified
against the code; the confirmed ones are reflected in the revisions above. Summary:

[cols="2,1,3", options="header"]
|===
| Finding (unanimous unless noted) | Verified? | Resolution
| Bare `put_if_absent` ≠ atomic insert; it drops the version/fence the ledger CAS carries | yes (`ledger/src/lib.rs:77` vs `object-store/src/lib.rs:247`) | primitive is fenced (D3)
| Existing object-store proof (manifest/lease) uses *fresh successor slots*, not reclaimable fixed keys | yes (`manifest.rs`, `partition_lease.rs`) | object-store → escape hatch; local-WAL default (D5)
| `delete` is unconditional → PK-`UPDATE`/reclaim races, orphaned slots | yes (`object-store/src/lib.rs:372`) | fenced tombstone delete (D3)
| Op-lock must not be demoted (it orders `ON DELETE CASCADE`) | yes (`catalog/src/manager.rs`, `dml/mod.rs:3332`) | op-lock retained; UNIQUE/FK stay in it (D3)
| Composite-key codec (`encode_primary_key_tuple`) collides / non-order-preserving / type-lossy | yes (`relational.rs:864`, self-documented) | typed `Identity` codec (D9)
| Metamodel "uniqueness on identity" procrustean for graph/TS/vector | yes (`orion .../memory_pool.rs`; surrogate `oid`) | metamodel narrowed to naming; primitive scoped to relational/document
| *(reviewers' shared premise)* a row insert is two durable writes (index + row) | **refuted for the PK** (`relational.rs:282`, `oid == PK`) | PK = one row-keyed-by-PK write; two-write case only for secondary UNIQUE
|===

**Also surfaced at the gate (record shape).** `ProximaRecord` is already the multi-modal meta-record
(`props` NF² tree + `edge` + `embeddings` + `sequence` + `refs` + identity/tenancy/temporal) — so no
`MultiModalMetaRecord` overhaul is needed; the record-shape consolidation is already banked. The real
tension is that it is a **fat union**; a composed `RecordCore` + `#[cfg]` modality-extensions refactor is
routed to the compile-time modality-composition track (#1180), **not** this MVP (ADR-072 D10). Scope
chosen at the gate: **typed identity now, composition deferred.**

**Verdicts reconciled:** Kimi (b, proceed-with-changes) and GLM/DeepSeek (c, rethink the MVP mechanism)
converge — all three keep the contract-consolidation thesis and reject the original MVP mechanism. Net:
proceed with the amended (fenced, local-default, op-lock-retained, typed-identity) MVP.

== Research calibration (P3)

After the P2 review, the design was calibrated against **10 full-text research papers** (systems + DB
theory) plus Google's Spanner columnar-engine disclosure. The papers **confirm the consolidation thesis
and the P2 reversals**, and drive two new decisions (ADR-072 D11/D12) and several refinements. Per-paper
briefs and section citations are archived with this RFC; the bibliography is below.

=== Consensus that binds the design

- **Uniqueness is the one operation that cannot be blind-written / made commutative — it always needs
  coordination.** Aurora DSQL's blind-write optimization skips the conflict check for *non-unique*
  indexes but **explicitly excludes unique indexes** <<biblio-dsql>>. This is the load-bearing reason
  `ConditionalKeyStore` must exist. *Corollary adopted:* non-unique secondary indexes become blind-writes
  keyed by the PK; only `UNIQUE` takes the coordinated path.
- **CAS + a version token is the universal uniqueness substrate, cleanly separable from each modality's
  engine** (Cornus <<biblio-cornus>>, ScalarDB <<biblio-scalardb>>, CCaaS <<biblio-ccaas>>, BatchWeave
  <<biblio-batchweave>>, DSQL <<biblio-dsql>>). Two refinements adopted: the conditional op **returns the
  current holder on conflict** (Cornus `LogOnce`), and the contract is **capability-typed** — each impl
  *declares* its atomic scope (ScalarDB *Atomicity Unit*), never a boolean.
- **Never reuse/overwrite a durable key slot; append + version-order + tombstone + reclaim behind an
  oldest-active-reader watermark** — unanimous (cMVBT <<biblio-cmvbt>>, BatchWeave <<biblio-batchweave>>,
  DSQL <<biblio-dsql>>). This **supersedes the P2 "fenced reclaim delete"**: the reclaim race dissolves by
  construction and MVCC version-ordering largely subsumes the explicit fence (ADR-072 D11). cMVBT flags
  in-place slot reuse as needing "more sophisticated synchronization" — a direct caution against reclaim.
- **Keep divergent implementations; unify the contract, not the engines.** Native per-modality storage is
  worth up to 188× vs non-native layouts (M2 <<biblio-m2>>); polystore keeps N *semantics* and pays with
  no cross-engine transactions (BigDAWG <<biblio-bigdawg>>). Validates "one contract, many impls."

=== Forks the research surfaced (and how we resolve them)

[cols="1,3", options="header"]
|===
| Fork | Resolution
| **Fence placement** — in-storage CAS vs. a separate coordinating tier + log-append | **Map to our two impls.** Local-WAL default = fence-in-storage; serverless escape hatch = per-key coordinating step + batched successor-slot log append (Aurora DSQL adjudicator+journal <<biblio-dsql>>; BatchWeave batch-manifest <<biblio-batchweave>>). One contract, two placements.
| **Reclaim discipline** — reclaim a slot + fence vs. append-only MVCC + tombstone | **Append-only MVCC** (ADR-072 D11) — unanimous across cMVBT/BatchWeave/DSQL.
| **Catalog metamodel** — one `…→Identity→Index→Constraint` chain vs. split logical/physical | **Split** governance-logical from physical-index; make the identity slot family-parameterized; **graph edges become a first-class relationship type, not an identity key** (U-Schema <<biblio-uschema>>, ADR-072 D12).
| **Storage⊥compute grain** — full decouple vs. layout-coupled for perf | Decouple *lifecycle* contracts; expose *physical layout as negotiable* (M2's 188× came from layout-coupling <<biblio-m2>>).
| **HTAP format** — one unified format vs. dual row+column | **Dual**, async-materialized columnar, analytical compute offloaded so OLTP never pays (Spanner <<biblio-spanner>>) — calibrates the F5 HTAP step.
|===

=== Modality calibration (P4) — vector, graph, time-series (ADR-072 D13)

A second research pass deep-read the per-modality literature (vector ×3, graph, the Cambridge
field-direction report) + time-series systems, to close the TS/vector residual risk. It **confirms the
thesis across every modality** and adds one architectural refinement.

[cols="1,3", options="header"]
|===
| Modality | Calibration (identity · shared vs specialized)
| *Relational / document* | natural composite PK / `_id` = **uniqueness** — the *only* modalities the fenced `ConditionalKeyStore` applies to.
| *Vector* | identity is a **surrogate** row-id (confirmed 3×: Compass <<biblio-compass>>, policy-aware <<biblio-vecpolicy>>, pgvector <<biblio-pgvector>>). Modality behind a shared columnar store + its **own ANN operator**, filter-agnostic; avoid fused per-attribute indices (n× storage).
| *Graph* | edge = **first-class relationship type**, stored identity **cardinality-dependent/optional** (GraphflowDB <<biblio-graphcol>>). Reuse columnar storage+codecs; specialize CSR + list-join (SAP-HANA-without-CSR is the documented failure).
| *Time-series* | `(series, ts)` = **ordering + high-cardinality**, not uniqueness. LSM+chunk+tiered+WAL; **IOx moved to columnar**; specialize retention/downsampling.
|===

**Net-new refinement — the shared record-store substrate is columnar/PAX, not a row heap.** The pgvector
teardown <<biblio-pgvector>> shows a *row* heap makes the store's page / TID-indirection / ACID machinery
dominate **55–85% of CPU cycles** (not distance math); columnar storage is also the reusable half of a
graph engine and the fix InfluxDB IOx adopted for TS. proximaDB's existing **PAX layout route** is promoted
to the standardized record-store substrate — that is what makes multi-modal-behind-one-contract perform.

**Enforcement refinements:** vector RLS must be **pre-filter/index-integrated, never naïve post-filter**
(authorization stays correct but recall silently collapses under selective tenant predicates); authorization
is a hard invariant decoupled from recall as QoS (<<biblio-vecpolicy>>). Graph positional offsets are
**stable materialized addresses** (gap-and-recycle) → a write-optimized delta merged lazily into CSR
(<<biblio-graphcol>>). Framing: the Cambridge report <<biblio-cambridge>> blesses disaggregation +
composable components but cautions "**interoperability, not unification**" and "a data lake ≠ integrated
data" — so the catalog metamodel is an *interoperability substrate*, not a universal language.

**Delete representation is tier-split (P5, ADR-072 D14).** MVCC is the *visibility / uniqueness* model
everywhere; its *physical* delete encoding follows the tier: row-level MVCC in the hot/local-WAL tier, and
**deletion vectors / merge-on-read** (roaring-bitmap per data object, Iceberg-v3 <<biblio-icebergdv>> /
Delta Lake <<biblio-deltadv>>) in the immutable cold columnar tier — because an object store cannot mutate
objects in place and copy-on-write would rewrite whole files. A hot-tier tombstone flushes to a DV entry,
purged at compaction behind the same reader watermark. A deletion vector **encodes deletes but does not
enforce uniqueness** — that stays with MVCC + the `ConditionalKeyStore` index. Build split: hot MVCC = F1d
(critical path), cold deletion vectors = F3v (parallel).

=== Production-systems calibration (P6)

Calibrated against three production multi-modal systems (full architecture docs + the Lance paper):
**LanceDB** <<biblio-lance>>, **Vespa** <<biblio-vespa>>, **Weaviate** <<biblio-weaviate>>. Net: **strong
convergent validation** — LanceDB independently built our storage/table half (columnar substrate + MVCC +
deletion vectors + successor-slot manifest + object-store storage⊥compute + surrogate identity), Vespa our
compute/serving half, Weaviate our tenancy/hybrid half. Three decisions added in ADR-072:

- **D15 — hybrid ANN+filter is a *cost-based* planner** (not pre-vs-post): a per-query selectivity
  estimator switches pre / post / **exact**; the predicate is a **global doc-id allow-list woven into ANN
  traversal**; **tenancy/RLS rides the same global filter, always ANDed** (Vespa + Weaviate). → *F7*.
- **D16 — storage ⊥ compute is *tiered placement***: match + first/second-phase compute runs
  near storage, only top-k rerank goes compute-far; the contract expresses both, plus a read-cache over
  object storage (Vespa + LanceDB). Do not promise full disaggregation on the hybrid hot path.
- **D17 — the background plane is first-class** (compaction / index-optimize / GC / read-cache), the place
  LanceDB's real production pain lives. → *F6*.

Refinements: adaptive encoding *within* columnar + 3-tier blob path (D13); adaptive deletion rep + a
**single unified row-mask engine** for deletion-vectors and filters (F3v/F1d); reverse-lex manifest naming
+ external-manifest fallback (F1c); tenant lifecycle (lazy-load + ACTIVE/INACTIVE/OFFLOADED + flat→dynamic→HNSW,
D6). Two open tensions recorded: **cross-tenant edges vs. fail-closed isolation** (Weaviate banned them),
and a **per-modality consistency knob** vs. one global model (Vespa's eventual floor is too weak for a
system of record).

=== Residual risk (honestly flagged)

- **Time-series and vector identity: now calibrated (P4)** as surrogate/ordering (not uniqueness) — but no
  *unified-metamodel* paper covers them, so their fit in the D1 catalog metamodel still rests on the
  per-modality engineering evidence above, not a single unifying formalism. Pressure-test before D1 is final.
- **Order-preserving key encoding** and **secondary-index maintenance** are thin in the research corpus —
  calibrate F0/F1 against system engineering (FoundationDB tuple layer, CockroachDB key encoding).
- **Vector-valued access predicates** (policy expressed as a vector, not metadata) are unsolved in the
  literature — out of scope for the MVP; needs a dedicated operator if required later.

== Migration Path

Additive and incremental — no modality is forced to change at once, and `default` behavior is
unchanged until each opts in. The order (leaf-first, lowest-risk-first) and the composite-PK MVP are in
**TD-FOUNDATION-1**. Divergent-access modalities (ledger, queue, timeseries) are *ratified* on their
own WAL — but re-expressed as **impls of the shared WAL/tiering contract**, so they stop carrying
bespoke tier code.

== Drawbacks

- A contract family is an abstraction tax; drawn too fine it ossifies, too coarse it leaks. Mitigation:
  contracts are invoked at coarse (batch/query) grain and are exactly the seams the map already shows.
- Widening adoption touches many crates over time (though each step is additive + feature-gated).
- The `ConditionalKeyStore` object-store impl trades latency for serverless operation; the hot impl is
  the opt-in escape hatch.

== Rationale and Alternatives

- *One WAL for everything* — **rejected.** The map + ADR-071 (ledger) + the queue's explicit
  "access patterns differ" prove divergent modalities need their own log. Consolidate the *contract*,
  not the log.
- *Status-quo silos* — the code-proliferation + inconsistent-security cost this RFC exists to stop.
- *A single god storage-engine trait* — too coarse; the repo already favors a *family* of narrow ports
  (`proximadb-storage-ports`). This RFC formalizes that family, it does not replace it with one trait.

== Prior Art

- Snowflake/Databricks **storage⊥compute separation** — swap either side behind a contract.
- ProximaDB's own **ADR-039** (DataFusion swappable behind the read-only `LogicalNode` IR) — the compute
  half of this decoupling, already accepted.
- **ADR-071** (ledger dedicated WAL) + the **queue** precedent — the "divergent access ⇒ own impl behind
  the contract" rule, generalized here.
- The **modality compile-time composition** handoff (docs/12-design/MODALITY_COMPILE_TIME_COMPOSITION)
  — the deployment axis this RFC's contracts make clean.

== Unresolved Questions

- _(Resolved P2)_ Composite-key encoding is a **new typed `Identity` codec**, not a reuse of
  `encode_primary_key_tuple` (documented-defective). Open: the per-`ProximaType` type-tag/collation table.
- _(Resolved P2)_ Default is the **generation-fenced local-WAL** impl; object-store is the escape hatch
  (reverses the earlier lean).
- The `Generation`/fence source for the local-WAL default (partition-lease generation vs a WAL-sequence
  epoch).
- How far to widen `RecordStore` adoption into observability/timeseries vs. keeping them contract-impl
  silos.
- The `ProximaRecord` union → composed `RecordCore` refactor (ADR-072 D10) — sequenced under #1180.

== Future Possibilities

- Cross-modal multi-key transactions once a transaction contract exists (the unwired
  `MultiModelTransactionManager` is the seed).
- FK / referential integrity as a `get` on `ConditionalKeyStore` (phase 2).
- HTAP: native compute (Volcano/DataFusion) runs TPC-H over data with genuine atomic OLTP integrity.

== Implementation Plan

Milestones live in **TD-FOUNDATION-1**; decisions in **ADR-072**. Headline: (1) extract
`ConditionalKeyStore` from the ledger core; (2) composite-natural-`PRIMARY KEY` MVP on the relational
insert path via the object-store impl; (3) widen contract adoption modality-by-modality, leaf-first,
each additive + feature-gated + benchmark-evidenced.
