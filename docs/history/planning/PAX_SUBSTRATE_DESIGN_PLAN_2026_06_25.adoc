== 1. Audit verdicts (assumptions falsified against code)

(`PAX_RECALL_RATCHET_2026_06_25`, ledger `pax_rabitq_sq8_recall_at_10`). Not gaming

| CONFIRMED | `record_range_gets` fires only at `segment_format.rs:253` (RaBitQ cascade) +

| 5 | automl/+adaptive tune ONLY HNSW/IVF, no io_trace, no geometry/quant
| PARTIAL (refuted on quant) | No io_trace ✓; no geometry ✓. **Refuted:** quantization
**is** a defined tunable — `automl/tuning.rs:902-920` `quantization_params()`
(`quantization_level`, `codebook_size`). ADR-026 audit line is factually wrong. See WS7.

| 6 | PAX single internal format; SST writes PAX for all modalities; writer modality-neutral
| REFUTED (current state) | `write_pax_segment(.., embedding_count, quant: VectorQuant, ..)`
(`segment_format.rs:113`), `embedding_count.max(1)` (l.126); `PaxBlockWriter` allocates
`embeddings: vec![Vec::new(); embedding_count]` (`block-format/writer.rs:203`). Canonical

Valid only as TD-162a target. See WS2.

| 7 | Coalesced write-path reuses SST/LSM for metering writer
| REFUTED (reusable-with-work) | Flush couples to AXIS (`handle_flushed_vectors`,
`flush/mod.rs:64`), `embedding_count`, `VectorQuant`. Skeleton generic; payload vector-
specific. Needs WS2-1. See WS6.

| 8 | Two-class gate (perf gateable; billing never gated) splittable without silencing billing
| PARTIAL (feasible; ADR mental model wrong) | **Billing authority is
`consumption_metrics.rs`** (`KOU_BYTES_TOTAL` l.74, `KEU_UNITS_TOTAL` l.87,
`OBJECT_STORE_OPS_TOTAL` l.39) — *separate* from `IoTrace`. `IoTrace.egress_bytes`/

`IoTrace` has no feature gate today. See WS4.

| 9 | Dual-sink: DrPathBuilder supports `_metering`/`_trace`; external OTLP emitter exists
| REFUTED / NEEDS-EXTENSION | `DrPathBuilder` only builds `data/{tenant}/{ns}/{coll}/`
(`path_resolver.rs:380`); no per-tenant `_metering`/`_trace` builder. `validate_id`
permits underscores (l.789-829); `branches_subprefix` → `{root}_branches/` precedent
(l.446). "Existing 30s emitter" is actually pull-only `/metrics/prometheus`
(`metrics_service.rs:163`) — no push emitter. See WS6.

| 10 | Mixed-read-safe PAX/Parquet/ProximaBlocks via magic-detect router
| PARTIAL | Router confirmed PAX (`PBLK`+`PAXSEG01`) + ProximaBlocks (`0x01`)
(`segment_format.rs:81-96`). **Parquet `PAR1` NOT wired** — enum has only `ProximaBlocks`
+ `Pax` (l.36-44); ADR l.35 overstates. `RecordReader` trait does **not** exist. See WS3.

== 2. Workstream map & revised critical path

The 10 fixes collapse into 8 workstreams. The two structural corrections vs the ADR-027
rollout are (a) **writer-neutralization (TD-162a) must precede the metering writer
(TD-161)** and (b) **billing authority is `consumption_metrics`, not `IoTrace`** — so the
TD-160 gate covers `IoTrace` wholesale and can never silence billing.

----
WS1 docs (R1,R2) ───────────► gates WS2/TD-162 (format-unification governance)
WS2 PAX modality-neutral writer + RecordReader (TD-162a) ─┐
WS3 Parquet PAR1 router arm (TD-162b) ────────────────────┤
WS4 trace two-class + billing authority (TD-160 reframed) ─┐ │
WS5 io_trace on live read path (TD-158) ◄── WS4 ───────────┘ │
WS6 DrPathBuilder paths (TD-164) ► coalesced metering (TD-161) ◄── WS2-1 + WS4
WS7 adaptive audit + quant correction (TD-159, ADR-026 edit)
WS8 evidence hardening (recall real-dataset; footer egress reconcile)
----

Critical path to "PAX = single format, metered": *WS1 → WS2-1 → TD-164 → TD-161*. The
trace gate (WS4) runs in parallel and gates WS5.

== 3. Workstreams (implementation-ready specs)

=== WS1 — ADR-027 documentation reconciliation (R1, R2)
*Problem.* (R1) ADR-027 l.10/l.101 cite `NATIVE_OLAP_ENGINE_BLUEPRINT_2026_06_22.adoc`
which did not exist on develop. (R2) the live, authoritative `…COURSE_CORRECTION_2026_06_04`
(self-declared "storage-model authority", l.250) states the opposite of ADR-027 on three
points: Parquet/Iceberg = "OLAP base/publication tier" (l.101-103); DataFusion =
"strategically non-negotiable" (l.132-135); PAX = "specialized layouts only as cataloged
access methods or projections" (l.56).

*Design (done in this PR).*

* Author `NATIVE_OLAP_ENGINE_BLUEPRINT_2026_06_22.adoc` (resolves the dangling xref;
  native columnar OLAP engine scans PAX column stripes + zone maps; DataFusion interim;
  migration phases; `RecordReader` seam).
* Add a "Reconciliation with the 2026-06-04 course-correction" section to ADR-027
  (Parquet role: base tier → interop seam + interim warehouse format; DataFusion: scoped
  to the interim executor; PAX: → single internal columnar format) as a **partial
  supersession** of the course-correction's storage-layer clauses.
* Add a forward pointer in the course-correction doc.
* Governance: ADR-027 is `Proposed`. **TD-162 (format unification) must not start until
  ADR-027 is `Accepted` with the reconciliation merged** — it overturns a doc currently
  labelled "non-negotiable".

*Acceptance.* No dangling ADR xref; ADR-027 has a Reconciliation section; course-correction
carries the forward pointer; ADR-027 = Accepted before TD-162 opens. *Effort: S.*

=== WS2 — PAX modality-neutral writer + `RecordReader` trait (R3-prereq, #6, #7) — TD-162a
*Problem.* `write_pax_segment` mandates `embedding_count`/`VectorQuant` and clamps
`.max(1)` (`segment_format.rs:126`); `PaxBlockWriter::new` allocates an embedding stripe
(`writer.rs:203`). Canonical columns (`oids`, timestamps, `edge_*`, `props_bytes`,
`labels_bytes`, `writer.rs:190-201`) are already modality-neutral, so vector-specificity
is narrow — *but* there is **no typed user-column stripe** (`FlatRow.user_columns`
exists, `record.rs:181`; PAX has only opaque msgpack `props_bytes`), so ADR-027's "one
prune stack serves relational projection" (l.30) is unmet for relational/OLAP. The
`RecordReader` trait (ADR l.35) does not exist.

*Design — three slices.*

. *TD-162a-1 (S, unblocks TD-161).* Make vectors optional:
+
[source,rust]
----
pub fn write_pax_segment(
    path: &Path, records: &[ProximaRecord], collection_id: &str,
    embedding_count: usize,        // 0 == non-vector segment (no embedding stripe)
    quant: Option<VectorQuant>,    // None == no quantization
    target_block: Option<usize>,
) -> Result<SegmentMeta>
----
+
Drop `.max(1)`; `PaxBlockWriter` skips the embedding stripe when `embedding_count == 0`;
flush derives `embedding_count = 0` for embedding-less records and skips AXIS indexing
(`index_flushed_into_axis` already early-returns on empty vectors, `flush/mod.rs:64-80`).
. *TD-162a-2 (M/L, unblocks relational OLAP on PAX).* Add a typed `user_columns` stripe to
`PaxBlockWriter` mirroring `FlatRow::from_record_with_user_columns` (`record.rs:197`),
with per-column zone maps — prerequisite for the native engine scanning PAX columns.
. *TD-162a-3 (S).* Introduce the `RecordReader` trait the ADR assumes; `read_segment_records`
becomes `SegmentFormat::detect(bytes).reader().read_records(..)`. Behavior-preserving.

*Acceptance.* 0-embedding PAX round-trip test (write→`read_segment_records`→field-equality,
mixed-read-safe #8); existing `pax_rabitq_sq8_recall_at_10` ratchet stays green; relational
projection test asserts bytes-read scales with projected columns. *Mixed-read safety:*
magic bytes unchanged; a 0-embedding segment is a valid PAX segment. *Effort: S + M/L + S.*

=== WS3 — Parquet `PAR1` router arm (R7, #10) — TD-162b
*Problem.* `SegmentFormat` (`segment_format.rs:36-44`) has only `ProximaBlocks` + `Pax`;
`detect()`/`is_pax_segment()` never test `PAR1`. ADR l.35 overstates a 3-format router.

*Design.* Add `SegmentFormat::Parquet`; `is_parquet_segment` checks leading+trailing
`PAR1` (`0x50 41 52 31`, disjoint from `PBLK`/`PAXSEG01`/`0x01`); route to a
`ParquetRecordReader` (WS2-3 trait) behind the existing `datafusion-integration` feature
→ **default-off** (#8). Extend the detect-precedence test (`segment_format.rs:376-388`).
*Effort: S + M (reader reuses in-tree DataFusion Parquet reader).*

=== WS4 — Two-class trace with correct billing authority (R4, #8) — TD-160 (reframed)
*Problem & correction.* ADR-027 says "split the IoTrace counters into billing vs perf" —
this **mis-locates billing**. Ground truth: the billing authority is `consumption_metrics.rs`
(`KOU_BYTES_TOTAL` l.74, `KEU_UNITS_TOTAL` l.87, `OBJECT_STORE_OPS_TOTAL` l.39), *separate*
from the task-local `IoTrace` (`io_trace.rs:118-159`, no feature gate today). `IoTrace.egress_bytes`/
`embedding_*` are derived copies (`record_kou_bytes`→`record_egress_bytes` l.605-610;
`record_keu_units`→`record_embedding` l.637-640). Following the ADR literally would
manufacture the entanglement the invariant fears.

*Design — TD-160 reframed.*

. Perf/geometry class = the **whole of `IoTrace`**; billing class = `consumption_metrics`
(untouched, always-on).
. Gate `IoTrace` **wholesale** behind a new `io-trace` cargo feature (absent today). Off →
every `record_*` (l.398-466) is an `#[inline(always)]` no-op; call sites unchanged
(helpers already no-op outside a scope via `IO_TRACE.try_with`).
. Keep `io_trace::record_egress_bytes`/`record_embedding` *defined* (no-op) when off, so
`consumption_metrics` — the billing path — compiles/runs identically. **Billing cannot be
silenced because it does not live behind the gate.**
. String→enum compaction (ADR l.47): `route`/`compute_ms` String key → `ShapeClass`/`EngineId`
enums (perf class, gated); add `route` to `IoTraceSnapshot` (omitted today, l.289-304).

*Acceptance.* CI guard: no `cfg(feature)` wraps any symbol in `consumption_metrics.rs`
(billing-never-gated, static). Build matrix on/off both compile the **server binary** (#11)
and both still increment `KOU/KEU` in a unit test. Bench: off-path is zero-cost. *Effort: M.*

=== WS5 — io_trace on the live AXIS/SST read path (#4) — TD-158
*Design.* Wire `record_range_gets`/`record_bytes_read`/`record_footer` into
`execute_*_search` (`sst/search/mod.rs`) per block fetched, and the object-store ranged
reader (`ranged_segment.rs`) when TD-151 lands — emitted through the gated perf class (WS4).
*Acceptance.* Query over a known N-block segment asserts `IoTraceSnapshot.range_gets`/
`bytes_read` match blocks touched; ratchet that whole-segment reads report ≥1 GET (C0 never
silently zero). *Effort: M. Depends: WS4.*

=== WS6 — DrPathBuilder system paths + coalesced metering writer + dual-sink (R5, #9) — TD-164 + TD-161
*Problem.* `DrPathBuilder::build` (`path_resolver.rs:668`) yields only `data/{tenant}/{ns}/{coll}/`
(l.380) / `accounts/{account}/{tenant}/{ns}/{coll}/` (l.376). `validate_id` (l.789-829)
permits underscores; `branches_subprefix`→`{root}_branches/` (l.446) and `operator_subprefix`→
`_operator/` (l.871) are precedents. No `tenant_root()`. No periodic push emitter (pull-only
`/metrics/prometheus`, `metrics_service.rs:163`); precedents to mirror: `cache.rs:108`
interval task, `MetricsPersistenceLayer` threshold snapshots (`shared_services.rs:1496`).

*Design — TD-164 (S, prerequisite).*
[source,rust]
----
impl DrResolvedPath {
    pub fn tenant_root(&self) -> String { /* mirror root_prefix() account/legacy split, stop at tenant */ }
    pub fn metering_subprefix(&self) -> String { format!("{}_metering/billing/", self.tenant_root()) }
    pub fn trace_subprefix(&self)    -> String { format!("{}_trace/perf/",      self.tenant_root()) }
}
----
Reserve `_metering`/`_trace`/`_branches`/`_operator` in a `validate_id` system-segment
denylist so a *user* collection can never collide (tightens isolation, #3). Mirror the
`operator_subprefix_is_rooted_and_validated` test (`path_resolver.rs:1269`) for both roots.

*Design — TD-161 (M/L, reordered after WS2-1 + WS4).* Reuse the LSM
memtable→flush→PAX→compaction primitive writing **0-embedding PAX segments** (WS2-1) under
`metering_subprefix()` (billing, always-on, full-fidelity, batched) and `trace_subprefix()`
(perf, gated, sample-ok) — no per-query object writes. Dual sink: (a) durable per-tenant
PAX; (b) a **new periodic push emitter** (tokio interval, mirror `cache.rs:108`) on
`SharedServices` exporting the Prometheus registry to OTLP/pushgateway. ADR-027's "existing
30s emitter" is corrected to "pull endpoint today; push is TD-161".

*Acceptance.* Path round-trip (both roots); `validate_id` denylist rejects a user collection
named `_metering`; K meters → ⌈K/threshold⌉ PAX segments under `data/{tenant}/_metering/billing/`
(no per-meter object), readable via `read_segment_records`; billing segment count independent
of the perf gate; tenant-A meters never escape `data/A/` (structural, fail-closed). *Effort:
TD-164 S; TD-161 M/L. Depends: WS2-1, WS4, TD-164.*

=== WS7 — Adaptive-tuning audit correction + quant (#5) — TD-159 + ADR-026 edit
*Problem.* ADR-026 l.148 "(c) do not tune quant" is false — `quantization_params()`
(`tuning.rs:902-920`) defines `quantization_level` + `codebook_size`. Accurate state:
latency-driven (p50/p99), no `io_trace`, no geometry — but quant IS in the param space.

*Design.* Correct ADR-026 l.137-148. TD-159 scope: verify whether `quantization_params()`
is invoked in the live loop (driver in `automl/service.rs:100-150` consumes
`AutomlPerformanceMetrics`, not the quant space directly) vs only defined; extend the engine
to consume `io_trace` (post-WS5) + add `target_block` geometry; recall-ratchet-gated. *Effort:
S (doc) + existing TD-159 (HIGH).*

=== WS8 — Evidence hardening (R6)
*Design.* (a) Before the TD-150 default-on flip, add a recall validation point on a **real
embedding dataset** (e.g. SIFT1M or 768-d ada/E5) at **N≥1M**, checked in as a dated artifact;
keep DIM=64 synthetic as the fast CI floor; gate the flip on the real-dataset run. (b)
Reconcile the footer-cache artifact's egress pricing (`$0.09/GB` internet) with the corrected
same-region-free model (byte savings have **no $ value**; the +29,900% GET fee is unoffset →
cost-negative). (c) Re-pin the Azure GET rate before the "10×" claim is customer-facing.
*Effort: S (doc/ledger) + M (real-dataset run).*
