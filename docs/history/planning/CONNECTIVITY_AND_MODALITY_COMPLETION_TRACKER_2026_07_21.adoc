== 1. End goal (definition of done)

ProximaDB is **multimodal** (vector, document, graph, timeseries, relational) and **multifaceted**
(REST, gRPC, Arrow Flight, pgwire, MCP). "Complete" means, for every *tracked* modality and every
*canonical* surface:

. **Write and read both work** end-to-end through the engine's own router — never a test/product
  bypass to an engine.
. **Durable + crash-recoverable** on the one shared substrate (unified WAL → memtable → coalesced
  flush → recovery), with the *flushed* format free to be modality-optimized.
. **Metered per dimension** (KSU storage / KRU read / KIU compute / KOU outgress / KEU embedding),
  `TenantContext`-stamped, fail-closed.
. **Deployable two ways from one build**: **enterprise SaaS** (multi-tenant, structural isolation,
  per-tenant object-store paths) and **BYOC** (customer's own cloud account + object store, same
  binary via the in-process edge collapse).

Non-goal for this MVP: multi-statement ACID transactions (pgwire `BEGIN/COMMIT`), cross-region WAL
replication, and SQL-over-Arrow-Flight. These ride named follow-ups (§8).

**Reconciliation of the 2026-07-21 review.** The review's "recovery replays vector batches only" is
precise about the *unified* `RecoveryManager` (`recovery_manager.rs:514-516` deserializes every WAL
batch into `Vec<ProximaRecord>` with **no dispatch on `UnifiedWALOperation` variant**), but graph and
timeseries do recover — via their own engine side-channels. The true defect is therefore **N parallel
recovery mechanisms instead of one dispatcher**, two of them gated OFF. That is the exact thing the
`ModalityRecoveryReplayer` seam (§4) collapses.

== 3. First principles — the two seams and one law

A record's journey is **identical across modalities**:

  surface → tenant-stamp → WAL(durable) → memtable(buffer) → flush(segment) → read(liveness-filtered) → recover → meter

The **only** legitimately modality-specific parts are: (a) the *flushed segment format* + its reader,
(b) the *post-flush index* (AXIS for vectors; adjacency IS the graph index; TS/doc index
incrementally), (c) the *query operators*. The **only** legitimately surface-specific parts are:
(a) the *wire encoding* (HTTP/JSON, HTTP2/proto, Arrow IPC, pgwire, JSON-RPC), (b) the *ergonomic
facade*. Everything else is shared.

That collapses the whole program to **two seams** — and the code is ~95% ready to *bend into* them
(no parallel reimplementation; see §4 for the confirmed bend points):

[cols="1,3", options="header"]
|===
| Seam | Shape
| **Storage seam** | One WAL (`UnifiedWALOperation`, already 8-variant), one memtable coordinator, one flush driver (ADR-069), one recovery dispatcher — with `ModalityBatch` + `ModalityMaterializer::do_flush` + `ModalityRecoveryReplayer` as the three trait/dispatch points behind which N modalities plug their format/index/replay.
| **Connectivity seam** | One canonical request envelope + one tenant-trust plane (`HeaderTrustPolicy`, TD-TENANT-1, already unified across all five surfaces) + one router (`ComputeScheduler` / `UnifiedQueryPort`, ADR-053) → N wire encoders. Surfaces are thin codecs over one core, not five stacks.
|===

**The law (made a mandatory contract in the rule seed, §7):** no modality may own a private WAL or a
private recovery path; no surface may own a private auth/tenant/routing path or a hand-rolled
request/response contract. New readers/writers emit the query-scoped I/O trace so the dimension they
touch is observable.

== 4. Extreme co-design — why unification is a cost lever, not cleanliness

Per `CODESIGN_DIMENSIONAL_ARCHITECTURE_2026_06_19.adoc`, we optimize across the storage↔compute↔network
boundary against the measured trace, toward each dimension's **dominant cost term** — for a cloud DB
that is **I/O round-trips + object-store operations + egress**, not CPU. The two seams each move a
dominant term:

* **One cross-modal flush driver → coalesced PUTs across modalities.** Today each modality that flushes
  does so on its own cadence; unifying under the ADR-069 driver lets N modalities' small segments
  batch into fewer, larger object PUTs — the Aurora/Neon/Turso "append→threshold-flush→compact"
  primitive ProximaDB already runs (ADR-027 Decision 3). Fewer PUTs = direct GB-op cost reduction and
  less read amplification/list cost. This is the small-files win applied cross-modality.
* **One recovery dispatcher → correct serverless restart on object storage.** ADR-063's
  catalog-driven restartability assumes every durable op is replayable from the one ledger; N
  side-channels break that assumption. Collapsing to `ModalityRecoveryReplayer` is what makes
  "no side RDBMS, restart from object store" actually hold for graph/TS/document.
* **One tenant/metering plane → structural isolation + accurate per-dimension billing.** Isolation is
  `DrPathBuilder`-structural, never a per-query predicate; metering lands KSU/KRU/KIU/KOU/KEU per
  tenant (ADR-027 Decision 4, dual-sink: durable per-tenant under `_metering/` + standard OTLP).

== 7. Deployment shape (SaaS + BYOC — one build)

Both deployment modes reuse the same two seams; only the *edge* and *object-store binding* differ.

* **Enterprise SaaS**: multi-tenant, structural isolation via `DrPathBuilder` (`data/{tenant}/{namespace}/…`),
  per-dimension metering (dual-sink, ADR-027 Decision 4), object-store-native catalog restartability
  (ADR-063), per-object access tier as the at-rest cost lever (ADR-036 — Blob endpoint, flat keys,
  HNS-off; `ObjectAccessTier`/`FileOptions.storage_class`, never per-cloud strings at call sites).
* **BYOC**: same binary; the in-process edge collapse (`IN_PROCESS_EDGE_COLLAPSE_HLD`) folds
  reverse-proxy / LB / API-gateway into the process with one policy plane (TLS, authn, ABAC, tenant,
  rate-limit, trace), pointed at the customer's own object-store account. Metering still emits the
  neutral usage event; pricing stays an AnvaiOps concern (open-core boundary, ADR-067).

== 8. Sequencing (owner decision: substrate-first)

----
M0.V1 estimator dedup  ──►  M0.V2 recovery dispatch  ──►  M0.V3/V4 graph parity + ModalityMaterializer
   (this PR)                 (never let a modality write ops recovery can't replay)
        │                                                            │
        └── docs + rule-seed contract (this PR) ────────────────────┘
                                                                     ▼
                              M2 document cutover · M4 TS→canonical · M5 relational durable DML
                                                                     ▼
                              Track C gaps (C1 REST graph-write, C2 gRPC TS svc, C5 MCP checkpoint)
----

Rationale: substrate is the commonality, the critical-correctness gap, and the cost lever;
connectivity is already the mature axis. V2 (recovery) is load-bearing before any modality writes new
WAL ops — land the replay side first. Each item is a small-blast-radius, in-place change (nothing is
released; no back/forward-compat burden) tested in isolation before moving on.

**Deferred (named triggers):** ACID transactions (ADR-018 Phase 3); SQL-over-Arrow-Flight; TS WAL
(first durability-requiring TS workload, TD-WAL-2 V5); cross-region WAL replication.

== 9. Mandatory contract

The **Multimodal Substrate Law** and **Unified Connectivity Envelope** rules are added to
`docs/agent-rules/CLAUDE.md.seed` (the committed source; the local `CLAUDE.md` is gitignored) so they
