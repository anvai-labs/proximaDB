== History

Planned a four-PR mini-phase to make an fp16 collection real end-to-end (create → insert → search,
recall@10 ≥ 0.99, canonical bytes ≈½ of fp32), each PR rollback-able behind the schema-v2 flag.

* **What shipped:** fp16 collections through REST/gRPC/pgwire (`CREATE TABLE … WITH
  (canonical_embedding_precision='fp16')`)/Arrow Flight/SDKs; WAL v2 segment header with magic-based
  v1/v2 dispatch (reverting the binary never strands v1 data); typed `EmbeddingValues` through ingest,
  WAL, SST and compaction.
* **Findings that reshaped the plan:** (1) a newly-identified prerequisite, INT-2.5 — the `precision`
  tag was advisory and every record reached PAX as fp32, so INT-3 would have been inert; (2) INT-3 as
  written assumed a PAX block writer, but SST blocks were Arrow IPC — delivered via the bridge instead.
* **Evidence:** `tests/fp16_canonical_bytes_metric_e2e.rs` (gauge),
  `arrow_block::writer::tests::fp16_file_is_approximately_half_the_fp32_size` (byte halving).
* **Deliberately out of scope (still deferred, owned by the LLD Phase 3 / §Open Items Deferred):**
  native fp16-fp16 kernels, adaptive policy auto-flip, bf16 / int8 canonical. External HTTP embedding
  clients still return fp32 and convert at the boundary.
