== Implementation Status

* **Slice A0 — route guard landed 2026-06-04.** `TableWriteRouter` now rejects DataFusion for
  row-level/VALUES DML and marks those writes `WalRequired`, even when the target table is
  OLAP-profile and declares `compute_route = 'datafusion-local'`. This prevents a single-row
  PostgreSQL-style write from bypassing the native WAL + row/delta commit path before OLAP
  publication. Focused tests:
  `query::table_write_plan::tests::values_dml_to_olap_table_stays_native_wal` and
  `services::dml::tests::explain_values_insert_to_olap_table_stays_native`.
* **Slice A1 — constraint-gap EXPLAIN metadata landed 2026-06-04.** Table-write route metadata now
  reports `constraint_enforcement` and `constraint_gaps`, so cataloged-but-not-yet-enforced unique,
  and foreign-key constraints are visible in `EXPLAIN` instead of being implied by DDL acceptance.
  CHECK constraints were subsequently moved out of the gap list by Slice B0. Focused tests:
  `query::table_write_plan::tests::route_metadata_discloses_cataloged_constraint_gaps` and
  `services::dml::tests::ddl_constraints_surface_as_route_metadata_gaps`.
* **Slice B0 — simple CHECK enforcement landed 2026-06-04.** `CatalogRow::validate` now enforces
  simple column-literal CHECK comparisons for SQL and fast-lane schema-on-write paths, preserves
  SQL unknown semantics for missing/null nullable inputs, and fails closed for unsupported CHECK
  expressions. Focused tests:
  `relational::tests::enforces_simple_check_constraint_on_write`,
  `relational::tests::rejects_simple_check_constraint_violation_on_write`,
  `relational::tests::check_constraint_unknown_value_passes`, and
  `relational::tests::unsupported_check_constraint_fails_closed`.
* **Slice B1 — stateful constraint fail-closed guard landed 2026-06-04.** Non-null UNIQUE tuples
  and non-null FK tuples now fail before mutation materialization until native unique-index and
  reference checks are implemented. Nullable UNIQUE/FK tuples keep SQL unknown/null semantics and
  do not require a stateful probe. Table-write `EXPLAIN` reports
  `unique_non_null_fail_closed` and `foreign_key_non_null_fail_closed` in
  `constraint_enforcement` while still listing UNIQUE/FK in `constraint_gaps`.
* **Slice B (CHECK extension) — column-to-column CHECK landed 2026-06-05.** `CatalogRow::validate`
  now enforces CHECK constraints comparing two catalog columns (e.g. `CHECK (lo < hi)`), not just
  column-vs-literal; NULL on either operand yields SQL UNKNOWN (row allowed). Tests:
  `relational::tests::{enforces,rejects}_column_to_column_check*`,
  `column_to_column_check_with_null_operand_is_unknown`. Commit `19ebbff4e`. Remaining Slice B work
  (index-backed UNIQUE/PRIMARY KEY enforcement, same-partition FK) needs DML/record-store state and
  stays as the next increment.
* **Slice A2 — projection freshness/lineage EXPLAIN metadata landed 2026-06-04.** Table-write
  route metadata now carries cataloged projection/publication details: projection kind, physical
  format, rebuild source, freshness mode/state, max lag, WAL/source range, last included position,
  rebuildability, invalidation policy, policy boundary, support status, and benchmark gate. This
  makes OLAP/publication route explanations explicit without claiming that delta-union freshness or
  transaction isolation enforcement is complete.

== Vision

ProximaDB should support latency-sensitive PostgreSQL-style OLTP and DataFusion-backed OLAP over
the same xCatalog schema and canonical record model without pretending one physical format is
optimal for both. The product contract is:

* xCatalog owns schema, constraints, indexes, workload profile, authority mode, policy, freshness,
  partitioning, and support maturity.
* WAL/log plus transaction metadata owns commit/replay authority.
* A native OLTP row/delta tier owns current-state reads, point DML, MVCC visibility, and constraint
  enforcement.
* PAX row-family remains the internal HTAP block-layout candidate where row-directory point access
  and column stripes both matter.
* Parquet/Iceberg/Arrow snapshots are OLAP/open-format publications consumed by DataFusion and
  external engines.

== Objective

Close the design and implementation gap between the live Volcano-over-`RecordStorage` relational
wedge and a credible PostgreSQL-compatible HTAP system. The immediate objective is not full
PostgreSQL parity; it is to define and build the seams that prevent OLTP correctness from being
lost when DataFusion and object-store OLAP paths are introduced.

== Non-Goals

* Do not claim full PostgreSQL transaction, lock, or constraint parity for MVP.
* Do not make Parquet/Iceberg the direct write authority for mutable OLTP tables.
* Do not introduce a second schema authority outside xCatalog.
* Do not support cross-shard foreign keys, deferred constraints, cascading actions, or distributed
  serializable transactions until the transaction coordinator and partitioning rules exist.

== Low-Level Seams

=== xCatalog Constraint Model

Add durable metadata for:

* primary keys and stable row identity;
* unique indexes;
* not-null/default/generated columns;
* check constraints;
* foreign keys with locality and support maturity metadata;
* isolation profile and freshness SLA;
* projection state for PAX/Parquet/Iceberg/Arrow publications.

Foreign-key v1 should be same-table/same-partition or explicitly local only. Cross-shard FKs,
deferrable constraints, and cascades stay Beta/Experimental until a transaction coordinator exists.

=== OLTP Commit Path

`DmlService`, `CatalogRow`, and `TableRecordStore` must enforce constraints before a mutation
becomes visible:

* validate row type/nullability/defaults/check expressions;
* consult current primary-key and unique indexes;
* validate local foreign-key references against the same visibility snapshot;
* append canonical WAL mutation;
* update the row/delta store and indexes atomically with visibility metadata.

=== Transaction And Visibility

Define the minimal MVP transaction profile:

* single-statement atomicity for DML;
* snapshot metadata for read consistency;
* row/table write conflict detection for primary-key and unique indexes;
* explicit rejection for unsupported isolation levels or cross-shard transactional semantics.

Serializable multi-statement transactions and distributed two-phase commit are post-MVP.

=== Volcano / Native Executor

Volcano remains the latency-sensitive OLTP executor. It should consume the same logical algebra as
DataFusion but choose native physical operators for:

* point lookup and small range lookup;
* primary-key and unique index probes;
* nested-loop/index lookup joins used for FK checks and selective OLTP plans;
* strong-freshness reads over WAL/row-delta state;
* plans that cannot tolerate stale OLAP publication watermarks.

=== DataFusion / OLAP Executor

DataFusion is the primary OLAP and MPP executor. It should read:

* Parquet/Iceberg/Arrow snapshots for scan-heavy analytical queries;
* cataloged PAX/Arrow-compatible scans when available;
* an explicit base-plus-delta union when `freshness_sla` requires records newer than the last
  published OLAP snapshot.

DataFusion must not bypass xCatalog policy/RLS, authority mode, or freshness checks.

== CAP And Consistency Policy

For single-node MVP, the important contract is ACID/MVCC behavior, not CAP. For distributed mode:

* OLTP partitions that promise PostgreSQL-style committed state should prefer CP behavior and reject
  writes/reads that cannot meet the isolation/freshness contract.
* OLAP projections may be asynchronously refreshed, but only with explicit `freshness_sla`,
  snapshot watermark, and `EXPLAIN` metadata.
* AP/eventual behavior is acceptable only for declared projections, caches, external delegated
  reads, or Beta/Experimental surfaces.

== Sequenced Slices

. **Slice A0 — Row-DML route guard.** DONE 2026-06-04: VALUES/row-level writes stay native/WAL
  even for OLAP-profile tables; DataFusion remains for analytical transforms, snapshot reads, and
  OLAP publication.
. **Slice A1 — Constraint-gap route metadata.** DONE 2026-06-04: table-write `EXPLAIN` reports
  native constraint-enforcement status and cataloged gaps for unique and foreign-key constraints.
. **Slice A2 — Catalog metadata completion.** DONE 2026-06-04 for EXPLAIN visibility: expose
  xCatalog projection freshness, lineage, repair source, policy boundary, support status, and
  benchmark-gate metadata through table-write route metadata. Remaining enforcement work stays in
  Slice E/F/G.
. **Slice B0 — Simple CHECK enforcement.** DONE 2026-06-04: enforce column-literal CHECK
  comparisons in `CatalogRow`; unsupported expressions fail closed until a real SQL expression
  evaluator is wired in.
. **Slice B1 — Stateful constraint fail-closed guard.** DONE 2026-06-04: reject non-null UNIQUE
  and FK tuples before WAL/storage mutation materialization until native unique-index and reference
  checks exist; expose those fail-closed semantics through table-write `EXPLAIN`.
. **Slice B — Constraint enforcement.** Enforce primary key, unique, not-null, and richer check
  constraints in `DmlService`/`CatalogRow`/`TableRecordStore`; reject unsupported foreign-key forms.
. **Slice C — OLTP index state.** Add current primary-key and unique-index access paths over the
  row/delta store with WAL recovery.
. **Slice D — Volcano physical operators.** Add index lookup and selective join operators that use
  the shared algebra but stay on the native path.
. **Slice E — Snapshot publisher.** Publish OLAP snapshots to Parquet/Iceberg/Arrow with cataloged
  freshness and repair source.
. **Slice F — DataFusion delta union.** Teach DataFusion table providers to read a snapshot plus
  eligible row/delta state when the route requires fresher HTAP visibility.
. **Slice G — Distributed gates.** Define partition-local transaction/FK rules and reject cross-shard
  semantics until a coordinator exists.

== Verification Gates

* pgwire DML tests cover primary-key, unique, not-null, and check constraint success/failure.
* Same-partition FK tests pass or unsupported FK shapes are rejected with clear SQLSTATE/error text.
* `EXPLAIN` reports `authority_mode`, `workload_profile`, `compute_route`, `freshness_sla`, snapshot
  watermark, and rejected route reasons.
* Volcano and DataFusion return identical results for snapshot-safe queries over the same table.
* Fresh HTAP reads either union delta state correctly or reject the route when freshness cannot be
  honored.
* Recovery tests rebuild row/delta/index state from WAL before accepting writes.
