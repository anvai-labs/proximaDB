== Provenance and bounded scope

Continuation `fix/p24-delete-readers-complete` cherry-picked GLM source commit
`51cefaaf2f7eaf904ace1d9f70ae250b2c0d864a` as `f5bc0f555` and incorporated its two uncommitted
reader/test fixes. The original worktree is preserved. Captured patch SHA-256:
`194ce951df770038620632be28cb30ed5893b5a4fc3b7367f63a2a33fb47fa5e`.

The engine bridge exposes snapshot files plus deletion descriptors. DataFusion applies physical
row-position masks before predicates/limits; deleted files disable page pruning so positions
remain valid. Row-group counts account for physical offsets, invalid positions fail, and
post-delete column statistics are demoted. Range cardinality avoids expanding large vectors
just to adjust statistics. The optional DuckDB adapter uses manifest-selected file provenance,
correct negated predicates, a bounded SQL expansion and consistent decoded local file paths.

Bulk append reloads inherited DVs with each fenced retry and retains their descriptors/Puffin
sizes. Data-file GC reads snapshots through the deletion-aware bridge and does not remove
Puffin objects. MATERIALIZE refuses a DV parent until native-state synchronization is proven;
it cannot rewrite live native rows over an independently deleted published view.

== Adversarial findings repaired

* Incorrect DuckDB predicate polarity, nested read_parquet source composition and doubled root
  paths; local file provenance also needs URL decoding and removal of the file scheme.
* Footer/count shortcuts could ignore DVs. Native raw-file scan admission now refuses those
  snapshots before footer elision; the supported published reader handles them.
* Path-only table-open caching cannot see an independent snapshot change. Published `/data`
  opens bypass it. WAL-only result caching is bypassed after resolving published dependencies.
* A mixed-query native row-cap fallback could replace published inputs with live native state.
  It now returns an explicit shared-snapshot refusal. Streaming Layer A remains available.
* A nonempty native WAL delta cannot be ordered against an independently published DV snapshot.
  That merge now refuses instead of restoring a deleted row. Empty-delta published reads work.

These are published-provider guarantees. Legacy/simple native-state reads do not acquire
external-DV synchronization, and disabling the provider gate is not a promise of published-view
semantics. A common publication/WAL visibility fence remains required for the writer slice.

== Remaining delivery

V3-first remains the decision. New-table v3 defaults, atomic legacy upgrade, row-lineage
allocation and live incremental update/delete publication are separate gates. No new v2 delete
writer is planned. Subject deletion still distinguishes current visibility, historical snapshot
access, snapshot expiry and physical erasure. Cache bypasses and explicit refusals may be
relaxed only after snapshot-keyed caching and a shared writer/read fence are proved.
