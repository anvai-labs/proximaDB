= TD-TIER-1 E1 filtered queries: the PAX filter-path mechanism and its cost

**Date:** 2026-10-28 · **Branch:** `bench/tier1-e1-filter` — runs executed at worktree HEAD `57d6f7bdc` (harness-extension commit over the anchor `290da7e7d` = develop `ef3f74b79` + zero-change anchor) with **binary sha256 `8f81632d…`** (built 2026-10-27 22:0x with `--features aws`; the anchor-tree family trap disclosed in the fragment-ladder artifact) · **TD:** link:../../10-quality/td/TD-TIER-1-collection-storage-policy-and-residency.adoc[TD-TIER-1] SC0/E1 · **Mechanism/design:** link:../../10-quality/td/TD-FPRUNE-1-filter-aware-cascade-arc.adoc[TD-FPRUNE-1] (P3/P4 named-open; this run supplies the corridor-class evidence its P2 gate awaited) · **Companion to** link:TIER1_E1_FRAGMENT_LADDER_2026_10_27.adoc[the fragment ladder].

== What this run establishes

1. **The filter-path mechanism, traced and measured.** A metadata filter on a
   trained PAX/SST collection (no HNSW) does not change the probe *plan* (same
   16-cell directory choice, same ~768k probed rows) but changes the read
   *shape*: the Stage-F allow-set fetch reads the **whole D region (props +
   scalar columns of every row) per query** before the filter-aware cascade
   runs. Measured at 3M: **834 MB of the 936.93 MB/query (89%) is the D
   fetch**; the cascade itself (Region A 8.3 + Region B 94.3 MB) is standard
   cost. The exact fallback (`search_pax_file_exact`) never fired
   (`whole_region_fallbacks: 0`; cascade = 99.8% of wall).
2. **The cost multiple.** Filtered vs unfiltered at 3M, same bed, same cap4,
   n=1000: **277.55 vs 52.74 req/q, 936.93 vs ~150 MB/q, p50 6.02 vs 0.27 s**
   (22×) in `object_cold`; `post_write`/warm within ~7% of cold (the 10 GB
   local disk cache cannot hold the D-region working set — cache-invariant).
3. **Selectivity-independence, proven twice.** The 50k probe showed match-all
   filters behave identically to 10%/50%/2%; the static
   `estimated_selectivity` trace labels (0.1/0.3) are heuristics, not
   measurements.
4. **The design direction (approved plan 2026-10-28; filed against
   TD-FPRUNE-1, not a new TD).** The fix is a storage↔compute co-design and
   maps onto FPRUNE-1's named-open phases plus three new ones: the footer-stats
   measurement this family supplies (P2's awaiting gate), **P3 per-cell stats**
   = per-cell min/max in an additive footer section, **P4 selectivity policy**
   = measured selectivity replacing the static table; new: residual-tail ON
   (store filter columns once, typed — shrinks the D region ~6×),
   filter-aware directory planning (order-prior on the M3 walk — remove only
   the filter half of the `filtered_or_exact` exclusion), and cell-scoped lazy
   Stage F (fetch D data only for walked cells; allow bitmap byte-identical
   invariant). Arithmetic targets from these measurements: residual-tail →
   ~242 MB/q; +cell-scoping → ~138 MB/q ≈ unfiltered parity. Full plan:
   `~/.claude/plans/compressed-drifting-wind.md` (session-local; this artifact
   + the TD-FPRUNE-1 update carry the design).

== Protocol

Fixed-object family on one bed: 3M SIFT128 learn-split corpus, REST ingest with
deterministic metadata props (`category=i%10`, `half=i%2`, `idnum=i`),
`--training-compaction-min-mb 1`, MinIO behind toxiproxy 5+5 ms, cap4 builds.
Filtered arms carry `--search-filters category:eq:3` (10% selectivity) and an
exact filtered ground truth (top-100 among matching rows, computed by brute
force per query window). **Recall gate relaxed 0.98 → 0.97 per user direction
2026-10-28** (the 0.98 gate fails every unfiltered 3M phase on geometric-nprobe
under-coverage, disclosed since the scale arms). n=1000 per phase except where
marked n=250.

== Bed and geometry (disclosed drift)

The build settled at **2 segments (1.284M/46c + 1.716M/62c, 1,257,460,918 B)**
— not the Flight family's 741 MB single segment: the REST+props path stores
**~419 B/row vs 247 B/row** (three int props ≈ 170 B/row of msgpack named-map
encoding: keys repeated per row, no dictionary, serde-enum wrappers). The
first reuse arm's idle server then **merged the 2-segment bed to 1 segment**
(the dynamic auto compaction budget fits 1257 MB when unloaded — the same
drift the fragment ladder's static-ceiling invariant guards against), so the
arm family measured the **terminal 1-seg 3M/62c bed**; the build's 2-seg
phases are kept as a disclosed footnote, and the unfiltered references were
completed on the 1-seg bed for matched geometry.

== The cap lever on the filtered path (the inversion, confirmed)

Filtered cap4 → cap16 (n=1000 vs n=250 — asymmetry disclosed; req/q is a
stable per-query metric): **277.55 → 100.01 req/q (−64.0%)**, GETs 275.55 →
98.01, p50 6019 → 4036 ms (−33%), bytes 936.93 → 896.94 MB (−4%, as expected —
the cap changes request count, not scan volume), recall 0.9747 → 0.9748,
post_write/warm again cache-invariant (80.4/81.4 req/q). For filtered queries
the range cap is the **dominant request lever** — a 64% cut where the
unfiltered 2-seg baseline measured −33% and the fragment ladder measured
−13…−16% at 2–4 segments. This is the design's "S2a floor" context: scan
coalescing already mitigates filtered requests; the co-design targets the
bytes (the 89% D-fetch) on top of it.

== The 50k semantics probe (pre-arm, same binary)

One bed, one query vector, `debug:true` traces: unfiltered 8 GETs / 7.75 MB
(directory probe at nprobe=2) vs filtered 24–35 GETs / 25–30 MB at
selectivities 10%, 50%, 2%, **and match-all** — filter *presence*, not
selectivity, flips the read path. Schema-declared `indexed`/`filterable`
columns changed nothing. The whole-corpus read at 50k is compounded by
`SearchMode::default()=Adaptive{100k}` + `EXACT_SCAN_MAX_BYTES=64 MiB` forcing
exact scans at that scale for both arms. Probe script:
`~/bench-beds/p5b-runs/e1p_filter_probe.py`.

== Mechanism (code-traced; file:line at worktree HEAD)

1. `centroid_directory_cells(..., filtered_or_exact = filter.is_some() ||
   force_exact)` returns an **empty map** — filtered queries lose directory
   planning, D6 decode keys, and zero-read segment skipping
   (`src/storage/engines/sst/search/mod.rs:2116`,
   `centroid_directory_reader.rs:37-38`).
2. Stage F (`pax_filtered_row_allow`, `segment_format.rs:1213`) fetches **all
   D-block bodies for the whole segment, per query**, parses the msgpack
   props per row, and builds the `RowAllow` bitmap.
3. The M3 filter-aware cascade then runs correctly (cells nearest-first,
   `allow.count_in_range` skips empty cells, adaptive nprobe;
   `coarse_probe_survivors :3433`) — which is why the probe telemetry looks
   identical to unfiltered while the bytes do not.
4. The REST trace labels (`hybrid_filter` / `full_precision_graph`) are
   post-hoc planner heuristics with empty statistics — cosmetic.
5. ADR-011 modes (PreFilter/Inline/PostFilter) are computed, threaded, and
   ignored for PAX collections (AXIS requires `index_configs`;
   `legacy.rs:89-92, 4522-4528`).

== What this does NOT establish

n=1 per cell (exploratory; directions, not distributions); learn-split corpus;
the 3M selectivity control arm was dropped (the 50k match-all probe
establishes selectivity-independence; re-runnable in ~3 h if review demands);
no default or pricing change; the design targets (242/138 MB) are arithmetic
from measured constants, not yet measured implementations.
