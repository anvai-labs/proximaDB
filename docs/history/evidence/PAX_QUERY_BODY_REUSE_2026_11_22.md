# PAX query-scoped whole-object reads

A cold ANN search of one 1K × 128d SIFT object used to request 748,270 bytes, then issue two more GETs inside those same bytes. The duplicate reads averaged 162,504 bytes per query. The reader can now serve the remaining ranges from the first validated response. The adaptive gate can use that same object for the footer and the eventual scan. This changes the transport beneath the existing scorers. [Original wire evidence and fixture](https://github.com/anvai-labs/proximaDB/blob/7c01ddca4/docs/history/evidence/PAX_SIFT_SCALE_REQUESTS_2026_11_22.adoc)

## Read policy

- Use ordinary collection discovery, retirement filtering, and verified directory facts. A query-local body only services a selected immutable segment. Compaction writes new keys. A fresh process still pays for a LIST when it must establish membership. Persistent object bytes alone cannot establish membership after a restart.
- On an ANN invariants miss, or when adaptive needs facts for one segment after a directory miss, compare the listed file length with the cold prefix. If the prefix reaches EOF, reuse its bytes through routing, filtering, ranking and hydration. An explicit approximate request retains the ANN scorer. Exact still requires the existing authority and visibility checks.
- `PROXIMADB_PAX_WHOLE_OBJECT_MAX_BYTES=8388608` also permits a full read of a listed object up to 8 MiB. The default allows only the ordinary prefix (normally 1 MiB) to qualify. The 8 MiB hard cap applies in either case. This setting does not widen partial reads of larger objects, modify the ANN merge cap or change the exact-scan budget.
- Validate the listed length, the coalesced header and trailer’s agreement on the footer extent, or the legacy PAX trailer and block index. Keep the resulting bytes within this query’s engine and storage assignment. A failed fill publishes no bytes. On an optional wider-read failure, try the existing range plan. Invalid ranges fail closed. Legacy RawF32 can reuse bytes while retaining its existing admission semantics.
- Queries reserve up to 8 MiB each against a shared 32 MiB nonblocking pool. Concurrent requests for the same object within the query share one fill. Under pressure the reader uses ordinary ranges. These limits cover retained query bodies. Decoder buffers, returned records and ordinary caches use separate memory. Long-lived invariants retain at most the usual prefix. A local slice issues zero physical GETs.

## What changed on the wire

One compacted object per corpus, 128d, ten SIFT queries, forced ANN, 8 MiB ANN **range-merge** setting. Each cold process starts with empty caches. The cost uses the archived S3 Standard, Azure Blob Hot and GCS Standard profiles at $0.40 per million GETs and $5 per million LISTs. Azure’s `abfs://` alias uses Blob. The dollar amounts cover read requests for this shape. Bytes, compute and latency still affect the deployment decision.

| Rows | Cold ANN before | Default after | 8 MiB whole-object option | Average object bytes, default → option | USD/M searches, default → option |
|---:|---:|---:|---:|---:|---:|
| 1,000 | 3 GET + 1 LIST | 1 GET + 1 LIST | 1 GET + 1 LIST | 748,270 → 748,270 | 5.40 → 5.40 |
| 10,000 | 4 GET + 1 LIST | 4 GET + 1 LIST | 1 GET + 1 LIST | 2,008,129 → 7,428,147 | 6.60 → 5.40 |
| 33,000 | 4 GET + 1 LIST | 4 GET + 1 LIST | 4 GET + 1 LIST | 4,148,994 → 4,148,994 | 6.60 → 6.60 |

The 1K default saves $0.80 per million cold searches versus the previous $6.20. At 10K the opt-in saves $1.20/M in requests while transferring about 5.17 MiB more per cold search. Larger corpora receive no benefit from this policy on this fixture. As a control, raising the **general prefix** to 8 MiB on the 33K object increased cold ANN response bytes to 11,489,026 without saving a GET. This difference is why the controls are independent. At 1K the immediate ANN repeat still needs one smaller GET and zero LISTs; a disk-cache reopen needs one smaller GET plus one LIST.

The 558 reconciled query windows (186 per configuration) preserved the ordered result IDs, observed route and overlap for every matching historical query. A separate normal-flush fixture wrote 10,000 rows as ten segments. Both directory-on and directory-off tests passed. With a published directory both first-query routes used 11 GETs and one LIST, and the incremental adaptive metadata GET count was zero. A ten-segment collection cannot obtain all ten objects in one GET. [Normal-flush counters](../../../bench_results/pax_query_body_20261122/normal_flush.json)

The source logs and query ledger capture cold, DRAM-repeat, restarted disk-cache and adaptive-policy windows. Compare ordered IDs, overlap, and the actual route with the original archive. The adaptive-policy worker runs query zero at each budget. The historical study recorded exact and adaptive controls under its first merge cap (4 MiB); all new paired arms use 8 MiB. Compare ANN with the historical 8 MiB arm and use the adaptive rows to check route and result parity. The wire counter includes GET, LIST and HEAD independently. These are Azurite observations with modeled prices; throughput, real-cloud tail latency and process peak RSS under concurrency remain unmeasured. ## Reproduce

The benchmark can be reproduced by combining the atlas harness at `7c01ddca4` with reader commit `050990408`. To reproduce from the repository, create a disposable worktree at the harness revision and cherry-pick the reader commit there. Build the SIFT test target with features `azure,io-trace`. The Azurite image ID for this capture was `sha256:c26024d62bf4a5b88a40968afd217234c00e1fc9a4790dc6105d1ca7979f6eec`. Supply the public TEXMEX SIFT corpus and an isolated Azurite endpoint. Run the scale driver with `--rows 1000 10000 33000 --caps-mib 8 --queries 10 --wire-markers`. Run once with default settings and once with only `PROXIMADB_PAX_WHOLE_OBJECT_MAX_BYTES=8388608`. Keep separate access logs and a fresh storage prefix for each run. The prefix control sets only `PROXIMADB_PAX_PREFIX_PREFETCH_BYTES=8388608`. For each archived pair, run the wire reporter with the same rows, cap and query count. [Scale driver](https://github.com/anvai-labs/proximaDB/blob/7c01ddca4/scripts/bench/pax_scale_cost.py) · [Wire reporter](https://github.com/anvai-labs/proximaDB/blob/7c01ddca4/scripts/bench/pax_scale_wire_report.py)

An authoritative manifest head is a separate publication decision. One extra PUT per publish would need more than 1.09 cold discoveries per publish to recover its modeled S3 Standard request cost. The SIFT replay does not measure the production ratio of cold discoveries to publishes. Adding a head GET before the existing LIST would increase the read bill. Replacing LIST safely requires writer fencing, snapshot retention and recovery. These read optimizations require no additional PUTs.
