= Storage Engine Selection Guide
:toc: left
:toclevels: 3
:icons: font
:source-highlighter: rouge
:last-updated: 2026-10-17

[.lead]
Choose the vector storage engine for a collection. Tiers come from
link:../SUPPORTED_SURFACE.adoc[the support contract]; this page carries no performance numbers
(see <<performance>>).

== Engines at a glance

[cols="1,1,3", options="header"]
|===
| Engine | Tier | Use it for

| **SST**
| Supported
| Every new collection unless you have measured a reason to choose otherwise (pass `engine="sst"`: omitting it auto-routes to HELIX until v0.5, TD-ENGSEL-1): real-time ingestion
and search, filtered vector search, PAX segments on object storage.

| **HELIX**
| Beta
| High-dimensional embeddings where locality ordering (PCA + Hilbert) helps. Measure recall on your
own data first: HELIX recall is open work (TD-HELIX-1..3), and roadmap v0.6 either fixes or
demotes it.

| **NOVA**
| Beta
| Mixed read/write workloads with progressive columnar layout.

| **VIPER**
| Deprecated (ADR-093)
| Existing collections only. New VIPER selections are rejected; removal is roadmap v0.6.

| **SWIFT**, **RAPTOR**
| Experimental, off by default
| Not for product use; deleted in roadmap v0.6 (ADR-006).
|===

[NOTE]
====
**Analytics is not an engine choice.** For analytical SQL (scans, joins, aggregates), use a
relational table over pgwire and `ALTER TABLE … MATERIALIZE` it: the planner then routes
analytical queries to DataFusion over Parquet (ADR-052). Vector engines serve similarity search.
====

== Use case recommendations

=== Real-time and RAG applications

**Recommended: SST**

Chat and agent memory, real-time recommendation, streaming ingestion, document and knowledge-base
retrieval with metadata filters.

[source,python]
----
from proximadb_sdk import ProximaDBClient, Protocol

client = ProximaDBClient(url="http://localhost:5678", protocol=Protocol.REST)

# SST is the Supported engine (the Python SDK sends it by default)
client.create_collection(
    name="knowledge_base",
    dimension=768,
    storage_engine="sst",
)
----

=== When to evaluate HELIX or NOVA

Only after measuring SST on your own data with the
link:../02-guides/vector-index-selection-and-benchmarking.md[index selection and benchmarking guide].
Both are Beta: compare recall and per-query I/O against SST before switching.

=== Experimental Engines (SWIFT, RAPTOR)

[WARNING]
====
**SWIFT and RAPTOR are experimental and OFF by default.** They live behind the
`experimental-engines` cargo feature; a stock build rejects them at the engine
factory. They are *not* part of the supported surface and are deleted in roadmap release v0.6. Enable only with `cargo build --features experimental-engines`.
====

When enabled, they target two niches not covered by the supported engines:

* **SWIFT** -- in-memory, exact nearest-neighbor for tiny collections (<10K vectors),
  prototyping, and small isolated multi-tenant sets. Use **SST** or **NOVA** instead for
  any supported workload.
* **RAPTOR** -- adaptive row-group layout for evolving/unpredictable access patterns. Use
  **NOVA** (mixed read/write) for supported mixed workloads.

Config knobs and bench numbers for both appear in the SWIFT/RAPTOR subsections of the
Engine Configuration Reference and Performance Benchmarks below (clearly marked experimental).
Do not build production collections on these engines.

== Engine Configuration Reference

=== SST Engine Options

[cols="2,1,3,2", options="header"]
|===
| Option | Type | Description | Default

| `compression`
| string
| Compression algorithm: `none`, `lz4`, `zstd`, `snappy`
| `lz4`

| `flush_threshold_mb`
| int
| MemTable size before flush to disk
| 64

| `bloom_filter_fpp`
| float
| Bloom filter false positive probability
| 0.01

| `block_size`
| int
| SSTable block size in bytes
| 65536

| `compaction_style`
| string
| `leveled` or `tiered`
| `leveled`
|===

=== HELIX Engine Options

[cols="2,1,3,2", options="header"]
|===
| Option | Type | Description | Default

| `pca_dimensions`
| int
| Target dimensions after PCA (0 = disable)
| 64

| `hilbert_bits`
| int
| Hilbert curve precision (higher = more locality)
| 16

| `cluster_size`
| int
| Vectors per locality cluster
| 256

| `enable_quantization`
| bool
| Enable PQ quantization for memory reduction
| false
|===

=== VIPER Engine Options (deprecated — existing collections only)

[cols="2,1,3,2", options="header"]
|===
| Option | Type | Description | Default

| `compression`
| string
| `zstd`, `lz4`, `snappy`, `gzip`
| `zstd`

| `row_group_size`
| int
| Parquet row group size
| 100000

| `enable_statistics`
| bool
| Column statistics for predicate pushdown
| true

| `parquet_version`
| string
| `1.0` or `2.0`
| `2.0`
|===

=== SWIFT Engine Options (experimental — off by default)

NOTE: SWIFT requires `--features experimental-engines` and is not a supported engine.

[cols="2,1,3,2", options="header"]
|===
| Option | Type | Description | Default

| `in_memory`
| bool
| Keep all data in memory
| true

| `exact_search`
| bool
| Disable approximate search (brute force)
| true

| `superblock_size`
| int
| Vectors per superblock
| 1024
|===

=== NOVA Engine Options

[cols="2,1,3,2", options="header"]
|===
| Option | Type | Description | Default

| `zone_map_granularity`
| int
| Rows per zone map entry
| 1000

| `progressive_search`
| bool
| Enable progressive refinement
| true

| `cache_size_mb`
| int
| Block cache size
| 128
|===

=== RAPTOR Engine Options (experimental — off by default)

NOTE: RAPTOR requires `--features experimental-engines` and is not a supported engine.

[cols="2,1,3,2", options="header"]
|===
| Option | Type | Description | Default

| `adaptive_pruning`
| bool
| Enable adaptive block pruning
| true

| `cache_hot_blocks`
| bool
| Cache frequently accessed blocks
| true

| `rebalance_threshold`
| float
| Trigger rebalancing at this skew ratio
| 0.3
|===

== Changing Engines

=== Migration Strategy

Engines cannot be changed in-place. To migrate:

1. Create a new collection with the target engine
2. Export vectors from the source collection
3. Import vectors to the target collection
4. Update application to use the new collection
5. Delete the old collection

[source,python]
----
# Export from the SST collection (pseudocode: page through the records with the REST scan
# endpoint or the Arrow Flight export in the Arrow export guide)
vectors = export_all_records("old_collection")

# Create new HELIX collection
client.create_collection("new_collection", dimension=768, storage_engine="helix")

# Import through the canonical record API
client.insert_records("new_collection", vectors)

# Verify and switch
assert client.get_collection_stats("new_collection")["vector_count"] == len(vectors)
----
