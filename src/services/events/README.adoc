= Event Services
:toc:
:toclevels: 2

== Overview

The Event Services module provides **server-level service wrappers** for event coordination systems. This follows the same pattern as `CollectionService` and `VectorOperationsService`, managing lifecycle, dependency injection, and providing clean APIs for other components.

== Purpose

*Primary Goal*: Provide initialized, ready-to-use event services at server startup with proper dependency management.

=== Why Not Use EventLog Directly?

The core AXIS EventLog (in `src/index/axis/eventlog/`) is a pure coordination library. This service wrapper adds:

1. **Lifecycle Management**: Initialize once at server startup, share across threads
2. **Dependency Injection**: Provide shared resources (collection cache, filesystem)
3. **Global Access**: Singleton pattern for easy access from storage engines
4. **Configuration**: Load settings from server config, environment, etc.

== Components

=== 1. EventLogService (log.rs)

Service wrapper around AXIS EventLog implementation:

[source,rust]
----
pub struct EventLogService {
    /// Core event log implementation
    inner: Arc<dyn EventLogServiceTrait>,

    /// Shared collection cache
    collection_cache: Arc<DashMap<String, Arc<Collection>>>,

    /// Filesystem factory for persistence
    filesystem_factory: Arc<FilesystemFactory>,
}

impl EventLogService {
    /// Initialize at server startup
    pub async fn new(
        collection_cache: Arc<DashMap<String, Arc<Collection>>>,
        filesystem_factory: Arc<FilesystemFactory>,
        base_storage_url: Option<String>,
    ) -> Result<Arc<Self>>;

    /// Notify about flush (blocks until persisted)
    pub async fn notify_flush(
        &self,
        collection_id: &str,
        flushed_files: Vec<String>,
        vector_count: usize,
        has_quantized: bool,
        has_fp32: bool,
        storage_engine: StorageEngineType,
    ) -> Result<()>;

    /// Check if file can be compacted
    pub async fn can_compact(&self, collection_id: &str, file: &str) -> bool;

    /// Other delegation methods...
}
----

=== 2. Global Service Access

Singleton pattern for easy access:

[source,rust]
----
/// Get global EventLog service instance
pub fn event_log_service() -> Option<Arc<EventLogService>> {
    GLOBAL_EVENT_LOG.lock().unwrap().clone()
}

/// Initialize global instance (called once at server startup)
pub async fn init_event_log_service(
    collection_cache: Arc<DashMap<String, Arc<Collection>>>,
    filesystem_factory: Arc<FilesystemFactory>,
    base_storage_url: Option<String>,
) -> Result<()>;
----

Usage in storage engines:

[source,rust]
----
// In flush operation
if let Some(event_log) = event_log_service() {
    event_log.notify_flush(...).await?;
}
----

=== 3. Event Persistence Layer (persistence.rs)

Filesystem-based storage helpers for events:

* **Atomic Writes**: Ensures events are fully written or not written at all
* **Cloud Compatibility**: Works with S3, GCS, Azure Blob Storage
* **Recovery**: Scan and restore events on restart

== Integration with Server Startup

=== Initialization Sequence

[source,rust]
----
// In main server startup (src/main.rs or server.rs)
async fn start_server(config: ServerConfig) -> Result<()> {
    // 1. Create shared resources
    let filesystem_factory = Arc::new(FilesystemFactory::new(config.fs_config).await?);
    let collection_cache = Arc::new(DashMap::new());

    // 2. Initialize CollectionService
    let collection_service = CollectionService::new(
        collection_cache.clone(),
        filesystem_factory.clone(),
    ).await?;

    // 3. Initialize EventLogService
    init_event_log_service(
        collection_cache.clone(),
        filesystem_factory.clone(),
        config.base_storage_url,
    ).await?;

    // 4. Initialize VectorOperationsService
    let vector_ops = VectorOperationsService::new(
        collection_service.clone(),
        filesystem_factory.clone(),
    ).await?;

    // 5. Start servers (REST, gRPC)
    start_servers(config).await
}
----

== Usage Patterns

=== From Storage Engines

Storage engines notify EventLog after successful flush:

[source,rust]
----
// In SST/VIPER/NOVA flush operation
pub async fn flush(&self, params: FlushParameters) -> Result<FlushResult> {
    // 1. Write data to disk
    let flushed_files = self.write_to_disk(&vectors).await?;

    // 2. Notify EventLog (synchronous - blocks until persisted)
    if let Some(event_log) = event_log_service() {
        event_log.notify_flush(
            &collection_id,
            flushed_files.clone(),
            vectors.len(),
            has_quantized,
            has_fp32,
            StorageEngineType::SST,
        ).await?;
    }

    // 3. Return result
    Ok(FlushResult { files: flushed_files, ... })
}
----

=== From AXIS Indexers

AXIS indexing workers consume events:

[source,rust]
----
// In AXIS indexer background task
pub async fn index_worker_loop(event_log: Arc<EventLogService>) {
    loop {
        // Get pending events
        let events = event_log.get_pending_events(10).await;

        for event in events {
            // Build indexes
            build_axis_indexes(&event).await?;

            // Mark complete
            event_log.mark_processed(&event.event_id).await?;
        }

        tokio::time::sleep(Duration::from_secs(1)).await;
    }
}
----

=== From Compaction Threads

Compaction checks if files can be safely deleted:

[source,rust]
----
// In compaction background task
pub async fn compact_files(&self, files: &[String]) -> Result<()> {
    // Check if all files have completed AXIS indexing
    if let Some(event_log) = event_log_service() {
        for file in files {
            if !event_log.can_compact(&self.collection_id, file).await {
                info!("Postponing compaction - AXIS indexes pending");
                return Ok(());
            }
        }
    }

    // Safe to compact
    self.merge_and_delete_files(files).await
}
----

== Relationship with AXIS EventLog

|===

== Error Handling

=== Graceful Degradation

If EventLog service is not available:

[source,rust]
----
// Storage engines check for None
if let Some(event_log) = event_log_service() {
    event_log.notify_flush(...).await?;
} else {
    // Continue without AXIS coordination
    warn!("EventLog not available - AXIS indexing may lag");
}
----

=== Failure Modes

[options="header"]
|===
| Failure | Impact | Mitigation

| EventLog service not initialized
| AXIS indexes not built automatically
| Manual index rebuild, recovery scan

| Event persistence fails
| Storage flush succeeds but event lost
| Retry logic, detect missing indexes on next scan

| Network partition (cloud storage)
| Events may be delayed or duplicated
| Idempotent event processing, deduplication
|===

== Metrics and Monitoring

=== Key Metrics

* **events_added_total**: Total events added to queue
* **events_processed_total**: Total events completed by AXIS indexers
* **event_lag_seconds**: Time between event creation and processing
* **can_compact_checks_total**: Number of compaction eligibility checks
* **pending_events_count**: Current queue depth
