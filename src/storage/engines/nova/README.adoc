= NOVA Storage Engine
:toc: left
:toclevels: 2
:icons: font

[abstract]
Progressive columnar storage engine with multi-level quantization for mixed workloads and adaptive search strategies.

== Overview

NOVA (New Optimized Vector Architecture) is ProximaDB's progressive columnar storage engine designed for mixed read/write workloads with intelligent quantization levels.

**Key Features**:

* Progressive search (Binary → INT8 → Full precision)
* Multi-level quantization storage
* Columnar Parquet format
* Operations-based modular design
* Adaptive query optimization
* Balanced read/write performance

== Progressive Search Strategy

NOVA's key innovation is progressive filtering through quantization levels:

=== Level 1: Binary Filtering (Fastest)

**Purpose**: Eliminate 90% of vectors quickly

**Characteristics**:

* 1 bit per dimension (32x smaller)
* Hamming distance computation
* ~100x faster than full precision
* High false positive rate (acceptable)

[source,rust]
----
// Level 1: Binary filter
let binary_vectors = self.load_binary_column().await?;
let candidates_l1 = binary_vectors
    .into_iter()
    .enumerate()
    .map(|(id, vec)| {
        let dist = hamming_distance(&query_binary, &vec);
        (id, dist)
    })
    .filter(|(_, dist)| *dist < threshold_l1)
    .collect();

// Keep top 10% for next level
candidates_l1.sort_by_key(|(_, dist)| *dist);
let top_10_percent = &candidates_l1[..candidates_l1.len() / 10];
----

=== Level 2: INT8 Filtering (Balanced)

**Purpose**: Refine to top 1% with good accuracy

**Characteristics**:

* 8 bits per dimension (4x smaller)
* Euclidean distance on quantized values
* ~10x faster than full precision
* 95%+ recall at this stage

[source,rust]
----
// Level 2: INT8 refinement
let mut candidates_l2 = Vec::new();
for (id, _) in top_10_percent {
    let int8_vec = self.load_int8_vector(*id).await?;
    let dist = euclidean_distance_int8(&query_int8, &int8_vec);
    candidates_l2.push((*id, dist));
}

// Keep top 1% (or top_k * 10) for final level
candidates_l2.sort_by(|(_, a), (_, b)| a.partial_cmp(b).unwrap_or(std::cmp::Ordering::Equal));
let top_1_percent = &candidates_l2[..(request.top_k * 10).min(candidates_l2.len())];
----

=== Level 3: Full Precision (Final)

**Purpose**: Exact top-k results

**Characteristics**:

* 32 bits per dimension (full f32)
* Exact distance computation
* Only computed for final candidates
* 99%+ recall

[source,rust]
----
// Level 3: Full precision rerank
let mut final_results = Vec::new();
for (id, _) in top_1_percent {
    let full_vec = self.load_full_vector(*id).await?;
    let exact_dist = euclidean_distance_f32(&request.query_vector, &full_vec);
    final_results.push(SearchResult { id: *id, distance: exact_dist });
}

final_results.sort_by(|a, b| a.distance.partial_cmp(&b.distance).unwrap_or(std::cmp::Ordering::Equal));
Ok(SearchResponse {
    results: final_results.into_iter().take(request.top_k).collect(),
})
----

== Multi-Level Quantization

=== Quantization During Write

NOVA quantizes vectors at multiple levels during insertion:

[source,rust]
----
async fn insert_batch(&self, vectors: Vec<VectorRecord>) -> Result<()> {
    // Quantize at all levels
    let binary = self.quantize_binary(&vectors).await?;
    let int8 = self.quantize_int8(&vectors).await?;
    let full = vectors;  // Keep full precision

    // Write to columnar storage
    self.write_binary_column(&binary).await?;
    self.write_int8_column(&int8).await?;
    self.write_full_column(&full).await?;

    Ok(())
}
----

== Operations-Based Design

NOVA uses a modular operations-based architecture (refactored):

=== Flush Operation

Location: `operations/flush.rs`

[source,rust]
----
pub struct FlushOperation {
    engine: Weak<NovaEngine>,
}

impl FlushOperation {
    pub async fn execute(&self, vectors: Vec<VectorRecord>) -> Result<()> {
        // Multi-level quantization
        let quantized = self.quantize_all_levels(&vectors).await?;

        // Write to Parquet
        self.write_parquet(&quantized).await?;

        // Update metadata
        self.update_index(&vectors).await?;

        Ok(())
    }
}
----

=== Compaction Operation

Location: `operations/compaction.rs`

[source,rust]
----
pub struct CompactionOperation {
    engine: Weak<NovaEngine>,
}

impl CompactionOperation {
    pub async fn execute(&self) -> Result<()> {
        // Merge multiple Parquet files
        let files = self.select_files_for_compaction()?;
        let merged = self.merge_parquet_files(&files).await?;

        // Rebuild quantization indices
        self.rebuild_quantization_indices(&merged).await?;

        Ok(())
    }
}
----

=== Search Operation

Location: `operations/search.rs`

[source,rust]
----
pub struct SearchOperation {
    engine: Weak<NovaEngine>,
}

impl SearchOperation {
    pub async fn execute(&self, request: SearchRequest) -> Result<SearchResponse> {
        // Progressive filtering
        let l1_candidates = self.binary_filter(&request).await?;
        let l2_candidates = self.int8_filter(&request, l1_candidates).await?;
        let final_results = self.full_precision_rerank(&request, l2_candidates).await?;

        Ok(final_results)
    }
}
----

== Best Practices

=== When to Use NOVA

✅ **Good For**:

* Mixed read/write workloads
* Large-scale similarity search (>1M vectors)
* Need for balanced performance
* Recall vs speed trade-offs
* Multi-tenant scenarios

❌ **Not Ideal For**:

* Pure write-heavy workloads (use SST)
* Pure analytical (use VIPER)
* Small datasets (<100K vectors)
* Maximum compression priority

=== Optimization Tips

**Quantization Tuning**:

[source,toml]
----
# Adjust filter ratios based on recall requirements
[storage.engines.nova]
binary_filter_ratio = 0.05  # Stricter Level 1 (fewer candidates)
int8_filter_ratio = 0.005   # Stricter Level 2

# Result: Faster search, slightly lower recall
----

**Batch Sizing**:

[source,rust]
----
// Optimal batch: 10K-50K vectors
let batch_size = 10_000;
for chunk in vectors.chunks(batch_size) {
    engine.insert_batch(chunk.to_vec()).await?;
}
----

**Compaction Tuning**:

[source,toml]
----
[storage.engines.nova]
compaction_threshold = 3  # More frequent compaction
# Trade-off: Better search performance, more write overhead
----

== Adaptive Query Optimization

NOVA adapts search strategy based on query characteristics:

=== Query Analysis

[source,rust]
----
async fn search(&self, request: SearchRequest) -> Result<SearchResponse> {
    // Analyze query characteristics
    let strategy = self.select_search_strategy(&request)?;

    match strategy {
        SearchStrategy::FullProgressive => {
            // Use all 3 levels (best for large result sets)
            self.progressive_search(&request).await
        }
        SearchStrategy::SkipBinary => {
            // Skip Level 1, use INT8+Full (better accuracy)
            self.int8_direct_search(&request).await
        }
        SearchStrategy::DirectFull => {
            // Skip quantization entirely (small datasets)
            self.full_precision_search(&request).await
        }
    }
}
----

=== Strategy Selection

[source,rust]
----
fn select_search_strategy(&self, request: &SearchRequest) -> SearchStrategy {
    let total_vectors = self.get_total_vectors();

    if total_vectors < 10_000 {
        SearchStrategy::DirectFull  // Too small for progressive
    } else if request.recall_target >= 0.99 {
        SearchStrategy::SkipBinary  // High accuracy required
    } else {
        SearchStrategy::FullProgressive  // Standard progressive
    }
}
----

== Troubleshooting

=== High Storage Usage

**Symptom**: Storage 28% larger than expected

**Cause**: Multi-level quantization overhead

**Solution**:
[source,toml]
----
# Disable binary quantization if storage is critical
[storage.engines.nova]
enable_binary = false

# Result: -3% storage, slower search
----

=== Low Recall

**Symptom**: Search results missing relevant vectors

**Cause**: Too aggressive filtering at Level 1/2

**Solution**:
[source,toml]
----
[storage.engines.nova]
binary_filter_ratio = 0.2  # Keep more candidates
int8_filter_ratio = 0.02   # Keep more candidates

# Or skip binary entirely
enable_binary = false
----

=== Slow Search Despite Quantization

**Symptom**: Progressive search not faster than full precision

**Cause**: Dataset too small or thresholds too loose

**Solution**:
[source,rust]
----
// Check if progressive search is beneficial
if self.get_total_vectors() < 100_000 {
    // Use direct full precision search
    return self.full_precision_search(request).await;
}
----
